# 运行与排障

> 状态：✅ 基础手册
> 最近更新：2026-10-28

本手册用于日常检查、常见故障定位和发布前核对。不要在生产环境复制未经确认的调试命令；不要输出环境变量、数据库连接串、Token、Cookie 或请求正文。

## 1. 健康检查

### 服务端

```bash
curl -fsS http://127.0.0.1:39990/api/health
```

关键字段：

- `ok`
- `version`
- `releaseStage`
- `storage`
- `chatEnabled`
- `filesEnabled`
- `providersEnabled`

### 容器

```bash
docker ps --format 'table {{.Names}}\t{{.Status}}\t{{.Ports}}'
docker logs --since 10m --tail 200 workpivot-server
docker logs --since 10m --tail 100 workpivot-browser
docker logs --since 10m --tail 100 workpivot-database
```

### 数据库 schema

```bash
docker exec workpivot-database sh -lc \
  'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -Atc \
  "select max(version) from workpivot_meta.schema_versions"'
```

只读取 schema 版本，不输出连接串。

## 2. 常见故障

### 页面能打开，但发送没有反应

检查：

1. 浏览器控制台是否有 CSP、混合内容或 JS 异常。
2. 服务端是否 healthy。
3. 反向代理是否正确转发 SSE，且关闭响应缓冲。
4. HTTP IP 访问是否符合当前前端兼容层；生产优先使用 HTTPS 域名。
5. 登录会话、额度或模型配置是否有效。

### 模型请求失败

- 检查供应商 URL、协议、模型 ID 和密钥状态。
- 执行模型连通测试。
- 检查上下文预算和本轮工具结果大小。
- 若模型不可用，不要假定任务已完成；保留错误并允许重试。

### 工具缺失

| 工具 | 依赖 |
| --- | --- |
| `web_fetch` | 服务端出网或代理配置 |
| `web_search` | SearXNG/Brave 配置 |
| `browser_visit` | Browser Service 和 Token |
| `execute_skill` / `run_code` | Worker、执行器镜像和任务授权 |
| `create_pdf` | Browser Service |
| Office 转 PDF | 包含 LibreOffice 的执行器镜像 |

工具缺失时先检查部署配置和容器健康，不要通过宿主 shell 临时替代。

### 文件生成失败

1. 检查执行器镜像是否包含对应 Office/Python/字体依赖。
2. 检查输入文件版本是否仍在授权范围。
3. 检查输出是否超过大小、数量或页数限制。
4. 检查 Skill 是否已确认发布并固定版本。
5. 生成成功但视觉异常时，记录为业务质量问题，不把结构有效当完整正确。

### 记忆没有生成

- 确认“自动整理”开关和对应层更新开关启用。
- 确认语句明确表达长期/项目/任务事实，而不是“好的”“继续”。
- 检查 `memory_jobs` 是否 pending/running/failed。
- 个人/项目记忆按项目作用域使用；旧全局记忆需要重新指定归属。
- 新规则每轮识别三层，满 10 轮再做补充分析；不要迫使模型为无信息对话制造记忆。

### 记忆已保存但回答没有使用

- 检查任务 `resource-scope` 的 `memoryScopes` 是否包含目标层，且对应层 `load_enabled=true`。
- 每轮会自动加载最多 8 条、约 3200 字相关记忆；其余细节应按需调用 `search_memory/read_memory`。
- 查询词与记忆没有直接匹配时只会补充各层最新一条概览，不能保证任意历史事实都进入上下文。
- 检查服务端是否已部署包含自动召回的执行链；仅升级页面不会改变服务端注入。
- 不通过复制完整私人记忆到日志来排障，使用作用域、条数、revision 和错误状态核对。

### 多终端任务或执行步骤不同步

- 项目/任务列表使用 `/api/workspace/stream?after=<version>`；同一任务过程使用 `/api/tasks/{id}/stream?after=<sequence>`。
- 检查反向代理是否为 SSE 关闭缓冲，并允许长连接。
- 工作区通知只携带用户、项目、任务和状态快照，不包含聊天正文；正文仍经过任务权限校验。
- 断线后客户端应携带最后版本/序号重连并补拉，不应通过重复发送消息追赶。
- 检查 `workpivot.workspace_state` 是否随项目/任务变更递增，以及 PostgreSQL `LISTEN` 连接是否健康。

### 额度未刷新

- 以 `Asia/Shanghai` 每天 12:00 为周期边界。
- 检查 `/api/auth/state` 返回的 `used`、`remaining` 和 `resetsAt`。
- 数据库时间与容器时区应一致为 `TZ=Asia/Shanghai`。

### 手机端提示无法连接服务器

依次检查：

1. 后台是否设置 `WORKPIVOT_MOBILE_ORIGINS=https://localhost,capacitor://localhost`。
2. 手机填写的后台地址是否为完整 HTTPS 根地址，不能带 `/api`、查询参数或账号密码。
3. 当前部署的 443 是否可达；若网络阻断 443，确认 Nginx 的 TLS-80 回退入口和客户端默认地址一致。
4. 证书域名是否与填写域名匹配。
5. 用户是否被停用、额度是否耗尽、临时密码是否尚未修改。

不要通过在安装包里关闭证书校验来“修复”连接问题。

### 登录成功后管理页空白或 403

- 确认账号角色为管理员。
- 确认临时密码已经修改。
- 检查 `/api/admin/access-policy` 与 `/api/users` 返回状态。
- 管理页只显示管理元数据，不展示其他用户私人聊天、文件和记忆正文。

## 3. 备份与恢复

任何升级或高风险操作前：

1. 停止新业务写入。
2. 同时备份 PostgreSQL 与文件卷。
3. 记录当前镜像 ID、schema、配置版本和主密钥保管状态。
4. 在隔离目标恢复并验证账户、项目、文件、版本、记忆和权限。
5. 恢复成功后切换入口；失败则保留旧环境。

详细流程见[备份与恢复](../03-project/deployments/backup-recovery-20261016.md)。

绝不要只备份数据库而遗漏文件卷，或只恢复文件而忽略版本与遗忘规则。

## 4. 升级与回退

升级顺序：

```text
冻结写入
  → 联合备份
  → 固定新镜像
  → 停旧服务
  → 执行 schema 迁移
  → 启动配套服务/Worker
  → 健康检查
  → 真实链路验收
  → 解冻写入
```

回退不能只切旧镜像。必须使用与旧镜像匹配的数据库、文件和配置。禁止在降级代码上直接读取已升级的数据而不验证兼容性。

## 5. 安全事件处理

如果怀疑凭据泄漏：

1. 立即撤销会话、轮换模型/浏览器/Worker Token。
2. 更换数据库口令和服务端主密钥前，先确认加密数据迁移方式。
3. 停止相关自动化与外发任务。
4. 保全脱敏日志和审计证据，不复制业务正文。
5. 检查公开仓库、镜像层、构建缓存和备份是否包含凭据。

如怀疑跨用户数据泄漏，应停止服务，执行数据库和文件访问审计，并恢复已确认安全的备份；不能只在前端隐藏数据。

## 6. 日常维护

### 每日

- 服务、数据库、浏览器、Worker 健康。
- 磁盘空间、错误率和任务失败趋势。
- 备份任务是否成功。

### 每周

- 抽查一份成果的版本、下载和预览一致性。
- 抽查一次记忆冲突与删除失效。
- 检查未处理的高风险告警和异常登录。
- 确认模型使用量与额度符合预期。

### 每次发布

- 更新 `STATUS.md`、发布说明和部署记录。
- 记录镜像 ID、版本、schema、迁移与回退路径。
- 执行文档链接检查、类型检查、关键集成测试和真实链路冒烟。
