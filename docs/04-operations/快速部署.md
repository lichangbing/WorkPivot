# 快速部署

> 状态：✅ 可用于单机/小团队试用
> 最近验证：2026-10-28
> 适用版本：`v0.3.0-rc.1`，schema v62

本指南使用仓库提供的一体化安装器准备 PostgreSQL、服务端、浏览器、SearXNG、Skill Worker、执行器和内置技能。首次试用优先使用脚本；生产环境还需完成 HTTPS、备份和容量验收。

## 1. 前置检查

```bash
docker version
docker compose version
openssl version
curl --version
node --version   # 备份/部分运维工具需要 22+
```

建议：

- 4 GB 以上内存，预留足够磁盘空间。
- 默认端口 `39990` 未被占用。
- 仅从可信仓库和已审阅提交构建镜像。
- 了解模型服务是否会接收业务数据。

## 2. 获取代码

```bash
git clone git@github.com:lichangbing/WorkPivot.git
cd WorkPivot
git log -1 --oneline
```

生产部署应固定到已验收 tag/commit，不使用移动的开发分支。

## 3. 一键安装

```bash
bash releases/deploy/install-local-stack.sh --auto-admin
```

默认行为：

- 项目名：`workpivot-stack`
- 端口：`39990`
- 数据目录：`~/workpivot-stack`
- 配置：`~/workpivot-stack/stack.env`，权限 0600
- 首次生成数据库、服务端、浏览器和 Worker 凭据

安装器完成后，访问：

```text
http://127.0.0.1:39990/
```

如果启用了 `--auto-admin`，管理员用户名和密码只应从安装输出或安全配置中获取。首次登录后立即修改密码，并验证 `.env`/`stack.env` 未进入版本控制。

## 4. 可选能力

### Office → PDF

```bash
bash releases/deploy/install-local-stack.sh \
  --auto-admin \
  --with-office-convert \
  --rebuild
```

镜像更大、构建更慢。未安装 LibreOffice 时，DOCX/XLSX/PPTX 生成仍可使用，但 Office → PDF 不可用；直接 HTML → PDF 仍可使用浏览器能力。

### 其他参数

```bash
bash releases/deploy/install-local-stack.sh --help
```

常见覆盖：

| 参数 | 用途 |
| --- | --- |
| `--port 39992` | 更换本地端口 |
| `--project <name>` | 更换 Compose 项目名和网络 |
| `--data-dir <path>` | 更换配置/数据目录 |
| `--rebuild` | 强制重建镜像 |
| `--seed-only` | 只发布/加载技能和模板 |
| `--with-chat-store` | 为旧文件链路启用 chat schema |

## 5. 首次使用

1. 打开页面并登录管理员账户。
2. 进入“设置 → 模型”，配置至少一个 OpenAI 兼容或 Anthropic 协议供应商。
3. 保存前执行连通测试；确认模型容量、价格和币种。
4. 创建项目，再创建任务。
5. 上传一个非敏感测试文件，选择允许读取的版本和记忆层。
6. 发送简单任务，验证流式回复、工具调用、成果下载和过程记录。
7. 创建一条明确长期偏好和一条项目约束，等待记忆整理后确认三层落库。

不要一上线就处理真实敏感资料。先用合成样本验证模型、权限、文件和恢复。

### 手机端连接

后台需显式允许 Capacitor 来源：

```dotenv
WORKPIVOT_MOBILE_ORIGINS=https://localhost,capacitor://localhost
```

Android 生产构建通过 `VITE_MOBILE_DEFAULT_SERVER_URL` 预置后台根地址。当前远程实例为：

```text
https://workpivot.lichb.cc.cd
```

下载当前 Debug 包：

```text
https://115-191-1-188.sslip.io:80/downloads/WorkPivot-android-1.3.apk
```

Windows 便携客户端：

```text
https://115-191-1-188.sslip.io:80/downloads/WorkPivot-Windows-portable.zip
```

解压后运行 `win-unpacked/WorkPivot.exe`。

当前包使用 WorkPivot 独立内测签名，只用于内部验收，不是应用商店发行版。

## 6. 安装后验证

```bash
curl -fsS http://127.0.0.1:39990/api/health

docker ps --format 'table {{.Names}}\t{{.Status}}\t{{.Ports}}'
docker compose \
  --env-file "$HOME/workpivot-stack/stack.env" \
  -p workpivot-stack \
  -f releases/deploy/compose.local-stack.yml ps
```

应确认：

- 服务端 healthy。
- 首页可打开，登录后可用。
- 浏览器服务和 Worker 健康。
- 数据卷存在且不可被普通用户直接读取。
- 数据库 schema 与发布记录一致。

## 7. 模型与网络

- 模型供应商由部署方选择；模型请求会把本轮授权上下文发送给该供应商。
- `web_fetch`、搜索和 Browser 能力需要对应服务配置。
- 未配置 Worker 时 `execute_skill`/`run_code` 不出现或明确失败。
- 内网地址、完整 URL 和浏览器页面访问仍受任务授权限制。

## 8. 生产加固

在 RC 试用环境完成后，至少补齐：

1. HTTPS 域名、反向代理和安全响应头。
2. 数据库、文件卷和配置的联合备份。
3. 独立低权限运行账户与最小网络暴露。
4. 资源限制、日志轮转、磁盘监控和告警。
5. 镜像固定、SBOM/许可检查和依赖更新策略。
6. 升级/回退演练与第二台机器恢复。
7. 真实业务样版的 Office、PDF、OCR 和检索验收。
8. 企业身份或明确的人工账户管理流程。

## 9. 停止与清理

停止服务但保留数据：

```bash
docker compose \
  --env-file "$HOME/workpivot-stack/stack.env" \
  -p workpivot-stack \
  -f releases/deploy/compose.local-stack.yml down
```

不要随意执行 `down -v`。它会删除数据卷，属于不可恢复操作。删除前先完成备份并确认目标项目名。
