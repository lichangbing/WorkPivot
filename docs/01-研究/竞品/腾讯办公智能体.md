> 一段话结论：WorkBuddy 用“任务 + 工作空间 + 专家执行 + 文件交付”定义了 AI 办公工作台，并通过插件化专家、Skill、MCP 连接器和多部署配置扩大覆盖面。最值得 WorkPivot 借鉴的是任务式产品心智、按任务选择 Office 路径、运行时会话一致性和私有化形态配置；不应照搬其厂商生态绑定、内部专有引擎或部分高风险实现。

## 1. 产品与用户

| 字段 | 观察 |
| --- | --- |
| 厂商 | 腾讯 / CodeBuddy 团队 |
| 定位 | 从自然语言任务到可验收办公成果的全场景 AI 办公工作台 |
| 目标用户 | 个人专业用户、企业业务团队、需要统一治理的组织 |
| 主要场景 | 行业调研、Word/Excel/PPT、数据分析、会议材料、自动化、连接器协作 |
| 产品入口 | Windows/macOS 桌面、Web/企业控制台、移动端和小程序、IM 助理 |
| 核心心智 | 说出目标 → Agent 执行 → 过程可见 → 结果区交付文件 |

官方操作采用“四步创建任务”：描述目标、选择工作空间、添加文件/截图/规则上下文、开始执行。界面按任务列表、对话过程和成果区分栏组织。

## 3. 产品结构与扩展体系

### 3.1 专家

专家是“角色切换”，由人格说明、领域方法、预置提示和所需 Skill/MCP 组成。专家团由协调者拆解任务、并行或接力执行，再汇总交付。专家本身不主动取得系统权限；实际读写仍受工具和连接器授权约束。

专家团成本明显高于单专家，产品也在探索协作层的质量与成本平衡。对 WorkPivot 的启示是：专家首先应是可追踪的配置资产，而不是绕过权限的“超级 Agent”。

### 3.2 Skill

Skill 采用 `SKILL.md + scripts/references/assets` 的目录形态，支持上传、搜索和从任务描述生成。Skill 动作以当前用户身份执行，非官方 Skill 存在提示词注入、越权、后门和第三方外发风险。

值得借鉴：

- 会话只加载当前任务需要的 Skill，减少工具干扰。
- Skill 包有清晰目录、版本、来源和资源。
- 专家、Skill、连接器分属不同层，便于独立治理。

不应直接复用：

- 未经审核的社区 Skill。
- “安装后立即可执行”而缺少试运行、版本固定和权限审计。
- 把第三方说明当可信系统指令。

### 3.3 连接器

连接器以 MCP/CLI 或 Skill/CLI 形式接入，支持个人授权、公共授权和启停。每个连接器独立授权，不完全依赖账号已拥有的第三方权限。

WorkPivot 应吸收“公共授权与个人授权分离”及“协作任务禁用个人凭据”的原则，但所有外部调用仍要逐次绑定工具、参数和目标 revision。

## 4. 运行与技术架构

2026-08-27 至 10-14 的本机静态观察得到以下结构，版本不同可能变化：

```text
Electron 桌面壳
  ├─ 本地会话与成果界面
  ├─ 每工作区独立 CLI Host 子进程
  │    ├─ Agent 循环、工具、子代理与会话
  │    └─ 本地 HTTP/ACP/心跳注册
  ├─ 本地 Office 文档引擎
  ├─ MCP 连接器聚合代理
  └─ 云端模型、同步、对象存储与遥测（视部署形态）
```

可确认的工程模式：

- 桌面 UI 与 Agent 运行时进程隔离，通过本地 HTTP/ACP 和心跳发现会话。
- 同一内核通过 `product.*.json` 裁剪出内部版、iOA、云托管和私有化等形态。
- 私有化配置关闭部分遥测和记忆个性化，但允许管理员配置兼容模型。
- 主 Agent 之外存在记忆选择、摘要、风险分类、问题重写等专职小模型任务。
- 会话、任务清单、文件历史、内容寻址 Blob、审计和产物索引用本地文件/SQLite 组合承载。

这些是观察与推断，不表示 WorkPivot 应照搬 Electron 端执行、超大工具面或本地文件模型。

## 5. 记忆

### 5.1 已观察结构

项目工作区中可见两层 Markdown：

```text
项目/.workbuddy/memory/
  ├─ MEMORY.md          长期背景、规则、决策、材料与产物索引
  └─ YYYY-MM-DD.md      按日累积的过程、经验和任务细节
```

一个受控项目样本包含 1 个长期文件和 43 个日期文件，总量约 675 KiB；日期文件大小差异很大，最大文件接近 132 KiB。安装包分析还发现按需读取 `MEMORY.md`、注入提示词和基于当前查询选择记忆的路径。

### 5.2 官方能力

官方说明记忆覆盖事实、偏好、人物关系和近期事项，模型从会话抽取，夜间整理并注入系统上下文。用户可查看、编辑、删除、导入或整体关闭。

### 5.3 借鉴与风险

值得借鉴：

- 长期约束与过程日志分开，长期文件保持短而稳定。
- 记忆按项目隔离，能定位材料、产物和决策依据。
- 自动整理作为后台作业，不阻塞聊天。

风险与待验证：

- 日期日志无限增长会增加读取预算和旧事实冲突。
- Markdown 自然语言文件缺少强类型修订、有效期和来源图。
- 自动整理如果没有逐条冲突确认，可能把旧金额、旧口径继续注入。
- 本机文件可见不代表所有记忆均明文，也不证明每次会话实际读取了哪些内容。

WorkPivot 不照搬“Markdown 即真相”：数据库保存事实、revision、来源、状态与作用域，文件只承载必要的可读导出。

## 6. Office 与文档交付

WorkBuddy 按文件类型和操作类型分流：

| 场景 | 观察到的路径 | 边界 |
| --- | --- | --- |
| Word 新建 | Markdown → HTML → 本地引擎 → DOCX | 短文样本跳过了部分预检/校验，不等于视觉保真 |
| Word 读取 | 查询真实编辑实例的正文、表格和结构 | 长文有截断，坐标在结构变化后失效 |
| Word 修改 | 复用实例 → 对象定位 → 替换 → 保存 → 读回 | 部分样式和节属性被重写 |
| Excel 新建 | openpyxl → LibreOffice 重算 → 公式/缓存检查 | 依赖环境和公式覆盖范围有限 |
| Excel 读取 | 简单范围直接用 SDK，复杂核算委派 sheet-agent | Windows 路径解析存在兼容性问题 |
| Excel 修改 | 单元格工具 → 保存 → 重算；异常时曾临时修补 XML | 不是可复制的常规保存方案 |
| PPT 新建/读取/修改 | SlideDSL/revision → 原生引擎；读取经 keyframe 转结构 | 只有静态证据，缺少本项目运行验收 |

关键结论：

1. 读取、局部修改、新建是不同流程，不能统一成“抽出正文再生成整份文件”。
2. 真实文档会话让编辑、用户预览和保存指向同一实例，值得借鉴。
3. 保存成功、公式重算、结构正确、视觉检查必须分别记录。
4. 跳过校验、临时修补 XML 和用退出码代表成功都属于应规避的行为。
5. WorkPivot 应继续使用不可变文件版本和显式失败，不复制腾讯原生编辑器。

## 7. 部署与商业形态

公开资料曾给出 SaaS 企业版与专有云的不同价格、席位和积分规则；价格可能变化，不作为当前采购承诺。专有云支持客户 IDC，流程包括企业初始化、定制客户端打包、成员导入、能力授权和分发。

私有化形态由同一内核配置裁剪，关闭遥测和默认记忆个性化，模型和连接器由企业受控配置。对 WorkPivot 的启示：

- 用构建形态配置控制遥测、模型可见范围和组织策略，避免维护多套分叉代码。
- 私有化默认克制采集，但必须显式配置模型、知识库、浏览器和执行器。
- 客户端分发包不能内置账号、密钥或私有环境参数。

## 8. 优势与限制

### 优势

- 产品叙事完整，从聊天自然过渡到任务与文件成果。
- 专家、Skill、连接器和资料库构成丰富生态。
- 桌面、Web、移动和 IM 多渠道入口降低使用门槛。
- Office 任务路径细致，重视真实文档实例和用户可见预览。
- 私有化采用配置裁剪，企业治理覆盖面广。

### 限制与风险

- 核心引擎和内部编排不公开，不能根据静态依赖推导完整行为。
- 与腾讯文档、网盘、IM 和企业生态结合较深。
- 工具面庞大。自动分类、多处默认行为和安全策略不一致都会增加治理成本。
- Skill/MCP 生态扩大攻击面，第三方内容不能默认可信。
- 记忆以自然语言文件为主时，冲突、时效和大量旧日志更难系统治理。
- 私有化硬件、网络、模型服务和 RAG 组件细节不公开，需售前确认。

## 9. 对 WorkPivot 的取舍

### 应吸收

- 任务式产品结构和三栏信息架构。
- 专家/Skill/连接器分层，扩展资产有来源、版本和启用控制。
- 项目级配置注入、公共授权与个人授权分离。
- 同一文档实例关联编辑、预览和保存。
- 形态配置控制私有化差异，默认关闭不必要的遥测。
- 主任务用主模型，摘要、记忆选择、风险分类等子任务使用小模型分流。

### 应避免

- 通过厂商文档、网盘、IM 深度绑定形成迁移壁垒。
- 未经审核的 Skill 直接获得文件、网络或外部写权限。
- 自动保存旧记忆而不处理修订、冲突和过期。
- 默认跳过 Office 校验或用临时 XML 修补掩盖兼容问题。
- 复制专有代码、提示词、模板和原生引擎。

### 差异化机会

WorkPivot 聚焦私有化、模型中立、任务级授权、可恢复副作用和可纠错三层记忆。与 WorkBuddy 相比，优势不应是“工具更多”，而应是：

- 每个任务能解释读了哪些文件版本、调了哪些工具、结果是否通过检查。
- 事实有 revision、来源、有效期和作用域，旧金额与旧决策不会无限混用。
- Office 文件真实落盘、成果可恢复，失败不发布半成品。
- 企业可以不依赖腾讯生态部署模型、数据库、浏览器和执行器。

## 10. 证据与限制

| 结论 | 主要证据 | 等级 |
| --- | --- | --- |
| 产品定位与任务流程 | 官方文档、官网 | A |
| 专家/Skill/连接器结构 | 官方文档 + 安装包插件结构 | A/B |
| Electron + CLI + 本地服务拓扑 | 安装目录、会话注册、端口与日志 | B |
| 私有化形态配置 | `product.selfhosted.json` 静态样本 | B |
| 项目记忆文件结构 | 单个项目只读样本 | B |
| Office 基础读改生成 | 静态代码 + 用户受控样本 | B |
| 完整原生引擎和视觉保真 | 未完整反编译、未覆盖复杂样版 | D / 未知 |

证据边界：

- 商业产品内部实现以观察和推断表述，不声称拥有源码事实。
- 版本升级后路径、默认行为和能力可能变化。
- 研究样本不包含真实客户材料、账号、密钥或私有提示词。
- 所有本机路径已在统一分析中脱敏，原始证据只保留机制和哈希/相对定位。
