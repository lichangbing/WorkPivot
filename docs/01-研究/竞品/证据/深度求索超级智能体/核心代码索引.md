## 1. 单一领域入口：`src/core/engine.ts`

位置：[上游源码](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/6337fc823ce20251c8de8085948165c81aaa701e/src/core/engine.ts)

关键观察：

```ts
export class Engine {
  receive(trigger: Trigger): ReceiveResult {
    return this.repo.atomic(() => this.intake.receive(trigger))
  }

  decide(triggerId: string, outcome: Outcome): Decision {
    return this.repo.atomic(() => this.evals.decide(triggerId, outcome))
  }

  report(ticketId: string, report: WorkerReport): Ticket {
    return this.repo.atomic(() => this.assignments.report(ticketId, report))
  }
}
```

可借鉴点：

- 外部事件、模型决策、执行报告都经过同一核心入口；
- 状态变更在事务内完成；
- Source、Tool、HTTP 不直接写领域状态；
- 调用方获得角色级接口，而不是完整写权限。

## 5. Worker 并发规则：`WorkerSlots`

位置：[上游源码](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/6337fc823ce20251c8de8085948165c81aaa701e/src/executor/dsh.ts)

```ts
used(): number {
  return new Set([
    ...this.running(),
    ...this.starting.keys(),
  ]).size
}

reserve(ticketId: string, by: 'launch' | 'wake' | 'person'): void {
  if (this.starting.has(ticketId)) return
  if (this.used() >= this.max() + (by === 'person' ? 1 : 0)) {
    throw new Later('No worker slot is free')
  }
  this.starting.set(ticketId, by)
}
```

可借鉴点：

- 同步预留在启动前完成，避免并发抢槽；
- 人工后续消息有额外一个槽；
- 运行中的 Worker 与正在启动的 Worker 都计入负载。


主 Router preset 的注释明确说明不包含 Subagent、Web、文件搜索和写入等技术工具。

结论：

```text
Router（主 Session）
    │
    └─ Engine/Ticket/Assignment
             │
             ▼
        Worker Agent
             │
             └─ 按需 Subagent
```

这是“多 Agent 主架构 + 可选子代理”，不是单纯的多子代理聊天室。

## 7. 持久副作用队列：`src/app/effects.ts`

位置：[上游源码](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/6337fc823ce20251c8de8085948165c81aaa701e/src/app/effects.ts)

```ts
export class Effects {
  enqueue<K extends EffectKind>(
    kind: K,
    key: string,
    payload: EffectPayloads[K],
  ): void {
    this.store.db.prepare(`
      INSERT INTO effect (kind, key, value, seq, due, since)
      VALUES (?, ?, ?, ?, ?, ?)
      ON CONFLICT(kind, key) DO UPDATE
      SET value = excluded.value,
          generation = generation + 1,
          attempts = 0,
          error = '',
          due = excluded.due
    `).run(...)
  }
}
```

可借鉴点：

- 在业务事务内记录副作用；
- `kind + key` 唯一，重复入队合并；
- `generation` 防止旧运行覆盖新 payload；
- 顺序、并发、重试、健康状态均属于宿主控制。

## 8. 工单执行生命周期：`docs/003-execution.md`

位置：[上游文档](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/6337fc823ce20251c8de8085948165c81aaa701e/docs/003-execution.md)

核心分类：

| 阶段 | 含义 |
| --- | --- |
| `person/delivery` | 输入投递失败，需要恢复 |
| `person/answer` | 等待人工回答 |
| `person/review` | 结果就绪，等待审查 |
| `person/blocked` | Agent 受阻 |
| `person/failed` | Agent 失败 |
| `working/queued` | 已授权，等待执行槽 |
| `idle` | 等待新 Trigger |
| `working` | 正在执行 |

可借鉴点：

- 状态按“在等谁、等什么”定义；
- 不只使用 `running/idle/error` 这类进程状态；
- UI 标签直接表达下一步需要谁行动。
