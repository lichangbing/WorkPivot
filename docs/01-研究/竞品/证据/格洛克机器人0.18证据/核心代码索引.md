## 2. Gateway 契约

### `source/shared/gateway-wire.ts`

[上游位置](https://github.com/b-nnett/grok-bot-0.18-reconstructed/blob/a9f633e09d49a85829b8236331b9e21f7e612634/source/shared/gateway-wire.ts)

关键常量：

```ts
GATEWAY_API_PREFIX = "/api"
GATEWAY_EVENTS_PATH = "/events"
GATEWAY_HEALTH_PATH = "/health"
GATEWAY_AUTH_SCHEME = "Bearer"
```

观察：

- 命令、事件、健康、头像和桥接通道有统一 path；
- trace、去重、network token 使用显式 header；
- WebSocket 不是主数据面，SSE 承载 Host 事件。

### `source/host/gateway-protocol.ts`

[上游位置](https://github.com/b-nnett/grok-bot-0.18-reconstructed/blob/a9f633e09d49a85829b8236331b9e21f7e612634/source/host/gateway-protocol.ts)

核心形状：

```ts
sendPrompt: (api, body) =>
  api.sendPrompt(parseCommandArgs(body))
```

观察：

- 所有 API 都是同构 `POST /api/<method>`；
- transcript、Agent、memory、Routine、Workflow、MCP、Box、附件等由统一表分发；
- 方法存在性在进入实现前检查，未知方法返回 404。

### `source/host/gateway-server.ts`

[上游位置](https://github.com/b-nnett/grok-bot-0.18-reconstructed/blob/a9f633e09d49a85829b8236331b9e21f7e612634/source/host/gateway-server.ts)

关键行为：

- Bearer token timing-safe compare；
- `/events` 返回 SSE，15s heartbeat，首包 `retry: 1000`；
- 请求体和响应有大小/压缩边界；
- 命令完成、错误和 trace 进入 telemetry；
- health 不泄露会话内容。

### `source/host/host-gateway-api.ts`

[上游位置](https://github.com/b-nnett/grok-bot-0.18-reconstructed/blob/a9f633e09d49a85829b8236331b9e21f7e612634/source/host/host-gateway-api.ts)

`sendPrompt` 的关键签名：

```ts
await manager.sendPrompt(args.prompt, {
  agentId: args.agentId,
  attachmentPaths: args.attachmentPaths ?? [],
  clientNonce: args.clientNonce,
  replyToId: args.replyToId,
  traceparent: args.traceparent,
  awaitTurn: ...
});
return { accepted: true };
```

观察：

- `accepted` 只表示 Host 接收；
- `clientNonce` 和 trace 随消息进入内部生命周期；
- 附件路径与名称、rich text、reply、fork、时间也显式传递。

## 3. Coordinator 与传输恢复

### `source/node-agent-coordinator/main.ts`

[上游位置](https://github.com/b-nnett/grok-bot-0.18-reconstructed/blob/a9f633e09d49a85829b8236331b9e21f7e612634/source/node-agent-coordinator/main.ts)

### `source/node-agent-coordinator/gateway/gateway-client.ts`

[上游位置](https://github.com/b-nnett/grok-bot-0.18-reconstructed/blob/a9f633e09d49a85829b8236331b9e21f7e612634/source/node-agent-coordinator/gateway/gateway-client.ts)

关键常量：

```ts
SSE_RECONNECT_MIN_MS = 1_000
SSE_RECONNECT_MAX_MS = 10_000
SSE_STALL_TIMEOUT_MS = 35_000
SSE_CONNECT_TIMEOUT_MS = 15_000
```

`sendPrompt` 重试条件：

```ts
const retryable =
  hasClientNonce &&
  (postNeverDispatched || dedupeProvenForBaseUrl)
```

观察：

- endpoint 变化时拒绝重放；
- 业务错误与传输错误分流；
- Host 声明 mint-dedupe 后才能把 endpoint 视作可安全重试；
- 重连使用 generation，旧 stream 不能写入新状态；
- 35s stall watchdog 由每次 reader 数据 kick。

### `source/node-agent-coordinator/gateway/sse-block-decoder.ts`

[上游位置](https://github.com/b-nnett/grok-bot-0.18-reconstructed/blob/a9f633e09d49a85829b8236331b9e21f7e612634/source/node-agent-coordinator/gateway/sse-block-decoder.ts)

观察：

- 独立处理跨 chunk 的 SSE 边界；
- 支持多 data 行合并；

## 6. Agent 与 Subagent

### `source/host/runner/tools/sand-subagent-management-tools.ts`

[上游位置](https://github.com/b-nnett/grok-bot-0.18-reconstructed/blob/a9f633e09d49a85829b8236331b9e21f7e612634/source/host/runner/tools/sand-subagent-management-tools.ts)

```text

StopSubagent    销毁并释放桌面资源
```

完成由宿主通知父 Agent，`CheckSubagent` 是诊断工具，不是完成轮询器。

### `source/host/runner/tools/sand-computer-use-subagent.ts`

### `source/host/runner/subagent-runtime.ts`

## 7. 可见交付与恢复

- 首个动作若是工具而不是文本 SendMessage，就注入一次提醒；

### `source/host/runner/send-message-reminder-middleware.ts`

### `source/host/extensions/transcript/ack-obligations.ts`

[上游位置](https://github.com/b-nnett/grok-bot-0.18-reconstructed/blob/a9f633e09d49a85829b8236331b9e21f7e612634/source/host/extensions/transcript/ack-obligations.ts)

## 11. 摘录规则

- 本文件只保留用于理解行为的短签名和常量；
- 不保存上游完整 Prompt、工具描述、前端资源或可运行重建；
- 使用固定 commit，避免未来主分支变化导致证据漂移；
- 代码位置只能证明“社区重建的这一版如此实现”，不能证明作者原始仓库的文件划分；
- 任何未来兼容实现都应重新依据 WorkPivot 自身模型和许可独立设计。
