# 竞品原始证据

> 状态：📚 证据库
> 原则：证据可追溯，结论回主卡

本目录保存单产品主卡不适合承载的官方纪要、安装包静态分析、运行记录、JSON 清单和哈希。文件内容描述当时的样本与验证边界，不代表 WorkPivot 的当前实现。

## 目录

| 产品 | 内容 |
| --- | --- |
| [WorkBuddy](腾讯办公智能体/) | 官方文档、技术架构、扩展系统、记忆、Office 读取/预览/生成实现与运行证据 |
| [豆包](字节豆包/) | 桌面端查看与编辑的运行观测、读取与生成的云端链路、资源包与引擎清单 |

| [DeepSeek Superagent Prototype](深度求索超级智能体/) | 固定提交源码快照、架构、核心代码索引与 WorkPivot 落地步骤 |
| [Grok Bot 0.18](格洛克机器人0.18证据/) | 发行物暴露链路、版本谱系、Gateway/SSE、Agent/Subagent、审批、Routine 与核心代码索引 |

## 维护规则

1. 新细节先判断能否归入产品主卡；只有可复现材料、长参数表、原始输出和日期证据才放这里。
2. 每个证据文件标题需包含产品、版本/日期和证据类型。
3. 不新增“某产品再分析 2、补充 3”式平行结论；主卡是唯一当前口径。
4. JSON 和截图只保留脱敏、可解释的字段；客户正文、账号、令牌和内部绝对路径不得入库。
5. 主卡引用证据时使用相对链接；证据文件中的内部链接由文档检查统一验证。
