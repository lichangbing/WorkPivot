# WorkBuddy Word 预览实现（运行实测 + 静态复核）

日期：2026-11-03。
样本：本机 WorkBuddy 5.9.3（Electron 37.10.3 / Chromium 138.0.7204.251，安装目录 `D:\Program Files\WorkBuddy`）。
方法：安装包逐字节静态提取（每个产物用 asar 声明的 integrity.sha256 校验）+ 一次受控运行观测（通过产品内建环境变量临时开启 CDP，只读观测，不改文件）。
作用：修正 [Word 实现深入分析](办公文字文档-20261017.md) 中"docxjs 即预览实现"的表述——docxjs 仍在包内，但只是兜底路径。

## 1. 结论

| 问题 | 结论 | 等级 |
| --- | --- | --- |
| Word 预览主路径 | 渲染进程用 `<iframe>` 加载本机腾讯文档 WebOffice 引擎页面 `http://127.0.0.1:<port>/static/doc/pc.html?...`，真实排版、可编辑 | 运行实测 A |
| 承载进程 | `editor_sdk.exe`（214,451,016 字节），HTTP 服务监听 39099 | 运行 + 静态 B |
| 文档身份 | `globalPadId = md5(绝对路径)`，同文件跨窗口/iframe 共用同一身份，由宿主去重 | 静态 A + 运行校验 |
| 编辑与保存 | URL 带 `local_edit=1&client=sdk_local&mode=edit`，工具条/大纲/状态栏可见；保存走宿主 `saveContext` 写回原文件，有冲突与租约处理 | 静态 B |
| 并发上限 | 宿主 `documentPreviewPoolCapacity = 5` | 静态 B |
| docxjs（docx-preview）定位 | 仅在 SDK 预览不可用（无 `getPreviewUrl` 或不支持该扩展名）时兜底渲染 | 静态 A |
| 资源来源 | `/static/doc/*` 由本地引擎提供；外网只剩字体、遥测与广告接口 | 运行实测 A |
| 与 Agent 的关系 | 同一端口的 `/mcp` 暴露 `tencent-docs-local`，供 agent CLI 复用同一引擎 | 静态 B |

## 2. 运行观测

### 2.1 开启 CDP 的方式

产品内建环境变量开关（main 进程 `applyCliCommandLineSwitches`）：

```js
let n = process.env.WORKBUDDY_REMOTE_DEBUGGING_PORT;
if (n && /^\d+$/.test(n)) {
  let t = ['http://127.0.0.1', 'http://localhost',
           `http://127.0.0.1:${n}`, `http://localhost:${n}`].join(',');
  electron.app.commandLine.appendSwitch('remote-debugging-port', n);
  electron.app.commandLine.appendSwitch('remote-allow-origins', t);
  e.logInfo(`[WorkBuddy] CDP remote debugging enabled on port ${n} (${t})`);
}
```

命令行传 `--remote-debugging-port=9222` 会被 Electron 启动器拒绝（`bad option`，退出码 9），只有环境变量生效。

### 2.2 观测到的目标与 URL

`/json/version` 返回 `Chrome/138.0.7204.251`、`WorkBuddy/5.9.3`、`Electron/37.10.3`。页面 target 为 `file:///D:/Program Files/WorkBuddy/resources/app.asar/renderer/index.html`，其子 frame 为：

```text
http://127.0.0.1:39099/static/doc/pc.html
  ?title=<文件名>.docx
  &localFilePath=E:\workspace\<项目>\<文件>.docx   ← 本报告已脱敏
  &globalPadId=<md5(absolutePath)>
  &local_edit=1&client=sdk_local&mode=edit
  &toolbar=show&outline=show&statusbar=show
  &editorSdkUrl=http://127.0.0.1:39099
  &_wbchat=1&wb_source=local
  &theme=light&colorScheme=light&workbuddyTheme=light&lng=zh-CN
  &openType=inline
```

对同一绝对路径独立计算 `md5` 得到的值与 URL 中的 `globalPadId` 完全一致，文档身份规则成立。

### 2.3 iframe 内部

- 全局对象：`tdocs`、`__fitPageInitZoom`、`__WB_DOCS_FEATURE_LIST__`（值 `{"aiEdit":true}`）、`__TencentDocs_WebOffice_LogCollection__`、若干 `docs-component-*` 自定义元素。
- `AppConfig` 同时保留多套配置（`MINIMAL_CONFIG / PLAYER_CONFIG / PREVIEW_CONFIG / PUBLISH_CONFIG / NORMAL_CONFIG / normal / reading`），其中 `runtime.domainName=docs.qq.com`、`apiRoot=//docs.qq.com/`、`staticPublicPath=//docs.gtimg.com/`、`libPublicPath=/static/doc/docs.gtimg.com/lib/js`——即线上腾讯文档前端被本地引擎接管了域名与静态路径。
- `pc.html` 自身 238,706 字节，`<head>` 内置 `window.__fitPageInitZoom=Math.min(Math.max((window.innerWidth-8)/912,0.1),2)`，即按 912px 基准自适应缩放。
- 文档渲染出 `canvas`、`svg`、`div` 混合结构，状态栏文案形如「第 1 页 / 共 14 页　8804 个字　100%」，说明是真实分页排版而非流式重排。

### 2.4 网络

页面共记录 95 条资源，其中 83 条来自 `127.0.0.1:39099`（`feature-pc-*.js/css` 分片，含 attachment、ocr、print、copypaste 等能力域）。本地网关还提供非静态接口：`/addon/editor-addons`、`/cgi-bin/online_docs/user_flag`、`/v2/user/attribute/get`、`/api/frontedcfgreader/scenes_calc`。

外网请求仅有：`docs.qq.com` 的商城/广告接口、`galileotelemetry.tencent.com`、`tpstelemetry.tencent.com`、`aegis.qq.com`，以及 `alloyteam-cdn.cdn-go.cn` 的字体子集。上报内容含版本串 `release_workbuddy_5.9_041a93d5`、`domain=127.0.0.1:39099`、文件名与文档 ID。

### 2.5 宿主 DOM 位置

iframe 的祖先链为 `IFRAME → div → div → div._mediaPreviewContent_1gewf_145 → div._mediaPreview_1gewf_1 → div.artifact-body → div.artifact-content`，React fiber 组件名为 `['iframe','div','div','SdkDocumentPreview','div','Body']`。iframe 样式为 `display:block;width:100%;height:100%;border:none`，**没有 `sandbox` 属性**。

## 3. 静态证据

### 3.1 渲染进程的分发分支（决定"走引擎还是 docxjs"）

产物 `renderer/assets/media-preview-KfFy8PYh.js`（261,084 字节，sha256 `c775e68d73da8bb8219ee17378019408e37ec5b14598668608024120f5199da2`），文件查看器 switch：

```js
case `document`: {
  if (canUseFileViewerSdkDocumentPreview(t, S)) {          // t = getPreviewUrl, S = 扩展名
    let e = null;
    S === `docx` ? e = <div className='empty-content'><p>{pe(`mediaPreview.componentError`)}</p></div>
    : S === `pdf` ? e = <Sd file={p} filename={u} />
    : S === `doc`  && (e = <div className='empty-content'…>`mediaPreview.unsupported`…</div>);
    return previewResult(<FileViewerSdkDocumentPreview filePath={d} title={u} size={p?.size}
             getPreviewUrl={t} fallback={e} … />);
  }
  if (S === `pdf`)  return previewResult(…<Sd …/>…);
  if (S === `docx`) return previewResult(<div className='file-viewer__media'><_d file={p} filename={u} /></div>);
}
```

```js
function canUseFileViewerSdkDocumentPreview(e, t) { return !!(e && It(t)); }   // It = 引擎支持该扩展名
_d = Q.lazy(() => import(`./docx-preview-Cwm5C_iI.js`).then(e => ({ default: e.DocxPreview })), …);
```

即：**能拿到 `getPreviewUrl` 且扩展名受支持 → 引擎 iframe；否则 docx 回退到 docxjs**，且 docxjs 的失败占位是 `mediaPreview.componentError`。`spreadsheet`/`presentation` 分支同构（`FileViewerSdkDocumentPreview` + 各自 fallback）。

`SdkDocumentPreview` 组件（同产物）负责宿主侧契约：

- 只接受来自本 iframe `contentWindow` 且 origin 匹配的消息；
- `isEditorSdkLoadStateMessage`：`state ∈ loading|ready|failed`，携带 `documentResourceUri`、`fileId`，用于维护 `isReady`/`fileId`；
- `isTencentDocsPreviewReadyMessage` 用于判定首次渲染完成（`frame ready` 诊断含 `sinceLoadStartMs`、`attempt`）；
- `isTencentDocsSaveShortcutMessage`：iframe 内 Ctrl+S 交给宿主保存；
- 主题/语言变更通过 postMessage 下发（`workbuddy:themeChanged`、`workbuddy:localeChanged`），`targetOrigin` 由预览 URL 推导；
- 焦点与缩放：`pointerdown`/`mouseenter` 时给 iframe 聚焦，并调用 `window.__workbuddyZoomShortcut.setSdkIframeFocused(true/false)`；
- 打开失败分类：`file_not_found`、`file_not_accessible`、`engineUnavailable`、超限**不当作失败**（走本地兜底）；`editor_sdk is not started`、`fetch failed`、`preview lease is stale`、`superseded`、`ECONNREFUSED`、`timeout` 视为可重试的引擎侧失败。

### 3.2 主进程注入

`main/tencent-docs-main-integration.js`（1,417 字节）注册 `documentService`、对话框宿主、`ENGINE_READY` 与 `RELOAD_EMBEDDED_PREVIEW` 推送；bootstrap 处注入：

```js
tencentDocsRuntime: { documentService: j, push: T, documentPreviewPoolCapacity: 5 },
docsService: { getPreviewUrl: (e, t) => j.createPreviewUrl(e, t), dispose: () => j.dispose() }
```

daemon 侧同构，并把 `localDocs:*` 暴露成 `getPreviewUrl`、`checkOpen`、`saveContext`、`releaseContext`、`forceReleaseContext`、`rebindSession`、`getDirty`、`activateContext` 等 RPC——预览、保存、冲突和租约都在宿主侧管理。

事件通道：`tencent-docs:openLocalFileInMainWindow`、`localFileAlreadyActive`、`previewPoolFull`、`engineReady`、`reloadEmbeddedPreview`，配合 `consume-pending-renderer-events` 做渲染进程未就绪时的补发。

### 3.3 引擎包源码（非猜测）

`node_modules/@tencent/tencent-docs-ai-engine`：`package.json` version `0.2.220-wb`，description 自述「spawn-and-supervise wrapper around the bundled `editor_sdk` binary（单端口同时提供 `/mcp` 与 `/static/<type>/pc.html`，默认 :39099，懒启动）」；`editor-sdk-version.json` 为 `{"version":"0.0.0.533"}`。

`lib/common/tencent-docs-service.js`：

- `DEFAULT_PORT = '39099'`、`READINESS_TIMEOUT_MS = 60_000`，启动参数 `--port`、`--cors_origin`、`--static_dir`、`--log_dir`、`-td_proxy=true`，就绪以 `/health` 200 为准（注释说明 Windows 上可能要 ~8s 解压内嵌 zip）。
- `buildPreviewUrl(port, filePath, options)`（第 230-250 行）：
  - `globalPadId = createHash('md5').update(filePath).digest('hex')`，注释明确「不能为了多开 preview 改成随机 per-view ID；同文件跨窗口/iframe 的并发冲突应由宿主做去重」；
  - `doc` 额外带 `editorSdkUrl: 'http://127.0.0.1:' + port`；
  - 返回 `http://127.0.0.1:${port}/static/${type}/pc.html?${params}`。
- `URL_CONFIG_MAP`（第 184-209 行）：`doc.params = {local_edit:'1', client:'sdk_local', mode:'edit', toolbar:'show', outline:'show', statusbar:'show'}`，`readonlyParams = {mode:'readonly', toolbar:'hide', statusbar:'hide'}`；`sheet` 用 `sdk_local_pure`，`slide` 用 `sdk_local_wb` 且 `hideTitlebar:1`。
- 支持扩展名（`lib/common/document-types.js`）：doc 类 `.doc/.docx/.dot/.dotx/.wps/.wpt/.docm/.dotm`；sheet `.csv/.xls/.xlsx/.xlt/.xltx/.xlsm/.xltm`；slide `.pptx/.ppt/.pps/.pot/.pptm/.ppsx/.ppsm/.potx/.potm`；pdf `.pdf`。

`main/kill-stale-editor-sdk-core.js`：启动前在非 Windows 用 `pkill -9 -f "<path> --port"` 清理残留；退出时用 `pkill -9 -P <pid> -x editor_sdk` 收割子进程（Windows 两条都跳过，依赖 SIGTERM→SIGKILL）。

## 4. 与既有证据的关系

1. [Word 实现深入分析](办公文字文档-20261017.md) 描述了 `docx-preview-component` 里的 JSZip + OOXML 解析链，那部分代码本轮复核仍存在（80,018 字节，sha256 `035e448831527008c46a8221c4c70191ab88891b69396152ce81c240ca1e28b8`），但它是**兜底渲染器**，不是默认预览路径。
2. 该报告记录的原生引擎 209,234,760 字节、`%LOCALAPPDATA%\Programs\WorkBuddy` 安装位置属于 5.8.x 样本；本轮 5.9.3 的引擎为 214,451,016 字节，安装位置为 `D:\Program Files\WorkBuddy`。版本升级会改变尺寸与路径，结论以版本为准。
3. 该报告"没有观察到把用户编辑写回 DOCX 的调用"是就 docxjs 而言的正确结论；实际写回由引擎 + 宿主 `saveContext` 完成。

## 5. 限制与未验证项

- 引擎内部解析、排版与保存算法未反编译（原生二进制 214MB，本轮只读身份与外围接口）。
- 本轮 REA 的 JS 图分析在本机被沙箱阻断（`EPERM … <uuid>.source`，phase `source-transfer`），所有渲染进程结论来自逐字节提取与源码审阅，**没有生成调用图**；引用代码是文件内原文。
- 只观测了一类本地 docx（14 页、8,804 字、含图片/表格）；云端文档、只读模式、并发 5 个上限触发、引擎缺失时的 docxjs 兜底均未实测。
- CDP 开关是产品内建环境变量，不属于公开 API，升级可能改变。
- 观察到的外网上报接口不做内容判定，仅说明预览渲染本身不依赖外网。

## 6. 对 WorkPivot 的启示

- **两条路线的取舍清晰**：docxjs 是零依赖、跨平台、只读渲染，适合"看内容"；内嵌引擎是真实排版 + 编辑回写，但绑定 214MB 专有二进制、本地 HTTP 端口和厂商生态。WorkPivot 若只需确认文档内容，不应引入引擎级依赖。
- **文档身份用路径哈希而非随机 ID**，让同一文件的多个视图共享状态，把并发冲突交给宿主去重，比让引擎各自为政更容易治理。
- **宿主-引擎契约值得抄**：iframe + postMessage 同步主题/语言、Ctrl+S 上交宿主持久化、ready/failed 状态机、租约与池上限（5）、`previewPoolFull` 这类显式背压。
- **安全边界要补**：iframe 无 `sandbox`、页面从 loopback HTTP 加载，安全依赖 loopback + `--cors_origin` 白名单；WorkPivot 采用类似形态时必须显式加 sandbox、限制 origin 与消息校验。
