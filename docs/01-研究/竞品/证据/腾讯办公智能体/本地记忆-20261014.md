## 1. 结论与证据边界

**已观察：本项目存在“项目长期记忆 + 按日工作日志”的 Markdown 两层持久化结构。** 它保存项目约束、材料与产物定位以及经验；不只是聊天全文，也不只是用户画像。`MEMORY.md` 侧重长期稳定信息，日期文件承载按任务累积的过程记录。

**未确认：** 实际 prompt 注入策略、自动/手动写入边界、模型选择、并发写入保护、云端同步及加密机制。这些必须由安装包调用链或运行记录证明，不能从目录名反推。

**安装包补证：** 主报告[第 4 节](运行过程复核-20261014.md#4-项目记忆如何与运行原理衔接)已找到桌面 MemoryCollector 与 prompt 模板消费链：满足模式/配置条件时直接读取 cwd 下 `.workbuddy/memory/MEMORY.md`，上限 10,000 UTF-16 单位；日期日志按需读取、由任务结束后的提示规则指导追加。当前长期文件为 10,308 单位，会在该读取路径命中截断条件。本报告以下“未确认”均指目录快照本身或具体历史会话，不否认已找到的静态设计路径。30 天提炼删除是模板要求，实际旧日志仍存，未证明可靠执行。

## 4. 日期日志的结构与维护痕迹

日期日志并非统一大小的简短摘要：最小 1,083 字节，最大 134,879 字节，相差约 125 倍。大日志含大量 Markdown 标题和分隔线；2026-09-16.md 有 12 个含时分形式的标题，2026-09-17.md 有 5 个。可确认同日文件能容纳多段记录，不能仅凭最终快照断言使用追加写、整文件覆盖还是合并写。

脱敏结构证据：

- `2026-07-18.md:8,25,40,43-45` 存在交付物扩展名引用，`:54` 出现 `MEMORY.md` 引用。
- `2026-09-16.md:25,49,61` 为分隔线，显示多个记录块；`:34,44,57` 含工具/修复/渲染类词；`:5,44,55` 含约束性词。
- `2026-10-13.md:18,20,46,48,60` 含完成或后续状态类词；`:26-29,77-79` 含交付物引用；`:53,65,99` 含约束性词；`:63,74,95,99` 含工具经验类词。
- 跨文件共 7 行出现 `MEMORY.md`：`2026-07-18.md:54`、`2026-08-29.md:5`、`2026-09-02.md:8,16`、`2026-09-17.md:218,543`、`2026-10-12.md:59`。这证明日志与长期文件之间有文本引用，不等同于成功读写审计。

上述是词型和结构观察，不将日志自述的“完成”当作交付物验收，也不把自然语言记录当成工具执行证据。没有对全部业务正文做事实核查。
