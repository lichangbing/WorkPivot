# 豆包（字节跳动）竞品研究

| 项 | 值 |
| --- | --- |
| 类型 | 通用 AI 助理（含内置文档编辑能力） |
| 研究状态 | 🔄 只针对文字文档查看/编辑做了专项复核；产品面未全面展开 |
| 首次研究 | 2026-11-03 |
| 最后复核 | 2026-11-03（桌面端 2.34.6） |
| 证据等级 | A/B：受控运行观测 + 安装包静态分析 |
| 许可 | 专有软件；内置文档引擎闭源，不得复制代码、资源包或引擎二进制 |

> 一段话结论：豆包桌面端把“看文档”和“改文档”拆成两条路径——浏览走**服务端转 PDF + pdf.js**，编辑走**随客户端打包的飞书 Bear 文档引擎**（`@ccm-vmok/office-word`）；两者在同一个标签页面板下靠显隐切换，引擎容器常驻热备。对 WorkPivot 的直接意义是：只读浏览不需要引入大型编辑器，保真浏览的难点在转换侧而不在渲染侧。

## 1. 产品与用户

| 字段 | 观察 |
| --- | --- |
| 厂商 | 字节跳动 |
| 形态 | Windows/macOS 桌面端、Web、移动端；桌面端为 Lark/飞书同源 Chromium 壳 |
| 定位 | 通用 AI 助理，对话为主入口，文档、云盘、表格、幻灯片作为内嵌能力 |
| 文档相关入口 | 对话页右侧画布、文档标签页、云盘文件列表 |
| 支持格式（宿主声明） | `.xlsx`、`.pptx`、`.csv`、`.docx`、`.doc` |
| 文档能力性质 | 导入为云文档后可编辑；不是“就地预览本地文件”的轻量预览器 |

## 2. 文档能力观察

| 能力 | 状态 | 观察 |
| --- | --- | --- |

## 3. 运行与技术架构

### 3.1 双路径

```
本地 .docx ──服务端转换──> 派生 PDF（签名 URL）──> pdf.js(react-pdf) ──> 可见标签页面板
        └──ttoffice──> clientVars ──> 飞书 Bear docx 引擎(iframe) ──> 隐藏热备面板（编辑时显形）
```

运行实测（CDP）显示：可见面板的 DOM 是 `.react-pdf__Document → .react-pdf__Page → textLayer`，页容器 908×1284、canvas 像素 1135×1605，文档 2 页即 2 个页容器；同一窗口另有 `doubao://` 下的 `ccm-office/preheat` iframe，`body` class 为 `wiki-office-multi-tab-canvas`，祖先节点带 `tabPanelRetainedHidden` 且 `opacity: 0`，内部 `contenteditable` 与 `canvas` 均为 0。

### 3.2 引擎

| 项 | 值 |
| --- | --- |
| 包标识 | `@ccm-vmok/office-word` |
| buildVersion | `1.0.0.1893` |
| 构建名 | `lark/ccm/office/docx` |
| 加载方式 | vmok 模块联邦 + Garfish，宿主 `@flow-web/desktop` 1.18.0 |
| 暴露 | 仅 `core`（26 同步 + 192 异步 chunk），shared `react/react-dom 17.0.2` |
| 资源位置 | 随客户端打包（`doubao_office.pak` 内 `static/v/w/`，432 个文件） |
| 内部模型 | `BLOCKTYPE.PAGE`、`page_config`、页边距、`pageBreakBefore`/`keepNext`、`.docx-page-block` |
| 渲染方式 | DOM 排版为主（`contenteditable` + 块服务），canvas 用于图表/图形/测量等局部 |

### 3.3 格式互转

- `ttoffice_docx_converter.wasm`：`Docx → clientVars` 与 `clientVars → Docx`，默认参数 `deterministic_seed: docx-body`；
- `lark_export.dll`（45.7 MB）：原生流式导入 `TTOfficeLarkImport`，带 `docToken`、`last_seq`、可取消，用于大文件与增量导出；
- 组件版本 `office_ttoffice 0.11.5`，按平台（win32-x64 / win32-arm64 / darwin-arm64）分发。

### 3.4 读取与生成都在服务端

读取：

- `biz.pak`（10,566 条目）校正扫描后，客户端**没有** `mammoth`/`docx2txt`/`SheetJS`/`pptxgenjs` 等解析库；此前的 `mammoth`、`openxml` 命中分别是 emoji 名称列表与 MIME 类型表，属假阳性。
- 命中的是 `pdfjs`（条目 `7476`，339,420 B 完整库）与 `clientVars`（条目 `8302`），即"渲染派生物"和"编辑器中间模型"，不是文档解析器。
- 对话读文档的桥是 `s2-office-chat-docx-rpc-bridge`（69,949 B）：`samanthaApiService.SkillPack({skill_type: SkillType.WriteAssistant})` + 按 `resourceId` 的 RPC 客户端；画布挂载在 `canvas-docx-panel` 与 `standalone-office-docx-canvas-definition`。
- 浏览态的取数请求为 `GET /samantha/preview/mget_meta`、`GET /samantha/pdf/ocr`（补文字层），说明"内容可读"由服务端负责。

生成：

- Word：`create_docx({pageToken,title,scene,parentNodeId})` 建云文档（失败埋点 `create_docx_error`），模板内容走 `AGWInsertTemplateContent`。
- 导出：`POST /space/api/export/create/`（`export_type`/`token`/`version`/`vc_tab`/`time_zone_offset`/`is_doubao_enterprise`），下载 `GET /space/api/box/stream/download/all/{token}?type=docx`；Excel、PPT 同构，下载埋点为 `ai_sheet_export_xlsx_download`、`ai_ppt_export_pptx_download`。
- PPT 是分阶段产物：`ai-ppt-outline` → `ai-ppt-template` → `ai-ppt-slide`，页面级资源由 vmok 引擎渲染。
- 产物以 `content_blocks_v2` 的 `BLOCK_ARTIFACT` 表示，带 `resource_id`、`resource_version`、`minor_version`、`snapshot_page_minor_version`；`NodeType` 枚举覆盖 `SlidePPT=9`、`DocxPage=10`、`Spreadsheet=12`、`CanvasWorkspace=16`。
- 画布预热受 AB 开关控制：`enable_docx_canvas_preheat`、`enable_slide_canvas_preheat`。

### 3.5 安装包结构

- pak v5 头 6 字节：`u32@0=version`、`u8@4=encoding`、`u32@8=count`；条目表自 12 起每条 6 B = `u16 id` + `u32 offset`（offset 在 +2，按 +4 读会整表错位）。
- 长度 = 下一 offset − 本 offset；多数条目为 gzip。
- `doubao_office.pak`（11,925 条目）= office 运行时与引擎；`biz.pak`（10,566 条目）= 主 Web、聊天与部分 office chunk。两者不可混用。

## 4. 对 WorkPivot 的取舍

值得吸收：

- **浏览与编辑分层**：只读场景不必背上编辑器运行时，WorkPivot 已选“转换 + PDF 阅读器”，方向一致。
- **文件身份显式化**：标签页绑定文件路径与会话，切换标签不重新解析文件。
- **保真基线落在“页”**：三家（豆包服务端、WorkBuddy 本地专有引擎、WorkPivot 隔离执行器）最终都归到 PDF 页，差异只在转换侧。
- **转换侧要补文字层**：豆包在派生 PDF 之外还调 `pdf/ocr` 补可选中文本，说明"能看"和"能取字"是两件事，转换服务要一并产出。
- **产物带版本快照**：生成结果以 `BLOCK_ARTIFACT`（`resource_id` + `minor_version` + `snapshot_page_minor_version`）表示，回放与对比有据可依。
- **生成分阶段**：PPT 拆成大纲 → 模板 → 逐页，比一次性生成整本更可控，也更容易中断恢复。

不应照搬：

- 云端转换：私有化与离线前提冲突，且把文档内容交给外部服务。
- 常驻热备引擎容器：数百 MB 资源与预载开销，只读场景无收益。
- 引擎二进制与资源包：闭源，不能随产品分发，也不具备许可基础。

与 WorkPivot 的关系：

| 维度 | 豆包 | WorkPivot（当前口径） |
| --- | --- | --- |
| 浏览 | 服务端转 PDF + pdf.js | 隔离执行器转 PDF + 浏览器阅读器 |
| 编辑 | 内置飞书引擎 | 不提供应用内编辑；修改由 Agent 产出新版本 |
| 离线 | 浏览依赖服务端 | 全部在私有环境内完成 |
| 许可 | 闭源 | 只用可分发组件（LibreOffice MPL / pdf.js Apache-2.0） |

## 5. 证据与限制

| 结论 | 主要证据 | 等级 |
| --- | --- | --- |
| 浏览走 pdf.js 渲染派生 PDF | CDP 实测 DOM + 网络请求 | A |
| 编辑走内置飞书 docx 引擎 | 安装包内 vmok manifest 与引擎 chunk | B |
| 读取与生成在服务端 | 客户端无解析库（校正扫描）+ `samantha/*` 请求 + 导出接口与埋点 | B |
| 生成分阶段且带资源版本 | `content_blocks_v2`、`BLOCK_ARTIFACT`、`ai-ppt-*` chunk | B |
| pak v5 结构与条目表 | 读取器实测（`u16 id` + `u32 offset`） | A |
| 引擎为隐藏热备容器 | 祖先节点 class 与计算样式 | B |
| 本地 `.docx` 与引擎间用 ttoffice 互转 | 宿主 main.js 静态代码与 wasm 加载器 | B |
| 编辑态切换行为 | 未点击验证 | D |

证据边界：只采样一份 2 页 `.docx`；未覆盖大文件、协同、断网、表格与幻灯片；服务端转换实现未取得，保真度不可核实。
