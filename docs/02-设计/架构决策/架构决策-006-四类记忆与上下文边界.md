## 1. 背景

此前“短期记忆、长期记忆、工作记忆、会话记忆、运行状态”等术语混用了三种不同维度：

1. **生命周期**：当前调用、会话、任务、长期；
2. **内容类型**：经历、事实、方法、偏好；
3. **归属范围**：用户、项目、会话、工作项。

WorkPivot 是后台持续运行的 Agent，不依赖桌面客户端关闭后即丢弃的进程内短期记忆。但后台常驻不等于模型拥有连续记忆：每次模型请求仍需重新组装上下文，任务仍可能暂停、恢复、并发或跨实例执行。

同时，聊天记录、文件字节、业务事实、记忆摘要和工作产出当前分别保存在不同模块。若继续用“记忆就是发给模型的上下文”描述，会导致：

- 把所有聊天和工具日志当作长期记忆；
- 每轮注入过多低相关内容；
- 项目摘要覆盖权威业务事实；
- 会话记忆、工作记录和运行状态互相重复；
- 模型把检索内容误当成系统指令；
- 删除、修订和权限变化无法正确传播。

## 2. 候选方案

| 方案 | 简述 | 主要优点 | 主要缺点 |
| --- | --- | --- | --- |
| A：三层作用域 | 保留 user/project/task 三类记忆名称 | 与当前代码接近 | 无法区分会话经历和实际工作台账 |
| B：认知四层 | working/episodic/semantic/procedural | 与常见 Agent 理论对齐 | 与 WorkPivot 的业务对象和现有页面不完全一致 |
| C：四类产品记忆 + 动态上下文 | 用户、会话、项目、工作记忆；每轮组装 ContextPack | 贴近后台任务交付、项目协作和成果定位 | 需要补齐工作记忆和会话摘要的数据模型 |

## 3. 决策

采用方案 C。

### 3.1 上下文与记忆

- **上下文是每轮模型调用时临时组装的输入。**
- **记忆是持久化保存、可被后续任务检索和复用的内容。**
- 记忆是上下文的一类来源，但不是上下文本身。
- 原始聊天、工具日志、任务运行、文件字节和业务事实不因“已经持久化”就自动成为记忆。

### 3.2 四类产品记忆

| 记忆 | 定义 | 主要回答的问题 |
| --- | --- | --- |
| 用户记忆 | 用户长期稳定的角色、偏好、职责和工作方式 | 用户是谁、通常怎样工作 |
| 会话记忆 | 一次会话的目标、角色、材料版本、讨论、决定、产出和未决事项 | 这次沟通做了什么、决定了什么 |
| 项目记忆 | 项目背景、规则、当前阶段、重要决策和派生概览 | 项目现在是什么状态 |
| 工作记忆 | 以工作项为中心的持久工作台账 | 安排过什么、怎么做的、产出了什么、成果在哪里 |

“短期/长期”描述保留周期，不与上述四类产品记忆并列。后台统一持久化，但按会话、项目、工作项和保留策略分别治理；长期记忆也不等于永久保存。

### 3.3 工作记忆和当前工作

工作记忆必须保存为可追踪工作项，而不是一段自然语言流水账：

```text
WorkItem
├─ 目标与任务
├─ 当前状态与下一步
├─ 使用角色 / 专家
├─ 输入材料及版本
├─ 计划和方法引用
├─ 运行与检查点引用
├─ 成果 ID、版本、哈希和存储位置
├─ 关键决定与未决事项
└─ 来源会话、项目、用户
```

约束：

- “当前工作”是某个工作项或该工作项的当前运行，不是全系统唯一任务。
- 后台可以有多个用户、多个任务并发运行。
- 技术实现继续保留 `task_runs`、`tool_dispatches`、租约、检查点和审批记录，作为工作项的执行实例和恢复依据。
- 不在工作记忆中复制完整工具日志、隐藏思考或文件字节；只保存可追溯引用和可读摘要。
- 文件位置使用不可变成果 ID、文件版本 ID 和哈希定位，不把可失效裸路径作为唯一凭据。

### 3.4 会话记忆和聊天记录

- 原始聊天消息、思考、工具调用和结果属于**事件记录/证据**。
- 会话记忆是会话中形成的结构化情景记录，不是整段聊天副本。
- 会话记忆至少记录目标、使用角色、材料版本、关键决定、成果、未决事项和下一步。
- 会话记忆可以引用工作项；一个会话可以有多个工作项，一个工作项也可以跨多个会话。

### 3.5 项目记忆和业务事实

项目记忆不是所有会话的滚动总摘要，而是可重建的项目认知视图，包含：

- 项目概览；
- 稳定项目规则；
- 已确认业务事实的引用；
- 重要历史决定；
- 当前风险和未决事项。

业务事实继续作为项目范围内可由 schema、revision、时间和证据约束的结构化业务真值。项目记忆引用业务事实 revision，不复制或覆盖权威值。

### 3.6 上下文装配

每轮 `ContextPack` 只装配当前问题所需内容：

```text
ContextPack
├─ 系统规则与当前用户请求
├─ 当前工作记忆
├─ 相关用户记忆
├─ 相关项目记忆
├─ 相关历史会话记忆
├─ 相关历史工作记忆
├─ 已确认业务事实
├─ 原始文件证据
└─ 当前 Skill / 程序方法
```

过滤顺序至少包括用户、项目、角色、材料版本、状态、有效期、来源完整性和删除状态。

### 3.7 事实与证据层级

| 层 | 职责 | 权威边界 |
| --- | --- | --- |
| 当前用户指令 | 本轮目标、范围和临时约束 | 不得静默改写已确认业务事实 |
| 已确认业务事实 | 项目业务值和关系 | 支持 revision、时间、证据和冲突 |
| 原始文件/聊天事件 | 事实证据和审计来源 | 内容不等于自动确认真实 |
| 项目概览/会话/记忆摘要 | 导航、连续性和个性化 | 必须有来源，可从原始证据重建 |
| 模型推断 | 候选解释或建议 | 必须标注推断，不能当作确认事实 |

### 3.8 写入路由

| 内容 | 默认写入 |
| --- | --- |
| 用户刚才的请求、回答和工具过程 | 对话事件 |
| 当前目标、步骤、等待、检查点 | 当前工作项及其运行记录 |
| 一次会话的决定、成果和未决事项 | 会话记忆 |
| 可跨任务复用的工作方法 | Skill / 程序知识 |
| 稳定用户偏好、职责和表达习惯 | 用户记忆 |
| 项目稳定背景、规则和概览 | 项目记忆 |
| 可结构化、可计算、可审计的业务值 | 业务事实 |
| 文件字节、页面快照、转换产物 | 原始文件/知识版本 |

一次临时要求不得自动提升为用户偏好、项目规则或业务事实。

## 4. 理由与取舍

- **选择依据：** 四类产品记忆直接对应 WorkPivot 后台执行、项目协作和成果交付，不要求为了“四层记忆”另造一套抽象。
- **接受代价：** 需要新增或统一会话摘要、工作项索引和上下文装配服务，并迁移当前 `task` 记忆口径。
- **放弃内容：** 不把聊天记录、运行日志或项目摘要直接当作业务事实；不让模型自行决定信息应写入哪一类长期数据。

## 5. 与当前实现的映射

| 目标概念 | 当前实现载体 | 状态 |
| --- | --- | --- |
| 上下文 | 系统提示、消息、资源范围、自动召回的记忆与业务事实、工具结果、Skill | ✅ 已运行 |
| 用户记忆 | `memories.scope=user`，当前按 project_id 隔离 | 🟡 已有，需明确全局/项目覆盖语义 |
| 项目记忆 | `memories.scope=project` + 项目事实与后续概览 | 🟡 部分实现 |
| 会话记忆 | `conversation_turns/conversation_events` 与长对话摘要 | 🟡 有原始记录和压缩，尚未形成统一结构化会话记忆 |
| 工作记忆 | `tasks/task_runs/tool_dispatches/artifacts` 等组合 | 🟡 能力分散，尚无统一 WorkItem 视图 |
| 任务记忆 | `memories.scope=task` | ⚠️ 当前实现先保留；后续归入工作记忆或任务工作项 |
| 业务事实 | 项目对象、事实/关系 series/revision、证据和冲突 | ✅ 已实现并部署 |
| 文件知识 | 不可变文件版本、解析分块、RAG、引用 | ✅ 已实现 |
| 程序记忆 | Skill、专家经验、工作流模板 | ✅ 已有，独立治理 |

本 ADR 不要求立即删除 `task` scope，也不要求一次性重建数据库。后续实现应按兼容迁移推进：

1. 先补 `WorkItem` 聚合视图，不复制运行和成果数据；
2. 再生成结构化会话记忆并关联工作项；
3. 最后统一产品导航、检索和 `task` scope 的兼容映射。

## 6. 约束

- 记忆不是系统指令，不得改变权限、执行范围或审批要求。
- 项目概览、会话摘要和用户偏好不能覆盖已确认业务事实。
- 摘要必须保留来源引用，可从原始事件和文件版本重建。
- 删除、撤权、来源失效和业务事实 revision 变化必须传播到项目概览、会话记忆和召回。
- 未完成、失败或中断的工作项不得被写成“已交付成果”。
- 成果位置以成果版本和哈希为准，不以聊天中的路径描述为准。
