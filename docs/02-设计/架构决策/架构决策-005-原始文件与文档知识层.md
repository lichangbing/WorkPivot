# ADR-005：原始文件与文档知识层

- **状态**：✅ 已接受
- **日期**：2026-10-28
- **关联设计**：[原始文件与多版本文档管理](../架构/数据/原始文件与多版本文档管理.md)、[RAG 知识库、版本与遗忘管理](../架构/数据/检索增强知识库与遗忘管理.md)

## 背景

WorkPivot 的对话记录、三层记忆和业务事实已进入 PostgreSQL。与此同时，用户仍会上传合同、报告、研报和 Office 文件，并持续产生新版本。需要明确 RAG 是否是系统记忆真相，以及原始文件如何保存、检索和演进。

## 候选方案

| 方案 | 简述 | 主要优点 | 主要缺点 |
| --- | --- | --- | --- |
| A：所有数据统一进入 RAG | 对话、记忆、事实和文档全部向量化 | 查询入口统一 | 事实冲突、版本和精确计算难以保证 |
| B：数据库事实 + 文档 RAG | 数据库保存权威业务数据；RAG 只索引非结构化文档 | 职责清晰、可审计、可重建 | 需要维护两套检索路径 |
| C：只直接读取文件，不做 RAG | Agent 每次读取原文件 | 实现简单 | 大量文档和长上下文不可扩展 |

## 决策

采用方案 B：

1. 原始文件是不可变事实源，按用户和版本 ID 保存。
2. PostgreSQL 保存文档身份、版本、权限、解析文本、知识分片和业务事实。
3. RAG 只是非结构化文档的派生检索层，可删除并重建。
4. 对话记录、记忆和业务事实不默认进入向量库。
5. 少量短资料直接读取；大量、长文档或跨任务资料才启用 RAG。
6. 项目知识库默认不入库；只有用户从候选内容中勾选并确认过的文本内容才能分片和索引。
7. 允许删除单个文件版本，删除时同步失效该版本的分片、向量和引用。
8. 当前 2 核 4 GB / 40 GB 单机继续用文件卷保存原件，不引入对象存储服务。

## 理由与取舍

- **选择依据**：结构化事实需要版本、约束和精确查询；语义相似度不能判断哪个金额或合同状态正确。
- **接受代价**：系统需要区分直接读取和文档检索两条路径，并维护文件版本与索引状态。
- **放弃内容**：不采用“全量对话和记忆统一向量库”的方案，不把 RAG 当作事实真相。

## 影响与后续行动

- 新文件版本必须创建不可变版本记录，禁止覆盖旧版本。
- 默认检索使用最新完成解析和索引的版本；旧版只做显式历史查询。
- 原始文件和 PostgreSQL 元数据必须成对备份。
- 公开网页和文档的文本内容均需用户确认后才能进入项目知识库。
- 解析完成不等于自动入库；聊天、思考、工具日志、临时网页、记忆、业务事实、页眉页脚、目录和无关章节默认排除。
- 一个文件可以只入库用户选择的部分章节，未选内容不得在重建索引时重新进入知识库。
- 新文件版本改变事实时，相关记忆和业务事实进入待复核，不自动覆盖。
- 单版本删除必须同步失效关联知识；删除当前版本后不自动启用旧版。
- 版本保留期限仍待产品确认，当前建议最多保留 100 个版本且不自动删除。
