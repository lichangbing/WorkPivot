# ADR-003 PostgreSQL 与文件混合存储

日期：2026-09-13。状态：主数据库选型已按用户要求确定；详细模型为实施设计，尚未迁移或部署。

## 决策

后台采用 PostgreSQL 作为系统记录和项目知识的主数据库。原始文档、成果快照、技能资源包与执行工作目录使用文件存储。后续语义检索采用 pgvector 扩展，索引是可以重建的派生数据。

不继续把账号、项目、任务、会话、聊天、配置、记忆、权限等 JSON 文件作为运行时主存储，也不把所有文件作为 Base64 写进数据库。关键关联与字段使用关系表；灵活元数据和解析器输出使用 JSONB；数值计算使用明确类型。

## 原因与代价

长期项目需要跨任务查询、指标计算、版本追溯和并发更新。关系、唯一约束、事务、索引及行级权限适合由数据库承担。现有 JSON 原子替换只能保护单文件写入，无法提供完整的跨文件事务。

文档和执行程序需要普通文件接口。保留文件存储可以避免业务数据库被大型二进制和工作缓存占满，也便于后续替换为对象存储。

代价：增加数据库运行维护、连接池、迁移管理，以及数据库与文件间一致性协议。必须联合备份数据库与文件，不能将单独的数据库备份当作完整系统备份。

## 权限与部署

账号及平台配置与个人业务表分开。应用管理员可以管理账号、公共能力和运行概况，不能读取其他用户项目、消息、文件、抽取数据和私人记忆。数据库运行角色不使用超级用户或 BYPASSRLS；个人表启用并强制 RLS。数据库运维身份与应用管理员身份不同。

PostgreSQL 使用独立持久卷和内部网络；不给公网发布数据库端口。原有 Docker socket 不挂载约束保持。版本、扩展和镜像摘要在实施时核验并固定，不使用浮动 latest。

## 新建部署原则

用户已明确不需要旧数据迁移。使用新 PostgreSQL 数据库和独立文件命名空间；不开发 JSON 导入、双写或旧 ID 映射。保留数据库结构升级脚本，不等于迁移历史业务数据。不迁移不意味着删除旧部署或文件。

RAG 知识库、数据版本和用户自主删除纳入核心范围。详见 [PostgreSQL与项目知识数据架构](../架构/数据/关系数据库项目知识架构.md) 与 [RAG知识库、版本与遗忘管理](../架构/数据/检索增强知识库与遗忘管理.md)。当前设计不代表运行版本已被替换。
