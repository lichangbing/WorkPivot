## 何时需要 ADR

- 新增或替换数据库、消息系统、运行时或核心框架。
- 引入新的信任边界、宿主权限、外部执行或网络出口。
- 改变身份、租户、数据共享、删除或备份模型。
- 改变 Agent 工具协议、权限审批或恢复语义。
- 形成难以在单个模块内回滚的兼容性约束。

普通页面调整、局部缺陷修复和无架构影响的文案变更不需要 ADR。

## 写作规则

从[_template-ADR.md](_架构决策模板.md)开始，至少包含背景、决策、替代方案、后果、约束和复核触发条件。

- 已接受的 ADR 不改写历史结论；重大改变新增 ADR 并在旧文档标注“被替代”。
- 状态使用“提议 / 已确认 / 已实现 / 已废弃 / 被替代”。
- 记录与代码、PRD、架构总览的关系。
- 不写敏感配置、真实凭据、内部账号和私有样本。
