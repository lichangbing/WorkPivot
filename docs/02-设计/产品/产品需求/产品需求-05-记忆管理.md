> **当前实现与目标口径**：RC.8 已持久化个人、项目、任务三层记忆，并具备每轮有界召回、自动保存、冲突确认、来源复核和十轮分析。产品级统一口径进一步确定为用户、会话、项目、工作四类记忆；原始聊天、`task_runs`、检查点和成果记录暂时承载会话与工作记忆能力，后续收敛为统一工作项和结构化情景摘要。

## 1. 目标

让 AI 能在后续工作中复用对用户有帮助的偏好、经历和成果索引，同时满足：

- 不把一次临时要求误记为长期偏好。
- 用户、项目和任务事实不串层、不跨项目泄漏。
- 新事实不需要逐条确认，减少打扰。
- 错误、修改、合并和冲突必须清楚展示并逐条确认。
- 每条记忆都能追溯来源、编辑、遗忘并停止加载。
- 上下文按当前问题动态装配，不随项目历史无限增长。
- 业务事实、原始证据、记忆摘要和模型推断有明确权威边界。

## 2. 用户场景

| 场景 | 期望行为 |
| --- | --- |
| 用户说“以后所有分析报告先给结论” | 形成个人层长期偏好，适用于当前项目范围 |
| 用户说“这个项目统一用万元” | 形成项目层约束，项目下任务可复用 |
| 用户说“本次最终输出 PDF” | 写入当前工作项约束，不升级为项目/用户偏好 |
| 用户说“刚才说的颜色改成绿色” | 对已有事实提出修订，显示单条冲突确认 |
| 用户删除某条记忆 | 立即停止加载，相关运行和旧上下文按规则失效 |
| 用户关闭某层加载 | 保留已有记忆，但后续运行不再注入该层 |
| 用户手动新增/编辑 | 用户明确提交后直接保存，不再弹自动确认 |

## 3. 四类产品记忆

| 记忆 | 核心问题 | 保存内容 |
| --- | --- | --- |
| 用户记忆 | 用户是谁、通常怎样工作 | 角色、职责、偏好、表达习惯和默认工作方式 |
| 会话记忆 | 这次沟通发生了什么 | 会话目标、角色、材料版本、讨论、决定、成果和未决事项 |
| 项目记忆 | 项目当前是什么情况 | 项目背景、稳定规则、当前阶段、关键决定和派生概览 |
| 工作记忆 | 做过什么、怎么做的、成果在哪里 | 工作项、状态、方法、运行引用、成果版本和下一步 |

“短期/长期”描述生命周期，不与上述四类记忆并列。后台统一持久化，但按会话、项目、工作项和保留策略治理。

边界规则：

- 上下文是每轮临时装配给模型的内容，不是记忆库。
- 原始聊天、工具事件和运行日志是事件/证据，不自动成为记忆。
- 会话记忆是结构化情景记录，不是整段聊天副本。
- 工作记忆是工作台账，不复制文件字节、完整工具日志或隐藏思考。
- 业务事实是结构化项目真值，不写入普通记忆后再被重复召回。

完整口径见[ADR-006](../../架构决策/架构决策-006-四类记忆与上下文边界.md)。

### 3.1 当前持久作用域与目标映射

| 层 | 内容 | 作用域 | 示例 |
| --- | --- | --- | --- |
| 用户 `user` | 稳定偏好、工作习惯、明确个人事实 | 当前按用户 + 项目隔离；临时任务可独立归属 | “报告先给结论” |
| 项目 `project` | 背景、目标、统计口径、长期约束、已确认决策 | 当前项目 | “金额统一使用万元” |
| 任务 `task` | 当前任务对象、范围、交付要求和临时约束 | 当前任务 | “本次输出 PDF” |

此表是 RC.8 的实际持久化作用域，不是最终四类产品记忆。`task` scope 暂作为工作记忆的兼容载体；会话记忆由 `conversation_turns/conversation_events`、长对话摘要和后续结构化摘要承载；工作记忆由 `tasks/task_runs/tool_dispatches/artifacts` 等组合承载。后续统一时不复制原数据，只建立聚合视图和兼容映射。

范围不明确时进入最小确定层级。一次临时要求不能升级为用户或项目记忆。

合同金额、日期、数量、业务对象和对象关系进入独立的[业务事实](产品需求-08-业务事实.md)系统。
业务事实使用项目对象、series/revision、证据与冲突状态；用户/会话/项目/工作记忆继续管理偏好、
经历、项目和执行上下文。二者不能互相覆盖。

## 4. 记忆生成

### 每轮识别

每次用户消息完成后，后台对当前持久作用域分别判断：

- 只提取本轮明确的新事实或修正。
- `evidence` 必须逐字来自本轮用户原话。
- 每项只表达一个可独立修改或删除的事实。
- 单轮最多 6 项。
- 寒暄、“好的”“继续”和无复用价值的一般问答不生成记忆。
- 明确指定给某位专家的方法进入专家经验，不重复写入当前三层持久记忆。
- 密码、密钥、Token 和敏感凭据不得保存。

### 十轮补充

个人和项目层每累计 10 轮有效对话再做一次跨任务整理：

- 发现重复出现的稳定偏好和项目约束。
- 去重、补充和合并不完整事实。
- 不把一次性要求提升为长期记忆。
- 不跨项目串用个人记忆。
- 自动化执行不计入十轮。

### 个人记忆归属

当前个人记忆按“用户 + 项目”隔离，在同一项目内跨任务使用。临时任务使用独立范围；旧全局个人记忆必须由用户确认归属后才能加载。不同项目的个人记忆不会互相注入。

## 5. 保存与确认

| 动作 | 默认处理 |
| --- | --- |
| 无冲突的新增 `add` | 自动保存为 revision 1，来源记为 `auto` |
| 修改已有事实 `update` | 生成待确认项，展示原文、建议和新内容 |
| 合并多条记忆 `merge` | 生成待确认项，展示全部原条目 |
| 后续纠正替代待确认项 | 保留单条确认，避免一次弹出一组卡片 |
| 用户确认/修改后确认 | 生成新修订，来源记为 `user` |
| 用户删除待确认项 | 等同拒绝，记录去重键，旧事件重放不反复弹出 |

确认界面一次只显示一条；处理或拒绝后显示下一条。关闭页面、超时、发送新消息都不代表同意。

自动保存与人工确认走同一个发布事务，仍校验：

- 用户与项目归属。
- 当前记忆版本 `epoch`。
- 来源任务、对话和证据仍有效。
- 目标记忆 revision 未变化。
- 对应记忆层允许更新。
- 目标未被锁定或删除。

## 6. 管理界面

### 已保存记忆

当前界面按个人、项目、任务分栏，以列表显示：

- 内容、revision、所属项目/任务。
- 修改、删除、锁定/解锁。
- 个人记忆可按项目筛选。
- 旧全局个人记忆显示“待指定归属”，确认前暂停加载。
- 分页加载，避免一次渲染大量正文。

### 待确认冲突

- 显示单条卡片，包含层级、项目/任务、建议内容、原文证据。
- 修改/合并时显示原内容或全部合并目标。
- 按钮为“确认保存 / 修改 / 删除”。
- 多条时显示“当前第 1 条，共 N 条”。

### 分析与设置

- 显示每层 10 轮累计进度、最近批次的 pending/running/completed/failed。
- 失败分析可手动重试。
- 自动整理总开关与各层加载/更新开关独立。
- 自动整理关闭不删除已有记忆。

## 7. 加载与注入

- 当前实现从三层已开启且属于当前作用域的内容中进行有界召回；目标架构再按四个产品记忆类别装配。
- 详细内容通过搜索/读取工具按需获取，不能一次注入全部记忆。
- 记忆是参考事实，不是系统指令，不能扩大文件、网页、工具或自动化权限。
- 本轮资源范围未显式选择记忆层时，当前实现默认加载三层中 `load_enabled=true` 的层。
- 关闭加载不删除记忆；关闭更新不允许后台继续生成。
- 删除、锁定、项目删除或来源撤销后，旧记忆和候选立即失效。
- 文件版本被删除后，仅由该版本运行支持且没有其他有效来源的记忆会标记“待复核”；搜索、自动加载和详情工具不再返回，直至用户核对并编辑保存。

## 8. 手动操作

### 新增

用户选择层级和归属后编辑内容。可以一次录入多条，但每条保持独立；用户点击保存即成为明确提交。

### 修改

必须携带当前 revision。保存后产生新修订；其他端使用旧 revision 保存会收到冲突提示。

### 删除

- 移入回收站并停止加载。
- 来源派生关系和旧上下文失效。
- 永久删除遵守回收站期限和人工确认。
- 管理员不能查看或代操作其他用户的私人记忆。

### 锁定

锁定只阻止自动修改/合并，不阻止用户手动编辑或删除。

## 9. 异常与安全

| 异常 | 处理 |
| --- | --- |
| 模型超时/格式错误 | 作业有界重试；超过次数标 failed，可手动重试 |
| 来源被删除/撤销 | 候选失效；不发布旧内容 |
| 文件版本删除导致记忆来源失效 | 停止检索和自动加载，保留原正文供用户复核；用户编辑后清除待复核标记 |
| 记忆 epoch 变化 | 当前候选失败，要求基于最新记忆重新整理 |
| 目标 revision 变化 | 冲突提示，不覆盖后续编辑 |
| 重复事件重放 | 使用来源、去重键和已拒绝记录抑制重复 |
| 项目变更或删除 | 项目层/所属个人层停止加载，进入删除关系 |
| 模型产生伪证据 | 拒绝保存，不进入待确认 |

## 10. 非目标

- 不保存聊天中的全部内容。
- 不自动推断敏感身份、健康、财务或其他高风险个人信息。
- 不将模型回答或工具猜测当作用户事实。
- 不维护与专家经验重复的方法记忆。
- 不允许记忆修改系统指令、权限或执行策略。
- 不保存聊天、工具日志或文件字节的完整副本作为记忆。
- 不把项目概览或会话摘要当作业务事实的唯一来源。

## 11. 验收标准

- [x] 一轮同时包含三层事实时，分别生成 user/project/task 记忆；四类产品记忆统一映射待后续实现。
- [x] 临时任务要求不升级为个人/项目事实。
- [x] 无冲突新增自动保存，不产生待确认项。
- [x] 修改/合并/冲突产生待确认项，一次只显示一条。
- [x] 真人确认后 revision 递增并保留逻辑记忆 ID。
- [x] 错误证据、跨项目目标、旧 revision 和锁定条目不能写入。
- [x] 不同项目之间个人记忆零串用。
- [x] 关闭加载不注入；关闭更新不生成新的事实；重新开启不重放旧关闭期间内容。
- [x] 删除后不再被搜索、概览、聊天或历史重放加载。
- [x] 十轮批量分析失败可重试，空结果成功且不凑数。
- [ ] 会话结束后生成带角色、材料版本、决定、成果和未决事项的结构化会话记忆。
- [ ] 工作项聚合视图可以回答“做过什么、怎么做的、成果在哪里”，且不复制现有运行和成果数据。
- [ ] 每轮上下文装配记录来源、过滤结果、revision 和预算，并可审计。

## 12. 指标

| 指标 | 目标 |
| --- | --- |
| 当前作用域归类正确率 | 固定中文样本集人工核对 |
| 无价值记忆率 | 持续下降，不以生成数量衡量成功 |
| 冲突重复弹卡率 | 同一事实被拒绝后不重复弹出 |
| 跨项目泄漏 | 0 |
| 自动保存审计覆盖 | 100% 可查来源与 decision source |
| 清理正确率 | 删除/项目删除后检索和注入零召回 |
