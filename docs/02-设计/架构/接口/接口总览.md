| 项 | 值 |

| 状态 | ✅ 当前接口基线 |
| 最近更新 | 2026-11-03 |
| 对应版本 | `v0.3.0-rc.4`，schema v71 |

本文是面向开发、测试和运维的整体接口设计，不是自动生成的 OpenAPI。字段细节可能随版本演进，路由、鉴权、幂等、版本冲突和 SSE 恢复原则属于当前兼容基线。实现与本表冲突时应先核对源码和版本，再同步修订文档和测试。

## 1. 设计原则

1. **服务端是权威状态源**：客户端可以缓存展示，但项目、任务、运行、交互、文件版本、记忆和业务事实均以 PostgreSQL 与受控文件卷为准。
2. **命令与事件分离**：HTTP JSON 接口执行创建、修改、确认、删除和查询；SSE 传播工作区变化、运行过程和待处理状态。
3. **授权不能藏在界面里**：每个接口在服务端校验身份、角色、任务归属、项目成员关系、资源 revision 和本轮读取范围。
4. **可重试操作必须幂等**：消息发送、上传、自动化运行、Skill 构建和批量写入使用 `requestId`；重复请求不能产生第二个副作用。
5. **可变配置使用乐观锁**：请求携带预期 `revision`，版本不一致返回 409，禁止后保存者静默覆盖。
6. **断线不重发危险操作**：客户端通过持久游标恢复事件；是否继续执行由服务端检查点决定，不由页面刷新触发。

## 2. 通用协议

### 2.1 请求

- 基础路径：`/api`。
- JSON 请求使用 `Content-Type: application/json`；普通 JSON 上限为 1 MiB。
- 文件上传使用 `application/octet-stream`，当前单次上限为 10 MiB；更大文件应拆分或在后续版本扩展分片协议。
- Skill 文本和资源包有独立上限；超出时返回 413。
- 鉴权成功后请求头使用 `Authorization: Bearer <token>`。登录、注册和 OIDC 换票接口不要求既有会话。
- 未登录访问 `/api/auth/state` 或 `/api/health` 允许；其他 `/api` 路由默认要求有效会话。
- 临时密码账户只允许修改密码和退出登录，其他请求返回 403。

### 2.2 响应

- 普通响应为 JSON，文件下载可为 `application/octet-stream`，个人数据导出为 ZIP，安全审计导出为 NDJSON，运行和同步流为 `text/event-stream`。
- 错误响应以 `{ "error": "面向用户的中文说明" }` 为主；客户端不得依赖内部异常文本做业务分支。
- 成功响应通常返回资源对象、`{ ok: true }`、新的 `revision` 或持久 ID。
- SSE 每个事件的 `data:` 是完整 JSON；事件类型位于 JSON 的 `type` 字段，不使用 SSE 的 `event:` 字段做版本契约。

### 2.3 状态码

| 状态码 | 语义 | 客户端处理 |
| --- | --- | --- |
| 200 | 查询或同步命令成功 | 应用返回并更新本地展示 |
| 202 | 已接受异步操作或重复请求 | 不重复触发副作用，继续观察任务/自动化状态 |
| 400 | 参数、游标、计划或状态转换无效 | 展示可修正提示，不自动重试 |
| 401 | 未登录、会话过期或被撤销 | 停止轮询和 SSE，回登录页 |
| 403 | 角色、所有权、项目成员关系或已停用账户拒绝 | 展示无权限；不得通过修改前端绕过 |
| 404 | 资源不存在、已删除或不属于可访问范围 | 刷新对应快照，不泄露资源是否存在 |
| 409 | revision/hash 冲突、幂等键复用、来源失效或状态已变化 | 重新读取最新状态，由用户确认后再提交 |
| 410 | 已停用接口 | 停止调用并迁移到替代接口 |
| 413 | 请求体、文件、Skill 包或输出超过限制 | 提示大小边界或拆分为多个文件 |
| 415 | 文件类型不支持该预览方式 | 保留下载能力，不伪造预览 |
| 422 | 内容格式可解析但不满足安全/业务约束 | 展示具体修正项 |
| 429 | 对话/Token 限额、认证限速、并发或试运行次数达到上限 | 显示可用时间、限额或排队状态 |
| 503 | 数据库、模型、Worker、浏览器或预览转换服务不可用 | 明确降级和重试方式，不切换到宿主执行 |

### 2.4 幂等键

以下写操作应生成 UUID `requestId`，超时重试复用同一个值：

- `POST /api/tasks/:id/messages`
- `POST /api/tasks/:id/interactions/:interactionId/respond`
- `POST /api/tasks/:id/steering`
- `POST /api/tasks/:id/notes`
- `POST /api/tasks/:id/files?requestId=...`
- `POST /api/tasks/:id/resume`
- 自动化草稿/手动运行和 Skill 构建相关写操作

同一 `requestId`、同一 actor 和同一语义载荷重试时，服务端返回既有结果或 202 duplicate；同一键用于不同载荷时返回 409。客户端不能因为连接中断就生成新的键重发。

### 2.5 revision、hash 与资源范围

- 项目、任务、偏好、访问策略、限额、专家、MCP、Provider、自动化、记忆、业务事实和 Skill 草稿等可变对象使用整数 `revision`，从 1 开始递增。
- 用户提交修改时传当前 revision。服务端在同一事务中比较并递增；不匹配返回 409。
- Skill 草稿和发布还使用内容 `hash`，确认时必须同时匹配 revision 与 hash。
- 不鼓励客户端提供数据库 `updated_at` 作为并发令牌；时间戳不替代 revision。

任务运行的本轮授权范围由 `resourceScope` 表示，字段含义如下：

```json
{
  "versionIds": ["文件版本 UUID"],
  "memoryScopes": ["user", "project", "task"],
  "scheduleIds": ["自动化 UUID"],
  "expert": true,
  "baseRunId": "上一运行 UUID 或 null"
}
```

- `versionIds`：本轮允许读取和作为 Skill 输入的文件版本，最多 100 个。
- `memoryScopes`：本轮允许召回的记忆层；未显式提供时按用户记忆加载开关补齐。
- `scheduleIds`：本轮允许查看、修改或停止的自动化。
- `expert`：是否启用任务/项目绑定的专家设定。
- `baseRunId`：提交时看到的上一运行 ID，用于发现另一个客户端已改变读取范围。

资源范围变化后，旧批准失效；文件被删除、自动化失效、专家 revision 改变或资源范围 epoch 改变时，当前运行停止并返回明确的 409/失败状态。客户端应重新获取 `GET /api/tasks/:id/resource-scope` 后由用户确认。

### 3.4 计划、运行中请求和交互

| 方法与路径 | 用途 |
| --- | --- |
| `GET /api/tasks/:id/plan` | 当前计划与步骤 |
| `GET /api/tasks/:id/steering` | 待应用/队列中的运行中请求 |
| `POST /api/tasks/:id/steering` | 排队补充、纠正或后续要求，返回 202 |
| `DELETE /api/tasks/:id/steering/:steeringId` | 撤销尚未执行的请求 |
| `GET /api/tasks/:id/interactions` | 统一待处理澄清、计划、授权和成果验收 |
| `POST /api/tasks/:id/interactions/:interactionId/respond` | 按 revision 回答；必要时空开下一轮 SSE |
| `GET /api/tasks/:id/permissions` | 兼容接口：待处理动作授权 |
| `POST /api/tasks/:id/permissions/:permissionId` | 兼容接口：仅本次允许或拒绝 |

统一交互的 kind 为 `clarification`、`plan_approval`、`action_permission`、`artifact_review`。同一运行只显示一个阻塞项。计划修改会保存新 revision 并将旧计划标记为 superseded；动作审批绑定工具、参数摘要、资源和调用 ID。

运行中请求的处理规则：

1. 新消息先持久化为待应用请求。
2. 模型流结束或工具批次到达安全点后判断与当前任务的相关性。
3. 相关请求进入当前上下文，撤销旧计划批准并重新规划。
4. 无关请求标记为后续队列，当前运行完成后再创建下一轮。
5. 用户撤销、任务停止或来源失效时，未执行请求进入 cancelled/stale，不会在重启后误执行。

### 3.5 文件、版本、成果与预览

| 方法与路径 | 用途 |
| --- | --- |
| `GET /api/tasks/:id/files` | 任务文件和成果列表 |
| `POST /api/tasks/:id/files?name=...&requestId=...` | 上传不可变原件；更新已有文档可带 `documentId` 与 `revision` |
| `GET /api/tasks/:id/files/:documentId/versions` | 文档版本列表 |
| `DELETE /api/tasks/:id/files/:documentId/versions/:versionId` | 删除单个版本，要求确认文本 |
| `GET /api/tasks/:id/file-versions/:versionId` | 下载指定不可变版本 |
| `GET /api/tasks/:id/file-versions/:versionId/preview` | 在线预览指定版本 |
| `GET /api/tasks/:id/file-versions/:versionId/preview-metadata` | 获取 Office 派生预览的源/PDF/转换器/字体包/文本层契约 |
| `GET /api/tasks/:id/file-versions/:versionId/structure` | 从原始文件固定版本的持久解析读取对象结构 |
| `DELETE /api/tasks/:id/files/:documentId` | 删除整份文档，要求 revision |
| `POST /api/files/cleanup` | 清理当前用户可回收的暂存文件 |

预览行为：

- PDF、PNG/JPEG/GIF/WebP/SVG、Markdown、TXT、CSV、JSON、HTML 直接返回受限内容类型和 CSP。
- DOCX/XLSX/PPTX 由隔离执行器转为只读 PDF；未配置执行器返回 503，未知类型返回 415。
- 预览只读取不可变版本，不触发“打开即修改”；继续修改必须产生新版本。
- 预览派生 PDF 只用于显示，不得作为 `read_uploaded_file`、`read_document_structure`、知识入库或事实证据的来源。
- Office 预览响应带 `X-WorkPivot-Preview-*` 溯源头；metadata 接口返回相同契约。缓存 key 包含源文件哈希、转换器版本和字体包哈希。
- 预览错误码为 `PREVIEW_UNSUPPORTED`、`PREVIEW_CAPABILITY_UNAVAILABLE`、`PREVIEW_BUSY`、`PREVIEW_TIMEOUT`、`PREVIEW_SYSTEM_FAILURE`；能力不可用时前端引导下载，系统故障才提供重试。
- 结构化读取支持 `offset`、`textOffset`、`parent`、`sheet`、`range`，偏移单位为 UTF-16 code unit，且只读取固定原始版本。
- 文件删除与知识、记忆、业务事实和成果版本的关系由同一事务或后续复核任务传播。

## 4. SSE 事件模型

### 4.1 工作区流

`GET /api/workspace/stream?after=<version>` 或 `Last-Event-ID`：

| type | 含义 |
| --- | --- |
| `workspace` | 当前用户可见项目/任务快照与单调版本 |
| `unavailable` | 认证失效（401）或游标不可恢复（409），客户端重新登录/取快照 |

工作区流不返回聊天正文。心跳每 15 秒触发一次补偿拉取并发送注释 `: ping`；连接最长 5 分钟，客户端应透明重连。

### 4.2 任务流

`GET /api/tasks/:id/stream?after=<sequence>` 或 `Last-Event-ID`：

| type | 含义 |
| --- | --- |
| `changes` | 任务持久事件增量、`nextSequence` 和 `snapshotSequence` |
| `state` | 当前任务、待审批、待交互、排队请求和专家建议的状态快照 |
| `unavailable` | 会话失效、任务越权或游标不可恢复 |

### 4.3 运行事件与持久元事件

运行开始接口直接返回 SSE `data`，常见 `type` 包括：

| 类别 | type |
| --- | --- |
| 文本与思考 | `assistant_delta`、`reasoning_delta` |
| 工具调用 | `tool_use`、`tool_status`、`tool_result` |
| 统一交互 | `interaction_request`、`interaction_resolved` |
| 兼容授权 | `permission_request`、`permission_resolved` |
| 计划与纠正 | `plan_update`、`steering_applied`、`steering_deferred`、`steering_cancelled` |
| 用量与错误 | `usage`、`error` |
| 恢复与终态 | `recovery`、`recovered`、`resumed`、`done` |

旧文件链执行入口可能发出 `gate_reject`；PostgreSQL 当前主链路以成果发布守卫、工具结果和 `error/done` 表达失败。客户端必须兼容旧事件，但新服务端不应依赖它表示当前运行状态。

`done.stopReason` 说明完成、停止、失败或中断原因；收到 `done` 才表示本次直接运行 SSE 结束。连接提前断开不代表任务已停止，应重连任务流或查询状态。

### 5.1 首次打开工作区

```text

  response: text/event-stream

  → done

```

  body: revision + response + requestId + resourceScope?

## 6. 错误恢复规则

1. **断线**：保留最后 SSE ID；使用 `Last-Event-ID` 或 `after` 重连。不要重新发送上一次用户消息。
2. **401**：停止连接并回登录页；重登后重新取工作区和任务快照。
3. **409**：重新读取资源、交互、计划或读取范围。若用户仍要执行，生成新的 `requestId`；幂等重试继续使用旧键。
4. **503 工具/服务不可用**：显示具体缺失能力。不得将 Office、Worker 或浏览器任务回退到宿主执行。
5. **运行中断**：查看任务状态和检查点；未闭合的工具标记为结果未知，不自动重放有外部副作用的调用。
6. **删除/失效**：知识片段、记忆、事实、专家或自动化来源失效后立即撤销相关上下文；用户重新确认后才能恢复使用。

## 7. 版本与兼容

- `/api/health` 的 `version`、`apiProtocol` 和 `interactionCapabilities` 用于客户端能力协商。
- 新增客户端可依据交互能力字段决定是否使用澄清 V2、计划审批、授权预览和成果验收；不能只依据前端版本号。
- 服务端不得静默删除旧字段或改变现有字段语义。破坏性变更需提升 API 协议/产品版本并提供迁移说明。
- 事件追加允许新增 type；客户端应忽略未知事件的可选展示字段，但对 `error`、`done`、`unavailable` 必须有明确处理。
- schema 迁移、服务端、Web、桌面和移动构建应成批发布。数据库回退前必须确认旧镜像能读取当前 schema。
