## 1. 形态原则

业务状态和生成文件以服务器为权威来源。客户端负责登录、交互、过程展示、按需缓存和下载，不在本地再部署一套数据库、RAG、模型服务或 Agent 执行器。

```text
Web / Electron / Android
          │ HTTPS + HTTP API / SSE
          ▼
WorkPivot Server
  ├─ PostgreSQL：用户、项目、任务、运行、记忆、知识、权限
  ├─ 文件卷：上传原件与不可变成果
  ├─ Worker：隔离 Skill / 代码执行
  └─ Browser：网页访问、截图与 PDF 渲染
```

## 2. Web

Web 是功能基线，提供完整工作台、管理后台、任务过程、成果预览和设置。前后端只通过 HTTP/SSE 通信，前端不得导入服务端业务实现，也不能依赖 Electron 专属 API。

生产环境应通过 HTTPS 反向代理访问；直接暴露服务端口、数据库端口或 Worker 管理接口不视为可接受的部署方式。

## 3. Electron

Electron 负责桌面壳、窗口交互、服务器连接和本地会话缓存：

- 无边框 36px 标题栏，保留拖动、最大化、关闭到托盘等能力。
- 登录页可在同一表单配置服务器地址、用户名和密码。
- 本地按“服务器地址 + 账号”隔离会话缓存，优先显示本地快照，再与服务端水位同步。
- 生成文件仍留在服务器；本地不批量下载全部成果。
- 主进程校验发送方、连接来源和任务访问权，只暴露具体缓存方法，不开放任意文件系统或 IPC。

本地缓存不等于完整离线模式：首次连接、身份确认和任务清单依赖服务端；离线发送队列和双向编辑暂不支持。

## 4. Android 与 iOS

采用 React、TypeScript、Capacitor，先交付 Android 测试版：

- 内置界面资源，服务器地址只用于 API，不作为远程 WebView 页面。
- 原生安全存储保存凭据；浏览器预览只保存在内存。
- 复用项目、任务、聊天、审批、记忆、Skill/MCP、产物下载和服务端权限。
- 后台继续执行，切到后台不等于停止；恢复前台按事件水位补拉。
- 文件按需下载，校验大小和 SHA-256，使用系统打开/分享。
- 发布版应使用 HTTPS，关闭明文和证书绕过；开发模式仅允许本机 HTTP。

Android 已能构建 debug APK；iOS 构建、签名和真机验收仍需 Apple 开发环境。通知、键盘、返回键、锁屏恢复与真机文件分享仍属于专项验收。

## 5. 多端一致性

所有终端使用同一任务事件流：

- 每次发送带请求幂等标识，重复提交不重复建运行。
- SSE 断线后按事件序号和分页水位补齐，不凭浏览器现有轮数猜测。
- Web、Desktop、Mobile 都能看到任务状态、工具步骤、待确认操作和成果版本。
- 一端确认或拒绝后，其他端刷新并收起失效卡片。
- 客户端缓存只是投影，冲突时以服务端权威状态为准。

## 6. 项目协作预留

当前以个人项目和小团队独立账号为主。项目成员、角色、显式共享、任务分派和撤权安排在后续 K09：

- 项目资料、成果和已确认项目记忆可显式共享。
- 私人聊天、个人记忆、专家经验和凭据不会因邀请成员自动公开。
- 共享概况带 revision、批准人、来源和适用期。
- 移出成员后停止后续 API、事件、下载和上下文使用；已下载或送至外部模型的内容无法收回。

## 7. 已知限制

- Electron 安装、升级和 Windows/macOS 签名验证仍需目标环境。
- Android 尚未完成正式签名、应用商店分发和稳定的国产推送通道。
- 多端同步以事件补拉为主，完整离线协作和 CRDT 不在当前范围。
- HTTP 明文只适合本地开发；跨设备部署必须配置 TLS。
- 本地会话缓存不能抵御同一系统账号下的恶意程序，不能宣称磁盘加密。
