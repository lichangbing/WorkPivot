# 安全审计与运行监控

> 状态：✅ RC.8 沿用 RC.6 基础基线；Prometheus、告警规则、系统状态和备份状态已接入
> 适用版本：`v0.3.0-rc.8`

## 1. 目标

正式版必须能回答四类问题：

1. 服务是否存活，是否具备接收新请求的关键条件？
2. 数据库、文件存储、Worker、浏览器和任务队列当前是否正常？
3. 谁在何时对什么对象执行了何种敏感操作，结果如何？
4. 备份是否成功，磁盘和运行租约是否正在接近风险边界？

监控、审计和业务日志分开：

| 数据 | 用途 | 默认内容 |
| --- | --- | --- |
| 业务日志 | 排障 | 请求模板、关联 ID、状态、耗时和用户 ID；不记录正文、Token 或查询参数 |
| 运行指标 | 监控告警 | 聚合计数、耗时、连接池、队列、磁盘和依赖状态 |
| 请求审计 | 安全管理 | 请求开始/结束、操作人、操作区域和结果语义；不保存请求正文 |
| 业务审计 | 追溯业务变更 | 模型、工具、审批、文件、知识、记忆、业务事实和管理操作 |
| 备份状态 | 灾备核验 | 最近成功时间、大小、schema 和失败代码；不保存备份路径或密钥 |

## 2. 健康与就绪

- `GET /api/health` 是进程存活检查，不访问数据库，版本为 `0.3.0-rc.8`。
- `GET /api/ready` 检查业务库、认证库和文件存储；关键依赖不可用或磁盘达到 95% 时返回 503。
- 浏览器和隔离执行服务是可选能力，未配置时状态为 `not_configured`，不冒充故障；已配置但不可用时在系统状态中告警。
- 服务容器健康检查使用 `/api/ready`，避免“进程活着但无法处理请求”被标为健康。

## 3. 指标

`GET /api/metrics` 返回 Prometheus 文本格式。认证规则：

- 配置 `WORKPIVOT_METRICS_TOKEN` 时只接受该 Bearer Token，适合 Prometheus 使用独立只读凭据。
- 未配置时只接受有效管理员会话，普通成员返回 403。

当前指标：

- 进程运行时间和常驻内存。
- HTTP 请求数、累计耗时和计时样本，维度仅方法、路由模板和状态类别。
- 业务/认证数据库连接池总数、空闲数和等待数。
- 文件存储使用比例。
- 运行中任务、过期租约、自动化排队/运行、记忆作业和解析作业。
- 警告与严重告警数量。

指标标签禁止包含用户 ID、任务 ID、文件名、URL、查询参数、正文和错误原文，避免高基数及敏感信息泄漏。

## 4. 系统状态

管理员“系统状态”页面和 `GET /api/admin/system-status` 汇总：

- 版本、生成时间、总体状态和 readiness。
- API、数据库、浏览器和隔离执行服务状态。
- 数据库连接池和文件容量。
- 运行、审批、自动化、记忆和解析队列。
- 最近备份状态。
- 可定位的告警代码和中文说明。

接口只允许管理员访问，不返回私人任务名称、聊天正文、文件名或凭据。

## 5. 告警阈值

| 告警 | 条件 | 级别 |
| --- | --- | --- |
| 服务未就绪 | `workpivot_ready == 0` 持续 2 分钟 | critical |
| 数据库不可用 | `workpivot_database_ready == 0` 持续 1 分钟 | critical |
| 磁盘预警/严重 | 使用率 ≥80% / ≥90% | warning / critical |
| 连接池等待 | 任一池 waiting >0 持续 5 分钟 | warning |
| 任务租约过期 | 过期租约 >0 持续 5 分钟 | warning |
| 浏览器/Worker 不可用 | 已配置但健康检查失败 | warning |
| 备份失败/过期 | 明文失败状态 / 最近成功超过 36 小时 | critical / warning |

告警通过 `releases/deploy/monitoring/workpivot-alerts.yml` 提供给 Prometheus。外部通知只发送摘要与运维入口，不发送业务正文。

可选监控编排：

```bash
docker compose \
  -f releases/deploy/compose.local-stack.yml \
  -f releases/deploy/compose.monitoring.yml \
  up -d prometheus
```

独立指标令牌文件必须放在受保护目录，并允许 Prometheus 容器用户只读该文件；令牌值不能写入 Prometheus 配置或 Git。

## 6. 审计覆盖

RC.6 起新增高风险功能时，必须同时列出：

```text
actor / target / action / result / reason
requestId / runId / correlationId / policy revision
createdAt / retention class
```

覆盖矩阵：

| 类别 | 必须审计 |
| --- | --- |
| 身份 | 登录、失败登录、限速、改密、登出、会话撤销、OIDC 绑定/撤权 |
| 管理 | 用户、限额、模型、MCP、Skill、专家、自动化、身份源和访问策略变更 |
| 任务 | 创建/停止/恢复、资源范围变化、计划审批、动作授权和成果验收 |
| 文件 | 上传、版本、下载、删除、回收站、恢复和永久清理 |
| Agent | 工具调用、外部动作、拒绝、超时、结果未知和副作用派发 |
| 数据 | 记忆、业务事实、知识入库、导出和删除传播 |
| 运维 | 指标读取、备份、恢复、审计导出、审计清理和配置校验 |

## 7. 日志与关联

- 每个 API 响应返回 `X-Request-ID`；调用方提供的合法 UUID 可以复用，否则服务端生成。
- 结构化访问日志只含时间、级别、请求 ID、方法、路由模板、状态、耗时和可选用户 ID。
- 未归类异常只记录请求 ID、路由和错误代码，不输出异常原文、查询参数或业务数据。
- 请求审计与访问日志使用同一请求 ID；后续业务运行通过 `requestId/runId` 关联。

## 8. 备份状态

配置 `WORKPIVOT_BACKUP_STATUS_FILE` 后，备份 CLI 在创建或校验成功时原子写入：

```json
{
  "version": 1,
  "status": "success",
  "finishedAt": "2026-11-04T00:00:00.000Z",
  "schemaVersion": 72,
  "databaseBytes": 0,
  "filesBytes": 0
}
```

失败时写入 `status: failed` 和稳定错误代码。状态文件只包含时间和大小，不包含连接串、密钥或备份路径。服务器以只读方式挂载状态目录。

## 9. 保留与安全

- 安全审计默认不自动清理；清理至少保留 30 天并要求人工预览和确认。
- 运行指标不替代审计，进程重启后进程内请求计数可以归零。
- 请求审计、业务审计和指标不能包含完整请求体、模型密钥、Cookie、数据库连接串或业务正文。
- 访问 `/api/metrics` 的任意认证失败必须记入请求审计。
- 监控和备份状态文件不提交 Git，不包含在客户端制品中。
