# 工具执行与 Agent 协作

| 项 | 值 |
| --- | --- |
| 状态 | 🛠️ `run_code` 与单层同步 `delegate` 已实现；多 Agent 协作不实施 |
| 适用范围 | 隔离执行、代码计算、子任务与候选团队协作 |
| 关联 | [Agent 循环与上下文](智能体循环与上下文.md)、[任务授权与安全边界](../安全/任务授权与安全边界.md) |

## 1. 职责边界

WorkPivot 区分三种“扩展执行”：

| 机制 | 解决的问题 | 是否共享协作状态 |
| --- | --- | --- |
| Skill/普通工具 | 已知流程与有限操作 | 否 |
| `run_code` | 没有专用工具时的受控计算和文件处理 | 否 |
| `delegate` | 将独立、长上下文子任务放到子循环 | 否，父只接收结果 |
| 多 Agent 协作 | 多角色围绕共享产物评审和返工 | 是，当前不做 |

不能把“父代理转发子代理消息”包装成协作。真正的协作必须有共享产物、轮次、可见性、终止协议和独立审计。

## 2. 通用代码执行 `run_code`

### 2.1 契约

```text
run_code {
  language: "python" | "node" | "sh"
  code: string
  inputs?: versionId[]
  outputs?: { name, documentId?, revision? }[]
}
```

代码在一次性隔离环境中运行，输入来自本轮已授权文件版本，输出先校验再按不可变成果发布。宿主路径、未授权文件和环境密钥不进入沙箱。

### 2.2 默认控制

- 无网络、只读根文件系统、非 root、独立临时工作目录。
- 单次超时、内存、输入、输出、并发和日志均有上限。
- 产物缺失、结构不合法、版本冲突或取消时整体失败，不发布半成品。
- 配置 Worker 时工具才出现；不可用时明确提示，不回退宿主 shell。
- PostgreSQL 链路可采用静默自动授权，文件链路和确认模式仍按授权矩阵执行；两者都需记录执行与产物。

### 2.3 当前限制

- 沙箱依赖固定镜像，未开放运行时安装任意依赖。
- PostgreSQL 链路的网络出口白名单方案尚未实现。
- 文件链路挂载模式仍需在 Linux/WSL 目标环境做真实容器验收。
- 只有聊天/专家对话提供 `run_code`，自动化使用独立工具集。

## 3. 单层子代理

`delegate` 的价值是把大量中间材料隔离在子循环中，只把结论带回主上下文。

```text
delegate {
  task: string
  context?: string
  max_steps?: number
}
→ { result, steps, stopReason }
```

约束：

- 只支持一层，子工具集剔除 `delegate` 和 `ask_user`。
- 只提供任务、有限背景和裁剪后的系统规则，不注入父对话全文。
- 复用父运行的用户、任务、文件策略和执行端，不增加权限。
- 同一运行内的委派串行；父取消向子循环传播。
- 子失败转换为工具结果，让父代理决定重试或换方案。

当前实现为同步单层版本；并行委派、续聊和异步通知未排期。

## 4. 多 Agent 协作

2026-10-24 决策为“不实施”。若未来重启，只评估两种可收敛协议：

| 协议 | 流程 | 适用场景 |
| --- | --- | --- |
| Panel | 角色独立产出 → 裁判汇总分歧 | 投研、方案评审、A/B 比较 |
| Review loop | 产出 → 评审 → 修订，最多两轮 | 报告、PPT、合同条款 |

必须具备团队运行、共享黑板、成员可见性、轮次上限、预算、裁判和独立审计。自由群聊、模型生成任意编排脚本、跨用户 Agent 市场不纳入。

重启前置是离线评测：至少 20 个真实办公任务，比较单 Agent、自检和 Panel 的质量、时延与成本；没有可量化收益不进入产品。

## 5. 失败与安全

| 场景 | 行为 |
| --- | --- |
| Worker 未配置 | 工具不可用，说明依赖缺失 |
| 超时或资源超限 | 终止作业，保留失败原因，不发布产物 |
| 输入越权 | 在启动沙箱前拒绝 |
| 子代理失败 | 返回结构化失败，父循环继续决策 |
| 父运行停止 | 取消子循环并撤销待执行操作 |
| 输出冲突 | 校验 revision 后拒绝覆盖 |
