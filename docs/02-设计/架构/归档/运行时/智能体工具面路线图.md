## 3. R004 结构化提问（已实现）

**场景**：需求不明确时（选格式、选范围、选模板），模型用带选项的卡片提问，而不是在正文里问一句然后停下。

**接口**

```
ask_user {
  question: string                 // ≤200 字
  options?: [{ label, description? }]   // 2–6 个；为空表示自由回答
  allow_free_text?: boolean        // 默认 true
}
→ { status: 'asked', questionId, question }
```

**设计要点**

1. 工具返回 `asked` 后**结束本轮**（与现有单轮模型兼容，不需要挂起状态机）；用户选择作为下一条用户消息进入历史，带 `[回答提问 <id>]` 前缀。
2. 同一轮最多一个待回答问题；重复调用直接返回同一 `questionId`，不重复弹卡。
3. 只用于**澄清需求**，不得替代授权卡（权限判定仍由 `evaluateAccess` 控制）；工具描述明确写死这条边界。
4. 与早停兜底的关系：`ask_user` 出现后本轮结束时**不触发** `onIdle` 追问，否则会催模型“别问了继续做”。
5. 前端：SSE `ask_user` 事件 → 对话区渲染选项卡片；选择后走普通发消息接口。
6. 审计：记录 `ask_user` 事件与选项数量，不记录用户未选择的项。

**验收**

- eval：参数校验（选项 2–6、超长拒绝）；重复调用返回同一 id；`asked` 后循环结束且不触发 idle 追问。
- 手工：卡片渲染、点击后作为用户消息继续、自由输入可用。
- 回归：授权拒绝后不会弹 ask_user 卡片代替。

**实现记录（2026-10-24）**

- `packages/server/src/database/ask-user.ts`：参数校验（问题 ≤200 字、选项 2–6、label ≤40、description ≤120），同轮重复调用复用同一 `questionId`。
- `packages/core/src/loop.ts`：新增 `Tool.endsTurn`，工具执行后本轮立即结束，因此不会触发 `onIdle`；`AgentEvent` 增加 `ask_user` 类型与 `questionId/question/options/allowFreeText` 字段。
- `packages/server/src/database/execution.ts`：提问以 `type=ask_user` 的 meta 事件持久化，走与工具事件相同的重放通道；回答仍是普通用户消息。
- 前端：`DatabaseWorkspace` 渲染选项卡片，点击后以 `[回答提问 <id>] <选项>` 发送；已回答的卡片按前缀置灰。
- 用例：`eval/R004-ask-user.mts`（5 项通过，已并入 `eval/run-all.mts` 的 R004 套件）。

## 4. R005 子代理（已实现）

**目标**：把“独立、可并行、上下文很长”的子任务放到独立循环里跑，主上下文只拿结论。这比事后压缩更彻底——压缩是补救，子任务是事前隔离。

**边界（本轮明确不做）**

- 只支持**单层**：子代理不能再次 `delegate`（工具集会剔除）。
- **同步**：父循环阻塞等待，不做后台并发、不做“稍后收取”。
- 不做跨任务/跨目录：子代理沿用父任务的工作目录与文件策略。
- 不做模型/供应商切换：与父相同。

**接口**

```
delegate {
  task: string            // 子任务目标，自包含
  context?: string        // 必要背景，≤4000 字；不传父对话历史
  max_steps?: number      // 1–50，默认 20
}
→ { result, steps, stopReason }
```

**设计要点**

1. **上下文隔离**：子循环只拿 `system`（裁剪版：工作目录 + 工具纪律）、`task`、`context`。父对话不注入，这是收益来源。
2. **预算**：单次 `max_steps` 默认 20、上限 50；时长上限 10 分钟；单轮只允许一个 `delegate` 在跑（并发调用串行化），避免成本和文件冲突叠加。
3. **权限继承**：子循环复用父的 `requestAccess` / `filePolicy` / `executeCommand`；授权卡标注 `delegate:<tool>`，用户仍看到真实动作。
4. **文件冲突**：写入沿用 `directory-lock`，父子同一目录串行；子代理写入的文件直接落在工作目录，父代理能看到。
5. **事件**：子事件带 `delegateId` 前缀转发，前端折叠展示；转写记录子步骤，便于复盘。
6. **取消**：父 `signal` 透传，父中止时子循环立即停止。
7. **失败**：子循环抛错或超预算时，以**工具结果文本**返回（含 stopReason），不炸掉父任务；父可决定重试或换做法。
8. **禁止递归**：子工具集剔除 `delegate` 与 `ask_user`（提问由父统一处理，避免两处弹卡）。

**验收**

- eval（假客户端）：子任务独立上下文（父历史不进入子请求）；`delegate` 从子工具集剔除；父中止传播；子失败返回错误文本而不抛出；并发两次 `delegate` 串行；`max_steps` 越界收敛。
- 手工：让子代理读一个大文件并只回摘要，主上下文消息数不增长；子代理写文件后父能读到。
- 成本：记录父子步数与耗时，确认没有失控放大。

**实现记录（2026-10-24）**

- `packages/server/src/database/delegation.ts`：子循环复用父级 client / requestAccess / filePolicy / executeCommand；
  子工具集剔除 `delegate` 与 `ask_user`；`max_steps` 校验 1–50（默认 20），时长上限 10 分钟；同一运行内用队列串行化。
- 子循环不传父历史，只有 `system`（子代理前缀 + 父规则）+ 一条 `user`（task 与 context）。
- 失败/超预算/取消一律转成工具结果 JSON（含 `stopReason`），不抛出中断父任务。
- `packages/core/src/loop.ts` 的 `AgentEvent.delegateId` 用于子事件前缀；`tool-events.ts` 保留该字段以便前端折叠。
- `packages/server/src/database/execution.ts` 按运行动态装配，子事件与父事件共用同一条持久化通道。
- 用例：`eval/R005-delegate.mts`（7 项通过，已并入 `eval/run-all.mts` 的 R005 套件）。

## 5. 后续候选（未排期）

| 候选 | 价值 | 成本 | 结论 |
| --- | --- | --- | --- |
| 后台进程（`process`/`write_stdin`） | 启服务、watch、长命令 | 高（worker 需长生容器 + 多路通道 + 回收） | 暂缓，等真实需求 |
| `apply_patch` 多段编辑 | 多文件改动 | 低 | 可与 `edit` 合并做 |
| `vision_analyze` | 读扫描件/截图 | 中（依赖多模态） | 看模型支持再定 |
| `session_search` | 检索历史会话 | 中 | 知识库已覆盖大半 |
| 媒体生成（图/视频/TTS） | PPT 配图 | 中高（外部服务） | 低优先 |

工具与循环本身的可用性改进不在这里排期，统一维护在 [优化清单-20261024](../../../../03-项目/计划/优化清单-20261024.md)（O-01 至 O-19）：授权卡文案、目录锁覆盖 `bash`、`read` 分页、输出头尾保留、用量采集、转写限长、执行模式闸门等。
