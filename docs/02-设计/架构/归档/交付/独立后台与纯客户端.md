# 独立后台与纯客户端（2026-09-08）

桌面端不再启动 Express、不再携带 Agent、文档库、项目文件或模型密钥；Electron 只负责窗口、托盘、服务器地址和连接提示。客户端加载后台托管的 React 页面，前端通过同源 HTTP/SSE 访问 API，后台执行账户校验、模型调用和任务操作。

当前链路：桌面/浏览器 → http://192.168.1.158:39800 → WorkPivot 后台 → 管理员配置的大模型。

## 桌面端

- 默认服务器为 http://192.168.1.158:39800；“服务器 → 更换服务器”可修改。WORKPIVOT_SERVER_URL 可由部署方覆盖。
- 地址保存在 Electron 用户配置目录的 connection.json；仅接受 HTTP/HTTPS 根地址，拒绝包含账号、密码、参数或片段的地址。
- 首先校验 /api/health 返回 WorkPivot 标识，然后加载远程页面。后台不可达时显示连接页面，不启动本地替代后台。
- nodeIntegration=false、contextIsolation=true、sandbox=true；导航限定当前后台来源，禁用新窗口。连接设置 IPC 只接受本地连接页面的主框架，远程页面不可修改客户端服务器地址。
- 安装包只含 main/preload、连接页面及图标，不再包含 server-node_modules、app-web-dist 或 skills。客户端不要求 Node、WSL 或 Docker。
- 原单机版账户、模型密钥和任务不会自动上传到服务器。当前是新部署，首次注册管理员后配置模型；如需迁移单机数据，应另做受控迁移，系统加密的本地密钥不能直接复制到 Linux 使用。

## 服务器

Ubuntu 26.04.1 / Docker 29.7.2，目录 /home/lichb/workpivot，Compose项目 workpivot，容器 workpivot-server。端口绑定 192.168.1.158:39800，业务使用两个独立命名卷。账户、模型密文、项目、文件和任务均保存在服务器。

服务非root运行，根文件系统只读，capabilities清空，禁止提权，自动重启。主密钥与初始化凭据只在服务器 .env 中保存，权限0600。首次注册说明单独保存为 first-login.txt，不包含主密钥。

沿用用户暂不允许Docker socket挂载的决定：服务不挂载socket，命令沙箱未启用，相关命令会明确失败，不回退到服务器宿主shell。对话和专用文件工具可用；真实模型仍须管理员配置。当前为内网HTTP，未配置域名HTTPS，不开放公网。

## 验证

- 客户端13项地址/构建隔离测试通过；类型、Lint、依赖检查通过。
- 打包态连接目标服务器成功，SMOKE OK、退出码0，本地后台数据目录未创建。
- 后台不可达时显示离线状态，测试退出码2，本地后台数据目录未创建。
- 目标服务器健康状态为healthy，/api/health、/api/auth/state、/及/admin返回200。
- 该轮未变更后台业务逻辑；部署使用此前已通过Linux回归与恢复彩排的镜像。未把已有普通服务或业务卷替换为WorkPivot资源。
