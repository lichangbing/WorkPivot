> **统一术语：** 上下文是每轮临时装配给模型的内容；记忆是持久化、可召回的用户/会话/项目/工作信息。原始聊天、工具日志、文件字节、业务事实和运行检查点即使持久化，也不自动成为普通记忆。四类产品记忆的权威定义见 [ADR-006](../../架构决策/架构决策-006-四类记忆与上下文边界.md)。

## 1. 目标

记忆用于在后续任务中复用稳定偏好、会话经历、项目认知和工作成果索引，降低重复沟通。它不是对话全文索引，也不是业务知识库或业务事实的替代品。

系统必须同时做到：

- 临时要求不误升为长期偏好。
- 个人、项目、任务事实不串层、不跨项目泄漏。
- 无冲突新增自动保存，减少逐条确认。
- 修改、合并、替代和冲突逐条确认，一次只处理一项。
- 来源删除、撤权或遗忘后，相关记忆停止加载。
- 模型推测、工具失败和未经证实的结论不能成为已确认事实。

## 2. 四类产品记忆

| 记忆 | 主要责任 |
| --- | --- |
| 用户记忆 | 用户角色、职责、偏好、表达和工作习惯 |
| 会话记忆 | 一次会话的目标、角色、材料版本、决定、成果和未决事项 |
| 项目记忆 | 项目背景、稳定规则、当前阶段、关键决定和派生概览 |
| 工作记忆 | 以工作项为中心的持久台账：做过什么、怎么做的、成果在哪里 |

“短期/长期”描述生命周期，不与四类产品记忆并列。WorkPivot 后台不依赖客户端进程内的短期记忆，但每次模型调用仍需要重新装配工作上下文。

### 2.1 当前持久作用域

| 层级 | 内容 | 默认作用域 | 更新方式 |
| --- | --- | --- | --- |
| 任务 | 目标、进度、步骤、待办、本轮约束 | 当前任务 | 每轮从运行证据更新；已完成需有可验证依据 |
| 项目 | 背景、目标、范围、口径、决策、交付要求 | 当前项目 | 每轮识别；每 10 个有效轮次补充整理 |
| 用户 | 角色、职责、偏好、工作与表达习惯 | 用户 + 项目 | 每轮识别；每 10 个有效轮次补充整理 |

“本次”限定任务，“这个项目”限定项目，“以后都”才可能指向用户长期偏好。范围模糊时保留在最窄确定范围或候选状态。

个人周期记忆按“用户 + 项目”隔离；无项目任务使用独立临时范围，不跨项目汇总私人资料。

### 2.2 目标与当前实现映射

| 目标记忆 | 当前载体 | 状态 |
| --- | --- | --- |
| 用户记忆 | `memories.scope=user` | 🟡 已实现项目内用户偏好 |
| 项目记忆 | `memories.scope=project` + 项目事实 | 🟡 已有，待补可重建项目概览 |
| 会话记忆 | 对话轮次/事件、长对话摘要 | 🟡 原始记录已持久化，待补结构化情景摘要 |
| 工作记忆 | 任务、运行、工具派发、成果版本 | 🟡 能力分散，待补统一工作项聚合视图 |
| 任务记忆 | `memories.scope=task` | ⚠️ 兼容保留，后续归入工作记忆 |

## 3. 数据模型

当前 PostgreSQL 实际核心对象：

- `memories`：记忆身份、作用域、项目/任务归属、当前 revision、锁定、复核、合并和删除状态。
- `memory_revisions`：内容修订。
- `memory_sources`：记忆与来源运行。
- `memory_suggestions`：新增、修改、合并、替代和冲突建议。
- `memory_jobs`：每轮记忆整理任务、租约和重试。
- `memory_controls`：三层加载/更新控制。
- `memory_templates`：角色记忆模板。
- `memory_analysis_turns` / `memory_analysis_batches`：每 10 个有效轮次的周期分析。
- `knowledge_state`：用户级记忆/知识 epoch。

正文与来源分开存储，日志不复制敏感全文。所有派生对象必须进入删除关系图。

设计早期提出的 `memory_entries`、`memory_candidates`、`memory_overviews` 不是当前实际表名，也没有独立的 `memory_overviews` 召回表。项目概览后续应实现为可重建派生视图，不得冒充当前已完成能力。

## 4. 写入流程

```text
新事件进入 outbox
  → 按用户/项目/任务合并增量
  → 第一遍识别三层候选及证据
  → 第二遍与有效记忆比较
  → 新增且无冲突：自动发布
  → 修改/合并/替代/冲突：逐条确认
  → 发布新 revision 并更新概览
```

每轮用户消息同时判断三层，单轮最多 6 项；个人和项目层仍保留每 10 个有效轮次的跨任务补充分析，用于发现稳定偏好和合并互补事实。

以下内容不得成为已确认事实：

- 模型自己的推测或计划；
- 工具失败、取消或未经验证的结果；
- 资料中要求模型执行的命令；
- 无明确依据、仅为补齐数量的内容；
- 已删除、撤权或超出当前知识 epoch 的来源。

## 5. 自动保存与确认

| 候选类型 | 行为 |
| --- | --- |
| 新建、无冲突、无替代目标 | 自动保存，`decision_source=auto` |
| 修改现有事实 | 待确认 |
| 合并多个条目 | 待确认 |
| 替代/冲突/用户纠正 | 待确认 |
| 来源失效或遗忘 | 文件版本删除时标记待复核并立即停止加载；遗忘则进入删除流程，不等待模型建议 |

确认界面使用单条流程：“当前第 1 条，共 N 条”；处理或删除当前项后才显示下一条。支持查看旧值、新值、差异、来源和影响范围。关闭卡片、超时或发送下一条消息都不等于确认。

手动新增或编辑由用户直接提交；仍生成新 revision。锁定条目只接受修改建议，后台不能用旧快照覆盖用户操作。

## 6. 周期分析

- 一轮指用户消息对应的一次成功完成运行；重试只计一次。
- 失败、停止和自动化执行不累计为周期轮次。
- 每批读取最多 10 轮原始用户消息和当前有效记忆。
- 用户级事务锁与行锁串行领取；租约支持重启恢复。
- 单批超过输入上限时明确失败，不静默截断后假装完整分析。
- 每批最多生成 3 项建议；无内容时记录空结果。
- 拒绝建议保留指纹，避免旧事件反复弹出。

## 7. 加载与检索

每轮装配的是 `ContextPack`，而不是“完整记忆库”：

```text
当前用户请求
+ 当前工作项/运行状态
+ 相关工作历史
+ 相关用户偏好
+ 相关项目概览
+ 相关会话情景
+ 已确认业务事实
+ 原始文件证据
+ 当前 Skill
```

过滤与排序原则：

1. 先检查用户、项目、角色、材料版本、删除状态和有效期。
2. 当前工作项和明确请求优先。
3. 精确业务值优先查业务事实，不依赖普通记忆或向量相似度。
4. 会话、项目和工作记忆用于连续性、背景和成果定位。
5. 只加载需要的摘要，详细内容通过工具按需读取。
6. 发现冲突时显式返回冲突，不把多个值混合成“当前事实”。

先加载小概览，再按需读取详情。检索必须按用户、项目、来源状态和 revision 过滤；关闭自动加载不删除记忆，关闭自动更新也不阻止后续手动管理。

记忆内容不能提升工具权限，也不能把文档中的命令变成系统指令。

当前实现每轮最多自动加载约 8 条、3200 字符的记忆；中文使用二至四字片段和英文词项做轻量相关性排序，再补各层最新条目。它不是完整语义检索，后续可增加结构化元数据、混合召回和重排，但权限、版本和证据硬过滤必须先于相关性排序。

## 8. 删除、遗忘与恢复

- 删除记忆进入可恢复状态，但立即从加载、概览、搜索和上下文中失效。
- 删除原始资料时，关联记忆、摘要、引用和 RAG 片段同步失效；只删除单个文件版本时，仅失去唯一来源的记忆进入待复核，保留正文供用户核对。
- 用户编辑并保存待复核记忆后清除审查标记；系统不会自动把旧内容重新启用。
- 永久删除后不能用版本回退恢复正文。
- 清空设置学习截点；旧对话、摘要、候选和重放事件不能让内容复活。
- 项目删除时，该项目范围内的用户记忆和周期分析一并进入回收流程。

## 9. 验收

1. “本次不写风险”“项目按万元”“以后先写结论”分别进入工作、项目和用户记忆。
2. 三层无冲突新增自动保存；修改、合并和冲突只生成单项待确认。
3. 工具失败、模型推测和旧事件重放不生成已确认事实。
4. 手动编辑与后台更新冲突时不静默覆盖。
5. 来源删除、项目撤权或清空后，相关内容和派生索引召回为零。
6. 十轮进度、失败重试、空结果和输入超限行为一致。
7. 不同项目不混用个人周期记忆；无关任务不加载项目口径。
8. 真实模型验证跨任务项目事实与临时任务约束的作用域差异。
9. 会话记忆不复制完整聊天，工作记忆不复制文件字节或完整工具日志。
10. 每轮上下文只选择与当前问题相关且有权限的用户、项目、会话、工作、事实和证据内容。

## 10. 已知限制

- 语义去重仍依赖模型比较，可能漏判同义事实或误判冲突。
- 升级前已经完成但未产生个人/项目建议的轮次不会自动重跑。
- 当前 schema 仍使用 user/project/task 三个持久作用域；会话记忆和统一工作记忆尚未完成数据模型收敛。
- 项目概览和完整语义检索仍要持续优化。
- 当前记忆召回是轻量词法排序，不是完整的混合语义检索。
- 已发送给模型的旧上下文不能追溯撤回，只能阻止后续重放。
- 自动保存的质量取决于来源证据和模型抽取，仍需真实业务样本评估。
- 用户记忆目前按项目隔离，不是跨项目全局画像；项目记忆也不自动等于项目成员共享记忆。
