# WorkPivot 项目介绍

> 版本：2026-10-26 ｜ 对应代码状态：schema 52，最新发布 v0.3.0-preview.33 / rc.1
> 本文用于向新成员、合作方或客户介绍 WorkPivot 的定位、能力、架构与使用方式。功能描述以当前代码为准，历史计划与已废弃方案不作为依据。

## 1. 一句话定位

**WorkPivot 是一个可私有化部署的企业级办公智能工作台**：用户用自然语言下达任务，AI 在用户真实的工作目录里读文件、查资料、执行代码、生成 Word / Excel / PPT，并把成果作为可下载的文件交付。

它不是一个"聊天框"，而是一个**有工作目录、有工具、有记忆、有权限边界的执行环境**。

## 2. 要解决的问题

办公场景里，通用聊天机器人有三个绕不过去的短板：

| 问题 | 通用聊天机器人的表现 | WorkPivot 的做法 |
| --- | --- | --- |
| 产出不可用 | 只在对话里给文字，用户还要自己复制粘贴排版 | 直接生成 .docx / .xlsx / .pptx，落到工作目录 |
| 看不见用户资料 | 只能靠用户粘贴，长文档直接超限 | 绑定真实工作目录，按权限读取本地文件与上传件 |
| 不可控 | 不知道它做了什么、动了什么 | 工具白名单、权限档位、授权卡、全量审计 |
| 不可信 | 声称生成了文件，实际没生成 | 成果核验闸门：声称的文件必须真实存在且非空 |

## 3. 核心能力

### 3.1 任务 = 对话 + 工作目录

每个任务绑定一个真实目录（默认在账号工作区内，按项目分文件夹）。AI 的读写、生成、下载都围绕这个目录进行：

- 创建任务时自动建立目录（`<项目名>-<6位随机>`）
- 上传的附件进入 `attachments/`
- 过程文件与成果都在目录里，用户可以在文件管理器里直接看到
- 临时任务单独存放，不注入长期记忆

### 3.2 Agent 循环与工具面

单轮对话是一个完整的 agent 循环：模型思考 → 调用工具 → 读结果 → 继续，直到产出结论或触发停止条件。

文件链路的工具面：

| 类别 | 工具 |
| --- | --- |
| 文件 | `read` `write` `edit` `ls` `grep` `find` |
| 执行 | `bash`、`run_code`（Python / Node / Shell） |
| 联网 | `web_fetch`、`web_search`（可配置）、`browser_visit`（配了浏览器服务时） |
| 过程 | `update_plan`、记忆读写、`deliver_files` |
| 扩展 | 技能加载 `load_skill`、MCP 外部工具 |

循环自身的工程约束：

- 步数与时长预算（默认 200 步 / 30 分钟）
- 相同工具 + 相同入参 + 相同结果重复 5 次即拦截，防止死循环
- 大结果落盘，模型只拿预览 + 路径
- 上下文按字符预算压缩，保留工具调用配对关系
- 只表态不动手时追问一次（早停兜底）

### 3.3 Office 交付

内置四个 Office 技能包：

| 技能 | 能力 |
| --- | --- |
| `office-routing` | 按需求路由到具体文档技能 |
| `docx-report` | 生成、读取、修改 Word（含样式、表格、页眉页脚） |
| `xlsx-report` | 生成、读取、修改 Excel（含单元格定位、公式、缓存值） |
| `pptx-report` | 生成、读取、修改 PPT（按幻灯片/形状定位） |

配套能力：

- **隔离执行器**：Office 生成在一次性容器里完成（无网络、只读根、非 root、CPU/内存限额）
- **格式转换**：可选用 LibreOffice 把 docx/xlsx/pptx 转 PDF
- **解析**：docx/xlsx/pptx/pdf 正文抽取，扫描件走 OCR（中英文）
- **核验**：生成后自检文件结构有效、能被打开，失败自动重试

### 3.4 技能系统

技能是"做法 + 资源"的打包：一份 `SKILL.md` 描述何时使用与步骤，可附带脚本、模板、参考资料。

- 全局技能与项目技能双层发现，按任务重新扫描
- 只能由用户确认后加载，模型不能自行启用
- 支持草稿、校验、隔离测试、发布四步
- 技能本身不执行任何东西；执行必须经由 `execute_skill` 工具，在沙箱里运行

### 3.5 记忆

三层记忆，按作用域隔离：

| 层级 | 位置 | 用途 |
| --- | --- | --- |
| 用户级 | 记忆目录 `MEMORY.md` + 条目 | 长期偏好、工作习惯 |
| 项目级 | 任务目录 `.workpivot/memory/` | 项目背景、约定 |
| 任务级 | 会话内 | 当前任务的事实 |

记忆由模型提议、用户确认后写入；已锁定条目模型不能改。用户可在管理界面查看、编辑、删除。

### 3.6 知识库与检索

- 上传的文档解析后切块入库，保留原段落、页码、单元格坐标
- 检索合并关键词与语义（pgvector），返回带来源定位的片段
- 引用必须给出文件名、版本与原文位置，抓取失败会明确返回"未完成"，不会偷偷用旧版本
- 删除或替换版本会撤销相关引用，避免答非所问

### 3.7 联网与浏览器

- `web_fetch`：读取公开网页、文本、JSON、RSS/Atom，转 Markdown，限制响应大小与超时
- `web_search`：支持 Brave 或自托管 SearXNG，先搜后读，结果过滤内网地址
- `browser_visit`：需要动态渲染或交互时使用；普通对话中与用户**共享右侧浏览器**，不重复执行用户已完成的登录与点击
- 网页内容一律视为不可信资料，不能作为指令

### 3.8 代码执行

- 一次执行一个脚本，Python / Node / Shell 三选一
- 容器内运行：无网络、只读文件系统、非 root、PID/内存/CPU 限额、超时回收
- 输入按授权范围挂载，产物必须显式声明
- 适合数据处理、格式转换、批量计算；不适合联网安装依赖

### 3.9 定时任务与自动化

- 按 cron 或周期创建自动化计划，绑定技能与网页来源
- 支持暂停、取消、查看历史执行
- 失败重试有次数上限，过期租约会被回收并标记中断，不伪造成功
- 执行记录可查看耗时、产物、错误原因

### 3.10 安全与权限

| 机制 | 说明 |
| --- | --- |
| 权限档位 | 确认模式 / 自动模式；界内自动、界外询问 |
| 授权卡 | 高危命令、界外路径、外部调用、隔离执行前弹卡，用户可"仅此次 / 本会话 / 永久" |
| 命令拦截 | 内置高危模式（`rm -rf` 等）拦截，删除进回收站 |
| 路径防护 | 词法与规范路径双重解析、符号链接拒绝、大小写归一 |
| 外部调用 | MCP 等外部工具始终逐次确认，不受档位影响 |
| 审计 | 每次工具调用、授权决策、执行结果落审计，可按用户/任务追溯 |
| 数据隔离 | 数据库全表行级安全（RLS），业务与身份角色均不可绕过 |
| 密钥 | 模型 Key 加密存储，日志与错误信息不输出连接串与密钥 |

## 4. 架构

### 4.1 两条运行链路

WorkPivot 同时保留两套存储实现，二者**并存但独立**，不能混用验收结果：

| | 文件链路 | PostgreSQL 链路 |
| --- | --- | --- |
| 入口 | `packages/server/src/app.ts` | `scripts/database-server.mts` |
| 结构化数据 | 本地 JSON / JSONL（账号工作区） | PostgreSQL（任务、消息、事件、版本） |
| 文件 | 工作目录里的真实文件 | 版本化存储：元数据入库、字节在文件卷 |
| 适用 | 单机/小团队，需要真实目录 | 多用户、需要审计与版本、需要 RLS |
| 状态 | 早期实现，仍在运行 | 主line，schema 52 |

两条链路共享同一套 `packages/core`（agent 循环、工具接口、模型客户端）与 `packages/shared`（类型、日志、路径）。

### 4.2 模块划分

```
code/
├── apps/
│   ├── web/          React + Tailwind + Vite（三栏工作台）
│   ├── desktop/      Electron 外壳（窗口、托盘、更新、本地服务托管）
│   └── mobile/       移动端骨架
├── packages/
│   ├── server/       HTTP/SSE、任务、权限、审计、文件、数据库仓储
│   ├── core/         agent 循环、工具注册、模型客户端、上下文压缩
│   └── shared/       共享类型、常量、日志、路径与租户
├── eval/             评估题库与回归脚本
└── scripts/          建库、发布、压测、迁移、校验脚本
```

### 4.3 一次任务的执行链

```
用户输入
  → 服务端鉴权与任务归属校验
  → 构造系统提示（工作目录、记忆、技能目录、工具纪律）
  → agent 循环（模型 ↔ 工具）
      ├─ 只读工具：直接执行
      ├─ 写/执行工具：权限判定 → 需要时弹授权卡
      └─ 执行类：交给隔离执行器（容器）
  → 成果落盘 / 版本发布
  → 核验闸门（声称的文件必须存在）
  → 流式回传（SSE）+ 落审计
```

### 4.4 隔离执行器

执行类工具通过 worker 调用一次性容器：

| 限制 | 值 |
| --- | --- |
| 网络 | 无（`--network none`） |
| 根文件系统 | 只读 |
| 用户 | 非 root（1000:1000） |
| 内存 / CPU | 512MB / 1 核 |
| 进程数 | 128 |
| 超时 | 120 秒 |
| 并发 | 2 |
| 输入输出 | 有大小上限，超出拒绝 |

## 6. 典型场景

**场景一：周报汇总**
上传三个部门的 Excel → AI 读取各表数据 → 汇总计算 → 生成带表格和图表的 Word 周报 → 用户下载。

**场景二：投标材料**
给出项目背景与公司资质 → AI 检索知识库里的历史案例 → 生成 PPT 大纲 → 按模板填充 → 输出可编辑的 .pptx。

**场景三：合同审阅**
上传合同 PDF → 解析正文（扫描件走 OCR）→ 按检查清单逐条比对 → 输出风险点与修改建议，附原文位置。

**场景四：定时情报**
创建每日 9 点的自动化：抓取指定网页 → 提取变化 → 生成摘要 → 留存历史执行记录。

## 7. 与同类产品的差异

| 维度 | WorkPivot | 通用聊天机器人 | 编程向 agent（Codex / Claude Code） |
| --- | --- | --- | --- |
| 目标 | 办公交付物 | 对话 | 代码仓库 |
| 产出 | docx/xlsx/pptx/pdf | 文本 | 代码与补丁 |
| 工作目录 | 真实目录 + 权限边界 | 无 | 代码仓库 |
| 多用户 | 账号隔离 + RLS + 审计 | 弱 | 无 |
| 部署 | 私有化（Docker / 本地栈） | SaaS | 本机 CLI |
| 权限 | 授权卡 + 档位 + 沙箱 | 基本没有 | 审批策略 + 沙箱 |

## 8. 当前进展

- 运行形态：文件链路与 PostgreSQL 链路均已实现；本地一体化栈可一条命令装齐数据库、服务端、浏览器服务、执行器与内置技能。
- 数据库 schema：52，包含任务、消息、事件、文件版本、知识库、记忆、定时任务、技能、专家、审计等。
- 内置技能：`office-routing`、`docx-report`、`xlsx-report`、`pptx-report`，另有示例技能。
- 客户端：Web 与桌面端可用，移动端为骨架。
- 质量：类型检查、静态检查、依赖边界、许可门禁与多套评估脚本；PR 前需全绿。

已知限制（如实说明）：

- Office 技能目前在执行器内只依赖 Python 标准库，图表能力有限
- 执行器无网络，无法安装第三方依赖
- 模型客户端目前只支持文本输入，不支持图片理解
- 长任务（超过 120 秒的后台进程）暂不支持
- 多 agent 协作经评估后决定不做

## 9. 快速开始

本地一体化栈（推荐，需要 Docker）：

```bash
# 默认项目 workpivot-stack、端口 39990、数据目录 ~/workpivot-stack
bash releases/deploy/install-local-stack.sh

# 自动创建管理员并打印初始密码
bash releases/deploy/install-local-stack.sh --auto-admin

# 额外安装 LibreOffice（支持 Office 转 PDF）
bash releases/deploy/install-local-stack.sh --with-office-convert --rebuild
```

安装器会完成：预检 → 生成受保护配置 → 创建网络 → 构建镜像 → 启动 worker → 建库与迁移 → 启动服务 → 发布技能与模板 → 验收。

安装后：访问服务地址 → 用管理员登录 → 在管理页配置模型并发布默认模型 → 新建任务。

开发校验：

```bash
cd code
pnpm typecheck      # 类型检查
pnpm lint           # 静态检查
pnpm eval           # 评估套件
pnpm eval:database  # 数据库集成（需要 Docker）
```

## 12. 常见问题

**Q：数据存在哪里？**
文件链路存本地工作目录；数据库链路把结构化数据存 PostgreSQL，文件字节存文件卷。两种部署的数据不互通。

**Q：AI 能看我电脑里的所有文件吗？**
不能。只能访问任务目录与用户明确授权的路径；界外访问会弹授权卡，且拒绝后不允许用其他工具绕行。

**Q：生成的文档能直接用吗？**
可以下载并继续编辑。生成后会做结构有效性自检；不通过会重试，不会把损坏文件当成果交付。

**Q：支持哪些模型？**
支持 OpenAI 兼容与 Anthropic 兼容协议，可接公有云或内网模型；管理员在管理页配置并发布默认模型。

**Q：能不能私有化部署？**
可以。本地一体化栈与 Docker 部署均为一键/一条命令，数据与会话不出内网（联网工具可单独关闭）。
