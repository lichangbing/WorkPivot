# 记忆可信度与上下文装配开发计划

> 状态：⏸️ 已暂停；仅完成概念、白皮书、ADR 与计划记录，未修改业务代码或数据库 schema
> 创建日期：2026-11-04
> 当前基线：`v0.3.0-rc.8` / schema v72
> 恢复开发起点：MR-01 统一证据引用
> 概念依据：[ADR-006 四类记忆与上下文边界](../../02-设计/架构决策/架构决策-006-四类记忆与上下文边界.md)
> 产品口径：[WorkPivot 产品白皮书](../../00-概览/产品白皮书.md)

## 1. 暂停时已经确认的结论

1. 上下文是每轮临时组装并发送给模型的内容，不是持久记忆本身。
2. 记忆是持久化、可召回的用户/会话/项目/工作信息。
3. 原始聊天、工具事件、文件字节、业务事实和运行检查点即使持久化，也不自动成为普通记忆。
4. 四类产品记忆为用户记忆、会话记忆、项目记忆、工作记忆；“短期/长期”只描述生命周期。
5. 工作记忆以工作项为中心，保存做过什么、怎么做的、成果在哪里；技术运行记录作为工作项执行实例保留。
6. 业务事实是项目结构化业务真值，不能被普通记忆复制后覆盖。
7. 每轮只装配与当前问题相关、有权限、未失效、未冲突的内容。
8. 当前 RC.8 已实现 user/project/task 持久记忆；会话记忆和统一工作记忆仍处于聚合/规划阶段。

## 2. 当前实现差距

### 2.1 记忆证据粒度不足

- `memory_sources` 只关联 `memory_id + run_id`，不能精确说明来源消息、页码、段落或文件版本。
- `memory_suggestions.evidence` 在确认前可保存逐字证据，但确认后缺少跨来源精确定位。
- 文件版本删除可以触发待复核，但当前不能枚举某条记忆的全部支持证据。

### 2.2 记忆修订文本化

- 当前 `memory_revisions` 主要保存 `content` 文本。
- 缺少稳定的 `claim_key`、结构化值、有效期和权威来源等级。
- 冲突主要依赖模型语义判断和候选流程，不能始终按同一个主体和属性严格归并。

### 2.3 会话与工作记忆尚未统一

- 原始对话和长对话摘要是分开的，但没有统一的结构化会话记忆对象。
- 任务、运行、工具派发、审批和成果已经持久化，但没有统一工作项聚合视图。
- 项目概览仍是规划项，不能作为独立可重建视图。

### 2.4 上下文装配不可解释

- 当前记忆按作用域和轻量词法相关性召回，业务事实和文件证据各有独立召回。
- 尚未统一记录“哪些候选被选中、为什么选、来源 revision、过滤原因和预算占用”。

## 3. 目标与非目标

### 目标

- 每条新记忆可以追溯到具体消息、文件版本、网页快照、成果或手工确认。
- 一条记忆可以关联多条支持、反驳和上下文证据。
- 结构化业务值使用稳定 claim key 管理修订和冲突。
- 冲突未决时不作为唯一事实注入模型。
- 上下文按当前工作项、项目、角色、材料版本和问题动态装配。
- 会话记忆和工作记忆通过现有持久对象聚合，不复制原始正文和文件字节。

### 非目标

- 不推翻当前 PostgreSQL、对话事件、任务运行和成果版本能力。
- 不在 RC.6 发布门禁中插入 schema 变更。
- 不把所有聊天、工具日志和文件复制成记忆。
- 不让模型自动裁决金额、日期、负责人等高影响冲突。
- 不为四类记忆机械创建四套互不关联的数据表。
- 不在本阶段实现跨项目全局用户画像、共享项目记忆或自动历史回填。

## 4. 开发任务

### MR-01 统一证据引用（P0）

- **目标**：为记忆、业务事实和工作摘要提供可核验来源。
- **工作**：
  - 定义 `EvidenceRef` 应用契约；
  - 支持 conversation event、document version、web capture、manual confirmation、artifact version；
  - 保存 `source_id/source_version_id/locator/quote/quote_hash/relation/observed_at`；
  - 新增 `memory_evidence`，一条记忆 revision 可关联多条证据；
  - 旧 `memory_sources` 保留兼容，标记为运行级粗来源；
  - 新证据引用逐字片段必须可在来源中复核。
- **验收**：
  - 每条新自动记忆至少一个可解析证据；
  - 文件证据带不可变文件版本和页码/段落/表格位置；
  - 删除来源后证据变为 stale，记忆停止召回或待复核；
  - 旧数据不被伪造为精确引用。

### MR-02 结构化记忆修订（P0）

- **目标**：让记忆可以稳定比较，而不只依赖文本相似度。
- **工作**：
  - `memory_revisions` 增加 `memory_type`、`claim_key`、`structured_value`、`authority`、`confidence`、`valid_from/valid_to`、`extractor_version`；
  - 优先覆盖金额、日期、数量、对象、负责人、成果和规则；
  - 纯偏好使用稳定偏好键和文本；
  - 一条记忆只表达一个可独立修订的断言。
- **验收**：
  - 同值新来源只追加证据，不新建冲突；
  - 不同作用域不会误判冲突；
  - 无有效期重叠的版本可以按时间共存；
  - 结构化值变更生成不可变 revision。

### MR-03 冲突治理（P0）

- **目标**：冲突显式化，不混合成模型自行猜测的答案。
- **工作**：
  - 基于 scope + claim_key + dimensions 建立冲突；
  - 保存 current/candidate revision 和双方证据；
  - 支持采用新值、保留旧值、分段共存、合并、拒绝；
  - 冲突记录 resolver、resolution、时间与理由；
  - 来源或目标 revision 变化后旧冲突失效。
- **验收**：
  - 冲突未决时只注入“存在待确认更新”；
  - 相同值不会重复弹卡；
  - 高影响冲突不能自动确认；
  - 冲突证据可逐条查看。

### MR-04 ContextPack 与召回追踪（P1）

- **目标**：统一定义每轮实际发给模型的内容。
- **工作**：
  - 建立 `ContextPack` 服务接口；
  - 组合当前工作项、四类记忆、业务事实、文件证据和 Skill；
  - 先做权限、版本、删除、有效性和冲突硬过滤；
  - 再按精确匹配、相关性、权威性、时间及预算排序；
  - 记录检索候选、过滤原因、选中内容、来源 revision 和预算。
- **验收**：
  - 不加载全量历史；
  - 跨项目、撤权、删除和冲突内容零注入；
  - 可以解释每条内容为何进入上下文；
  - 上下文变化后活动模型流按既有 epoch 规则停止。

### MR-05 会话记忆（P1）

- **目标**：保存“这次沟通发生了什么”，不复制整段聊天。
- **工作**：
  - 会话结束或关键检查点生成结构化情景记录；
  - 字段包括目标、角色、材料版本、决定、成果、未决事项、下一步和来源事件；
  - 摘要与工作项关联，可从原始事件重建；
  - 摘要新版本不覆盖旧版本。
- **验收**：
  - 新会话可按项目、角色、材料版本和任务找相关历史；
  - 摘要中的关键决定必须可追溯来源；
  - 删除来源后摘要进入待复核。

### MR-06 工作记忆聚合（P1）

- **目标**：回答“做过什么、怎么做的、成果在哪里”。
- **工作**：
  - 定义 WorkItem 只读聚合模型；
  - 聚合任务、运行、检查点、交互、Skill 引用和成果版本；
  - 成果保存 artifact/version/hash/locationRef；
  - 当前工作项与其运行状态区分；允许多任务并发；
  - 第一阶段不复制现有运行和成果数据。
- **验收**：
  - 能从工作项定位输入版本、方法、运行和成果；
  - 不把工具日志和隐藏思考塞入工作记忆正文；
  - 失败或未交付工作不能标成完成成果。

### MR-07 项目概览（P2）

- **目标**：让新会话快速理解项目，但概览不成为事实源。
- **工作**：
  - 从项目记忆、已确认业务事实、会话记忆和工作记忆生成概览；
  - 概览带来源 revision、生成时间和失效条件；
  - 业务事实变化或来源删除后自动失效重建。
- **验收**：
  - 概览可删除并重建；
  - 概览不能覆盖业务事实；
  - 受权限限制的角色看到不同概览。

### MR-08 管理与证据界面（P1）

- **目标**：用户可以核查记忆来源和冲突。
- **工作**：
  - 已保存记忆增加来源数量、来源类型和“来源较粗”标记；
  - 展开后查看聊天、文件版本、页码/段落、引用片段和哈希；
  - 冲突左右对照及处理选项；
  - 工作记忆显示成果版本和位置；
  - 长证据按需读取，不一次加载全文。

### MR-09 迁移、兼容与评测（P0/P2）

- **迁移**：
  - 新表/字段使用增量 schema；
  - 双读或兼容投影先于切换；
  - 历史记忆仅建立运行级来源，不补造 quote 和 locator。
- **评测**：
  - 证据引用正确率、来源失效传播；
  - 同值去重、跨作用域隔离、时间版本；
  - 冲突误报/漏报和未决冲突零注入；
  - 上下文 precision、token 使用和无来源事实率；
  - 工作记忆成果定位成功率；
  - 跨项目/撤权泄漏为 0。

## 5. 推荐实施顺序

```text
MR-01 证据引用
  → MR-02 结构化 revision
  → MR-03 冲突治理
  → MR-04 ContextPack
  → MR-05 会话记忆
  → MR-06 工作记忆
  → MR-07 项目概览
  → MR-08 管理界面
  → MR-09 迁移与评测并行贯穿
```

MR-05 和 MR-06 可以在 MR-01 稳定后并行；MR-07 必须等待项目事实、会话记忆和工作记忆有稳定来源。

## 6. 恢复条件

恢复本计划前需要确认：

1. RC.6 正式发布门禁是否结束，是否允许启动 schema 变更。
2. 是否确定 `memory_evidence` 采用独立表还是复用业务事实证据表。
3. 哪类记忆必须结构化，哪类允许纯文本。
4. 旧记忆是否进入重新核验队列。
5. 项目成员是否共享项目记忆，还是继续按用户私有。
6. 会话记忆的保留期和工作记忆的归档策略。
