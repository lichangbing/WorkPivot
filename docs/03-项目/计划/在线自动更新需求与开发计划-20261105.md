# 在线自动更新需求与开发计划

| 项 | 值 |
| --- | --- |
| 状态 | ✅ 已实现；Android 与 Windows 覆盖升级验证通过 |
| 登记日期 | 2026-11-05 |
| 关联版本 | `v0.3.0` 发布材料 |
| 优先级 | P1，先做 Web 提示更新和 Android 安全下载，再建设 Windows 签名更新 |
| 目标 | 用户无需手工寻找下载地址即可发现、校验和安全安装新版本，同时保留当前会话与业务数据 |

## 1. 产品需求

用户应能在客户端在线发现新版本、查看版本号和发布说明，并选择合适时间更新。更新过程必须避免以下情况：

- 不因一次断网、更新源异常或服务端滚动发布而阻断当前任务。
- 不静默安装来源、哈希或签名不可信的程序。
- 不因升级清空登录态、项目、任务、记忆、业务事实或本地未确认输入。
- 不以“已下载”冒充“已安装”；必须区分发现、下载、校验、等待安装、安装完成和失败。
- 不自动重复创建升级任务，也不在用户明确确认前重启并中断正在运行的 Agent。

## 2. 平台边界

| 平台 | 第一阶段行为 | 约束 |
| --- | --- | --- |
| Web | 检测服务端 SPA 构建版本或资源哈希；显示“有新版本，刷新后更新” | 标签页有运行中任务或未提交输入时先提示，不强制刷新；刷新后由服务端持久状态恢复 |
| Android | 读取版本清单，HTTPS 下载 APK，校验包名、版本、SHA-256 和签名摘要，交给系统安装器 | Android 不允许普通应用静默安装任意 APK；必须由用户确认系统安装，继续使用现有 `com.workpivot.mobile` 和同一发布签名 |
| Windows | Electron 主进程检查签名更新源，后台下载并提示重启安装 | 使用受信任的代码签名证书；安装失败或启动失败必须保留上一可用版本 |

Web 前端资源更新不能替代服务端版本升级。Android 客户端与服务端分别有版本号，并通过 API 协议范围判断兼容性；服务端升级后仍应允许未超出兼容窗口的旧客户端继续工作。

## 3. 更新清单

建议由服务端提供只读更新清单，并允许配置静态 CDN 镜像。清单至少包含：

```json
{
  "channel": "beta",
  "platform": "android",
  "version": "1.10",
  "build": 11,
  "minimumBuild": 9,
  "downloadUrl": "https://example.com/downloads/WorkPivot-android-1.10.apk",
  "sha256": "<64 hex characters>",
  "packageName": "com.workpivot.mobile",
  "signerSha256": "<certificate digest>",
  "minimumApiProtocol": 1,
  "maximumApiProtocol": 1,
  "releaseNotesUrl": "https://example.com/releases/1.10",
  "mandatory": false,
  "publishedAt": "2026-11-05T00:00:00.000Z"
}
```

校验规则：

- 版本必须单调递增；拒绝低于本机 build 的包。
- 下载只允许 HTTPS；禁止重定向到非白名单域或明文地址。
- APK 在调用系统安装器前校验 SHA-256、包名、versionCode、签名摘要和协议范围。
- 签名摘要必须与当前安装应用一致，否则拒绝并提供人工支持入口。
- `mandatory` 只用于存在安全风险或服务端最低兼容版本提升；普通功能更新必须允许稍后处理。
- release notes 只展示纯文本或受限 Markdown，不渲染远程脚本。

## 4. 检查与交互

- 启动登录恢复后检查一次。
- Android 回到前台、Windows 唤醒以及 Web 标签页重新可见时检查，但同一前台周期最多一次。
- 前台持续使用时每 6～24 小时检查一次，加入随机抖动，避免所有客户端同时请求。
- 网络失败、清单 5xx 或 CDN 超时只记录内部诊断，不向用户弹错误；下一次触发时重试。
- 发现普通更新时使用非阻塞状态条，允许“稍后”和“查看更新”。
- 新版本已下载并校验后显示“安装并重启”；运行中任务、未提交输入和审批待处理时明确提示影响。
- 下载失败保留当前版本，不破坏已保存安装包；下载过程支持取消和断点续传。
- 更新检查与下载失败不得清除登录凭据或业务缓存。

## 5. 发布与回滚

- 客户端发布流程必须生成清单、APK/ZIP、SHA-256、签名信息和发布说明，并做一次从旧版本升级的真实安装验证。
- Android 禁止更换 `applicationId` 或发布签名；签名密钥只保存在受保护发布环境，不能进入仓库、日志或分析文档。
- Windows 更新源和安装包均需签名；保留上一版本和回滚说明。
- 先内部 beta 渠道，再逐步扩大；服务端需能暂停清单发布或撤回有问题的版本。
- 非强制版本允许用户跳过；强制版本也必须说明原因和最低安全版本。
- 更新失败给出可复制的诊断编号，不展示 Token、服务器凭据或本地文件路径。

## 6. 开发拆分

| 阶段 | 交付 | 验收 |
| --- | --- | --- |
| AU-01 | 版本清单协议、校验器和更新源配置 | 合法/非法版本、哈希、平台、协议和降级测试通过 |
| AU-02 | Web 构建版本检测与非阻塞刷新提示 | 部署前后检测正确；运行中任务不被自动刷新；恢复后状态一致 |
| AU-03 | Android 更新检查、下载、校验和系统安装确认 | 1.9→下一测试版原地升级成功；错误签名/哈希被拒绝；断网不影响当前会话 |
| AU-04 | Android 前台恢复检查、下载恢复和强制版本策略 | 切换 Wi-Fi/蜂窝后继续下载或静默重试；不重复下载 |
| AU-05 | Windows 签名更新与回滚 | 旧版升级、安装失败回滚、签名错误拒绝和任务恢复通过 |
| AU-06 | 发布清单自动化和撤回开关 | 版本制品、哈希、签名和说明自动校验；暂停发布后新客户端不再收到该版本 |

## 7. 当前实现

- AU-01：服务端提供只读 `/api/client-updates`，清单支持文件注入、暂停开关、发布日期过滤和严格 schema 校验；共享层校验 HTTPS、版本单调、平台、协议范围、哈希和 Android 签名字段。
- AU-02：Web 检测服务端版本变化，仅显示非阻塞刷新提示，不自动打断任务。
- AU-03：Android 1.11 已实现前台/网络恢复检查、HTTPS 断点续传、200 MB 上限、SHA-256、包名、versionCode 和签名一致性校验，再交给系统安装器确认。
- AU-05：Windows RC.8 已实现启动、解锁和手动更新检查，下载 ZIP/EXE、限制大小和 SHA-256 校验；当前打开已校验制品供用户安装，不冒充静默安装或自动回滚。
- AU-06：发布脚本从真实制品计算 SHA-256 并生成客户端更新清单；`WORKPIVOT_UPDATE_ENABLED=0` 或清空清单可暂停分发。

## 8. 当前结论

客户端更新基础链路、8 项契约测试和 Android 1.11 真机安装已通过。Android 1.9 → 1.11 已在 GitHub 硬件加速模拟器完成原地升级，应用数据目录标记保留；Windows RC.6 → RC.8 已在真实 `windows-latest` 完成覆盖替换和用户数据保留验证。24 小时真实混合负载由产品负责人豁免，`v0.3.0` 已按正式发布边界发布。
