## 1. 当前基线

### 1.1 Word 生成链

当前 Word 不是由前端编辑器生成，而是 `docx-report` Skill 在隔离执行器中调用 Python：

```text
Agent
  → docx-report Skill
  → template.py / edit.py
  → verify.py / convert.py
  → uploadArtifacts
  → document_versions
  → 任务成果区
```

现有能力：

- `template.py` 按 JSON 字段填充 DOCX 模板；
- `edit.py` 对限定段落和简单表格单元格做文字修改；
- `verify.py` 核对 DOCX 结构与指定正文；
- `convert.py` 可选调用 LibreOffice 转 PDF；
- 文件通过 `document_versions` 保存不可变版本，知识索引、下载、删除和回收站均绑定版本。

现有边界：

- Python 修改器不处理修订、内容控件、域、链接、文本框和复杂对象；
- 当前已完成右侧统一工作区、PDF/图片/文本/HTML/CSV 预览，以及 DOCX/XLSX/PPTX 经隔离执行器转 PDF 的只读预览；
- LibreOffice PDF 转换受 Linux 字体替换和布局差异影响；
- 现有 `verify.py` 只证明结构和文字，不证明视觉版式。

### 1.2 需要补齐的用户路径

```text
在右侧打开 Word
  → 看到与下载文件对应的只读分页预览
  → 切换历史版本
  → 需要修改时要求 Agent 生成新版本
  → 原版本保留，知识索引按版本规则复核
```

## 2. 目标与非目标

### 2.1 目标

1. Word 文件可在右侧栏直接分页预览，不再只能下载。
2. 用户能判断标题、字体、表格、页眉页脚和分页是否正确。
3. 预览与 Agent/知识读取严格分离，派生 PDF 不得成为内容读取源。
4. 原始文件固定版本可提供稳定、可定位的结构化读取接口。
5. 固定 Linux 字体与渲染环境，避免不同机器显示结果漂移过大。
6. 明确预览不一致时的降级提示，不能静默展示错误版式。

### 2.2 非目标

- 本轮不提供应用内编辑：预览区只读，改动由 Agent 生成新版本；
- 本轮不实现在线多人协作、批注流转和修订审批；
- 本轮不替换 Python `docx-report` 生成链；
- 本轮不扩展 Excel、PPT 和 PDF 编辑；
- 本轮不承诺任意复杂 Word 文件无损往返；
- 不通过解析 DOCX XML 自研通用 Word 排版引擎；
- 不在未完成真实样本验收前改造生产容器和数据库 schema。

## 3. 候选方案

| 方案 | 预览效果预期 | 编辑能力 | 部署与许可 | 结论 |
| --- | --- | --- | --- | --- |
| LibreOffice → PDF | 中低，字体和版式容易漂移 | 无 | 最轻，现有依赖 | 只能作基线和兜底 |
| ONLYOFFICE Docs | 高，独立 Office 渲染引擎 | DOCX 完整编辑 | 独立容器；AGPL/商业授权 | 首轮主候选 |
| Univer Pro | 中高，取决于 OOXML 导入和字体 | 可定制文档编辑 | React SDK；高级能力需 Pro | 第二候选 |
| SuperDoc | 高，DOCX 原生模型 | Word 专项编辑 | AGPL/商业授权 | 前两者不达标时评估 |

### 3.1 推荐顺序

1. **B0：LibreOffice PDF 基线**，使用现有链路生成对照结果。
2. **B1：ONLYOFFICE POC**，优先验证分页、中文、表格和页眉页脚保真度。
3. **B2：Univer Pro POC**，验证能否在 WorkPivot 内提供更深度定制的编辑体验。
4. 只有 B1/B2 都不能满足 Word 编辑时，再评估 SuperDoc 商业授权。

选择依据不是功能数量，而是同一批真实 Word 样本的视觉和往返效果。

## 4. 目标架构

```text
                    现有 Python 生成 / 修改链
                              │
                              ▼
                    document_versions（不可变）
                              │
                 ┌────────────┴────────────┐
                 │                         │
          右侧只读预览                  完整编辑页
                 │                         │
        OnlyOffice/Univer           所选编辑引擎
                 │                         │
                 └────────────┬────────────┘
                              ▼
                  保存为新 document version
                              │
                 ┌────────────┴────────────┐
                 │                         │
          知识索引重新核对             审计与版本记录
```

首期增加 `WordSurface` 前端适配层，业务页面不直接依赖具体 SDK：

```ts
interface WordSurface {
  mode: 'preview' | 'edit'
  taskId: string
  documentId: string
  versionId: string
  revision: number
  onSaved(versionId: string): void
}
```

右侧栏只使用 `preview`。完整编辑打开独立任务路由，避免在 320–900px 的侧栏内塞入完整 Ribbon、菜单和浮层。

## 5. 文件与版本规则

1. 编辑器读取的是确定版本，不是“当前文件路径”。
2. 编辑器保存时提交 `documentId + baseRevision + baseVersionId`。
3. 服务端以现有 `files.upload()` 的 `revision` 乐观锁生成新版本。
4. 保存冲突返回 `409`，禁止覆盖他人或 Agent 已生成的新版本。
5. AI 生成和人工编辑不能同时写同一 `documentId`。
6. 内容发生变化后，原知识入库确认不自动沿用；按现有规则进入重新核对。
7. 不删除被编辑的旧版本；用户通过版本链比较和恢复。
8. 编辑器不得直接写入任务目录或 `.workpivot` 文件。

## 6. 安全边界

- Word 文件 URL 必须绑定当前用户、任务和版本，并使用短时签名；
- ONLYOFFICE 使用 JWT、受限回调地址和独立内部网络；
- iframe 只允许配置的编辑器源，补充 CSP `frame-src` 限制；
- 不把文件卷直接挂载给编辑器容器；
- 禁止宏、外部关系、嵌入对象和签名文件进入首期 POC；
- 下载、预览和编辑都再次校验任务访问权限；
- 保存回调幂等，重复回调不能生成多个相同版本；
- 临时转换文件按任务隔离并及时清理；
- 不记录 Word 正文、Cookie 或文件访问令牌。

## 7. 字体基线

Word 效果不能只由 SDK 决定，必须固定字体清单：

```text
西文替代：Carlito、Caladea、Liberation Sans/Serif/Mono
中文替代：Noto Sans CJK SC、Noto Serif CJK SC、思源黑体/宋体
```

要求：

- 浏览器和服务器使用同一字体包版本；
- 记录字体包哈希到预览缓存元数据；
- 对 `Microsoft YaHei`、`SimSun`、`Calibri`、`Cambria`、`Arial`、`Times New Roman` 建立明确映射；
- 渲染镜像启动时检查 `fc-match` 和字体文件存在；
- 缺字体时在结果中标出，不静默替换后宣称视觉通过；
- 渲染引擎或字体包变化时使旧预览缓存失效。

### POC-W3：选型评审

- 汇总视觉、往返、编辑、性能、许可和运维结果；
- 只要出现内容丢失或静默破坏，即不能进入生产；
- 选定一个生产引擎，另一个停止维护 POC 分支；
- 若两者均不达标，暂时只上线 PDF 预览和下载，不强行开放编辑。

### MVP-W1：Word 只读预览

- 在右侧栏增加“预览”入口；
- 按文件版本加载，不依赖本地同步目录；
- 支持加载中、失败、缺字体和不可预览状态；
- 版本切换与现有历史版本窗口保持一致；
- 缓存 key 包含 `versionId + renderer + fontManifest`。

### MVP-W2：人工编辑

- 从预览打开独立编辑路由；
- 显示“基于版本 vN 编辑”和保存状态；
- 保存时校验 revision，成功后生成 vN+1；
- 保存失败保留编辑内容，不丢草稿；
- 保存后刷新成果版本，并使知识入库状态进入待复核。

### MVP-W3：Python 与编辑器互通

- Python 生成文件 → 编辑器打开；
- 编辑器保存文件 → Python `verify.py` 和 `read_document_structure` 读取；
- Python 局部修改后的版本 → 编辑器再次打开；
- 确认未支持对象不会被静默删除；
- 不支持往返时在进入编辑前阻止并给出下载入口。

### MVP-W4：部署与回退

- 增加编辑器服务的 Compose 配置、健康检查和资源限制；
- 配置内部网络、JWT、字体卷和预览缓存；
- 保留旧路径：关闭编辑器开关后，仍可预览、下载和用 Python 继续修改；
- 准备镜像、配置、权限和回退步骤。

### RO-1：预览与读取分离为硬规则（P1，✅ 已完成）

- 明确两条通道：**预览**用于展示，**读取**用于给 Agent/知识入库供内容；禁止把预览派生的 PDF 文本层当读取源。
- 在 `code/packages/server` 内禁止 `preview.pdf` 进入读取链路（`read_document_structure`、`extract`、转换后的文本抽取）。
- 提示词与技能文档同步声明该约束，避免 Agent 自行"读预览 PDF"。

**验收：** 代码与提示词中无预览产物被读取的路径；新增单元测试或检查脚本对该约束回归。

### RO-2：转换结果契约补字段（P1，✅ 已完成）

- `DocumentPreview.officePdf()` 返回值补 `sourceSha256`、`converterVersion`、`stage`（如 `sandbox`/`libreoffice`）、`elapsedMs`。
- 字段命名与现有 `docx-report/scripts/convert.py` 返回的 `mode/structure/recalculation/render/visual/missingFonts` 保持同一套语义，不新增平行概念。
- 预览缓存 key 由 `versionId` 扩展为 `versionId + sourceSha256 + converterVersion`，转换器升级后旧缓存自动失效。

**验收：** 同一 `versionId` 在不同转换器版本下不复用缓存；返回体可追溯到源文件哈希与转换器版本。

### RO-3：预览失败分级（P1，✅ 已完成）

- `415`（非 Office 文件）与 `503`（转换能力未启用）归为"能力不可用"，前端给下载 + 本地打开入口。
- `502`（未生成或 PDF 无效）归为"系统故障"，前端提供重试。
- 返回体增加 `reason` 枚举，前端不再靠状态码猜测语义；错误码职责写进接口文档。

**验收：** 三类失败各有固定 UI 表现与可重试性；不会把"文件不支持"显示成"系统错误"。

### RO-4：结构化读取接口（P2，✅ 已完成）

- 为 DOCX 提供段落 ID、字符区间、表格 cell 矩阵；为 XLSX 提供 `values` + `formulas` 双视图。
- 定位契约固定：偏移单位为 UTF-16 code unit，区间左闭右开，结构变更后旧索引失效。
- 读取一律基于确定版本（`versionId`），不接受"当前文件路径"。

**验收：** 同一版本重复读取结果稳定；结构变更后使用旧索引会被明确拒绝。

### RO-5：扫描件 PDF 标记（P2，✅ 已完成）

- 转换后检测文本层；`hasTextLayer=false` 时在预览与读取结果中标记。
- 读取接口对无文本层文件返回空文本并提示"需 OCR 或人工查看"，不返回伪造内容。

**验收：** 扫描件与文字版 PDF 在接口与 UI 上可区分。

### RO-6：版本元数据记录派生预览（P2，✅ 已完成）

- `document_versions` 元数据记录派生预览的 `sha256`、`converterVersion`、生成时间与字体包哈希。
- 转换器或字体包变化时使该版本的预览缓存失效并重新生成。

**验收：** 任取一个版本可回答"这份预览由哪版转换器、哪套字体、何时生成"。

### 明确不采用的做法

- 常驻热备预览容器（资源常驻、生命周期复杂）；
- 引入专有 Office 引擎与其资源包（许可与体积不可控）；
- `--no-preflight --no-verify` 式跳过校验换取速度；
- 由渲染进程自行拉起转换服务。

### RO 交付记录（2026-11-04）

- 预览派生 PDF 只存在进程内 LRU 缓存，不进入文件卷、解析、知识或事实证据链路。
- `preview` 接口和 `preview-metadata` 接口返回源文件哈希、PDF 哈希、转换器版本、字体包哈希、阶段、耗时、生成时间和文本层状态。
- 缓存 key 为 `versionId + sourceSha256 + converterVersion + fontPackSha256`，执行器字体包变化后不得复用旧结果。
- `structure` 接口从原始文件固定版本读取段落、表格、工作表和区域，偏移单位为 UTF-16 code unit。
- PDF 解析持久化 `hasTextLayer`；扫描件标记为 `false`，OCR 来源和置信度继续单独记录。
- 预览错误使用稳定错误码，415/503 能力不可用时引导下载，408/429/502 等可恢复故障才提供重试。
- schema v71 增加 `document_processing.has_text_layer` 与 `document_versions.preview_*` 元数据。
- 数据库回归 852/852；文档预览、解析元数据、工作区 UI、TypeScript、ESLint 和生产构建通过。

## 9. 验收指标

### 9.1 效果

| 指标 | POC 门槛 |
| --- | --- |
| 样本打开成功率 | 100% |
| 正文、表格、页眉页脚文字丢失 | 0 |

| 关键页视觉阻断问题 | 0 |
| 字体缺失未提示 | 0 |
| Python `verify.py` 读取保存结果 | 100% |

视觉对比至少记录：

- 页数、分页位置和页面尺寸；
- 中文字体、行距和换行；
- 表格列宽、合并与跨页；
- 页眉、页脚和页码；
- 图片、图表和文本框位置；
- 编辑前后同一页截图差异。

### 9.2 性能

POC 先测量，不在未测试前承诺生产 SLA。首轮目标：

- 预热后 10MB 以内 Word 的预览可交互时间 P95 小于 5 秒；
- 保存生成新版本 P95 小于 5 秒；
- 单个编辑会话内存有明确上限；
- 关闭页面后临时会话和进程可回收。

### 9.3 数据一致性

- 重复保存回调不生成重复版本；
- revision 冲突返回 `409`；
- 旧版本哈希不变；
- Agent 与人工同时修改时最多一个成功；
- 删除或撤权后旧预览 URL 失效；
- 知识入库状态不会自动沿用旧确认。

| --- | --- |
| ONLYOFFICE 容器较重 | 独立服务、资源限制、按需启用 |
| AGPL/商业许可不匹配 | POC 前完成许可确认，商业集成优先评估 Developer Edition |
| Univer OOXML 保真不足 | 使用同一真实样本验收，不采用功能表代替效果 |
| 字体替换导致分页变化 | 固定字体包和 fontconfig，缓存绑定字体哈希 |
| 编辑器保存破坏 Python 可读结构 | 每次保存后运行 Python 结构验证，失败阻断发布 |
| AI 和人工并发覆盖 | baseRevision 乐观锁和任务级互斥 |
| 编辑后旧知识继续被引用 | 内容变更后使知识确认失效并进入重新核对 |
| SDK 锁定 | 前端通过 `WordSurface` 适配层隔离，业务页不直接依赖 SDK |
| 预览 PDF 被当作读取源 | RO-1 写成硬规则，代码与提示词双向约束并加检查 |
| 转换器升级后旧预览被沿用 | RO-2 缓存 key 带 `converterVersion` 与 `sourceSha256` |
| 失败语义混淆误导用户 | RO-3 失败分级与 `reason` 枚举，前端按语义而非状态码处理 |
| 字符偏移单位不一致 | RO-4 固定 UTF-16 code unit + 左闭右开区间 |

回退策略：

1. 关闭 `word_surface_enabled` 开关；
2. 右侧退回“下载 + 历史版本”；
3. 保留 Python 生成、修改和 LibreOffice 转换；
4. 已生成的编辑版本继续可下载，不物理删除；
5. 编辑器服务故障时不让任务和成果链路不可用。
