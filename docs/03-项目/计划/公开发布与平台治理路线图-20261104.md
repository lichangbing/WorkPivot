# WorkPivot 公开发布与平台治理路线图

| 项 | 值 |
| --- | --- |
| 状态 | ✅ 已确认；RC.8 客户端更新与交付验收已部署，正式版门禁继续收口 |
| 制定日期 | 2026-11-04 |
| 当前基线 | `v0.3.0-rc.8`，schema v72 |
| 目标 | 从单机 RC 收口为可正式发布版本，再分阶段建设多实例、安全治理、服务管理、监控和审计能力 |
| 原则 | 功能版本与补丁版本分开；平台能力不能塞入正式版补丁；未经目标和环境验收的能力不标记为可用 |

## 1. 路线结论

建议采用以下版本序列：

```text
v0.3.0-rc.8
    ↓
v0.3.0-rc.7
    ↓
v0.3.0-rc.6
    ↓
v0.3.0          单服务器、Web/Windows 主用，Android Beta 的正式版
    ↓
v0.3.x          正式版补丁，只修缺陷、安全问题和兼容性
    ↓
v0.4.0          服务端管理 + 多服务器部署/联动 + 高可用基础 + 安全检查
    ↓
v0.5.0          监控告警 + 不可变审计 + 运维治理 + 第三方安全审核
    ↓
v0.6.0          多故障域容灾、规模调度和企业运营
    ↓
v1.0.0          稳定企业版，提供兼容性承诺和完整发布认证
```

### 2.0 RC.8 客户端更新与交付验收

RC.8 不改变数据库 schema，重点是让客户端能够安全发现和获取更新，并关闭正式业务交付证据：

- Web 检测服务端版本变化并显示非阻塞刷新提示。
- Android 1.11 与 Windows RC.8 从只读清单检查更新，校验 HTTPS、平台、版本、API 协议、摘要和 Android 签名。
- Android 更新包交给系统安装器确认；不允许静默安装或绕过系统签名边界。
- 五项真实 DeepSeek/Worker/Office 业务验收、Office 固定视觉回归和移动换网/草稿真机测试完成。
- 1.9 → 1.11 覆盖升级因目标机已是 versionCode 12 且 release 包禁止降级而未关闭；必须改用旧版本设备或下一版本自然升级验证。

### 2.0.1 RC.7 移动恢复补丁

RC.7 只处理 Android 换网后的移动连接缺陷并重发客户端，不新增数据库迁移：

- 工作区和任务 SSE 使用指数退避、抖动、前台立即重连和持久水位恢复。
- 正常订阅轮换静默处理；全局只保留一个恢复提示，恢复后立即清除。
- 401 停止重连并重新登录；任务游标 409 重新读取快照；用户意图不因重连重复提交。
- Android 1.9 使用原包名和原发布签名覆盖构建；在线自动更新只登记需求，不纳入本补丁完成项。

不把多服务器部署直接塞进 `v0.3.0`。`v0.3.0` 的正式发布范围明确为：

- 单服务器 Docker Compose。
- Web 和 Windows 为正式支持客户端。
- Android 随 RC.8 更新并完成真机安装、换网和草稿验证，但在 `v0.3.0` 保持“正式支持的 Beta 客户端”口径。
- PostgreSQL 与本地持久文件卷配套部署。
- 单机监控、备份、恢复和人工运维可用。
- 不承诺应用多副本、跨主机文件共享、自动扩缩或跨机房容灾。

## 2. `v0.3.0` 正式发布门禁

### 2.1 RC.6 范围

RC.6 只处理正式发布阻断项，不增加业务功能：

| 编号 | 交付 | 验收标准 |
| --- | --- | --- |
| GA-01 | 支持矩阵与发布边界 | 明确 Web、Windows、Android、OIDC、Office 转换和支持的部署形态 |
| GA-02 | 正式服务器升级 | 远程从 RC.3/schema v70 升级到 RC.6/schema v72，迁移前备份、升级后可回退 |
| GA-03 | 客户端重新构建 | Android APK、Windows 客户端与同一服务端协议构建；安装、升级、卸载、重装和回滚通过 |
| GA-04 | 双物理设备 | 至少一台真实 Android 设备与一台独立桌面/浏览器会话完成登录、任务、纠正、审批、断线恢复和文件交付 |
| GA-05 | 24 小时持续运行 | 混合模型调用、文件、搜索、浏览器和执行任务；无未解释进程退出、内存持续增长、重复副作用或任务泄漏 |
| GA-06 | 真实业务验收 | 至少 5 个脱敏真实形态任务，覆盖报告、表格、演示、合同/制度阅读和业务事实修正 |
| GA-07 | 升级与回退演练 | schema v70→v72、镜像升级、数据库和文件卷联合恢复、旧镜像回退均有记录 |
| GA-08 | 账号主链路 | 管理员、注册用户、停用用户、临时密码、修改密码、额度和会话撤销完成真实页面回归 |
| GA-09 | 发布制品 | 镜像、客户端、SHA-256、SPDX/依赖清单、发布说明、运维手册和回退包齐全 |
| GA-10 | 缺陷门禁 | 无未关闭 P0/P1；P2 必须有明确影响、绕行方式、责任人和后续版本 |

### 2.2 RC.6 最小生产可观测性

正式版不能只靠人工执行 `docker logs`。RC.6 至少交付：

- `/api/health` 与 `/api/ready` 分离：存活、数据库、必要依赖和只读降级状态分开报告。
- 结构化 JSON 日志：请求/任务/运行关联 ID；默认脱敏 Token、Cookie、密码、数据库连接串和完整业务正文。
- 基础指标：HTTP 请求量/错误率/延迟、数据库连接、模型失败分类、任务积压、Worker/Browser 可用性、上传与磁盘水位。
- 备份状态：最近成功时间、失败原因和恢复验证结果。
- 告警规则：服务不可用、备份失败、磁盘 >80%/90%、数据库连接 >80%、任务最老等待超时、Worker/Browser 心跳缺失。
- 管理页只读“系统状态”视图：版本、schema、服务健康、容量、备份和最近告警。

这不是完整监控平台，但不满足以上条件不能称为正式生产版。

### 2.3 RC.6 安全门禁

正式版前完成内部安全审核，不等同于外部渗透测试：

- 更新威胁模型、信任边界、数据流和部署假设。
- 按 OWASP ASVS Level 1 做认证、会话、访问控制、输入校验、文件、SSRF、密钥和错误处理检查。
- 检查所有高风险管理操作是否有权限、revision、审计和撤销路径。
- 执行依赖漏洞、许可证、密钥和敏感信息扫描。
- 完成审计事件覆盖矩阵：登录、权限、配置、文件、模型、工具、审批、导出、删除、备份和失败操作。
- 确认审计查询、导出和保留策略不会泄露跨用户正文。

## 3. `v0.4.0` 服务端管理与多服务器部署

### 3.1 产品目标

从“单机可运行”升级为“服务端统一管理、无状态应用可以水平扩展、节点可以联动并具备基础高可用能力”。本版本是平台治理主线，不只包含对象存储或无状态 API。

### 3.2 交付包

| 编号 | 功能 | 关键约束 |
| --- | --- | --- |
| MS-01 | 无状态 API | 会话、任务、游标、限流和工作区版本不依赖单个进程内存 |
| MS-02 | 对象存储抽象 | 原件和成果迁移到 S3 兼容对象存储；数据库只存元数据和对象键，不共享 NFS 路径 |
| MS-03 | 多实例锁与额度 | 目录锁、队列领取、对话额度、并发额度和后台任务使用 PostgreSQL 原子机制 |
| MS-04 | 工作区与 SSE 分发 | 多 API 实例可接收同一任务事件；断线游标跨实例恢复，不依赖进程内 EventEmitter |
| MS-05 | Worker 注册与 drain | Worker 上报能力、容量和心跳；发布时停止领取，在途任务完成或保存检查点后退出 |
| MS-06 | 滚动发布 | 新实例通过 readiness 后接流量；旧实例先 drain；数据库迁移采用向前兼容的 expand/contract |
| SRV-01 | 服务端管理面 | 统一查看和配置 API、Scheduler、Worker、Browser、执行控制器和对象存储；操作必须审计 |
| SRV-02 | 节点注册与联动 | 节点能力、版本、容量、心跳、租约和状态进入数据库；禁止进程间隐式广播作为真相源 |
| SRV-03 | 多服务器高可用基础 | API 多活、Worker 故障接管、数据库健康检查、负载均衡和对象存储故障关闭 |
| SRV-04 | 多机安全检查 | 节点身份、内部认证、网络分区、Docker Socket 边界、跨节点文件授权和审计一致性 |
| OBS-01 | 指标与追踪 | Prometheus 兼容指标、OpenTelemetry 请求/任务/工具关联追踪；禁止把正文和参数写入标签 |
| AUD-01 | 审计事件升级 | 统一事件 ID、actor、target、action、result、reason、requestId、runId、correlationId 和策略版本 |
| SEC-02 | 多实例安全审核 | 对对象存储、跨节点认证、网络边界、共享缓存、Worker 注册和审计一致性做威胁评审 |

### 3.3 多服务器部署建议

首阶段不直接上 Kubernetes。推荐拓扑：

```text
HTTPS 负载均衡
  ├── WorkPivot API 实例 A
  └── WorkPivot API 实例 B
          ↓
   PostgreSQL / 队列 / 审计
          ↓
   S3 兼容对象存储
          ↓
   独立 Worker / Browser / 执行控制节点
```

- 数据库优先使用受管 PostgreSQL 或独立数据库节点，不在应用节点运行主数据库。
- 文件必须使用对象存储版本能力，不能继续依赖单机 Docker volume 跨节点共享。
- API、Scheduler、Worker、Browser 和执行控制器分别部署、分别扩缩。
- Docker Socket 只允许执行控制器持有；业务 API 和普通 Worker 永远不挂载。
- 暂不引入 Redis；只有当 PostgreSQL 队列、锁和事件分发出现明确容量瓶颈并通过 ADR 后才增加。
- Kubernetes 仅在节点数量、弹性调度或组织运维要求明确后进入 `v0.6.0` 评估，不提前引入。

### 3.4 验收门禁

- 两个 API 实例交替接收请求，重复提交、SSE 重连和工作区同步无丢失。
- 任一 API 实例被强杀后，任务状态和事件可由另一实例恢复。
- 两个 Worker 竞争同一任务时只产生一个执行租约和一份副作用。
- 对象存储短暂失败时文件发布失败关闭，数据库不留下幽灵版本。
- 发布过程中至少一个 API 实例持续提供只读服务；旧实例 drain 后无在途任务丢失。
- 审计可按 correlationId 串联 API、任务、工具、审批和成果发布。

## 4. `v0.5.0` 安全治理与可观测治理

### 4.1 产品目标

让管理员能够安全地观察、告警、审计和治理已有服务端管理能力，而不是依赖 SSH、直接 SQL 和人工日志搜索。

### 4.2 后台服务管理

| 编号 | 功能 | 说明 |
| --- | --- | --- |
| ADM-01 | 服务与节点视图 | API、Scheduler、Worker、Browser、执行控制器、数据库和对象存储的版本、健康、容量、心跳和最后变更 |
| ADM-02 | 作业管理 | 查看队列、运行中、失败、重试、死信和结果未知作业；支持重试、取消和隔离，不直接编辑数据库 |
| ADM-03 | 配置发布 | 模型、限额、注册策略、功能开关和告警规则使用 revision；高风险配置需要双人确认或二次确认 |
| ADM-04 | 安全操作 | drain、重启、重试、撤销会话、隔离节点等操作必须审计；默认禁止远程 Shell 和任意命令执行 |
| ADM-05 | 备份与恢复管理 | 定时备份状态、备份校验、恢复预检和恢复审批；实际恢复仍需受保护运维通道 |
| ADM-06 | 支持包 | 导出脱敏的版本、配置摘要、健康、日志索引和诊断结果，不包含业务正文和密钥 |

### 4.3 监控与告警

- SLO 看板：可用性、API 延迟、任务成功率、交付成功率、模型错误率、队列等待和存储增长。
- 告警中心：严重级别、去重、抑制、确认、负责人、静默和恢复通知。
- 告警路由：站内、邮件、Webhook；外部通知只发送摘要和链接，不发送业务正文。
- 值班视图：当前故障、受影响服务、最近变更、备份状态和运行手册入口。
- 监控自身故障检测：指标采集中断、告警发送失败和日志积压必须可见。

### 4.4 审计中心

| 编号 | 能力 | 验收 |
| --- | --- | --- |
| AUD-02 | 不可变审计归档 | 应用角色不能更新/删除审计；归档到对象存储后记录哈希 |
| AUD-03 | 审计检索 | 按时间、操作人、对象、动作、结果、风险、correlationId 查询和分页 |
| AUD-04 | 保留与清理 | 按事件类型设置保留期；安全、身份、删除和备份审计不可使用普通日志清理策略 |
| AUD-05 | 导出与核对 | 管理员按范围导出 NDJSON；导出行为自身入审计；抽查与运行事件一致 |
| AUD-06 | 防篡改检查 | 定期验证归档摘要；缺失或篡改产生高优先级告警 |

### 4.5 安全审核

- 邀请独立第三方进行代码审计和黑盒/灰盒渗透测试。
- 范围覆盖认证绕过、会话、RLS、对象存储越权、SSRF、MCP、Worker、管理员操作、文件上传和审计。
- 对 ASVS Level 2 中适用于私有化办公系统的控制项形成证据矩阵。
- P0/P1 必须在正式发布前关闭；不能以“仅内网”或“前端已隐藏”接受。
- 发布 SBOM、依赖漏洞处置记录和最终安全审核报告索引。

## 5. `v0.6.0` 多故障域容灾与规模调度

### 5.1 交付目标

- 在 `v0.4.0` 基础高可用之上，建设多可用区数据库和对象存储复制。
- 跨机房/故障域服务发现、容量调度和灾难恢复切换。
- 数据库迁移和应用滚动升级支持跨故障域恢复。
- 正式定义并验证跨故障域 RPO/RTO。
- 故障演练：API/Worker/Browser/对象存储/数据库主节点故障、网络分区、磁盘写满、备份恢复。
- Kubernetes/KEDA 仅作为规模化选项，必须先用压测证明收益和运维成本。

### 5.2 建议目标

| 指标 | 目标 |
| --- | --- |
| 计划外可用性 | 单区域 99.9% 起步 |
| RPO | ≤ 15 分钟 |
| RTO | ≤ 2 小时 |
| 发布回退 | ≤ 30 分钟切回上一稳定版本 |
| 审计丢失 | 已确认提交事件为 0 |
| 副作用重放 | 0 |

这些目标需要通过实际演练证明，不能只写在架构图上。

## 6. `v1.0.0` 稳定企业版

`v1.0.0` 不再是“功能特别多”，而是承诺稳定契约：

- API、事件、插件/Skill 和部署接口有明确兼容周期和弃用流程。
- 支持多实例和经过验证的高可用/容灾拓扑。
- 外部安全审核无未关闭高危；关键安全问题有持续跟踪机制。
- 监控、审计、备份、恢复、升级和故障演练成为常态能力。
- 至少完成多个真实客户形态的业务验收，而不只是合成样本。
- 发布支持矩阵、SLA 边界、已知限制、运维手册和灾难恢复手册。
- 补丁、功能版和不兼容变更严格遵守语义化版本。

## 7. 安全审核节奏

安全审核不是只放一个版本做一次：

| 阶段 | 审核类型 | 放行条件 |
| --- | --- | --- |
| 每个 RC/正式补丁 | 自动扫描、依赖、密钥、权限和审计回归 | 无新增高危，关键回归通过 |
| `v0.3.0` | 内部威胁模型与 ASVS L1 | 无未关闭 P0/P1，审计覆盖主链路 |
| `v0.4.0` | 多实例架构安全评审 | 跨实例、对象存储、Worker 和网络边界通过 |
| `v0.5.0` | 独立代码审计与渗透测试、ASVS L2 | 高危关闭并复测通过 |
| `v0.6.0` | 高可用与故障安全演练 | RPO/RTO、恢复、撤权和审计完整性通过 |
| `v1.0.0` | 发布安全认证与证据冻结 | 支持矩阵内全部控制项有证据 |

以下为一名主开发配合测试/运维时的规划值，不作为固定承诺：

## 10. 上线前部署安全审核基线

每个目标环境上线前至少核对：

- 主机与容器：系统补丁、非 root、只读根文件系统、capabilities、seccomp、PID/CPU/内存限制。
- 网络：仅公开必要端口；数据库、执行控制、浏览器调试和管理入口不暴露公网；出站代理默认拒绝。
- SSH 与主机管理：禁用密码登录、限制来源、密钥轮换、审计登录、应急管理员和离任撤权。
- 密钥：模型、数据库、Worker、Browser、对象存储和主密钥分离保管；配置文件权限 `0600`；禁止进入 Git、镜像层和普通备份。
- 数据库：应用/认证/管理/调度角色分离，禁止业务角色拥有 DDL、BYPASSRLS 和超级用户权限。
- 文件与对象存储：版本、加密、生命周期、跨用户隔离、签名 URL 有效期和删除传播。
- 备份：数据库、文件/对象、配置和密钥配套备份；备份加密；恢复在隔离环境验证。
- 供应链：镜像固定摘要、依赖漏洞、许可证、SBOM、构建来源和旧镜像保留。
- 审计：登录、权限、配置、工具、审批、文件、导出、删除、备份和高风险失败事件可检索。
- 监测：服务、数据库、磁盘、队列、Worker、Browser、模型错误和备份失败均有告警。

## 11. 暂不进入当前版本

- 应用内自由编辑 Office 文件。
- 完整多租户计费、组织同步和企业微信深度集成。
- 无审计的 Agent 自由协作或自由生成并执行编排脚本。
- 在 `v0.3.x` 补丁版中引入多服务器架构。
- 为了“看起来先进”提前引入 Kubernetes、Redis、微服务或第二套任务队列。
