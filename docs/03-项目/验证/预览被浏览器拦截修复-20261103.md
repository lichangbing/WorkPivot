# PDF 预览被浏览器拦截修复（2026-11-03）

| 项 | 值 |
| --- | --- |
| 状态 | ✅ 已修复并部署 |
| 影响版本 | `v0.3.0-rc.3` 增量修复 |
| 影响范围 | 右侧工作区 PDF 与 Office 转 PDF 只读预览 |
| 浏览器 | Google Chrome 156.0.8078.47 |

## 问题

右侧工作区打开 PDF 时，iframe 内显示：

```text
This page has been blocked by Chrome
```

## 根因

前端把 PDF blob 放入 `iframe sandbox=""`。Chrome 内置 PDF 阅读器不允许在任意 sandbox iframe 中启动；实测 `allow-same-origin`、`allow-scripts` 等组合仍被拦截。普通 iframe 可正常渲染同一 PDF。

原自动化只断言 PDF iframe 存在，没有读取 iframe 内容，因此“元素存在但 Chrome 拦截内容”仍会假通过。

## 修复

- PDF iframe 移除 `sandbox`，保留 `referrerPolicy="no-referrer"`。
- PDF 内容仍来自认证 API，先下载为内存 blob，再交给 Chrome 内置阅读器。
- HTML 预览继续使用 `sandbox=""` 和前端清洗，不降低不可信 HTML 的隔离边界。
- 自动化改为生成真实 PDF，断言 iframe 不再带 sandbox，且 iframe 不出现 Chrome 拦截提示。

## 验证

- 对照测试：同一 PDF 在 sandbox iframe 显示拦截，在普通 iframe 正常渲染。
- `pnpm eval:workspace-right-panel` 通过。
- TypeScript、ESLint、Web 生产构建通过。
- 本地真实任务上传 PDF 后，通过 Chrome 在右侧工作区渲染成功，未出现拦截提示。
- 正式环境公网前端资源已确认使用新版 PDF iframe；`/api/health`、首页和管理页正常。

## 部署

- 本地服务端容器：healthy。
- 正式服务端容器：healthy。
- 正式 UI 仅更新前端构建；数据库 schema 保持 v70，无迁移。
- 正式回退镜像：`workpivot-server:pre-preview-fix-20261103`。

## 已知边界

当前修复保证 Chrome 内置 PDF 阅读器能够打开图片型和文字型 PDF。移动端 WebView 是否内置 PDF 阅读器仍需在目标 Android 设备上验证；无内置阅读器的环境应保留下载入口或后续接入 PDF.js。
