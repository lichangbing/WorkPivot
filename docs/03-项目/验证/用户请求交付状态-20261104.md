# 用户请求交付状态验收（2026-11-04）

## 交付

- 共享 `RequestDeliveryView`：区分运行阶段和用户可见交付阶段，不复制会话正文。
- 交付状态：`not_visible / acknowledged / delivered / blocked`。
- 运行阶段：`accepted / running / waiting_user / stopping / completed / interrupted / failed / stopped`。
- 状态来源：现有 `task_runs`、`conversation_events`、待处理交互和 `resumed` 续跑链。
- 会话首屏、任务 SSE state 和 `GET /api/tasks/:id/deliveries` 返回当前请求状态。
- Web/移动端在用户消息下显示已接收、处理中、等待用户、中断、失败或已交付。
- 工具与思考继续进入可折叠过程区，不作为最终答复。
- 首个正文前崩溃、部分正文后中断、完成但无正文、失败和停止均有明确用户状态。
- “继续”运行归回原始用户请求；已派发工具继续按 R006 不重放。
- 交付状态与无反馈恢复分别由 `WORKPIVOT_INTERACTION_DELIVERY_STATE_V1`、`WORKPIVOT_INTERACTION_NO_FEEDBACK_RECOVERY` 控制。

本阶段从现有持久记录派生状态，没有新增数据库表，schema 仍为 v71。

## 覆盖边界

- 运行中没有非空助手正文时显示已接收，不伪装已回复。
- 有可见正文但仍在运行时显示处理中。
- 只有运行完成且存在可见助手正文才显示已交付。
- 完成但无正文显示“缺少可见答复”，不显示正常完成。
- 等待授权/澄清显示等待用户，而不是失败。
- 首字前中断保留中断终态，不伪造回复。
- 部分正文后中断保留已有片段，同时保持可继续状态。
- 已派发工具结果未知时不会因为补交付状态而重放。
- 自动续跑仍默认关闭，并继续受未决派发和次数上限约束。
- 会话分页只返回当前根请求相关状态。
- 异常循环续跑链不会重复输出或死循环。
- 状态使用 `role=status`、`aria-live=polite`，Web/移动端语义一致。
