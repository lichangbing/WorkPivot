# 业务事实治理与企业身份验收（2026-10-28）

## 交付范围

| 能力 | 实现 |
|---|---|
| 可逆实体合并 | 名称/别名候选、事实键和关系键冲突预检、合并记录和拆回 |
| 表格候选导入 | XLSX、DOCX、CSV 列映射；保留工作表、行列、证据、单位和币种；用户确认后写入 |
| 项目共享事实 | 所有者、编辑者、只读成员；共享项目事实，私人任务和聊天保持隔离 |
| OIDC 基础 | 组织、身份源、待授权绑定、PKCE、一次性完成凭据、会话签发和审计 |
| 执行边界 | 服务端无 Docker socket、只读根、全量降权；执行器不挂载应用数据 |

数据库结构为 schema v67。v66 包含实体治理、表格导入和 OIDC 基础，v67 包含项目共享事实策略。

## 已知边界

- 当前没有真实企业 IdP、企业微信应用或组织同步账号；`iam-01` 基础已通过本地 Keycloak，供应商级接入仍需实际配置。
- 项目协作当前共享项目元数据和业务事实，不共享私人任务、聊天、个人记忆或项目知识文件。共享知识版本与成员审批流仍待后续。
- 实体合并遇到事实键或关系键冲突会安全拒绝，要求先人工核对；不会自动把不同金额合并。
- 表格导入只处理解析器可定位的表格列；复杂跨行合并、图表和扫描表格仍需人工核对。
- 移动端已有业务事实列表和冲突处理，实体合并、表格导入和 OIDC 管理入口目前只在 Web 管理端。
- 已建立中文业务事实固定用例文件，但本轮没有供应商模型质量分数；不能用合成专项替代真实业务准确率。

## 复现入口

```bash
cd code
pnpm typecheck
pnpm lint
pnpm eval:parser-metadata
pnpm eval:business-governance-ui
pnpm eval:execution-boundary
```

数据库和 OIDC 专项需要一次性 PostgreSQL；OIDC 另需固定版本 Keycloak 本地实验容器。测试数据与凭据不进入仓库。
