# 移动端断网恢复与 Android 1.9 验收（2026-11-05）

## 结论

`v0.3.0-rc.7` 已完成移动端换网恢复的代码修复、自动化验证、服务端构建部署和 Android 1.9 覆盖安装包构建。真实手机来回切换 Wi-Fi/蜂窝网络仍需作为下一项人工验收；本轮不把自动化模拟等同于真机验收。

## 根因

1. 服务端工作区和任务 SSE 约每 5 分钟主动结束订阅，旧客户端把正常 EOF 当作连接故障。
2. 工作区重连成功只更新数据，没有清除旧的传输错误。
3. 记忆、专家、摘要、模型状态、执行模式和资源范围各自轮询；同一断网被多个组件分别显示。
4. 工作区把 401 包成普通错误，主应用无法识别会话失效，可能持续重连。
5. 任务流游标失效后仍用旧水位重试，缺少重新取快照的恢复路径。

## 修复

- 工作区与任务 SSE 使用 1～10 秒指数退避和 20% 抖动；网络恢复或页面重新可见时立即重连。
- 已稳定运行超过 30 秒的 EOF 视为正常订阅轮换，静默重连。
- 全局传输状态由工作区 SSE 维护；局部轮询遇到网络错误时保留已加载数据，不再产生独立告警。
- 恢复成功后清除传输故障状态。
- 401 停止重连并触发一次会话退出；多个并发 401 去重。
- 任务流 409 重新读取最新会话快照并重置水位。
- 用户消息待确认期间复用同一 `requestId`，恢复不自动重发。

## RC.8 真机复验

设备为 HONOR `PTP-AN00` / Android 16，应用 `com.workpivot.mobile` `1.11` / versionCode `12`。USB 调试授权后完成了以下检查：

1. Android 1.11 冷启动成功，现有账号、任务和“3 层记忆”设置保留。
2. 同时关闭 Wi-Fi 和移动数据，断网 3～9 秒只出现一个“网络连接已中断，正在恢复同步，任务不会丢失”提示。
3. 恢复网络后 4～16 秒内提示消失并回到“已同步”，未发现 FATAL 崩溃或新增重复任务。
4. 在输入框保留非空草稿后断网 8 秒，草稿仍在；恢复网络 15 秒后草稿仍在，登录态和当前任务未丢失。
5. `uiautomator` 层级确认恢复后 `EditText` 内容未清空。

证据文件位于 `local-runtime/acceptance/android-runtime/`：

- `before-1.11.png`
- `network-offline-3s.png`、`network-offline-9s.png`
- `network-recovering-4s.png`、`network-online-16s.png`
- `draft-before-offline.png`、`draft-offline-8s.png`、`draft-online-15s.png`、`draft-online.xml`

覆盖升级未通过：设备已经是 versionCode 12，Android/HONOR 不允许 release 签名包降级安装 versionCode 10。执行 `adb install -r -d WorkPivot-android-1.9.apk` 返回 `INSTALL_FAILED_VERSION_DOWNGRADE`。没有使用卸载清数据的方式绕过，因为这会破坏本项要验证的登录态、任务和草稿保留目标。
