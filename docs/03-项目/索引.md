## 交付原则

1. **实现、验证、部署分开记录**：代码完成不代表验收通过，部署命令成功不代表用户链路可用。
2. **当前状态只有一个入口**：本目录以 `当前状态.md` 为高层快照，历史文件只提供证据。
3. **真实模型与合成测试区分**：记录必须写明数据来源和测试环境。
4. **版本与 schema 配套**：升级、回退和备份必须记录数据库版本、镜像和配置。
5. **未完成项保留可见性**：不能用“下一步”或计划日期掩盖当前缺口。

## 状态更新要求

当一项功能发生实质变化时，同批完成：

1. 更新对应 PRD/架构文档。
2. 在专项验收记录写明验证范围。
3. 更新 `当前状态.md`。
4. 如已部署，补部署版本、schema、健康检查和回退材料。
5. 如存在真实业务不可验证项，明确标出，不用合成测试替代。
