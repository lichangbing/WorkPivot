## 1. 背景与目标

- **为什么调研**：桌面端必有是已确定的基线约束；私有化交付对体积、离线安装、安全边界有硬要求。需要决定桌面壳框架，才能搭 `apps/desktop` 工程骨架。
- **决策截止**：ADR-003（桌面端框架）之前；进入设计阶段前应定案。
- **有利条件**：本研究已完成三个真实产品的实证分析，两个框架各有生产级样本，无需纸面对比。

## 2. 实证样本（证据来源）

| 框架 | 样本 | 形态 | 实测数据 |
|------|------|------|----------|
| **Electron** | WorkBuddy（商业） | Electron 壳 + 内嵌 CodeBuddy CLI 子进程 | exe **204MB** + app.asar **283MB**（安装约 500MB）；Chromium 全家桶；Electron 主进程 + 多渲染进程 |
| **Electron** | OpenWorkBuddy（开源复刻） | **Express 服务器直接住进 Electron main**，agent 循环同进程；无构建前端 | 依赖仅 10 个包；用 Electron 自带 Chrome 做 mermaid 渲染/离屏截图/桌面宠物透明窗；单进程形态 |
| **Tauri v2** | MyAgents（开源工程派） | Tauri 壳（Rust）+ 内置 Node v24 Sidecar（Global + 每会话一个）+ React 19 前端 | exe **95MB**（含内置 Node 运行时）；系统 WebView（Win=WebView2/mac=WKWebView）；Rust 层承载 PTY/文件IO/搜索/进程编排/OCR |

## 3. 对比矩阵（全部按实测证据填写）

| 维度 | 权重 | Electron（WorkBuddy/OWB 实证） | Tauri v2（MyAgents 实证） | 备注 |
|------|------|-------------------------------|---------------------------|------|
| 安装体积 | 高 | ~500MB（WorkBuddy）/ OWB 类似量级 | **~95MB**（3-5 倍差距） | 私有化分发/升级带宽直接受益 |
| 内存占用 | 高 | 每窗口独立 Chromium | 系统 WebView 共享 | MyAgents 多 Tab 场景优势更大 |
| 渲染一致性 | 中 | **同源 Chromium**，跨平台像素级一致 | 依赖系统 WebView，Win/mac 行为有差异 | OWB 的 SVG 流式渲染/截图等对引擎敏感的场景 Electron 更稳 |
| 安全模型 | **高（企业）** | 需自律（contextIsolation/CSP 手工配） | **Capabilities 最小权限 + IPC 白名单**；MyAgents 更进一步：控制面强制过 Rust 代理，WebView 零直连 | 企业客户安全评审的显著差异项 |
| 系统能力层 | 高 | Node 生态（node-pty/better-sqlite3/koffi） | **Rust 生态**（portable-pty/Tantivy+jejieba/原生进程树句柄/OCR） | Tauri 把系统能力收进 Rust 层的分层是 MyAgents 的核心优点 |
| AI 运行时承载 | 高 | 可同进程（OWB 式，最简）或子进程（WorkBuddy 式） | 必须 Node Sidecar（我们的内核选型 Cordis/jiti/pi 均为 Node/TS） | **两种都成立**：WorkBuddy=CLI host 子进程；MyAgents=Sidecar Owner 模型 |
| 离线私有化安装 | **高** | **自包含**（Chromium 随包），离线最省心 | 需处理 **WebView2 依赖**（Win10+ 多数自带；离线镜像需捆绑 bootstrapper，成熟方案但多一步） | Electron 在纯离线环境有边际优势 |
| 团队技能门槛 | **高（决策性）** | JS/TS 即可，招聘容易 | **需要 Rust 能力**（系统能力层）；MyAgents 证明可行但团队成本真实存在 | ⚠️ 本选型唯一未确认的前提 |
| 多 WebView/内嵌浏览器 | 中 | webContents/BrowserView 成熟 | v2 支持（MyAgents 用 unstable 多 WebView 做内嵌浏览器，零权限隔离做得更好） | 都可用，Tauri 隔离模型更严格 |
| 生态成熟度 | 中 | 10 年生态，资料/库最多 | v2 稳定但生态较新；本赛道已有 MyAgents/dsh 邻近实践 | Electron 兜底性强 |
| 升级/自动更新 | 中 | electron-updater 成熟 | Tauri updater 插件（MyAgents 在用） | 均可 |

## 4. 两种落地形态（比框架选择更重要的架构决策）

实证给出两条已验证的组装路线：

### 形态 A：OWB 式——单进程同居（快）

```
Electron main = Express 服务器 + Agent 运行时 + 前端静态资源
（mermaid/截图白嫖 Electron 的 Chrome；桌面宠物=透明窗）
```
- ✅ 最少进程、最少代码、最快 MVP；适合「单机版先行」的第一版
- ❌ agent 重任务卡主进程（OWB 自己的已知债）、崩溃域不分、系统能力无独立安全层

### 形态 B：MyAgents 式——壳/系统层/AI 层三分离（稳）

```
Tauri 壳（Rust：PTY/文件IO/搜索/进程编排/更新）
  ↕ 控制面强制过 Rust 代理 + Management API 反向通道
Node Sidecar（内置 Node v24：Cordis 内核 + jiti 扩展 + pi 式循环）
  ↕ localhost HTTP/SSE
前端（React/Vue 任选，WebView 渲染）
```
- ✅ 崩溃域隔离（MyAgents 的 Sidecar Owner/generation 治理现成可抄）；安全边界清晰（企业刚需）；系统能力 Rust 化
- ❌ 进程模型复杂度、Rust 门槛、冷启动链路长（需做 OWB 式启动体检教训的预案）

> **注意**：形态 A/B 与框架并非强绑定——Electron 也能做三分离（WorkBuddy 就是 Electron+CLI host 子进程），Tauri 理论上也能同居但失去 Rust 层意义。**先选形态，再选框架**。

## 5. 关键验证（PoC，落 ADR 前执行）

1. **WebView2 离线安装演练**：在一台无 WebView2 的离线 Win10 虚机上装 Tauri 应用（捆绑 bootstrapper），验证私有化安装脚本（对应 releases/ 部署包规范）
2. **最小竖切**：按形态 B 搭 20 文件级 demo——Tauri 壳 + Node Sidecar（跑一个 jiti 加载的扩展）+ SSE 流式到前端；同时用 Electron 按形态 A 做对照，各测冷启动/内存/安装体积
3. **Rust 承载力评估**：盘点团队/招聘能否支撑系统能力层的 Rust 维护（PTY/进程树/文件IO 是长期活）；若不能，决策自动落到 Electron
4. **内嵌浏览器需求确认**：若 A05 首版就要，两框架各做一页多 WebView 内存对比

## 6. 结论与建议

- **推荐**：**Tauri v2 + 形态 B（MyAgents 路线）为首选**——体积 3-5 倍优势、企业安全模型、Rust 系统能力层、Sidecar 治理模式全部有 MyAgents 源码背书（可直接对照实现）；**前提是 PoC-3（Rust 承载力）通过**
- **备选**：**Electron + 形态 A 起步 → 演进到形态 A'（Express+运行时拆子进程）**——当团队为纯 JS 或交付窗口极紧时采用；OWB 证明形态 A 能撑到 v0.x，WorkBuddy 证明 Electron 路线能走到商业终态，不算妥协
- **理由**：我们的定位（企业私有化）把安全模型和体积的权重推高；而 AI 内核反正独立于壳（Node），三分离形态让壳的选择在未来可替换（形态 B 下换壳成本 ≈ 重写系统层绑定）
- **风险与缓解**：Rust 门槛→系统能力层可渐进（先用 Tauri 插件 fs/shell/process，自研 Rust 模块按需增加）；WebView2 离线→bootstrapper 拌进私有化安装包并在部署文档固化；渲染不一致→前端避免引擎敏感技巧（OWB 的 SVG 流式渲染若上 Tauri 需专门验证）
- **是否落 ADR**：✅ PoC 通过后落 `ADR-003-桌面端框架`（与 ADR-001 后端栈、ADR-002 编排内核并行推进）
