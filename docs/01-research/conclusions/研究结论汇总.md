## 2. 产品定位建议

**WorkPivot = 面向企业内部群体的私有化智能工作台**：以桌面端为第一入口（Web-ready 同架构），Agent 在真实工作目录中执行任务并交付可验收的文件成果（PPT/Word/Excel/报告），通过「专家·技能·连接器」扩展体系支撑不同企业的智能化应用，全栈可离线私有化部署。

**差异化定位**（对照 WorkBuddy 的竞争空白）：

1. **私有化模型自由**：WorkBuddy selfhosted 仅 1 个内置模型；WorkPivot 以「OpenAI+Anthropic 双协议 + Ollama/vLLM 热插拔」为企业客户保留模型选择权（C03，P0）
2. **集成中立**：不绑任何厂商生态（对照 WorkBuddy 深度绑定腾讯文档/会议/微信支付）；连接器化接入
3. **开放生态对齐**：记忆/人设/技能/插件格式对齐 OpenClaw、agentskills.io、MCP、ACP 等事实标准，企业可复用社区内容
4. **企业登录原生**：OAuth2/OIDC 兼容 + 飞书登录（J07 基线）

## 3. 目标客户画像（含待验证假设 ⚠️）

- **假设主要客群**：数据合规要求高、需要私有化部署的中大型企业内部团队——重点画像为**知识密集型岗位**（投研/咨询/研究院/政府数字化），依据：① 用户实际工作目录为 PE/VC 咨询项目（文档密集、版本迭代快、交付物验收导向）② 此类客户对「数据不出内网」付费意愿最强（WorkBuddy 专有云 316 元/人/月、100 席起验证了市场）
- **使用者角色**：业务成员（下任务收成果）、企业管理员（管控模型/技能/权限）、IT 运维（私有化部署）
- ⚠️ **Q5（首批种子客户是谁）/Q6（企业规模与并发）待确认**，影响 D07/E06/J 模块的取舍节奏

## 4. MVP 功能范围建议（需求清单 P0 摘要）

**桌面客户端**（A01 壳/A02 多任务三栏/A03 过程可视化）＋**工作区**（B01 目录落盘/B02 版本号文件名交付）＋**内核**（C01 编排/C02 双协议/C03 私有化模型热插拔）＋**技能**（D01 SKILL.md 热加载）＋**任务韧性**（F01 转写持久化/F02 成果核验闸门/F03 强制收尾）＋**文档生成**（H01-04 Word/PPT/Excel + 写后自检）＋**安全**（I01 沙箱/I02 权限档位/I03 审计/I04 密钥加密/I05 高危防护）＋**工程**（K01 评测体系/K02 原子落盘）。

不在 MVP：多租户硬隔离、企业管理后台、企业知识库、IM 接入、代码插件自生成（详见需求清单 P1/P2 分层）。

## 5. 技术路线（全部定案）

| 决策 | 结论 | 状态 |
|------|------|------|
| 语言栈 | 全栈 TypeScript/Node | ✅ |
| 桌面框架 | Electron（形态 A 同居起步 → 压力信号触发拆 A' 子进程） | ✅ |
| 编排内核 | Cordis 模式 + jiti（PoC 后落 ADR-002） | ✅ 方向已定 |
| 内核三能力 | ①动态加载（可逆效应）②自动生成→用户确认→加载（技能先行 P1、代码插件 P2 带沙箱审批）③记忆生成走确认流 | ✅ |
| 模型接入 | OpenAI 兼容 + Anthropic 双协议；Ollama/vLLM 热插拔 | ✅ |
| 记忆检索 | sqlite-vec 混合检索（零外部向量库） | 🔶 建议采纳 |
| 生态对齐 | OpenClaw 格式/agentskills.io/MCP/ACP | ✅ |
| Web 策略 | 桌面第一入口 + Web-ready（L0 免费自带/L1 服务器部署 P1-P2/L2 管理后台 P2）；UI 禁用 Electron 专属 API | ✅ |
| 认证基线 | OAuth2/OIDC 兼容 + 飞书登录（桌面走系统浏览器+loopback 回调+PKCE；Web 走标准 code flow；token 走 I04 加密；认证与 RBAC 分离，飞书组织架构可作角色来源） | ✅ |

**架构蓝图**（形态 A）：

```
Electron 主进程 ─ 窗口/托盘/更新
 └ Express+SSE ─ 前端(Web-ready) ← localhost ← 渲染进程/浏览器
 └ Cordis 内核 ─ agent 循环(pi 式 7 工具基线)/jiti 扩展/技能/记忆/双协议网关/安全
数据：~/.workpivot（本地优先，原子落盘+.bak）
交付：releases/vX.Y.Z（离线安装包+部署编排+发布说明）
```

## 6. 风险清单与缓解

| # | 风险 | 等级 | 缓解 |
|---|------|------|------|
| R1 | Cordis 生态小众、学习曲线 | 中 | vendor 锁版本（dsh 同款）；退路=自研三概念精简内核；PoC 前置 |
| R2 | 安全是企业成交门槛（沙箱/密钥/审计） | 高 | 全部 P0；三家竞品明文存 key 是反面教材，密钥加密（DPAPI/Keychain）做基础要求；WorkBuddy sandbox-cli/审计格式可直接对标 |
| R3 | 形态 A 主进程压力（agent 长任务卡 UI） | 中 | 拆分边界纪律（UI 只走 HTTP/SSE）+ 触发信号（掉帧>200ms/内存阈值）+ OWB 的「eval 已验证子进程可行性」证据 |
| R4 | 文档生成质量不稳 | 中 | 技能化（OWB ppt-design「内容纪律」范式）+ 写后自检 + K01 评测基线 |
| R5 | 自动生成确认流打扰用户 | 中 | Hermes「用户确认前置」+ nudge 归零机制；审批卡片只在对话内出现 |
| R6 | Electron 体积/内存（对照 Tauri 3-5 倍差距） | 中 | asar 拆分/差分升级，对标 ~200MB；记入技术债（TECH-02） |
| R7 | 巨型竞品挤压（WorkBuddy 免费+生态+两天一版） | 高 | 差异化=私有化模型自由+集成中立；不打 SaaS 正面战 |
| R8 | 团队产能未知（小团队 vs 大投入） | 高 | 竖切优先：MVP=「一个会话+工作目录+文档生成+安全」最小闭环，其余按需求清单分层 |
| R9 | 自动生成代码插件的安全面（P2） | 中 | 三层防线强制（vm 沙箱+白名单代理+真人审批），沙箱安全评审通过才启用 |
