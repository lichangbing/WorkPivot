## 1. 产品概述

- **厂商与背景**：腾讯（腾讯云 / CodeBuddy 团队）推出的企业级 AI 智能体平台与智能工作台
- **产品定位**："一人指挥，全行业专家执行"——通过自然语言下达指令，AI Agent 自动完成任务交付，覆盖从策略到交付的全流程
- **目标客户**：需要效率提升的中小企业与团队；企业版面向有管控诉求的组织
- **发展状态**：据报道采用"人和 AI 混编开发"模式，小团队两天完成初始版本，上市后保持约 2 天一个版本的迭代节奏

## 2. 核心功能拆解

| 功能模块 | 具体能力 | 成熟度 | 备注（亮点/短板） |

| 多专家智能体 | 内置 100+ 行业专家智能体 | ✅ | 核心卖点："一人指挥，专家执行" |
| 多模型协同 | 腾讯混元、DeepSeek 等多模型混合调度 | ✅ | 模型层解耦，可按任务路由 |

| 桌面智能体 | 本地电脑规划并执行多模态复杂任务，多 Agent 并行 | ✅ | Agent 在端侧执行，可操作本地文件 |

## 3. 客户端与部署形态

- **客户端**：桌面端（主入口）+ Web + 微信/企业微信 + 小程序，全平台覆盖
- **部署方式**：个人/团队版免部署、安装即用（SaaS 为主）；企业版（WorkBuddy Enterprise）提供企业级管控
- **模型接入**：公有云大模型为主；企业版模型接入细节待补充

## 5. 架构与技术观察（推断，待验证）

- 桌面端承载 Agent 执行（可操作本地文件与多模态任务），云端负责模型调度与知识库
- "多专家多模型"暗示存在统一的 Agent 编排层与模型网关层
- 团队记忆/知识库面向组织级共享，需要租户级权限隔离设计

## 6. 对 WorkPivot 的启示

- **值得借鉴**：
  - "任务交付"而非"对话"作为产品核心心智
  - 多专家 Agent + 多模型调度的分层设计
  - 桌面端作为 Agent 执行载体的形态
- **应当规避**：
  - 与腾讯生态深度绑定（腾讯文档/网盘）——我们面向不同企业，需保持集成中立性
- **差异化机会**：
  - WorkPivot 主打**私有化部署**，可切入数据不出内网、有合规诉求的客户（WorkBuddy 以 SaaS 为主）
  - 面向"不同企业的智能化应用"，可强化面向企业定制/二次扩展的能力（Skills/插件机制）
