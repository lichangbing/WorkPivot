# 主界面布局规范（参考 ZCode 模式）

> **来源**：2026-09-06 用户验收反馈——"参考 ZCode 这个模式：左侧项目/插件/任务这些内容，左侧下方是用户的情况，中间最下部是模型选择、模式等内容"。本文为桌面主界面的布局规范与实现方案。
> **状态**：📝 规范定稿，待实施（tasks-m1 批次 2 · UI 重构 U1-U4）。
> **原则**：严格对齐 ZCode 桌面版的信息架构，不自由发挥；WorkPivot 特有能力（权限档位/记忆/成果区）映射到对应位置。

## 1. ZCode 布局拆解（参考基准）

```
┌────────────┬───────────────────────────────┬────────────┐
│ 左栏（窄）  │ 中栏（会话）                    │ 右栏（编辑器）│
│ ＋新建任务   │ 顶条: 标题|📁工作目录|分支|变更   │            │
│ 🔍搜索      │ ─────────────────────────────  │            │
│ ⚡自动化    │ 消息流（用户/助手/工具卡片）       │            │
│ 🧩插件市场  │ ─────────────────────────────  │            │
│ [分组|项目] │ ┌───────── 输入区 ─────────┐   │            │
│ ▸ 项目A     │ │ 提出后续修改要求…          │   │            │
│   ├对话(时间)│ │ ＋  完全访问▾  模型▾  ➤发送 │   │            │
│ ▸ 项目B     │ └──────────────────────────┘   │            │
│ ──────────  │                               │            │
│ 任务        │                               │            │
│ ──────────  │                               │            │
│ 👤用户 套餐⚙ │                               │            │
└────────────┴───────────────────────────────┴────────────┘
```

关键特征：
1. **左栏自上而下**：主操作按钮（新建任务）→ 高频功能入口（搜索/自动化/插件市场）→ 分组切换（项目）→ 项目树（展开即对话/任务列表，带相对时间）→ **底部用户区**（头像/ID/套餐/设置齿轮）；
2. **中栏最下部 = 输入区**：输入框 + 附件 + **权限模式选择** + **模型选择** + 发送——模型与模式在"手边"，不在远处菜单里；
3. **中栏顶部 = 会话上下文条**：标题、工作目录、分支、变更摘要；
4. 右栏为文件/编辑器（WorkPivot 对应为成果区）。

## 2. WorkPivot 逐区映射规范

### 2.1 左栏（自上而下）

| 区块 | 内容 | 对应能力/需求 | M1 状态 |
|------|------|--------------|---------|
| 主按钮 | **＋ 新建任务**（点击→选择：临时任务 或 项目下任务） | A02 | U1 实现选择流 |
| 功能入口 | 🔍 搜索（Ctrl+K 占位）/ ⚡ 自动化（F06）/ 🧩 技能市场（D01） | A05/F06/D01 | 占位入口，点击提示"批次 3" |
| 分组切换 | `[项目]` / `[任务]` 两个 tab：项目=两级树（现有）；任务=全部任务的平铺列表 | A02/F2 | U1 |
| 项目树 | 项目（📁，可收起）→ 任务（状态灯 + **相对时间**："刚刚/5 天"） | F1 | U1 补相对时间 |
| **底部用户区** | 头像 + 用户名 + 角色徽标（管理员/成员）+ ⚙ 设置 | J01/M1-04 | U2 |

### 2.2 底部用户区与设置面板（⚙）

- 用户区常驻：头像圆标（用户名首字）+ 用户名 + 角色徽标 + ⚙；
- ⚙ 打开**设置面板**（左栏内弹出，非独立页）：
  - 权限档位（四档切换，同 I02）
  - 记忆开关（E01 一键关闭）
  - 模型状态只读（当前激活供应商/模型；"去后台配置"链接——桌面端不配模型，F3）
  - 退出登录
- 管理后台入口（/admin）：仅管理员可见，置于设置面板内（不再放 header）。

### 2.3 中栏

- **顶部会话工具条**（替代现 header）：任务名 + 📁 工作目录 + 状态徽标（运行中/已中断…）+ ▶ 继续任务（中断时）+ 转写查看 + **变更摘要**（本次会话产出/修改文件数——M0 先显示文件计数，增删行数 M1 批次 3）；
- **消息流**：现状保留（用户气泡/助手 markdown/工具行折叠/授权卡/记忆卡/完成卡片）；
- **输入区（中栏最下部，对齐 ZCode）**：
  - 左：**＋ 附件**（文件选择 → 等效 @引用注入）与 `@` 补全提示（保留）；
  - 中：输入框（Enter 发送/Shift+Enter 换行）；
  - 右：**权限档位下拉**（四档，从 header 移入）→ **模型选择下拉**（激活供应商+模型，从 header 移入）→ 发送/停止按钮。

### 2.4 右栏

成果区维持现状（目录 + 版本链 + 转写查看入口）；文件预览列批次 3。

### 2.5 输入区附件与 @ 补全（2026-09-06 增补，用户指示）

1. **@ 补全弹窗**：输入框键入 `@` 时，上方弹出工作目录文件清单（来自 /files 接口），继续输入即过滤；↑↓ 选择、Enter 确认、Esc 关闭；选中后以 `@相对路径 ` 写回输入框（等效 @引用注入）。
2. **附件上传三入口**：粘贴（Ctrl+V 带文件）、拖拽文件到输入区、附件按钮选择——三者等价，均进入**待发送附件托盘**。
3. **附件托盘**（输入框上方展开）：多文件并列（卡片 w-40）；每卡：文件图标+文件名（截断）+大小+**上传进度条**；右上角 **×** 可移除（上传中移除=取消）；上传失败标红。
4. **上传业务逻辑**：POST /api/tasks/:id/attachments（裸体流+?name=，XHR onprogress 上报进度）；服务端写入任务工作目录 `attachments/`（basename 消毒防穿越，重名自动加序号）；发送消息时 attachments 名单内的文件内容自动注入模型上下文（等效 @引用），注入后文件仍保留在工作目录。
5. **交互态**：拖拽悬停时输入区高亮（虚线蓝框）；粘贴非文件内容走原文本粘贴逻辑。

## 3. 与现状（M0 实现）的差异清单

| # | 差异 | 类型 |
|---|------|------|
| 1 | 左栏缺主操作按钮组（新建/搜索/自动化/技能市场） | 新增 |
| 2 | 左栏缺分组 tab（项目/任务）——现为临时区+项目树混排 | 重排 |
| 3 | 任务列表缺相对时间（"刚刚/5 天"） | 新增 |
| 4 | 缺底部用户区（现用户信息在 header 右侧） | 移位 |
| 5 | 缺 ⚙ 设置面板（权限档位/记忆开关散在 header 与后端） | 新增 |
| 6 | 模型选择与权限档位在 header——需移到**输入区**（ZCode 位置） | 移位 |
| 7 | 顶条缺工作目录/状态徽标/变更摘要的整合呈现 | 补全 |
| 8 | 新建任务无统一入口流（现：分组行内联表单）——改为顶部主按钮→选择去向 | 重排 |

## 4. 实施方案（tasks-m1 批次 2 · UI 重构 U1-U4）

| ID | 任务 | 说明 |
|----|------|------|
| U1 | 左栏信息架构重构 | 顶部按钮组（新建任务/搜索占位/自动化占位/技能市场占位）+ 分组 tab（项目/任务）+ 项目树补相对时间 + 底部用户区 |
| U2 | ⚙ 设置面板 | 权限档位切换、记忆开关、模型状态只读+后台链接、退出登录——全部从 header 移入面板；后台入口仅管理员可见 |
| U3 | 输入区改造 | ＋附件（文件选择→@注入）、权限档位下拉、模型选择下拉（切换即时生效，C04 M0=全局激活范围）、发送/停止 |
| U4 | 顶部会话工具条 | 任务名/工作目录/状态徽标/继续任务/转写查看/文件变更计数 |

**不做（明确出界）**：多窗口/主题市场（需求池）；文件预览（批次 3）；i18n（已决策不做）；搜索全文索引（P2，先做标题过滤占位）。

## 5. 验收标准

1. 左栏自上而下 = 新建任务 / 搜索·自动化·技能市场入口 / 分组 tab / 项目树（相对时间）/ 底部用户区——与 ZCode 结构一致；
2. 模型选择与权限档位在**输入区**操作，切换即时生效（模型=下轮请求生效；档位=立即）；
3. ⚙ 设置面板含：权限档位、记忆开关、模型状态（只读）、后台入口（admin）、退出；
4. 桌面端无任何模型/用户配置入口（F3 不回退）；
5. 全部既有评测回归通过（UI 改动不影响 API 层）。
