# 企业身份接入通用设计与本地验收

日期：2026-10-19。用户确认尚无实际企业身份源，先完成通用设计与本地测试环境。本文件衔接统一计划IAM-01—06；不启用WorkPivot第三方登录，不迁移现有账号和私人资料，不将协议实验视作业务接入完成。

## 现有工程与本次交付

当前`AccountRepository`以`identity.users.id`为内部身份，密码及auth_version在credentials中，会话校验包含禁用/过期/撤销和版本；业务侧以owner_user_id与RLS隔离。数据库管理页目前主要提供创建/列表，账号生命周期仍需补充管理入口。现有用户/角色不能直接充当企业成员或部门模型；只增加一个第三方登录按钮会遗漏绑定、撤权与运行权限。

本次交付为详细设计、独立Keycloak容器、双realm合成用户、真实浏览器授权码/PKCE实验及负向检查。使用现有Playwright及Node.js密码学API验证实验输出，没有给生产添加自制OIDC验证器或新依赖。正式接入应选成熟OIDC客户端库，完成锁定版本和许可检查；企业微信保持独立适配器，不伪装成OIDC。

## 技术取舍

| 方案 | 用途与取舍 |
|---|---|
| Keycloak官方容器（采用，26.8.0固定版本） | 提供实际发现文档、签名密钥、登录表单、客户端校验和两个身份域；独立实验，不成为WorkPivot生产强制依赖 |
| 自制模拟IdP | 适合将来的错误响应、时钟及密钥轮换注入；不足以单独证明第三方兼容性，本轮不以模拟服务代替真实协议服务 |
| 真实企业微信/现有企业OIDC | 是最终验收目标；当前缺少应用模式、企业及回调条件，不猜测或录入生产配置 |

Keycloak使用官方镜像`quay.io/keycloak/keycloak:26.8.0`，start-dev仅用于本地实验。仅绑定127.0.0.1:40190，实验回调127.0.0.1:40191；不修改39986业务服务，不挂载业务文件、数据库或Docker socket。测试数据在临时容器文件系统，受保护导入文件留在被Git忽略的`local-runtime/iam-lab`。

## 身份、组织和权限模型（待实施）

| 对象 | 核心约束与管理动作 |
|---|---|
| 企业organizations | 稳定内部UUID、显示名称、状态、revision；平台管理员创建/停用，停用先撤销企业入口与授权，不删除私人资料 |
| 企业成员memberships | organization_id+user_id唯一；成员状态、来源、本地人工禁用标志、版本；外部同步不得覆盖人工停用；退出一个企业不删除其他企业身份 |
| 身份源identity_providers | 企业、类型、issuer或企业/应用范围、client_id、加密凭据、精确回调、启用状态与版本；显式测试后启用，修改issuer需新建身份源，不能将旧绑定转指另一家 |
| 外部映射external_identities | OIDC以身份源范围内的精确issuer+subject标识；企业微信以可信平台/企业/应用范围+外部用户ID标识；关联内部user_id，不按邮箱、姓名或手机号自动合并 |
| 登录事务login_transactions | 随机state摘要、浏览器绑定摘要、PKCE、nonce、身份源版本、目的（登录/绑定）、当前内部用户、固定回调、到期/消费状态；不允许客户端直接传subject完成绑定 |
| 身份审计identity_events | 操作人、企业/身份源/目标内部ID、动作、结果、原因分类、时间/关联ID；不可变，不存code、access/refresh/id_token、密码或完整claims |

映射唯一约束、事务和行锁共同防止重复绑定/并发建号。当前资料归属不变，首次外部登录不得因同邮箱覆盖本地账号。首版建议管理员预配置企业成员，未知身份返回“等待授权”；自动即时建号/JIT策略需在真实接入时明确，不隐式开启。企业管理员角色与现有平台管理员分离，外部管理员claim不自动提升本地权限。

成员关系不直接赋予共享资料权限。IAM-05发布指定文件版本时再生成独立共享授权，源版本、片段、向量、下载与模型引用统一判断。现有私人聊天、记忆和专家不随成员加入公开。

## 登录与绑定流程（待实施）

1. 用户选择已启用的身份源；服务端创建5分钟有界登录事务，state/nonce/PKCE均随机。使用HttpOnly、Secure、SameSite=Lax浏览器绑定cookie；returnTo只允许站内枚举路径。正式环境HTTPS，不能把实验HTTP例外带入业务配置。
2. 服务端从已批准issuer发现端点，验证discovery issuer完全匹配；端点主机和内网访问由专门身份源配置批准，不从请求参数或网页指令获得。发现/JWKS请求限制大小、超时、跳转及目标，不能变成SSRF入口。
3. 使用Authorization Code+PKCE S256，精确登记redirect_uri、scope最小化openid/profile，email只作展示。首版不启用implicit、密码grant、动态客户端注册或任意OAuth用户信息接口。
4. 回调先验证浏览器绑定、state存在/到期/未消费、身份源版本和启用状态；原子消费事务后服务端交换code。拒绝重复参数和重复回调，失败只允许重新发起，不复用未知结果的code。
5. 成熟库校验签名算法白名单、JWKS、iss、aud/azp、exp/iat、nonce及协议要求；未知kid只允许有界刷新，不降级为不验签。用户信息接口若调用，sub必须与ID Token一致。
6. 已绑定且有效成员才签发WorkPivot自身会话，外部token不作为本地API凭据；本地会话记录身份源/企业和权限版本。首版不申请offline_access，不长期保存refresh token，原始令牌完成用途后丢弃。
7. 绑定已有本地账号必须从已登录会话发起，并重新验证当前密码或已有可信认证；外部认证完成后展示身份源/企业及脱敏身份，明确确认后绑定。回调中的user_id不能决定绑定目标；冲突拒绝，不自动迁移。
8. 解绑需重新认证并确认仍存在另一条有效登录方式；禁止删除最后应急管理员的恢复入口。解绑、身份源停用、成员退出会撤销相关会话及授权，保留业务资料与审计。

企业微信适配器必须先区分自建应用/第三方服务商，服务端获取可信外部身份并核对企业应用范围，复用上述事务、绑定和会话流程；不能用前端提供的corpId/userId替代官方返回。纯OAuth没有标准ID Token时需明确受信用户信息接口，首版不做“任意OAuth自动兼容”。

## 管理页面与审计（随功能交付）

- 平台管理“企业与成员”：企业筛选、启停、成员列表、状态/来源、人工禁用、版本冲突、影响预览和确认；不展示成员私人内容。
- 企业管理“身份源”：配置/测试/启停、精确回调展示、密钥只替换不回显、最近测试状态、失败分类；外部健康测试不等于已经建立成员权限。
- 个人“登录方式”：显示当前绑定、上次使用、绑定/解绑、影响说明和二次认证；不显示原始subject之外的完整claims或令牌。
- “同步与撤权”：最近成功/失败、授权范围变化、待核对差异、重试及对账；供应商失败或空结果不能触发全员删除。同步来源更新与本地人工禁用分栏显示。
- “身份审计”：登录/绑定/解绑、配置/凭据替换、成员启停、同步和撤权记录，按企业/身份源/结果筛选导出；复用请求安全审计记录前置拒绝，业务成功与变更同事务保存。导出、保留和清理需要单独明确范围，不能直接沿用请求日志的清理函数删除身份审计。

## 撤权、故障和恢复

正式阶段设计目标：服务端收到明确撤权后立即阻止新会话/读取，活动运行在下一授权检查点且目标不超过30秒失效；实际外部离职事件到达时间取决于供应商通知及对账周期，不能承诺整个链路即时。

角色/成员权限版本参与请求、下载、SSE重连、RAG、背景计划、模型上下文及成果发布校验。停用企业身份源只撤销其关联会话，不自动禁用个人本地账号；平台禁用用户则撤销全部入口。同步不能重新启用本地禁用用户。第三方故障时保留受控本地应急管理，不开放无验证登录。

联合备份保存映射、组织和审计，秘密依既有加密主密钥边界保存；恢复时清除未完成登录事务、撤销外部会话、暂停身份入口并重新核对配置/组织，不恢复旧code或自动放大权限。回退可以停用新增入口，不得靠关闭RLS或将私人数据公开实现兼容。

## 统一实施次序与验收矩阵

| 阶段 | 交付 | 退出标准 |

| IAM-01 | 组织/成员/外部映射与原子绑定基础、对应管理及审计 | 内部ID/历史数据不变；相同subject跨issuer隔离；并发绑定唯一；无可信证明不绑定 |
| IAM-02/03 | 一个真实企业微信应用和一个真实OIDC源 | 接入信息齐备、回调/密钥/二次认证、首登策略确认；成功与失败回调完整验收 |
| IAM-04 | 组织同步和撤权闭环 | 漏事件、重放、范围缩小、同步故障与人工禁用优先级通过 |

## 本地操作

在`code`目录执行：

```bash
docker pull quay.io/keycloak/keycloak:26.8.0
pnpm iam:lab start
pnpm iam:lab status
pnpm eval:iam-lab
pnpm iam:lab stop
```

管理入口为`http://127.0.0.1:40190/admin/`，两个issuer为`http://127.0.0.1:40190/realms/wp-lab-a`与`wp-lab-b`。端口40191仅在验收接收器运行期间监听，不是业务回调端口。测试会用真实浏览器完成登录，不需要把合成密码发给模型。

合成管理员/用户密码及客户端secret只写入`local-runtime/iam-lab/credentials.json`（0600），父目录0700；启动输出只显示路径。realm导入文件和env文件也属于测试凭据，不能入库或分享。重复start等待就绪而不覆盖凭据；同名但没有专用标记的容器拒绝操作。stop只删除本实验容器，不操作其他容器，保留本地凭据文件供再次启动；其临时数据库随容器移除，重启会重新导入合成账号并生成新的签名密钥，旧token不能视为持续有效。

机器需Docker、已安装的工程依赖及Chrome；验收可用`WORKPIVOT_TEST_CHROME`指定已有浏览器路径。Keycloak实验资源限制为2 CPU/1GiB内存，数据tmpfs 256MiB；这不是生产容量配置。40190/40191冲突时明确失败，不抢占已有服务。本实验不使用真实业务用户、不挂载业务数据库/文件卷，仍需按本机敏感测试配置保管凭据文件。

Keycloak单实例用户主键跨realm唯一，两个样本采用不同内部ID、相同用户名和邮箱；对同一有效签名令牌更换预期issuer必须拒绝。相同subject在独立issuer下的业务映射唯一性仍属IAM-01数据库验收，不能以本地协议实验提前勾选。
