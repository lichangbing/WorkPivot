# 专家智能体与经验管理

状态：2026-09-16，规划完成，尚未实现。基线为公网 preview.38 / PostgreSQL v24。本文不代表已发布功能，也不指定下一次数据库迁移编号。

## 1. 产品目标与名称

让用户选择一个长期使用的专业助手；助手每次开始工作时知道自己的职责、应遵循的方法、用户确认过的经验，以及当前任务进度。持续改进发生在配置、记忆和技能层，不宣称训练或修改基础模型。

用户入口称“专家”，整体能力称“专家智能体”。内部包括：

| 概念 | 作用 | 示例 |
|---|---|---|
| 专家设定 | 专业身份、职责、判断原则、输出要求 | 周期行业研究员，区分事实与推断 |
| 启动规则 | 每次开始工作的固定检查顺序 | 读取项目标准、确认资料版本、检查未完成事项 |
| 专家经验 | 经用户确认的可复用方法、纠错经验及适用条件 | 比较库存前核对统计范围与时间口径 |
| 专家技能 | 关联已发布的 Skill 与需要的工具能力 | 财务分析、研报生成、表格处理 |
| 任务恢复 | 从该任务检查点和后续事件恢复进度 | 已核对收入，现金流仍待检查 |

现有个人、项目、任务三层记忆继续保持原定义。专家经验单独管理，不把现有三个 scope 直接改成四层。个人偏好归个人记忆，项目事实归项目记忆，当前进度归任务状态；只有跨任务可复用的方法进入专家经验。

## 2. 首版边界

纳入当前单用户版本的新增工作包 K11；完成 K11-01 至 K11-05 后进入已有 RC 验收。多用户调度和项目协同仍为第二、第三阶段，Office/PDF/RAG扩展继续暂缓。

- 后台发布专家模板；用户选择并建立自己的专家实例，也可从空白创建。普通任务可继续使用默认助手，不强制选专家。
- 每个项目可设默认专家，每个任务只有一个当前专家；任务可覆盖项目默认。项目默认只影响之后新建的任务，不批量改动已有任务。
- 首批提供“通用研究员”模板，复用现有周期型、成长型、中小市值型项目记忆模板。行业分类先作为项目判断框架，不重复做三套相似专家。财务、项目负责人等模板后续按实际验收补充。
- 支持设定与启动规则编辑、经验手动增删改/锁定、自动经验候选与用户确认、Skill关联和任务启动加载。
- 首版不做专家团队编排、自动委派、多专家并行、自动发布Skill、跨用户经验聚合或专家市场交易。

## 3. 使用与管理界面

沿用现有黑白主题、图标和三栏布局，不整体重做界面。

用户设置增加“专家”，展示“我的专家”和“可用模板”。详情分“设定、经验、技能”；启动规则放在设定内。经验展示内容、适用条件、来源、版本、锁定状态及加载/自动整理开关。支持新增、修改、删除和待确认建议，不把所有内容塞入聊天输入区。

在任务标题附近提供紧凑的专家选择入口；右侧现有技能与MCP区域标明当前专家。新任务继承项目默认，可改为其他专家或默认助手。运行中禁止切换专家，待授权状态同样禁止；空闲时切换会明确说明下轮按新专家工作。

后台 /admin 增加“专家模板”菜单，管理草稿、版本、发布、停用及Skill要求。管理员只能编辑公共模板，不能查看用户私有专家经验。模板升级不静默覆盖用户副本，用户查看差异后采用；首版采用完整模板版本替换并保留旧版本，不自动合并自定义改动。

模板停用后不能新建实例或升级；用户已有副本保留。Skill/MCP撤权、禁用始终按实际权限即时生效，不因专家模板仍引用它而绕过限制。

## 4. 启动与任务恢复

1. 校验用户、任务、专家实例归属与状态。解析任务显式选择；无选择时使用默认助手。
2. 固定本轮专家版本、关联Skill版本、经验版本及用户知识epoch，确保执行中不混入新配置。
3. 加载受限长度的专家设定与启动规则，读取三层记忆开关、专家经验加载开关。
4. 根据任务主题读取有限经验概览，按需读取正文。首版使用关键词与受限概览，不依赖embedding或向量服务，不默认注入所有经验。
5. 加载用户已确认的任务摘要、后续事件、执行状态与产物版本，核对待办。近期五轮和历史滚动展示保持现有行为。
6. 将上述内容纳入现有模型上下文预算后开始执行；不足时走摘要确认或明确报错，不能悄悄截断关键规则。

平台权限与执行边界优先；专家设定不能扩大工具权限。经验、资料和历史摘要均是参考内容，不提升为系统命令。用户本轮明确更正优先于经验；项目具体标准与通用经验冲突时标明冲突并按具体要求处理，不能合成矛盾结论。

恢复只重建上下文，不自动重跑命令、外部调用或结果不确定的执行。冷启动、服务重启、模型切换都从服务端持久状态读取，不依赖客户端保存工作资料。

切换专家不删除原对话，但旧专家设定及经验不再自动加载。若现有压缩摘要混入旧专家经验，先让该检查点失效并基于可用来源重新整理，经用户确认后使用；不能把旧专家的规则偷偷带入新专家。

## 5. 经验形成与确认

在一轮正常结束且出现明确纠错、用户明确要求记住方法，或有工具结果支持的可复用流程时，后台受限作业提出候选。失败/取消轮次不自动认定为成功经验；错误及修复只有在修复得到验证时才能形成相应方法建议。

初始每轮最多3条候选；记录来源任务/轮次、证据、适用范围、建议新增/修改/合并及目标版本。复用现有记忆整理的排队、租约、去重和确认设计，但独立区分经验候选，避免同一句用户偏好同时写入个人记忆和专家经验。

用户查看“为什么建议记住”、原经验与差异，可以编辑后确认、拒绝。自动执行模式不等于允许保存经验；未经确认的经验不参与后续任务。锁定禁止自动修改/合并该条；关闭自动整理不删除已保存经验；关闭加载后停止使用该专家经验。

经验必须携带适用条件，单次案例不自动升级为普遍规律。首版允许一条有明确用户指令的经验候选，不以固定次数代替用户判断。经验成熟后可由用户发起“整理为Skill草稿”，此转换列入后续增强，仍走现有校验、审核和发布流程。

## 6. PostgreSQL 存储与权限

以下为原始设计模型。RC.1 实际将模板/私人实例统一存入 experts（public 区分），版本与 Skill 绑定保存在 JSONB；经验历史保存在 history，来源为 source_runs/source_files 数组，合并继承完整来源集合。任务关联和私有表强制 RLS，schema v25 为实施依据：

| 对象 | 关键字段与职责 |
|---|---|
| expert_templates / expert_template_versions | 后台公共模板、发布指针、停用状态；不可变发布版本 |
| user_experts / user_expert_versions | owner_user_id、名称、模板来源版本、自定义设定、启动规则、当前修订及开关 |
| expert_skill_bindings | 专家版本关联Skill名称与发布版本要求；不复制密钥，不自动加载或授权 |
| expert_experiences / expert_experience_versions | 所属用户和专家、正文、适用条件、revision、锁定和有效状态 |
| expert_experience_sources | 经验版本与任务、运行、文件版本、被合并经验的完整来源关联 |
| expert_experience_jobs / suggestions | 来源epoch、租约、重试、候选状态、目标revision及确认最终稿 |
| projects / tasks / task_runs 扩展 | 项目默认专家、任务专家选择、本轮版本快照与已使用经验版本引用 |

所有私有表强制RLS，管理员业务接口也不能绕过。关联关系必须校验同一owner，防止伪造专家、任务或经验ID。模板只是可读公共资料，不能通过模板关联查询用户副本、来源或使用者名单。

使用revision做并发修改控制，确认建议需匹配来源epoch与目标版本；多端重复确认幂等，冲突决定返回已处理。SSE只在归属校验后发送当前任务的经验候选变化通知；通知不携带其他用户内容。

## 7. 删除、失效与可追溯

- 手动删除经验：立即停止检索/注入；清除其历史正文、未决修改/合并稿及派生摘要中的有效引用。只保留无正文的必要删除审计。
- 修改、删除、关闭加载或切换专家：更新知识epoch，使使用旧经验的活动上下文与候选失效；运行中不得继续使用已撤销内容，沿用现有保守停止/重发机制。
- 删除任务、项目或来源文件：同事务让相关派生经验、候选及摘要失效并清除受影响正文，不能只删原文却保留派生记忆。无法安全拆分的合并经验整条失效，用户可重新手动建立。
- 手动创建且无来源依赖的独立经验不因任意任务删除而被清除。由候选编辑确认的经验仍保留来源关系，不能用编辑操作切断删除传播。
- 删除私有专家：清除经验及候选，关联项目/任务退回默认助手，历史聊天保留但旧专家上下文失效；有活动任务时拒绝删除并提示先停止。
- 备份遵循独立保留策略；正常删除不承诺立即抹除历史备份。恢复演练必须覆盖删除记录重放，防止已遗忘数据恢复后重新进入检索。

这部分是首版核心要求，不复用现有不完整的文件派生记忆删除机制后就声称完成。经验抽取与确认上线前必须补齐其来源链及级联失效测试。

| K11-02 | 专家选择、启动加载、Skill关联、运行版本快照与任务恢复 | K11-01 | 同一专家跨任务加载正确；项目默认只影响新任务；运行中不能切换；恢复不重执行 | 已实现并通过本地验收 |
| K11-03 | 私有经验CRUD、检索、开关、锁定、版本、来源与删除传播 | K11-01/02 | 只加载当前专家的有效经验；切换/删除后旧内容不回流；上下文受预算限制 | 已实现并通过本地验收 |
| K11-04 | 自动经验整理、去重/纠错/合并、确认UI及多端通知 | K11-03 | 候选有证据；未确认不生效；多端确认一次；关闭与锁定有效；来源失效拒绝迟到结果 | 已实现并通过本地验收 |
| K11-05 | 真实模型与浏览器验收、WSL部署、文档及RC收尾 | K11-01至04 | 用户纠正→候选→编辑确认→新任务使用→删除后不再使用；恢复与备份验收 | 本地通过；公网 SSH 不通，远端发布待执行 |

## 2026-09-16 RC.1 实施结果

当前实现与验收以 [RC.1 发布说明](../../../releases/v0.3.0-rc.1/RELEASE-NOTES.md) 为准。自动抽取仅处理用户明确提出的方法；最近十条经验直接加载，其余按关键词工具检索。恢复演练覆盖当前一致性快照及旧备份结合较新可信清单的删除回放。离线恢复工具会撤销旧上下文，清理已遗忘内容；缺少较新清单时不能推断未记录删除，禁止未经核验直接上线。
