## 1. 目标与范围

本方案补齐单用户版从“核心办公流程可用”到“可以长期保存个人工作资料并稳定升级”的差距。范围包含以下八项：

1. PostgreSQL、文件和配置的联合备份与恢复；
2. 基于 pgvector 的关键词与向量混合知识检索；
3. OCR、表格结构和解析状态等文件处理增强；
4. 文件、成果、知识和记忆的统一版本、回收站、恢复与彻底删除；
5. 模型容量感知、超长历史分批压缩和来源追踪；
6. Token、费用、预算提醒和模型连通性；
7. API Key、会话、个人数据导出/清空及 Skill/MCP 数据访问说明；
8. 安装、升级、迁移、回退和故障验收。

2026-10-16 最新优先级：用户将“对话搭建私人 Skill → 校验/试运行 → 弹窗确认 → 自动发布并加载”提升为最高优先级，基础定时任务紧随其后；两者加入当前单用户版，先于原八项的未完成任务执行。默认仅创建者可见，必须由用户在弹窗确认后才能加载。详见[对话 Skill 与基础定时任务](对话搭建Skill与基础定时任务.md)。

完整多用户公平调度、项目成员协作、组织架构和 WorkPivot 自身 SSO 不在当前单用户版范围内。

2026-10-16 新增下一版本：用户已确认在当前单用户版（新增 SK/ST 及原八项）完成之后实施后台全容器部署和定时网页采集增强；基础持久计划/队列已提前到 ST，下一版本复用并补齐公平性与资源治理；首版包含私人网站登录、人工接管，以及管理员批准的内网 OA/ERP/报表访问。硬件暂不确定。此处的网站登录/SSO 不等于建设 WorkPivot 企业统一登录。详细设计见[容器部署与定时采集](容器部署与定时采集调度方案.md)。下一版本范围已确认，本轮仅设计并入计划，尚未开发。

## 2. 总体原则

- PostgreSQL 保存业务记录，文件存储保存原件与成果；备份、恢复、删除必须同时覆盖二者。
- 向量和全文索引是可重建的派生数据，不作为唯一事实来源。
- 恢复必须在停止写入的环境执行，先验证备份，再创建恢复前快照；失败不得覆盖当前可用数据。
- 删除默认进入有保留期的逻辑回收站；彻底删除需要再次确认，并同步失效检索、记忆、摘要和运行上下文。
- Token 与费用记录服务于可见性和提醒。单用户版默认不硬性阻断任务，除非用户明确启用预算上限。
- 明文凭据不进入日志、备份清单和个人数据导出。联合数据库转储包含加密模型配置及密码哈希，按敏感备份保管；服务器加密主密钥独立保存，不打入备份包。

## 4. 统一技术设计

### 最高优先级：对话 Skill 与基础定时任务

先补私人技能隔离，再接对话草稿与试运行；用户弹窗确认后原子发布并加载，下一轮生效。紧随实现对话计划草稿、时间预览、独立弹窗确认、持久调度和后台离线执行。技能确认不等于定时运行授权，计划固定技能发布版本。详细流程、数据兼容及验收见[SK/ST设计](对话搭建Skill与基础定时任务.md)。联网、网页登录和全容器执行依然属于下一版本。

2026-10-16 补充确认：参考 Hermes，将“描述需求/沉淀已验证做法 → 私人草稿 → 校验试运行 → 弹窗确认 → 持久保存 → 下一轮按需读取 → 修订再确认 → 独立设置计划”纳入同一 SK/ST 交付。SK-01 同时包含数据库文件树和最小软删除/恢复；SK-02 包含任务成功后的沉淀建议与同主题修订；SK-04/05 验证渐进读取、不可变版本、修订差异、回退及关联计划保护。临时执行容器清理不丢持久技能，ZIP 仅供导入导出。完整回收站与彻底删除沿用原第4项，不另排重复任务；后台策展、自动合并与周期提醒不加入本轮。现有两周 SK、一周 ST 估算不变，实施复核若超出统一调整主表，不能省略上述验收以维持日期。

### 数据安全与生命周期

**联合备份包**由 `manifest.json`、PostgreSQL 自定义格式转储和文件树组成。清单记录格式版本、应用 schema 版本、创建时间、文件数量、字节数和每个载荷的 SHA-256。创建时先写临时目录，全部校验后原子发布。`verify` 可离线检查完整性。

恢复流程为：停止写入 → 校验备份 → 生成 before-restore 备份并捕获当前遗忘清单 → 单事务恢复到空数据库 → 校验 schema/权限/文件引用 → 撤销旧会话及运行状态 → 回放遗忘规则 → 发布新文件目录 → 人工核对后切换配置。CLI 当前要求恢复前源仍可访问，不覆盖现有服务；数据源完全损毁的 CLI 模式另待补充。

统一版本模型保留现有 `documents/document_versions`，增加逻辑删除、回收站列表和恢复动作。知识分片、记忆来源、上下文摘要按来源有效性统一失效。永久删除在保留期之后清除数据库记录和磁盘对象。

验收：备份→独立空环境恢复→文件逐项哈希一致→登录、任务、记忆和成果可用；备份中断不产生可见成品；删除后检索为零，恢复后重新可用。

### 知识与文件理解

为每个 embedding 模型建立独立 `embedding_space`，分片向量记录模型、维度和版本。查询先执行权限和有效版本过滤，再合并全文排名与向量距离；回答引用文件名、版本及页码/工作表等位置。模型变化使用新空间重建，完成后原子切换。

OCR 作为隔离解析作业的可选步骤，只处理无可提取文本的 PDF 或图片；保留 OCR 引擎、语言、置信度和页码。Excel解析保存公式文本、缓存值和数据类型；03C已实现并验证隔离容器内受控重算，支持范围见文末，不代表任意公式均可计算。解析状态显示排队、处理中、完成、部分完成、失败和重试原因。

验收：固定中文问答集记录关键词、向量和混合检索的命中率；跨用户与已删除来源召回必须为零；扫描 PDF 可检索并定位页码；Excel 公式限制明确展示。

### 文档能力与 Office Skill 改造（2026-10-17 纳入计划）

用户确认将 WorkBuddy 研究启发形成的改造方案记录到统一开发计划。本次只更新计划，尚未实施。研究依据见[Office处理开发参考](Office处理开发参考-WorkBuddy分析-20261017.md)，竞品结果不代表 WorkPivot 已实现。

**职责划分**：智能体理解需求、选用流程和工具、组织执行与解释结果；Office Skill 承载工作流程、模板、业务规则、脚本示例和验收要求；文档工具提供有明确参数的读取、定位、修改、生成和检查接口；共用底层负责解析、OCR、转换、读写和重算；知识库消费解析结果，再做分块、向量化、检索和引用。基础文档识别属于智能体可调用的通用能力，不归属于知识库或 Office Skill 独占。

在现有 `document-processing`、文件工具、知识检索和隔离执行机制上整理共用能力，不另建重复解析服务或文件版本系统。同一文件版本可复用解析结果，但必须按调用者重新校验权限、删除和版本有效性。结果包含正文/表格/位置、文件版本、状态、读取范围、截断、OCR来源及不支持内容；解析配置或引擎版本变化时不能误用旧结果。

三条流程分别实现和验收：

- 读取：直接调用文档工具，按需分页、检索或触发 OCR，不要求先加载 Office Skill。
- 修改：读取结构 → 定位对象 → 修改副本 → 校验 → 发布新版本；不默认提取内容后重建整份文件。结构变动后重新定位，版本冲突停止发布。
- 新建：参考 Skill 和模板 → 隔离执行生成脚本 → 校验 → 发布成果。

保留 `load_skill` 与 `execute_skill`：加载只读取指引，复杂业务仍允许脚本执行；加载不增加文件或网络权限。通用解析、转换和重算实现从技能重复逻辑中整理到共用底层，工具和执行容器按需复用。既有私人技能、不可变发布版本、弹窗确认和定时任务固定版本规则继续有效，不能静默改写已发布技能。

按场景补齐必要的结构化接口：读取表格区域、修改单元格、查找替换文字、基于模板生成文件。接口名称和具体依赖在实施时核对代码与官方资料后确定；不预先引入一整套编辑器或通用平台。所有输入使用授权文件版本，由后端映射容器路径；复用现有成果批次发布、取消与版本冲突处理。

**验收与发布**：分别记录执行、保存、可重新打开、目标内容核对、公式写入/重算、修改范围、结构和视觉检查状态。未执行视觉检查不得宣称保真；重算超时或不支持公式明确返回，旧缓存不冒充本次结果。必要检查失败、取消或版本冲突时不发布半成品，保留原件和已有可用版本。

统一执行顺序为 SU-R2-03A → 03B → 03C，再进入 SU-R3；03 是汇总项，不重复计工。03C 内先补 OCR、重算和复杂格式检查，再扩展 PPT 并独立验收。Word/Excel 以读取、新建、局部修改六类真实样本验收，增加跨用户、删除失效、分页截断、版本冲突、取消和失败不发布测试；沿用现有 Skill/定时执行场景做兼容回归。

#### 验收样本与失败规则

1. Word三类场景：中文标题/正文/表格生成；长文分页读取；跨文本片段替换和表格修改。检查目标文字、原件哈希、无关内容及承诺样式；含图片、页眉页脚、批注的复杂样本用于界定支持边界。
2. Excel三类场景：多工作表与合并单元格读取；生成真实公式；修改输入后重算。分别核对公式字符串、缓存、业务预期与实际收到的需求；错误公式、超时、外链及大表截断有明确结果。
3. PDF包括纯文字、扫描、混合页、旋转及低质量页；页码和来源可追溯，识别不到内容不能返回“成功且完整”。
4. PPT包括中文、图片、表格、长文本及溢出；检查生成、读取、局部修改，并核对未修改页。渲染不可用记录为未完成视觉验收。
5. 共用失败矩阵：越权、源版本删除、发布冲突、Worker中断、取消、依赖/字体缺失、解析/重算超时、产物缺失。必要检查失败不发布；可恢复失败给出原因，沿用现有队列和重试机制，不另建调度器。
6. 交付记录逐项标明“代码实现/自动测试/真实模型/浏览器/已部署”。工具外层completed或进程退出码不能替代内部处理状态和文件读回；也不能把竞品通过记录记为本项目通过。

本轮不包含完整在线Office编辑器、实时协同、宏执行、任意复杂格式完全保真或专有引擎复刻。若关键修改场景必须引入新的编辑平台，先提交技术选型与范围影响供用户确认；普通工具参数、文件组织和已确认范围内的修复自行推进。所有新增代码注释和说明统一中文。

### 上下文、用量与安全

模型配置保存上下文容量、输入/输出单价和币种。每次供应商响应记录 provider、model、输入 Token、输出 Token、估算方式和费用；供应商未返回用量时标记估算，不能伪装成精确值。提供任务、日、月汇总和预算提醒。

长历史继续使用完整轮次分批压缩，并增加摘要事实到来源事件的映射。预算优先采用供应商用量和模型配置；没有 tokenizer 时继续使用保守估算并在界面标注。

安全补强包括：密钥替换/撤销、日志脱敏检查、登录失败限制、会话列表与撤销、个人数据导出、清空流程以及 Skill/MCP 的可访问数据说明。导出包默认不包含 API Key、密码哈希和服务器内部密钥。

验收：用量汇总与供应商返回一致；估算与精确值明确区分；预算提醒只触发一次且不丢任务；撤销会话后下一次请求失效；导出包无密钥；清空后业务数据和派生索引均不可访问。

### 发布与故障验收

固定安装和升级入口：环境预检、数据库迁移、配置备份、滚动或停机升级、健康检查、失败回退。迁移只前进，回退通过恢复升级前备份完成。发布物记录代码版本、schema 版本和兼容范围。
