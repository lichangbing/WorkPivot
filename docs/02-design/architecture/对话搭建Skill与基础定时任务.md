# 对话搭建 Skill 与基础定时任务

日期：2026-10-16；实施更新：2026-10-17。状态：SK-01—05 已实现并完成本地闭环验收，未部署；ST 仍为已确认设计、待开发。优先级与排期统一见[主计划](单用户正式发布补强方案.md)，不单独维护第二份排期。

## 1. 用户已确认

1. 对话搭建 Skill 提升到最高优先级，排在现有八项补强的未完成任务之前。
2. 生成完成后必须弹出应用内窗口，经用户明确确认才能加载；不是仅展示聊天卡片，也不能把继续聊天、关闭窗口或自动执行模式当成同意。
3. 默认仅创建者可见和使用，公共共享另走发布流程。
4. 基础定时任务紧跟 Skill 提前做；完整联网抓取、登录接管和容器调度仍在下一版本。
5. 用户此前确认的私人网页登录、人工接管和受控内网访问范围不变，但不是本次基础定时任务的已具备能力。

## 2. 用户流程

### 对话搭建技能

用户可以说“把这次核对 Excel、生成 Word 的做法保存为技能”，也可以从零描述“做一个每次按指定格式整理销售报表的技能”。Agent 只读取用户指定对话/附件，生成 SKILL.md、必要脚本、资源引用及验证用例草稿。先校验格式、路径、依赖和边界，再执行必要的隔离试运行。

生成结束显示“查看技能草稿”入口，并弹出确认窗口。窗口包含用途、触发场景、输入输出、文件清单、脚本/说明预览、访问范围、校验及试运行结果；修改现有技能时展示差异和将替代的版本。

按钮为“保存并启用”“仅保存草稿”“继续修改”“取消”。只有“保存并启用”会在事务中发布私人版本并加入当前用户已加载列表。失败不出现半发布或半加载状态。用户可通过列表重新打开未决窗口，刷新后恢复草稿及确认状态。

加载在下一轮模型请求生效，不改变已启动运行的技能快照，也不自动重发刚才的用户消息。模型收到的是实际启用结果，不能仅根据草稿文本宣称已加载。旧版本继续保留，支持后续停用和回退。

### 从技能设置定时任务

用户可以继续说“每天上午九点运行这个技能，处理这个项目里的最新销售表，生成日报”。系统先解析结构化草案，不立即创建活动计划。缺少时区、资料选择规则、目标项目或执行内容时，只补问实际缺失项；一般使用账号时区和当前项目，但都在窗口明确展示。

弹出计划确认窗口，展示自然语言时间、时区、接下来三次触发、绑定的技能版本、输入选择规则、输出位置、运行限制、补跑策略及站内提醒规则。按钮为“确认并启用”“保存为停用计划”“修改”“取消”。Skill 确认不等于同意定时运行；两者分别记录决定。尚未启用的 Skill 可以先准备计划草稿，但只有 Skill 完成确认后才能启用计划。

示例交互：

> 用户：把这次报表处理做成技能，并设置工作日早上九点自动运行。
>
> 系统：生成私人技能草稿并校验 → 弹窗确认保存并启用 → 展示工作日 09:00、Asia/Shanghai、接下来三次触发和文件选择规则 → 弹窗确认定时计划。

如果用户只说“工作日”，首版按周一至周五解释并明确显示“不含法定节假日调休判断”，不宣称已接入中国节假日日历。一次性时间、每日、每周和固定间隔均支持；高级 cron 使用已验证的成熟解析库。定时计划不依赖用户浏览器在线。

### 完整闭环与各步交付

2026-10-16 用户确认将参考 Hermes 的流程及保存、加载、改进和保护机制纳入开发计划。下表细化已有 SK/ST 任务，不另开一套排期；SK 已完成本地实现，ST 仍待开发，详见[实施与验收记录](../../03-project/skill-build-closeout-20261017.md)。

| 步骤 | 用户与系统行为 | 留存内容及失败处理 | 任务 |
|---|---|---|---|
| 1. 描述或沉淀方法 | 从零描述需求，或指定已完成任务中的有效做法；仅补问缺失的输入、输出与处理规则 | 记录指定来源及访问范围；任务失败时不把未验证做法写成成功经验 | SK-02 |
| 2. 生成私人草稿 | 生成用途、触发条件、输入输出、操作步骤、注意事项、验证方法及必要脚本/资源 | 持久草稿和修订；排除密钥和未经选择的业务样本；同主题已有技能优先提示修改 | SK-01/02 |
| 3. 校验与试运行 | 检查结构、引用、权限和依赖；有脚本时用代表样本隔离执行，按报告有界修复 | 报告绑定内容哈希；缺执行能力或验证失败时保留草稿并说明原因 | SK-03 |
| 4. 用户弹窗确认 | 展示文件、权限、样例成果及版本差异；选择保存并启用、仅草稿、修改或取消 | 确认绑定修订；未确认不得发布加载；重复提交只产生同一版本 | SK-04 |
| 5. 保存并按需使用 | 原子保存私人发布版本并启用；下一轮先发现名称/说明，需要时读取正文和具体资源 | 运行固定 release_id；当前在途运行不换版；不得把所有脚本和参考资料塞入每轮提示 | SK-04/05 |
| 6. 使用后改进 | 根据用户纠正或明确失败证据提出修订，展示新旧差异、重新验证和弹窗确认 | 旧版仍有效，新草稿不覆盖旧版；可回退；不得静默修改正在执行的版本 | SK-02至05 |
| 7. 独立设置计划 | 对话提出时间和输入规则，预览未来三次触发，另弹窗确认后后台执行 | 固定技能版本及输入规则；用户离线仍可运行；技能升级不自动变更计划授权 | ST-01至04 |
| 8. 停用、删除与恢复 | 可停用技能，删除前展示关联计划/专家；普通删除进回收站，恢复需重新检查权限 | 停用/删除阻止新运行并撤销在途发布资格；历史与恢复规则见下文 | SK-01/05、原第4项 |

首版支持用户主动要求沉淀，也允许任务成功后给出“保存为技能”的建议入口；建议本身不创建活动技能。重复建议按任务和来源去重。暂不增加固定每 N 轮强制提醒、独立后台策展代理或自动合并/归档任务；Hermes 的这些治理机制保留为后续评估，不扩大本次排期。

### 保存在哪里、为何不易误删

用户看到“我的技能 → 技能名称 → 说明/脚本/资源/版本”，这是文件树视图。服务端继续以 PostgreSQL 中的草稿和不可变发布快照为持久事实来源，复用现有 `files` 相对路径与 Base64 内容结构，增量增加私人身份、确认和生命周期记录。示意结构如下，路径不是用户电脑上的真实永久目录：

```text
我的技能/销售日报/
  SKILL.md
  scripts/build_report.py
  references/report_rules.md
  assets/report_template.docx
```

ZIP 只用于主动导入/导出，保存时不要求压成 ZIP；执行时按固定版本展开到本次沙箱，临时目录和容器清理不删除数据库中的技能。草稿保存、发布和回退分别校验 revision/hash，避免并发编辑覆盖。生成脚本及注释使用中文，代码标识与工具指令保留准确原文。

SK 阶段必须交付最小恢复保护：普通删除记 `deleted_at`、删除修订及操作人，隐藏并禁用技能，不直接物理删除草稿和发布快照；已有回收站完整界面在原第4项统一完成前，提供技能列表中的“已删除/恢复”入口。恢复回到停用状态，不复用旧确认、不自动恢复计划；重新校验和确认后才能启用。保留期限和彻底删除沿用原第4项统一策略，不在本设计另设天数。

删除窗口列出关联专家、活动计划和正在运行的任务。依赖删除技能的计划暂停并提示处理，不能悄悄改绑同名技能；在途任务不得再发布成果。普通回退保留被计划或历史引用的旧版本。彻底删除须由所有者明确确认，先处理引用和运行，再移除正文、脚本、样本及缓存，并按统一遗忘规则避免备份恢复后复活；审计只保留必要标识和操作结果。数据库和技能随联合备份恢复，验证恢复后为停用状态。

### 加载与持续改进规则

“已启用”表示进入当前用户可用目录，不表示每轮读取全部文件或已经执行。下一轮发送可见技能的名称、说明与版本信息；模型选中后通过受控读取获取正文，再按需读取资源。目录变化可通过用户范围的版本号/变更摘要同步，禁止向其他用户泄露技能名称。停用、撤权和删除需在读取、执行及成果发布三个节点复核。

修订流程统一为“提出改进 → 新草稿 → 差异及试运行 → 弹窗确认 → 新发布版本”。使用记录关联技能版本、运行及结果，作为修复证据，不将整个用户对话无选择复制进技能。手工回退同样展示目标版本、权限和计划影响并确认，禁止以回退绕过当前撤权或恢复已删除来源。

## 3. 现有代码不能直接复用的边界

- 管理 Skill 包的现有路由仅限管理员，不可简单去掉角色检查后开放全部目录。
- `skill_releases` 和 `skill_catalog` 当前 SELECT 策略公开，必须先建设私人可见性，再允许普通用户生成及发布私人技能。
- 当前包名称是全局主键，不能把用户填写的名称直接当作跨用户唯一身份；也不能依靠猜不出的名称代替 RLS。
- `load_skill` 只读取已经加载的已发布资源，没有创建、发布或启用能力。新增构建工具与读取/执行工具分离。
- 当前执行器只接受已发布、已加载的版本。草稿试运行需独立受限路径，不能为试运行偷偷发布或放宽现有加载检查。
- 当前 `schedules.ts` 是旧 JSON 存储和进程内自调用，不适合作为当前数据库部署的定时任务实现。

## 4. 私人技能数据与兼容设计

优先复用现有草稿、不可变发布版本、选择列表、校验和执行系统。通过增量迁移补充稳定 skill_id、显示名称、可见性、构建来源及状态；保留现有全局内部 name 主键与外键，以降低一次迁移影响面。旧公共技能保留已有内部名称和可见性；新私人技能由服务器分配符合现有校验的 UUID 派生内部名称，用户看到可重复的显示名称。内部身份不随显示名称修改。

- 草稿仅所有者读写；私人发布版本、目录、资源下载、依赖和加载都必须经过 owner/RLS 检查。
- 公共技能继续走管理员管理路径；私人创建接口独立，不因管理员身份自动开放其他人的私人技能正文。
- 公共发布另生成明确公开的版本副本，重新检查包含的文件和敏感资料，不能把私人草稿悄悄变成公共目录。
- 专家绑定、执行快照、历史日志和计划使用稳定 skill_id + release_id，兼容旧内部名称引用；迁移时逐项验证映射，不允许同名私人技能覆盖公共版或其他用户技能。
- 最小新增记录包括 skill_builds、build_sources、skill_trials、skill_activation_requests。构建记录关联用户、任务、请求标识、草稿修订、内容哈希、权限说明和有效性状态。
- 确认记录绑定确切的草稿修订、内容哈希、验证结果和权限范围。用户编辑、模型重生成、来源删除、停用或权限变化后旧确认失效。
- 私人技能及来源纳入备份、数据导出、回收站和彻底删除；保存方法前移除对话中的密码、令牌及不必要业务样本，资源需要用户明确选择保存。

## 5. 构建、试运行、确认与启用

构建状态为 `generating → draft → validating → ready_for_review → activated`，失败进入 failed，编辑后回到 draft，取消/来源失效进入 cancelled/stale。校验和试运行报告只对具体内容哈希有效。

拟新增的 Agent 工具为 propose_skill、revise_skill_draft、validate_skill_draft、trial_skill_draft、get_skill_build。工具只生成或处理当前用户草稿，不提供可绕过弹窗的 activate/publish 工具。最终启用走已认证用户界面的确认接口。

草稿试运行使用独立 trial_id 和服务端固定快照，仅给执行器本次批准的输入及草稿资源；默认合成样本，不自动读取整个项目。脚本语法/依赖检查后，在当前无网络沙箱中有界执行，回收预期输出用于预览，不覆盖已有业务成果。正文型技能只需格式及引用校验；脚本型技能默认要求代表性试运行成功才能启用。缺少执行器或必要样本时可保存草稿，不能伪报通过。

通过试运行只证明对应样例，不意味着获得额外权限。需要联网、网页登录或外部副作用的草稿可以展示和保存，但当前阶段明确标记缺少运行能力，禁止自动在宿主安装依赖、联网测试或把未验证能力标记可用。限制生成/修复次数、模型调用、执行时长、文件数量和字节数，失败后展示报告而非无限重试。

“保存并启用”事务先锁构建和草稿，复核 owner、revision/hash、来源、校验及试运行，再写不可变发布版本、私人目录引用、当前用户选择和确认终态。重复点击或网络重试返回同一 release_id；多端同时修改返回冲突；确认后响应丢失可查询终态，不重复发布。关闭窗口、超时、聊天中的一般“好的”和自动执行模式不会触发此接口。

## 6. 基础定时任务范围

2026-10-17 页面细化：按用户要求制作[自动化独立页面原型](自动化独立页面原型.md)，总览采用卡片面板，独立新增／编辑页选择 Skill、执行要求和周期；对话草稿统一进入此页面。界面与交互待用户确认，ST 业务接口和调度仍待开发。

首版支持定时运行已确认的私人/可见公共 Skill，使用已保存项目资料，执行离线 Office/Python 处理或可用模型整理，成果存到指定项目下。只要用户主动设置并确认，可在离开网页后运行；登录会话到期不删除计划，但账号被禁用、Skill/资料被撤权时不得执行。

不在本次基础范围内：浏览器访问网站、任意联网脚本、网站登录、自动外发邮件/消息以及任意外部 MCP 写操作。这些需要下一版本受控网络/登录能力和独立授权。创建草稿时若发现网站 URL 等要求，清楚展示所缺能力；可保存停用计划，不伪装为能正常抓取的活动计划。

### 计划确认窗口

| 项目 | 设计 |
|---|---|
| 执行内容 | 技能、固定发布版本、参数及用途 |
| 归属 | 当前用户与明确项目；不能代他人创建或运行 |
| 时间 | 用户时区、自然语言描述、下一次及随后两次时间 |
| 输入 | 固定文件版本或明确的“每次选择最新资料”规则；后者限定项目、名称/类型和选择条件 |
| 输出 | 每次运行独立任务记录与成果；历史列表聚合展示，不无限续写一条对话 |
| 运行策略 | 不重叠、补跑上限、超时、重试、停用/取消 |
| 提醒 | 默认站内；成功无新增变化可静默，失败或需要用户处理时提醒 |
| 状态 | 草稿、启用、暂停、需要处理；排队/执行状态属于各次运行 |

时间含糊或输入不完整时不启用。“最新资料”不是任意读取全部文件，必须显示可审阅的解析规则；每次运行实际解析出的输入版本记录在运行快照中，原件后续被删则撤销在途发布。

拟新增工具 propose_schedule、revise_schedule_draft、propose_schedule_change、list_my_schedules、get_schedule_run。对话可以提出修改时间、切换版本、暂停、恢复或删除计划。计划启用、变更运行范围/频率、暂停后恢复均走已认证确认窗口；删除窗口列出是否停止当前运行，默认保留历史成果。用户明确要求暂停或停止某次运行时，可通过受限pause_schedule/cancel_schedule_run工具立即降低执行权限，但必须定位到本人具体计划/运行并校验修订，不把含糊指代解析为停止全部任务。首次选择“立即试运行”单独显示实际执行及模型消耗，不能把建计划等同于立即执行。

## 7. 持久调度和版本规则

复用[容器与定时采集设计](容器部署与定时采集调度方案.md)的计划、运行、步骤、租约和通知模型，先实现离线子集。现在提前完成的 ST 任务在下一版本复用，不再建一套独立调度器。

- `schedule_drafts` 保存解析结果和确认状态；`schedules` 保存已确认的计划；`schedule_runs` 唯一键 `(schedule_id, scheduled_for)`；手动试运行按独立 request_id 去重。
- `schedule_grants` 绑定 owner、计划 revision、release_id、输入选择规则、允许的只读/成果写入工具和时效。后台使用内部服务执行身份，不持久保存用户 Bearer 会话，不伪造管理员登录。
- 计划启用及下次运行时间同事务提交。调度器先生成持久运行，再推进游标；双调度器、服务重启和响应丢失均不重复触发。
- 已确认计划固定 Skill 发布版本。用户更新并加载新版后，旧计划仍使用原版并显示可更新；切换版本或扩大范围需重新确认，不自动继承授权。
- 每次运行快照记录参数、Skill 版本、输入版本、模型配置版本、授权和 fence。引用所需的旧发布版本不因普通回退被删除；Skill 禁用/撤权优先于版本固定。
- 同一计划最多一条活动运行，忙时合并保留一次；默认停机最多补跑一次，默认时区 Asia/Shanghai。周期最短间隔拟为 5 分钟，可按管理员策略调整。
- 初期全局定时执行 1 个、每用户 1 个并发，独立于聊天设置后台上限；资源繁忙排队，不能仅在每个 API 进程内分别计数。
- 模型费用和执行预算沿用运行限制；用量模块未完成时显示限制与可用估算，不能声称已具备精确费用保护。
- 遇到人工审批或摘要确认时持久化为需要处理并释放执行槽，站内提醒；无人回应不自动批准。基础计划使用独立运行任务，避免长期历史不断膨胀。
- 结果不明的外部副作用禁止重放；基础版不允许这类步骤无人值守执行。只读模型失败可按现有规则有限重试，执行失败不直接重复所有脚本步骤。
- 暂停只阻止新触发，界面另选是否停止当前运行；取消和删除校验当前 revision/fence，旧请求不能误停下一次运行。
- 备份恢复后计划默认暂停、旧授权撤销、运行标记中断，不自动补跑恢复前动作；用户核对计划后重新启用。

第一步先验证已有 PostgreSQL + pg-boss 候选的事务、最小权限和领取模型；若不合适按 ADR 选择受限领取实现，不重新发明通用 cron 引擎。当前宿主 Skill worker 可以作为离线执行后端，先补内部任务身份及并发/租约，不以此声称全后台已容器化；下一版本 CN-02 替换执行后端时保持相同协议。

## 8. 优先级、依赖与验收

| 编号 | 优先级 | 交付 | 验收重点 |
|---|---|---|---|
| SK-01 | P0 首位 | 私人技能身份、RLS、持久文件树、版本及最小软删除/恢复 | 两用户同显示名不冲突；旧公共技能可用；清理沙箱不丢技能；恢复为停用 |
| SK-02 | P0 | 对话生成/修改草稿、来源与结构校验、沉淀建议 | 明确需求/现有流程都可生成；建议不启用；同主题提示修订；来源越权/删除和生成取消不回流 |
| SK-03 | P0 | 独立草稿试运行、错误修复反馈和预览 | 不偷偷发布、不加载草稿、不覆盖业务文件；失败报告真实 |
| SK-04 | P0 | 弹窗确认、原子私人发布并加载 | 未确认零加载；关闭/刷新/编辑/多端/重复提交安全；下一轮生效 |
| SK-05 | P0 | 端到端验收、按需读取、修订回退及删除保护 | 真实模型生成 Office 技能；下一轮按需执行；修订再次确认；旧版/计划不串版；删除暂停关联计划且可恢复 |
| ST-01 | P0 紧随 SK | 对话计划草稿、时间解析及确认窗口 | 未来三次时间正确，含糊时间补问，不确认不启用 |
| ST-02 | P0 紧随 SK | 持久计划/运行、最小队列、授权与租约 | 双调度器不重复、重启补跑一次、任务不重叠、账号撤权生效 |
| ST-03 | P0 紧随 SK | 后台离线 Skill 执行与成果发布 | 浏览器关闭仍运行；固定版本/输入快照；错误不伪造成功 |
| ST-04 | P0 紧随 SK | 管理界面、站内提醒、暂停取消、备份及故障验收 | 权限与提醒幂等、刷新恢复、旧 fence 及恢复后暂停 |

最高优先级不意味着跳过私人隔离、格式/试运行或用户确认。SK-01 是后续全部对话技能接口的前置门槛；ST 必须复用 SK 版本和私人可见性。具体日期只维护在主计划。

## 9. 与历史文档的关系

本设计覆盖旧 PRD 中“保存立即热生效”、私人技能按目录覆盖公共技能及首版不实现对话生成的历史表述；当前规则为生成草稿、弹窗确认、私人发布/加载、下一轮生效；本地 SK 实现已按此验收。公共 Skill 管理继续独立，不取消已有管理员管理边界。

原八项补强恢复后仍需完成；完整网络抓取、人工登录和全容器调度仍按 CN 下一版本交付。此文不将已设计能力标记已实现，不改变运行中的本地/公网服务，也不创建任何实际业务定时任务。
