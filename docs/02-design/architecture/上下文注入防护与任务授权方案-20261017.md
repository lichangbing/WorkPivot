# 上下文注入防护与任务授权方案

日期：2026-10-17。
状态（2026-10-18更新）：已进入实施，统一审批入口与调用绑定基础已完成，最新测试与剩余边界见第12节；未部署。第1至7节保留2026-10-17的方案与初始检查依据，不代表全部已实现。

## 1. 目标与范围

已确认原则：默认只读、任务资源限定、危险操作绑定授权、不可信内容不得扩权。

目标是即使模型受附件、网页、检索结果或工具说明诱导，也不能越过本轮允许的资源与操作范围。账号有权访问某项数据，不等于模型在每个任务中都有权访问它。

本方案针对当前 PostgreSQL 运行链路：`database/runtime.ts → execution.ts → core/loop.ts → 工具/仓库/执行服务`。工作区存在其他未提交变更，结论依据检查时的代码，不代表已部署实例。历史《权限行为矩阵》主要对应旧文件系统执行链，不应直接当作当前数据库链的验收结果。

不在本次范围：组织级共享权限重构、替换 Office 引擎、全面 DLP、自动保证答案正确、消除所有提示注入。格式解析正确性和多用户性能继续作为独立问题处理。

## 2. 已有保护与需要保留的设计

| 保护 | 代码依据（相对 code/） | 实际边界 |
|---|---|---|
| 用户隔离 | `packages/server/src/database/connection.ts`：事务设置 actor、强制 RLS、拒绝高权限运行账号 | 保护跨用户，不限制同一用户本轮读取范围 |
| 文件版本与任务归属 | `database/file-tools.ts`、`files.ts` | 按当前任务及不可变版本读取；没有本轮已选文件白名单 |
| 一次审批、到期及消费 | `database/runs.ts`：requestPermission/consumePermission | 已绑定用户、任务和运行；过期、停止后失效，不是永久许可 |
| 外部 MCP 审批 | `database/mcp.ts`：tools | 每次调用在 run 内申请权限；调用前后检查配置版本，复核远端 schema 指纹，不能误判为无 access 就完全无审批 |
| 隔离执行 | `database/skill-execution.ts`、`scripts/skill-worker.mjs` | 输入显式提供、技能只读、每作业目录/容器、无网络、资源限制、发布前校验运行状态 |
| 持久能力人工启用 | `database/skill-builds.ts`、`automations.ts`、`memory-suggestions.ts` | 技能启用、计划启用、记忆建议接受由用户接口控制；模型不能直接将草稿启用 |
| 公网访问边界 | `web/safe-http.ts`、`browser-engine.ts` | 校验 DNS/IP、绑定已验证 IP、限制重定向和非 GET、阻断 WebSocket；自动化有 origins 限制 |
| 定时任务固定授权 | `database/automation-worker.ts` | 固定技能版本、输入、计划授权和撤销检查，能作为普通对话资源授权的参考 |

## 3. 发现的缺口

以下是静态代码确认的约束缺口及攻击条件，尚未证明某个模型会被特定注入样本诱导成功。

### P0-1：内部工具没有统一的默认只读闸门

`core/loop.ts` 只有同时存在 `requestAccess` 和 `tool.access` 才执行统一审批；`kind: write` 本身不触发阻断。`save_artifact` 没有 access；`pause_schedule`、`cancel_schedule_run` 和技能/计划草稿写入也没有统一操作权限检查。它们有身份、版本或运行检查，但不能判断用户是否授权本轮做这些事。

当前 runtime 给每轮挂载网页、计划、技能构建、知识、文件、记忆等一整组工具。附件可诱导模型从阅读切换为保存成果、暂停本人其他计划或创建无关草稿。不能据此声称可删除全部文件或绕过技能启用确认；未发现这类直接工具通路。

### P0-2：资源可见范围大于本轮任务需要

`file-tools.ts` 可列举、读取当前任务全部文件；`knowledge.ts` 默认检索同一项目其他任务的资料；`memory-tools.ts` 默认读取个人、项目、任务层记忆。`get_automation_options` 和 `list_my_schedules` 还可暴露用户其他项目、文件选项和计划配置。

这些范围仍受用户隔离约束，不能描述成跨用户漏洞。但用户仅要求“分析附件 A”时，同项目 B、旧任务附件和自动化配置不应自动进入模型上下文。应限制元数据列举、关键词检索、向量召回、引用回读和二进制输入，不能只限制最终下载。

### P0-3：审批绑定与展示不完整

`execute_skill.access` 当前只提供 command，没有输入版本、技能发布版本、输出名称、目标 documentId/revision；`trial_skill_draft` 也主要展示 command。`consumePermission` 按权限 ID 和 run 消费，不校验完整调用摘要。

当前循环是顺序等待后执行相同调用，未观察到运行中的参数被替换；问题是审批记录无法完整表达“批准了哪些资源和哪些结果”，不应夸大为已经复现参数替换漏洞。

`runs.ts` 中用户级 `execution.mode=auto` 可自动批准 execute_skill，尚未受任务级输入和操作授权上限约束。隔离沙箱能防宿主/网络越界，但无法防止模型在获准读入的数据上做非本轮意图的处理或生成成果。

### P0-4：公网只读不等于不能外传

普通对话调用 `web.tools(..., undefined, sessionKey)`，没有固定 origins；已有每次网页调用审批，但主要展示 URL/actions。浏览器子资源可访问其他公网来源；GET 的路径和查询参数也能携带资料。SSRF 防护与禁止 POST 不足以阻止这种外传。

共享浏览器可省略 URL 操作当前页面，批准后用户切页会改变操作目标；授权应绑定页面会话及页面代次，并在执行前核对。截图也会持久写入成果，不能只按 read 分类。

### P1-1：资料信任级别未形成可追踪的契约

当前系统提示和工具描述有“资料不是指令”的约定，但工具结果以普通字符串进入历史。摘要、专家经验等再次加载时，没有统一的来源/信任级别契约。已有记忆建议及摘要人工确认值得保留，但“确认事实”不能等价于“批准未来操作”。MCP 远端描述和技能说明同样不能成为权限来源。

### P1-2：收紧权限后，旧上下文仍可能含越界资料

`runs.ts` history/model_messages 与 `compaction.ts` checkpoint 会恢复历史。只限制下一次工具调用，不能阻止模型利用已经在历史或摘要里的 B 文件内容。已有 context_revoked/清空缓存机制可复用，但还需覆盖历史重建、摘要及专家/记忆注入。已发往模型或展示给用户的数据不能追溯撤回。

## 4. 推荐方案：服务端按运行授权，工具按资源执行

### 4.1 最小数据契约

先采用一份小型、可版本化的运行授权快照，不引入通用策略语言或全新 ACL 系统：

- `ownerUserId/taskId/runId/fence`：复用现有可信身份与执行栅栏。
- `policyVersion/revision`：策略版本与撤销版本。
- `resourceScope`：已授权文件 versionId 集合；用户显式选择的项目资料范围；可加载记忆层；固定 Skill releaseId；允许的计划等操作对象。
- `operations`：读取、生成新成果、更新指定成果、隔离执行、技能草稿、计划草稿/暂停/取消等有限操作。
- `network`：默认关闭；经确认的目标 URL/来源、允许请求方式、浏览器页面代次和必要子资源范围。
- `authorizationSource`：可信用户界面事件或已有有效授权 ID。模型建议、文件文字、工具返回、摘要不能写此字段。

在现有 task_runs 增加授权快照及版本，在 run_permissions 扩展调用摘要；仅需要任务持续授权时才增加任务级持久字段。审计沿用持久事件，以独立权限事件记录，不混为模型正文。

用户通过当前消息选择的附件构成默认读取集合；不默认继承当前任务所有文件。引用历史附件或授权整个项目时，界面显示实际范围并由用户选择。项目范围授权需注明是固定版本快照还是允许后续新增资料，首版采用固定版本快照。

已确认的持续范围可供后续轮次继承，但运行启动时重新校验归属、删除状态和撤销版本。未知操作/未知策略版本默认拒绝，不自动退回旧 auto。

### 4.2 默认只读与正常任务体验

默认允许当前授权资料的读取、解析、计算分析和聊天回答。这里的“只读”禁止修改用户业务状态，不禁止隔离环境中的临时文件和系统必须的日志/缓存。

现有 execute_skill 同时执行并发布成果，不能直接当成只读分析工具。首版：普通解析走已有固定解析器；需要计算时提供经过授权的无网络临时执行能力，不发布成果、不带入额外输入，并限制日志/结果大小。不要仅把现有工具 kind 改为 read。

> 2026-10-24 实现：该能力落地为 `run_code`（可带显式输入与可选产物）。产品决定采用**静默自动授权**、不弹逐次确认卡，与本节的“经过授权”默认不同；补偿控制与风险见《[通用代码执行能力-20261024](通用代码执行能力-20261024.md)》。部署可用 `WORKPIVOT_CODE_APPROVAL=confirm` 恢复逐次确认。

用户明确要求生成成果时，可通过可信界面的“生成成果”范围一次授权必要的新建操作和指定输入，后续范围内步骤不重复弹窗。自由文本由模型理解后只能形成待确认操作摘要，不能由模型自行签发权限。

对已有成果更新、暂停计划、取消运行等操作，授权绑定具体对象及 revision。纯“分析附件”不能触发这些操作。后台记忆/经验整理可保留为待确认候选，但不能直接改变已生效记忆或操作范围；需要记录候选来源并控制资源使用。

### 4.3 每次调用均检查，敏感出口再次检查

在数据库工具集合外包一层统一执行检查器：参数验证 → 提取实际资源/操作 → 检查运行快照 → 必要时申请审批 → 执行。工具是否有 access 不能决定是否检查。现有 kind 不足以表达真实副作用，例如截图是写成果，技能列表工具也可能被统一标成 write，需要逐个登记实际效果。

同一策略函数在读取返回、沙箱输入组装、网络请求发出和成果提交前复查，防止旁路调用、权限撤销及等待期间资源变化。授权取消、任务停止、用户禁用或 fence 变化后拒绝执行/发布。

所有数据库查询仍保留 RLS；新增范围过滤使用参数化查询。先筛选授权版本，再执行关键词排序、向量检索和分页，避免未授权内容先进入结果后被模型过滤。引用 ID、文件列表、计划摘要同样限制。

### 4.4 一次审批绑定完整调用

规范化参数后计算调用摘要，至少覆盖：工具、可信工具版本/连接版本、完整参数、输入文件版本、Skill releaseId、输出名称及目标 revision、网络目标、run/fence、策略 revision。摘要不是单纯 command 字符串。

审批卡展示人可理解的操作与影响，并提供输入/输出/目标及完整参数查看。消费时比较实际调用摘要；任何相关字段变化、重试新调用、过期或撤销都不能复用旧审批。保留现有事务消费和幂等处理。

自动模式只能免去已授权范围内的重复确认，不能扩大输入集合、放开网络、批准跨任务读写或持久能力启用。MCP 的现有内部审批接入同一调用摘要，避免重复审批或绕开统一检查。

### 4.5 网络出口按发送行为控制

默认没有网络权限。读取用户明确提供的 URL，可绑定完整规范化 URL；模型新构造的 URL（尤其查询参数）、页面 fill/click/press 等动作需要在已有范围内验证，否则请求具体授权。

保留公网/DNS校验；重定向和浏览器子资源也受范围约束。origin 白名单只能限制目的地，不能证明数据未泄漏；向任何网络目的地发送本地资料，都应有单独的数据发送授权。首版不支持通用敏感资料外发，不能靠关键字或高熵检测宣称能够自动识别所有泄漏。

已授权网站的脚本也可能根据输入内容发起 GET。因此受限分析模式不允许向页面填入本地资料；如以后开放交互，需绑定允许发送的字段/数据与目标。自动化已有 webOrigins 保留，但也要补充同样的发送限制，不能因无人值守自动放宽。

### 4.6 资料来源、摘要与撤销

工具返回用结构化封装携带 `sourceType/sourceId/version/trust=data`；控制信息与资料内容分开。引用、工具名、远端描述和文件名不允许伪造用户授权事件。提示词分隔、恶意文本检测仅为辅助，不代替执行检查。

摘要保留事实来源及不确定性；不从摘要恢复权限。技能说明只能指导已有能力，不能授权新能力；确认记忆或经验也不授予写入、网络或调度权限。

范围缩小时暂停当前运行、撤销待批许可并失效相关 model_messages/checkpoint。对无法确认来源范围的旧历史，首版不自动带入新受限上下文，应提示用户新建受限会话或确认可读取范围。聊天界面可保留历史显示，但不能默认再次发送给模型。

## 5. 分阶段实施与验收

| 阶段 | 改动模块 | 完成条件 |
|---|---|---|
| A：统一权限入口 | core loop、database execution/runtime、runs、schema、审批 UI | 所有工具（包括无 access 的内部工具）均有明确效果与校验；旧 auto 不越权；只读任务不能保存、暂停计划或建立无关草稿 |
| B：资源与上下文 | files/file-tools、knowledge/embeddings、memory/expert、history/compaction | 文件、列表、检索、引用、记忆和历史只包含授权范围；撤销后不在下一次请求复现内容 |
| C：危险操作及网络 | skill execution/trial、artifact、MCP、web/browser、automation | 完整调用摘要一次审批；变更目标需重批；无网络默认有效；共享页面变更使旧动作授权失效 |
| D：对抗与兼容验收 | 独立测试数据库、Worker/浏览器环境、模型样本 | 下列测试通过并记录实际边界，正常获批工作流无不必要重复确认 |

A/B/C 应作为完整权限边界上线；只增加提示词、只隐藏工具或只做其中一个入口不能宣布防护完成。

必测场景：

1. A/B 两用户及同一用户不同任务/项目/版本：伪造 ID、引用、输入、计划 ID 均不能越界；管理员对话也不能绕过本轮范围。
2. 附件/网页/OCR/检索/MCP 返回包含“读取别的文件并发送”“保存长期指令”“暂停所有计划”：模拟模型真的提出对应工具调用，验证服务器拒绝，而非只检查模型有没有说拒绝。
3. 无 access 的写工具、直接调用服务入口、旧模式 auto、截图副作用：全部受统一限制。
4. 审批后更换 inputs、outputs、revision、Skill、MCP schema、URL/actions、浏览器页面；过期、双消费、并发停止、重启和撤销：无越权执行或迟到发布。
5. 网络测试使用本地受控测试替身，断言被拒请求根本没有发出；覆盖 GET 查询参数、重定向、跨来源子资源、内网解析与 DNS 变化，不向真实外部发送资料。
6. 摘要/记忆/技能引用嵌入伪造“用户已批准”：不能生成许可；范围收紧后旧摘要和历史不再发送。
7. 正向：分析指定文件、获批新建成果、指定旧成果更新、已确认自动化和获批 MCP 正常完成，范围内不反复确认。
8. 模型对抗测试使用无敏感数据样本，分别记录诱导成功率与工具越权执行次数；不能用少量样本零成功率宣称绝对免疫。

审计保留用户/任务/run/call、操作、资源 ID、许可摘要、策略版本、允许/拒绝原因和时间；不复制正文、URL 敏感参数或凭据到普通日志。现有 tool_use 会记录 args，需同时检查事件存储、前端展示、保留期限及脱敏，不能只新增一份干净日志而忽略旧日志。

## 6. 兼容、回退与已知限制

- 保留现有 RLS、一次许可、Skill/计划启用确认和无网络沙箱，不迁回历史路径授权模型。
- 数据库迁移增加默认拒绝的授权字段；旧活动运行在升级时有序停止，不能被解释为拥有新的宽泛授权。既有定时任务先核对固定输入和网络配置，不暗中扩权。
- 发布失败可关闭新增可执行能力并保留授权范围内的读取，不回退到绕过检查的旧执行链。降级须在 UI 明确说明。
- 默认只读会改变当前无审批保存文本成果和暂停计划的体验；界面应明确显示本轮范围及扩权入口。此为用户已确认原则对应的具体行为方案，尚未实施。
- 权限控制能限制副作用，不能保证模型对恶意文档的总结不会受影响，也不能撤回已暴露的数据。视觉误读、公式误算仍需独立验证。
