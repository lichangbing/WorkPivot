# 手机客户端方案

## 已确认范围（2026-10-20）

采用 React、TypeScript、Capacitor，同时设计 Android/iOS，先交付 Android 内部测试版本；首批设备为荣耀 MagicOS 10。暂无 Apple 开发者账号，iOS 构建、签名和真机验收单独记录，不以共用网页构建替代。

首次使用展示登录页，服务器地址为空，由用户填写；不再使用已经删除的公网域名。有效会话自动进入项目任务。参考用户提供的三张豆包截图：聊天主屏、左侧抽屉、分组设置页。桌面界面保持现有设计。

聊天展示所属项目/任务、正文、过程与人工确认。侧栏包含项目与任务及功能入口，底部用户和设置。记忆建议在聊天中确认、修改、拒绝；个人/项目/会话记忆和专家经验归属明确。输入区保留附件、确认/自动模式、模型、发送/停止。

## 技术决策

- 新建 `code/apps/mobile`，内置界面资源；服务器地址仅用于 API 请求，不作为远程 WebView 页面地址。
- 共用现有 PostgreSQL 后台和权限边界，复用纯对话事件合并逻辑，不复制 Agent 执行器。
- 原生凭据使用 Keychain/Keystore 插件；浏览器开发预览只保存在内存，不能称为安全持久登录。
- API 地址使用 HTTPS，不接受含账号密码、查询参数、片段的地址。开发模式允许本机 HTTP；发布版不全局放开明文和证书校验。
- HTTP/SSE 连接显式指向配置服务器。跨域仅由部署方明确配置允许的来源，不启用任意来源或 Cookie 跨域凭据。
- 后台继续执行任务，手机切后台不意味着停止。恢复前台补拉事件，发送重试保持请求标识，审批由后台校验是否仍有效。
- 文件体按需下载，手机不自动同步全部过程材料。退出/换服务器清除凭据和当前会话。
- 国内通知后续评估荣耀及其他厂商通道，不能只依赖 FCM；通知不包含私有正文。
