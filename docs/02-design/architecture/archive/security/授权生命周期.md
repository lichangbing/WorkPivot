# 授权作用域与等待生命周期（RL1-06/07）

更新时间：2026-09-08。此文描述当前实现；四档完整行为矩阵仍由 RL1-04 单独验收。

## 授权语义

| 决策 | 生效范围 | 生命周期 |
|------|----------|------------|
| allow（允许一次） | 当前请求 | 不写入任何授权集合 |
| deny | 当前请求 | 拒绝后唤醒执行器 |
| session | 用户 + 任务 + 路径 + 读写模式 | 同一任务正常多轮对话复用；停止、断线、删除任务或服务重启失效 |
| forever | 用户 + 任务 + 路径 + 读写模式 | 持久化；管理员可撤销；不跨用户或任务继承 |

读取和写入分别授权，写入授权也不隐含读取。已存在目录授权包含子路径；文件或尚不存在的目标仅精确匹配。路径先转绝对路径并统一 Windows 大小写，通配符、相对路径、缺失归属或畸形授权条目不参与放行。

readonly 始终拒绝写入，即使已有写入授权；ask 的写入仍逐次询问。高危命令和其他 scope=once 卡片只接受 allow/deny。Shell 不能可靠声明其真实读写模式，因此不复用文件授权，也不保存命令 session/forever 授权。

本轮路径归一不等同操作系统执行隔离；符号链接真实路径检查、Linux 命令边界、环境变量限制由 RL2 完成。记忆晋升确认使用独立通道，不在本轮文件/命令授权等待改造范围内。

## 持久化与升级

`config/permissions.json` 使用 version=2，grants 每项记录 id、userId、taskId、path、mode、subtree、createdAt。写入通过 store 原子写入与一代备份。

version=1 的全局 allowDirs 不包含用户、任务和读写模式，升级后不自动继承，访问须重新确认。首次保存新授权时旧文件保留为 `.bak`。不修改用户交付文件。旧 `/api/settings` 的 allowDirs 保留空数组以兼容客户端，完整列表仅由管理员接口提供。

后台「路径授权」显示用户、任务、路径、访问模式、包含子目录与授权时间；支持刷新、撤销。撤销同时清理该任务内存会话授权；其他有效永久授权仍按各自范围生效，不回滚已完成的操作。

## 等待与清理

- 请求绑定任务所有者和任务 ID；管理员可以代管正确任务，但不会使用管理员档位执行。
- 默认等待上限 120 秒，超时自动 deny；服务端评测可注入更短超时，HTTP 客户端不能控制。
- stop 或 SSE 断开触发 AbortSignal，立即删除 pending、清除计时器及监听器、唤醒等待。
- 批准与停止同时发生时，执行器在运行工具前再次检查 signal，已停止不继续执行。
- SSE 的 permission_resolved 事件说明决策、超时或停止；界面移除可操作授权卡。断线/流结束也收起遗留卡片。
- running 在执行器 finally 中释放；断线不提前删除 running，避免同任务重入后旧执行清理覆盖新执行。SSE 关闭即停止心跳，结束连接不再写事件。
