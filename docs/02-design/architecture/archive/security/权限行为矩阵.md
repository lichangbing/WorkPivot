# 四档权限行为矩阵（RL1-04）

2026-09-08：记录当前实现，逐格对应 `code/eval/W11-permission-matrix.mts` 的 `RL1-04 档位 × 场景` 断言，共 28 格。测试仅判定权限，高危命令不实际执行。

| 场景 | readonly 计划模式 | ask 变更前确认 | workdir 自动编辑 | auto 完全访问 |
|---|---|---|---|---|
| 界内读 | 允许 | 允许 | 允许 | 允许 |
| 界内写 | 拒绝 | 单次确认 | 允许 | 允许 |
| 未授权界外读 | 拒绝 | 路径确认 | 路径确认 | 拒绝 |
| 未授权界外写 | 拒绝 | 单次确认 | 路径确认 | 拒绝 |
| 普通命令 | 拒绝 | 单次确认 | 允许 | 允许 |
| 高危命令 | 拒绝 | 单次确认 | 单次确认 | 单次确认 |
| 引用 Windows 界外绝对路径的普通命令 | 拒绝 | 单次确认 | 单次确认 | 允许 |

路径确认支持允许一次、任务会话、任务永久授权；单次确认只接受允许或拒绝。历史路径授权仍不能提高 readonly 写权限或绕过 ask 逐次写确认。跨用户、跨任务、读写范围、撤销、取消与超时由 W11-permission-lifecycle 覆盖，见 [授权生命周期](授权生命周期.md)。

已知差异：auto 的界外文件与界外命令行为不一致。本批保留现状，不把“完全访问”标签理解为统一放行规则。RL2 必须继续收敛路径、符号链接、命令与文件工具的边界；命令文本正则不是执行沙箱。

# 项目记忆治理（RL1-08 首步）

- 新项目记录创建人为负责人，显式成员名单默认仅创建人；管理员可改派并分配成员。管理员始终可管理。
- 旧项目没有名单时保留团队共享，由管理员代管；保存名单后按显式成员访问。默认项目也保留此兼容方式。
- 项目记忆读取、编辑和清空接口按成员身份校验，负责人和管理员可编辑，其他成员只读；修改保留一代 `.bak`，记录审计。
- 记忆查看与注入使用任务所属项目目录；未选择任务及临时任务不提供项目记忆。历史自定义任务目录中的记忆文件不自动搬迁，需负责人整理到所属项目记忆中。
- 调整成员会中止该项目正在运行的任务并清理会话授权，下一轮重新校验。已展示给用户或送入模型的历史内容无法追溯撤回。
- 全局记忆开关仅管理员可改；成员看到状态但无法切换。
- 本批落实 HTTP 接口与界面。Agent 通用文件工具、任意任务目录和脚本仍可能绕过项目记忆编辑入口，执行层治理依赖 RL2；不能把本批视作完整文件隔离。

验证：W11 138/138，全套 305/305。后台项目成员面板与负责人选择已浏览器核对；保存按钮的 UI 点击被自动审批阻止，因此界面保存验收待允许后补做，接口保存与交接已由回归覆盖。
