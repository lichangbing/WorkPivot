# Electron 本地会话存储与服务端同步

2026-10-19 用户确认：Electron 在用户电脑上保存会话，优先读取本地再与服务端同步；生成文件仍保存在服务器。本设计替代“服务端集中存储与项目组协作预留”中客户端不维护长期会话副本的旧约束，不改变服务端执行和文件存储边界。

## 数据边界与实现

- 服务端 PostgreSQL 仍为对话权威来源。客户端保存已读取的用户消息、助手回复、思考、工具事件及分页水位；历史随读取逐步缓存，不在启动时批量下载全部账号历史。
- 生成文件留在服务器。本地聊天只保存附件标识、名称、删除标志等引用；用户明确下载或原有可选成果同步另行处理，本功能不调用成果下载。
- Electron 主进程在 `app.getPath('userData')/conversations/` 下按服务器完整地址与账号哈希分目录，任务名也用哈希。采用每任务 JSON 原子替换，不新增数据库或本地后台依赖。文件权限0600、目录0700；这是系统账号下的本地文件保护，不宣称磁盘加密或抵御同一系统用户的恶意程序。
- 单任务32 MiB，单账号/服务器256 MiB。超过单任务上限明确提示并继续使用服务端；总量超限按较早写入顺序清理其他任务缓存，需要时重拉。清理不删除服务端数据。
- 主进程验证已连接服务器、主框架发送方和登录身份，服务端任务清单限定允许读取/写入的任务。渲染层只能调用具体缓存方法，不能指定本地路径。令牌仅用于请求和内存哈希比对，不写入会话缓存。

## 加载与同步

1. 登录后由主进程独立确认账号和可访问任务，再建立仅当前进程有效的缓存句柄。
2. 打开任务先显示本地快照；仍请求服务端最新对话快照确认有效性。
3. 依据本地水位通过 conversation-changes 分页补齐离开期间的事件，不只拼接最近五轮；复用事件ID去重和现有SSE追赶。
4. 服务端确认前允许查看本地副本，但不启用发送；失败明确显示未同步状态并自动重试。原有服务端事件、内容分页被读取后同样落盘。
5. 服务端水位回退时放弃本地快照，以服务端为准。任务删除/撤权时清理对应缓存并使旧写入租约失效；账号任务列表变化及30秒周期检查同步删除。
6. 退出登录或主框架导航锁定内存句柄，同一账号下次在线登录可以重新绑定。不同服务器/账号不能读取彼此缓存。

当前 Electron 仍加载服务器提供的界面，首次启动、身份确认和任务列表依赖服务端。本次提供的是已登录客户端的本地优先历史读取与断线保留，不是完整离线冷启动、离线发送队列或双向编辑聊天。浏览器继续使用现有服务端读取，不引入IndexedDB。

## 管理与审计

用户菜单增加“本地会话记录”，显示缓存任务数、占用、最近保存时间与上限；支持清空当前服务器/账号的本地副本。清理需确认，不删除聊天或服务器文件，当前页面停止重新写回，重新打开任务后恢复缓存。

本地管理日志保留最近100条清空、损坏清理、删除同步和容量清理记录，仅含时间、动作及数量，无聊天正文、令牌或原始任务名称。管理记录由主进程本地保存，不冒充服务器安全审计。

## 客户端窗口与服务器入口（2026-10-19）

用户确认去掉系统标题栏与传统菜单栏，采用统一的 36px 自定义标题栏；保留拖动、双击最大化、最小化、最大化/还原与关闭到托盘。预加载脚本提供独立样式的标题栏，连接配置页与远程工作区共用；主进程仅接受当前主窗口、主框架及已连接来源或本地连接页的窗口操作。原生编辑菜单保留快捷键但不显示菜单栏。

登录首页将服务器地址、用户名、密码放在同一表单，直接连接并登录；不再通过“更换服务器”按钮打开独立页面。登录后从“设置 → 服务器连接”查看当前地址并打开客户端本地配置页。浏览器不显示客户端专用设置。连接失败仍能操作窗口及重新配置地址；会话继续按服务器/账号隔离，生成文件留在原服务器。切换前应先发送或保存未提交的输入。

实现采用 Electron 的无边框窗口与拖动区域机制：[官方窗口交互说明](https://www.electronjs.org/docs/latest/tutorial/custom-window-interactions)。不引入新的窗口管理依赖。

### 登录首页地址输入（2026-10-19）

Electron 的远程登录页直接显示服务器地址输入框；修改目标后，主进程先检查服务兼容性，再向用户填写的目标发起登录，成功后在目标来源写入会话令牌并进入工作区。原页面不会收到目标服务器令牌，密码不写入本地配置或日志。网络、地址、密码错误留在表单提示；本地离线首页也提供相同三项输入，恢复连接后直接登录。当前服务器首次初始化仍使用原注册流程，切换到未初始化服务器不会擅自创建管理员。普通浏览器仍登录当前站点，不显示桌面地址输入。

HTTP 与 HTTPS 均受支持；本机回环调试可使用 HTTP，多设备正式部署应使用 HTTPS 保护登录与会话传输。可通过反向代理提供 TLS，例如 [Caddy 自动 HTTPS](https://caddyserver.com/docs/automatic-https)；内网自建 CA 需要客户端正确安装信任，不关闭证书校验。本轮没有部署 HTTPS 或更改服务端口。

Linux 解压目录重新打包后会重置 chrome-sandbox 的权限，运行前需管理员重新设置 root:root 与4755。客户端重启加载新预加载脚本；单独刷新网页不足以升级桌面桥。
