## 1. 两条 PDF 路线

| 场景 | 路线 | 原因 |
| --- | --- | --- |
| 从零生成报告、方案、分析 | 安全 HTML → Chromium `page.pdf()` → 版本化 PDF | 分页、中文、表格、页眉页脚和页面方向可控，不依赖 Office |
| DOCX/XLSX/PPTX 转 PDF | Office 文件 → LibreOffice → PDF | 保留原文档页面模型，HTML 重排不能代表原稿转换 |

直接生成 PDF 不依赖 LibreOffice；Office 转换要求执行镜像包含 LibreOffice、Poppler 和中文 Noto 字体。依赖缺失时明确失败，不发布半成品。

## 2. `create_pdf` 安全边界

- 模型只提交安全 HTML 片段、无目录文件名、标题和版式参数，不提交宿主路径。
- 正文最大 256 KiB，最多 100 页、16 MiB；纸张仅 A4、Letter、Legal。
- 浏览器关闭 JavaScript、Service Worker 和全部网络请求。
- 禁止脚本、表单、iframe、object、embed、link、meta、base 与事件处理器。
- 生成后检查 `%PDF-` 文件头和页数，再进入不可变成果版本。
- 页面打印成功只代表结构有效；视觉检查必须单独记录。

## 3. Office 工作流

### 3.1 读取

优先使用结构化文档工具读取正文、段落、表格、工作表和区域，按需分页/分块。返回实际读取范围、截断、OCR 来源和无法支持的对象，不能用“full”文件名推断内容完整。

### 3.2 新建

优先复用 Skill、模板和成熟文档库。流程为：

```text
大纲/字段 → 模板或文档库 → 隔离生成 → 重新打开 → 结构及目标内容核验 → 发布版本
```

### 3.3 修改已有文件

```text
复制源版本 → 读取结构 → 定位对象 → 限定修改 → 保存副本
  → 重新读取 → 核对目标与其他内容 → 发布新 revision
```

结构变化后重新定位；无法保留承诺格式时明确限制或拒绝，不能默认重建整份文件冒充局部修改。

### 3.4 成果发布

- 原件保持不可变，修改生成新版本。
- 目标 revision 冲突、必要检查失败、取消或产物缺失时不发布。
- Word、Excel、PPT 分别记录执行、保存、重新打开、公式/结构、视觉检查状态。
- 下载和预览使用认证 API，不暴露宿主绝对路径。

## 4. Excel 与公式

- 读写工作表时使用稳定 sheet ID，不能只依赖显示名。
- 公式表达式（OOXML `<f>`）和缓存值（`<v>`）分别读取、分别核对。
- 需要重算时在隔离环境调用 LibreOffice，并设置超时、取消和资源限制。
- 宏、外链和任意公式执行不在当前支持范围，必须明确拒绝或标记。
- 缓存值存在不代表本轮重算成功；退出码成功也不代表业务公式正确。

## 5. PPT

生成路径使用现有 PptxGenJS 或受支持模板；读取按页面和对象解析；修改优先限定文字或对象，不默认重建原稿。

视觉检查包括页面尺寸、文字溢出、对象越界、图片/字体缺失和关键页布局。渲染不可用时标记“视觉未检查”，不能宣布保真通过。

## 6. 与知识库的关系

Office 文件解析结果可进入项目知识库，但前提是用户确认入库，并绑定固定文件版本。聊天读取和知识检索可复用同一解析结果，但每次使用都重新检查权限、删除状态和版本有效性。

文件新版本不会静默替换知识库旧结论；重新解析完成后原子发布新片段，旧片段按策略失效。

## 7. 已知限制

- 复杂 Word 样式、页眉页脚、批注、Excel 外链/宏和 PPT 动画未完成全面保真。
- 扫描件 OCR 质量和低质量 PDF 仍需真实样本评估。
- LibreOffice 重算可能超时，且不能覆盖所有 Excel 公式。
- 无视觉渲染时不能认证版式。
- WorkBuddy 的专有引擎、代码和模板未复用；仅借鉴任务分流、参数化操作和保存后检查。
