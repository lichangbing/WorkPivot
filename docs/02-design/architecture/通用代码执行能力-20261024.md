# 通用代码执行能力 run_code（2026-10-24）

## 1. 背景与目标

用户要求：没有现成 Skill、也没有对应工具时，WorkPivot 能自己写代码（Python 等）解决问题，例如读取 PPT、处理文件、做自定义计算，而不是直接回答“做不到”。

已有的隔离执行链路（宿主 worker、一次性 Linux 容器、无网络、只读根文件系统、tmpfs `/workspace`、120 秒、2 并发、16MiB）本来就为 Skill 脚本准备，能力足够；缺的是一个不绑定 Skill 的通用入口。本方案新增 `run_code` 工具，复用同一条链路。

## 2. 现状与缺口（实现前核对）

| 场景 | 实现前状态 |
| --- | --- |
| 读取已上传的 PPT/PDF/Office | 支持：后台解析器（`.pptx` 分支）产出结构化文本，`read_uploaded_file` 分页读取 |
| 访问网页 | 支持：`web_fetch`（静态、无 JS）、`browser_visit`（动态页，需浏览器服务） |
| 读取本机任意路径 | 不支持（PostgreSQL 链路 `filePolicy: () => false`，没有宿主路径权限） |
| 自己写代码执行 | 只有 `execute_skill`：必须绑定已加载 Skill，且必须显式声明输入与产物 |
| 技能草稿试运行 | `trial_skill_draft`：技能作者路径，最多 8 次，产物不发布 |

缺口：模型遇到“没有专用工具”的任务时，只能绕道编造 Skill，或者放弃。`run_code` 填补这一格。

## 3. 决策

### 3.1 新增 `run_code`，不扩展 `execute_skill`

`execute_skill` 的语义是“按已加载 Skill 的指引执行”，授权卡、技能版本绑定、输入输出契约都围绕它成立。把 `skill` 变成可选会让同一工具的语义分叉，审批卡也说不清“执行的是什么”。因此新增独立工具，但**复用**沙箱客户端、产物发布事务与运行栅栏。

### 3.2 静默自动授权（用户确认）

PostgreSQL 链路原本没有“auto 档”：`requestPermission` 对每个写操作都弹卡。用户在方案确认时选择**不弹卡、直接执行**，理由是希望模型在无人工介入时也能自己解决中间步骤。

落地方式：工具在 `access()` 中声明 `auto: true`（由服务端代码固定，模型参数无法设置）；`requestPermission` 只对白名单内的工具（当前仅 `run_code`）直接写入一条 `consumed + allow` 的许可记录并返回 `automatic: true`，执行器不再等待人工决定。发布事务仍按同一调用摘要复核（`checkToolPermission`），所以“参数在等待期间被替换”这类风险依然被挡住。

补偿控制（重要）：

- 输入必须落在本轮已授权的文件版本范围内（`checkResourcesInTransaction`），未声明进 `inputs` 的文件根本不进沙箱；
- 产物必须声明并通过任务归属、revision、运行栅栏、执行日志状态校验，失败一律不回写；
- 无网络、无宿主路径、只读根文件系统、120 秒、2 并发、16MiB 由 worker 强制；
- 代码以工具调用事件形式保留在对话里（截断到 8000 字符），因为静默执行没有授权卡可查；
- 部署可用 `WORKPIVOT_CODE_APPROVAL=confirm` 恢复逐次确认，无需改代码。

风险：模型可以在无人工确认的情况下对“已授权文件”做非预期计算。由于没有网络出口、也不能写宿主路径，影响面限于计算时间、可删除的产物和已授权资料的读取；但“读到的资料被用来生成什么”不再有人工拦截点。这是本决策的已知代价。

### 3.3 网络：默认无，只按任务级白名单开放（未实现）

网页访问已有受控出口（URL 白名单、配额、审计）。给代码沙箱开任意网络等于绕过出口控制，并引入 SSRF 与数据外发风险，因此**不提供“全开着”的开关**。2026-10-24 产品决定：需要外网时按任务预授权一组域名，沙箱只能经出口代理访问这些域名，并逐条审计；实现方案与未实现原因见 4.1。默认仍是 `--network none`，提示词要求不得用代码代替网页访问。

## 4. 接口契约

```
run_code {
  language: "python" | "node" | "sh"
  code: string                       // ≤ 65536 字符
  inputs?: string[]                  // ≤10 个文件版本 ID；省略 = 挂载本轮授权的全部文件
  outputs?: [{ name, documentId?, revision? }]   // ≤10 个，name 只填文件名
}
```

- **工作目录（2026-10-24 追加）**：`inputs` 省略时，服务器把本轮授权范围内的全部文件（上传原件与已生成成果）按原名挂到 `/workspace/inputs/<版本ID>/<原文件名>`，并生成 `/workspace/manifest.json` 列出 `{versionId,name,size,path}`。显式填 `inputs` 只挂载这些版本。两种情况都受 16MiB 总量约束，超限时返回明确提示让模型收窄范围。
- 代码写入 `main.py` / `main.cjs` / `run.sh`，命令分别为 `python3 main.py`、`node main.cjs`、`/bin/sh run.sh`，工作目录 `/workspace`；
- `outputs` 为空时只返回标准输出（截断 16000 字符），沙箱内写出的文件全部丢弃；
- `outputs` 非空时必须写到 `/workspace/<name>`，任一缺失或版本冲突则整体不发布。

语言环境：Python 只有标准库与 Pillow；Node 通过 `NODE_PATH` 获得 `docx`、`exceljs`、`pptxgenjs`，且因 `NODE_PATH` 只对 CommonJS 生效，入口固定 `.cjs`、必须用 `require`。当前不能联网安装依赖。

### 4.1 联网（已定方案，未实现）

用户选择：**任务级预授权域名**，只放行 pypi/npm 等白名单。落地要点（尚未写代码）：

- 授权范围新增 `networkHosts`，随资源范围一起持久化；`run_code` 只能使用其子集，范围内没有域名时继续 `--network none`；
- worker 建 `--internal` Docker 网络 + 出口代理容器，沙箱只能连代理；代理按来源容器 IP 查本作业域名白名单，按 CONNECT 主机名放行并记录每条请求；
- 依赖安装仅允许 pypi/npm 域名，且需镜像内已有 pip/npm；
- 该方案必须先在 WSL/Linux 上验证容器网络与代理，本机无法测试，因此未实现。

## 7. 已知限制

- 静默执行没有人工拦截点，只保留对话事件与执行日志；
- 沙箱无网络、无 numpy/pandas/matplotlib，不能安装依赖，复杂数据分析能力有限；
- 工作目录是“本轮授权文件的快照”，不是宿主目录；要看服务器上的真实目录需要另行设计（曾评估只读挂载，未采纳）；
- 联网与运行时安装依赖尚未实现（方案见 4.1），当前只有 `--network none`；
- 单次 120 秒、2 并发、工作目录与产物各 16MiB；授权文件超过 16MB 时须用 `inputs` 收窄；
- 工具只在配置了 worker（`WORKPIVOT_WORKER_URL` + `WORKPIVOT_WORKER_TOKEN`）时出现，未配置时模型仍应说明“执行服务未配置”；
- 只在聊天/专家对话挂载；自动化计划使用独立工具集，暂未提供 `run_code`；
- `run_code` 与 `execute_skill` 的产物发布逻辑仍有少量重复，后续可合并为同一执行器。

## 8. 文件链路实现（当前主线，2026-10-24 追加）

前面的 3–7 节描述的是 PostgreSQL 链路。线上正式部署是文件链路，它有真实的用户工作目录（`<工作区>/.accounts/<用户ID>/<项目目录>`），因此 `run_code` 在文件链路另有一套实现。

- **工具**：`code/packages/server/src/code-tools.ts`。脚本写到工作目录的 `.workpivot/run-code/<时间戳-随机>/` 下（`main.py`、`main.cjs`、`run.sh`），用户可在文件树里看到并复核。
- **执行通道**：与 `bash` 共用 core 的 `executeShell`，由调用方注入，避免两套执行逻辑。
- **执行放置（C 方案）**：
  - worker 配置了 `WORKPIVOT_WORKSPACE_VOLUME` 时，请求改为 `mount.subpath`（任务目录在工作区卷内的相对路径），worker 用 `volume-subpath` 把**该任务目录直接挂成 `/workspace`**：不复制、不回写，文件实时可见，容器仍是无网络、只读根、非 root、512MiB、120 秒。
  - 未配置该卷时退回原「复制快照 + 回写」，worker 会回传“已回写/已删除”清单。
  - 曾评估的 `local` 模式（服务进程内直接执行）已撤回：与服务同 UID，可读其他账号工作区与 `/data/workpivot`，不适合多用户服务器。
- **子路径安全**：`workspace-mount.ts` 的 `workspaceSubpath` 拒绝工作区根、界外路径、含 `..` 的路径和超长路径；worker 的 `validateMount` 只接受相对子路径，卷名来自 worker 自身配置，请求不能指定卷。
- **并发**：`directory-lock.ts` 按工作目录排队，同一目录同时只有一个 `run_code` 执行（挂载模式没有回写冲突检查，串行是替代手段）。
- **镜像**：执行器镜像已含 `python3`/`py3-pillow`，C 方案无需改服务端镜像。

验证：`code/eval/run-code-file-chain.mts` 8 项（脚本落盘与命令拼装、node/sh 入口、Windows 拒绝 sh、参数与权限拒绝、审批摘要、同目录串行）；`code/eval/run-code-mount.mts` 6 项（子路径换算、越界与超长拒绝、worker 校验、请求体切换为挂载模式）。真实挂载与容器内读写仍需在 WSL/Linux 上验证。
