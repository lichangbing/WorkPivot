# 执行模式与授权矩阵（2026-10-24）

状态：执行模式已接线（`run_code` 生效），计划闸门、联网首次确认、文件链路统一仍待实现。本文件是已确认的产品口径，实现按此为准。

## 1. 两种模式

| 模式 | 定位 | 行为 |
| --- | --- | --- |
| **确认模式（manual）** | 更严格 | 进入执行前确认一次；联网首次确认一次；危险操作单独确认 |
| **自动模式（auto）** | 少打扰 | 只有危险操作才确认 |

未设置时按“自动模式”处理，不改变已有部署的行为。部署可用 `WORKPIVOT_CODE_APPROVAL=confirm` 强制确认，优先级最高。

## 2. 授权矩阵（数据库链路）

| 类别 | 工具 | 确认模式 | 自动模式 |
| --- | --- | --- | --- |
| 只读检索 | `read_uploaded_file` `read_document_structure` `list_uploaded_files` `list_artifacts` `search_project_documents` `read_document_citation` `search_memory` `read_memory` `search_expert_experience` `load_skill` `list_my_skill_builds` `get_skill_build` `get_automation_options` `list_my_schedules` | 不弹 | 不弹 |
| 联网读取 | `web_fetch` `web_search` `browser_visit` | 本轮首次弹一次 | 不弹（仍受公网/域名限制） |
| 生成成果 | `save_artifact` | 计划闸门覆盖 | 不弹 |
| 隔离执行 | `execute_skill` `run_code` `trial_skill_draft` | 计划闸门 + 首次执行确认 | 不弹 |
| 技能草稿 | `propose_skill` `revise_skill_draft` `validate_skill_draft` | 不弹（草稿需页面确认才生效） | 不弹 |
| 定时任务提案 | `propose_schedule` `propose_schedule_change` | 不弹 | 不弹 |
| 定时任务变更 | `pause_schedule` `cancel_schedule_run` | 弹 | 弹 |
| 外部 MCP | 任意 `external` 工具 | 每次弹 | 每次弹 |
| 删除类 | 目前数据库链路无删除工具（界面操作） | 界面确认 | 界面确认 |

## 3. 自动模式仍然确认的危险行为

1. 外部 MCP 调用（外部系统不可控，参数可能含敏感数据）
2. 取消/暂停正在运行的定时任务
3. 删除文件或覆盖已有成果（文件链路适用；数据库链路产物是新增版本，不会发生）
4. 访问任务目录之外的路径（文件链路）
5. 命中 `DANGER_PATTERNS` 的高危命令

## 4. 计划闸门

确认模式下，模型完成只读调研、准备进入执行时：

1. 第一次调用非只读工具前弹一次卡：展示计划摘要与即将执行的第一个动作
2. 用户允许后，**本轮**后续非危险动作不再逐次确认
3. 用户拒绝后，模型停止执行并说明原因
4. 闸门按“本轮一次”，新开对话重新确认

自动模式没有闸门。

## 6. 边界

- 执行模式不改变**权限范围**：能读哪些文件版本、能调哪些外部工具，仍由任务授权范围与工具白名单决定。
- 执行模式不能扩大 MCP 的可用范围；MCP 始终逐次确认。
- 用户拒绝不是“换工具重试”的信号：同一路径/同一动作不得绕过（见访问纪律）。
- 静默执行不减少审计：仍然记录 `run_permissions`（`consumed/allow`）、工具事件与执行日志。
- 文件链路与数据库链路的默认档位不同，统一前不要假设两者语义一致。
