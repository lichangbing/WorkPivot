## 1. 目标

Agent 循环负责把一次用户任务持续推进到可验证结果，而不是在模型首次生成文本后无条件结束。上下文工程负责在有限模型窗口内保留目标、约束、近期证据和工具调用配对，避免长任务因历史膨胀而遗忘或断链。

本设计要同时满足：

- 目标未完成时能识别“只表态、未行动”的早停并追问一次。
- 工具调用与结果保持合法配对，压缩不能破坏供应商协议。
- 长对话摘要由用户确认后才能替换活动上下文。
- 子任务使用隔离上下文，主循环只接收结论和产物引用。
- 授权、取消、恢复和模型重试不以牺牲副作用安全为代价。

不在本范围：无限上下文、自动改写历史原文、无审计的多 Agent 群聊。

## 2. 运行模型

```text
用户消息
  → 组装系统规则、有效记忆、资料范围和工具定义
  → 调用模型
  → 文本 / 工具调用 / 提问 / 完成
  → 工具执行、授权与结果持久化
  → 判断继续、早停补偿、压缩或结束
  → 核验成果并发布
```

每轮至少持久化运行标识、输入范围、开始与结束时间、模型用量、工具事件和停止原因。恢复时依据事件判断已经派发的副作用，不能重放不确定的写操作。

## 3. 循环策略

### 3.1 正常推进

模型返回工具调用时，由服务端统一校验参数、资源范围与操作权限；结果以结构化事件回到下一轮。只读工具在声明安全时可以并行，写入和执行工具必须独占或串行。

### 3.2 早停补偿

以下情况允许触发一次 `onIdle` 追问：

- 用户明确要求生成、修改、导出或执行，但本轮没有调用任何工具；
- 模型文字承诺“接下来会做”，随后却没有行动；
- 任务已有明确后续步骤，继续成本低于重新发起。

普通咨询问题不触发；最多追问一次，`idleLimit=0` 可关闭。`ask_user` 结束时不得再触发早停追问，否则会和结构化提问冲突。

### 3.3 模型流失败

仅在尚未输出任何增量时重试一次。已经输出后中断必须保留部分事件并按失败或中断处理，不能重放整段文本，否则用户会看到重复回答。

## 4. 两层上下文治理

| 层级 | 触发 | 处理 | 用户是否确认 |
| --- | --- | --- | --- |
| 循环内轻量压缩 | 接近单轮字符预算 | 修剪早期工具结果和旧助手文本，保留系统消息与最近完整轮次 | 否，可逆地省略内容 |
| 长对话检查点 | 跨轮历史接近模型容量 | 按完整轮次分批摘要，生成待核对版本 | 是，确认后才进入活动上下文 |

轻量压缩只替换消息 `content`，不删除消息，确保 `assistant(tool_calls)` 与 `tool(tool_call_id)` 的配对仍合法。长对话摘要保留原会话，不自动写入个人或项目记忆，也不能提升为系统指令。

### 摘要确认状态

```text
生成中 → 待确认 → 已确认
             ├→ 已拒绝
             └→ 已失效（来源删除、撤权或版本冲突）
```

未回复、超时、刷新或继续发消息都不视为同意。预算耗尽时保留输入草稿并提示确认；来源变化后旧摘要失效。原始事件、重放事件和旧检查点不得让已遗忘内容复活。

## 5. 工具面的边界

| 能力 | 接口 | 当前判断 |
| --- | --- | --- |
| 联网检索 | `web_search` | 已实现；只返回摘要，正文由 `web_fetch` 读取 |
| 结构化提问 | `ask_user` | 已实现；结束本轮，不代替授权卡 |
| 子任务 | `delegate` | 已实现单层同步版；父子上下文隔离 |
| 文件精确编辑 | `edit` | 已实现；要求唯一匹配或显式全量替换 |
| 后台长进程 | `process` / `write_stdin` | 暂缓；需要长期容器、通道回收和资源治理 |

工具不在多，而在于类别齐全、权限可解释、失败可恢复。新增工具必须说明真实副作用、资源范围、超时、取消和审计字段。

## 6. 关键不变量

1. 不删除未闭合的工具调用对，不从轮次中间截断。
2. 压缩摘要不携带新权限，工具结果和资料文本始终是不可信数据。
3. 模型文字“完成”不能代替文件存在、结构有效和读回核验。
4. 停止、撤权或来源删除后，等待中的模型和工具不得继续发布。
5. 子代理不继承超出父运行的权限，不能递归委派或自行请求用户授权。

## 7. 实现与验收

- `packages/core/src/loop.ts`：循环、结束原因、`onIdle`、工具结束语义。
- `packages/core/src/context.ts`：轻量压缩与工具结果修剪。
- `packages/server/src/database/compaction.ts`：长对话摘要、版本与确认。
- `packages/server/src/database/execution.ts`：数据库链路事件与工具编排。
- 自动化链路使用更严格的完成条件，不启用宽松早停补齐。

现有自动用例覆盖只表态继续、压缩后工具配对、无输出流重试、精确编辑、结构化提问、单层委派和父级取消传播。真实模型仍需覆盖长文约束保持、多次压缩、用户更正、来源撤销和恢复后继续。

## 8. 已知限制

- 字符预算是保守近似，不等于供应商精确 tokenizer。
- 轻量压缩省略的早期工具结果需要模型重新读取。
- 长对话摘要的递归来源链、极端超限和删除竞态仍需持续压测。
- 单层同步委派不能并行扇出、续聊或异步收取。
- 自动化任务暂不开放通用后台进程和 `run_code`。
