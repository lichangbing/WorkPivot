# PostgreSQL 与项目知识数据架构

日期：2026-09-13。状态：实施设计；PostgreSQL 选型已确定，代码和当前部署仍使用文件存储。按用户最新要求，不做旧数据迁移；RAG、版本管理和用户自主删除纳入核心范围。

## 1. 目标与边界

2026-09-13 补充：首版采用服务端集中存储、用户端轻量交互，各用户独立使用，项目组信息同步留待后续。数据归属、成员和权限预留以[服务端集中存储与项目组协作预留](服务端集中存储与项目组协作预留.md)为准；下文 owner_user_id 个人模型不应被实现为所有未来项目内容只能由项目所有者创建的约束。

项目是长期业务空间，任务是一次具体工作。用户上传、对话、生成成果可以持续沉淀为有来源、有版本、有适用时间的知识。查询和计算不依赖把全部历史塞入模型上下文。

服务端拥有主数据；桌面客户端保留连接设置、界面偏好和已交付成果的单向同步副本。过程材料不自动下载到本机。

## 2. 数据归属

| 内容 | 主存储 | 说明 |
|---|---|---|
| 账号、角色、会话、临时密码状态 | PostgreSQL | 密码仍为哈希；新会话只存令牌摘要及有效期 |
| 项目、任务、运行状态、计划、授权 | PostgreSQL | 事务更新、版本冲突检测 |
| 对话、工具事件、持久化运行记录 | PostgreSQL | 追加记录；分页和事件序号，不写成一个超大 JSON |
| 模型、MCP、技能发布、角色模板和设置 | PostgreSQL | 公共配置与私人配置分别建模；凭据字段加密 |
| 三层记忆、事实、决策、抽取结果 | PostgreSQL | 来源与版本可追溯 |
| 原始文档、上传附件、成果不可变快照 | 文件存储 | 数据库存元数据、归属、对象键、哈希和状态 |
| Skill 中可编辑文本 | PostgreSQL | 每个文件有版本；发布时生成不可变资源包 |
| Skill 二进制资源、模板二进制、解析大对象 | 文件存储 | 数据库存资源引用；脚本和模板可物化到执行目录 |
| 执行工作目录、缓存、临时文件 | 文件系统 | 不是知识主库；持久化、保留期和成果发布单独控制 |
| 应用配置中的数据库连接凭据、主加密密钥 | 部署秘密或环境配置 | 不明文进入业务表，不把解密主密钥放在同一数据库 |
| 调试日志 | 标准输出/轮转文件 | 安全和业务审计单独入库；不得记录密码、令牌和完整敏感正文 |
| 向量与全文索引 | PostgreSQL/pgvector | 可从已保存内容重建，不作为原始事实唯一副本 |

初期文件存储沿用服务器持久卷，通过统一 BlobStore 接口读写；未来可切换对象存储，不改变业务表。数据库保存对象键，不保存依赖宿主机的绝对路径。

## 3. 系统数据模型

以下为逻辑表组，精确 DDL、索引与迁移脚本在实施阶段提交。

| 表组 | 核心字段/用途 |
|---|---|
| users / user_credentials | 用户 ID、规范化唯一用户名、角色、密码哈希、需改密标志、停用状态、认证版本 |
| auth_sessions | user_id、token_digest、expires_at、revoked_at、认证版本；不持久化明文令牌 |
| user_settings / platform_settings | 个人设置与平台非敏感设置；明确版本字段 |
| projects | owner_user_id、名称、状态、说明、工作区键、revision |
| tasks | owner_user_id、project_id、标题、状态、是否临时、工作区键、revision |
| task_runs / task_events | 每次运行、序号、事件类型、JSONB 载荷、开始/结束时间、失败原因 |
| messages / message_parts | 消息角色、序号、正文、思考与工具内容分类、关联运行；附件单独关联 |
| plan_items / permission_grants | 计划步骤和授权范围、有效期、决策、关联任务/运行 |
| schedules / job_runs / notifications | 定时配置、执行记录、用户通知 |
| provider_configs / mcp_connections | 公共或个人能力配置，凭据加密，私密配置不能借管理接口泄露 |
| skill_packages / skill_versions / skill_files | 包、不可变发布版本、文本/二进制引用、草稿版本 |
| skill_catalog / user_skill_selections | 明确发布到公共市场的版本、个人加载选择；草稿默认私有 |
| role_memory_templates | 平台发布的默认角色记忆，不包含个人知识 |
| audit_events | 操作者、动作、对象 ID、时间、结果；只保存必要元数据 |
| outbox_events / background_jobs | 可靠后台处理、幂等键、重试、租约和失败状态 |

通用约定：服务端生成 ID；时间使用 timestamptz；关键实体有 created_at、updated_at、revision。新数据使用统一 UUID；无需兼容或导入旧文件中的历史 ID。关系与权限字段是普通列，不隐藏在 JSONB 中。

任务事件唯一约束为 (owner_user_id, run_id, sequence)。任务启动先在事务中验证/变更状态并创建运行和 outbox 事件，提交后调度。worker 通过租约/心跳处理崩溃恢复；长时间模型调用不持有数据库事务。

## 4. 项目资料与来源

| 表 | 核心内容 |
|---|---|
| documents | 逻辑文档、owner_user_id、project_id、名称、类别、可用/归档状态 |
| document_versions | document_id、版本号、blob_id、来源任务、上传时间、文档日期、哈希、解析状态 |
| blobs | owner_user_id、对象键、大小、SHA256、MIME、staging/ready/deleting 状态 |
| task_documents / message_attachments | 某次任务/消息使用的明确文档版本 |
| extraction_runs | 文档版本、解析器版本、抽取规则版本、模型标识、状态、错误、开始/完成时间 |
| document_elements | 标题、段落、表格、图注等内容元素，父子关系、排序和来源位置 |
| content_chunks | 可检索片段、关联抽取批次及元素、文本、标题路径、来源定位 |
| source_refs | 指向文档版本或对话片段的定位信息，使用显式外键和二选一约束 |
| artifact_versions / deliverables | 不可变成果版本、所属任务、文件对象、发布状态和当前交付版本 |

document_versions 与 extraction_runs 分开：同一原件可以重新解析，不能伪造成用户上传了新版本。新解析批次成功并通过基本校验后，事务切换 active_extraction_run；失败保留之前可用的索引与结果。

文件来源定位示例：PDF 页码及区域；Word 段落序号和标题路径（页码并非始终可靠）；PPT 幻灯片；Excel 工作表和单元格范围。对话来源定位到 message_id、part_id、文本范围。

附件默认属于当前项目，同时提供“仅本次任务”选项。临时任务资料不自动进入其他项目。跨项目引用必须显式选择并验证同一用户权限；不得通过全局搜索隐式打通所有项目。

## 5. 表格和结构化知识

抽取分为原样表格和标准化事实两级，不让模型直接覆盖唯一原始记录。

| 表 | 用途 |
|---|---|
| extracted_tables | 表格名称、所属抽取批次、工作表/页码、区域、表头、行列规模 |
| table_columns | 列标识、原始表头、推断类型、单位、业务含义、人工确认状态 |
| table_rows | 表格、行号、类型化 JSONB 值、来源定位；按行分页，避免整份工作簿一个 JSON |
| table_cell_metadata | 有需要的单元格公式、原始文本、缓存值、合并信息、数字格式；不为所有空白格建行 |
| business_object / business_object_alias | 企业、客户、人员等已消歧业务对象及别名；合并操作保留可撤销记录 |
| metric_definitions | 指标名称、允许单位、统计口径及定义版本 |
| business_fact_series / business_fact_revision | 稳定事实标识与不可变值版本；主体、指标、期间、数值、维度、口径、状态 |
| business_fact_evidence | 事实版本到 source_refs 的多对多证据关系 |
| decisions / decision_revisions | 项目决策、依据、适用范围、生效时间和替代关系 |
| extraction_reviews | 人工修正、冲突、确认/驳回记录及操作者 |

数值使用 numeric；原始单位和标准化单位分别保存，换算记录规则。日期使用 date/timestamptz；缺失值是 null，不当作 0。数值、文本、日期等事实值使用明确类型字段及约束，JSONB 用于灵活维度和解析细节。经常查询的通用字段必须独立列和索引；高频领域可增加发票、合同等专用关系表。

表名和生命周期以[业务事实模型与项目检索](业务事实模型与项目检索-20261028.md)为准：
`fact_series / fact_revisions` 是本节早期通用称呼，落地时分别使用
`business_fact_series / business_fact_revision`。前者只表达稳定逻辑事实，后者保存不可变值版本；
修改值不能覆盖原版本，也不能另起一条无关联事实。

示例事实：owner/project=A用户/A公司研究；主体=A公司；指标=营业收入；期间=2026-01-01至2026-06-30；数值=1260000000；币种=CNY；合并口径；来源=半年报第2版/利润表!D12；状态=待确认。

同一主体+指标+期间仍可能存在合并/单体、审计/未审计、实际/预测等不同口径，不能用简单唯一约束消灭这些记录。冲突建立关联并保留双方证据；发布时间、上传时间、事实适用时间和系统记录时间分开。人工确认结果不被后续自动抽取静默覆盖。

公式与计算值分别保存；未重新计算的缓存值不标为最新结果。统计和聚合由受限参数化查询/计算服务执行，大模型解释结果。模型不能直接连接数据库、运行任意 SQL 或读取凭据。

## 6. 三层记忆与检索

memory_entries 保存 owner_user_id、scope（user/project/task）、project_id/task_id、内容、类型、来源、状态、revision、有效时间、是否允许自动加载。用 CHECK 约束 scope 与作用域字段组合，再用复合外键验证归属。

记忆包括偏好、目标、工作口径、已确认结论；大文档正文与明细表留在资料库。自动抽取对话时标记用户陈述、用户确认、模型建议、假设，不把模型推测自动升级为事实。role_memory_templates 是平台默认指引，独立于个人数据，不能覆盖用户已确认知识。

新任务仅加载简短项目背景/用户偏好；根据当前问题通过知识工具检索片段、查询结构化数据并引用 source_refs。来源内容作为不可信资料处理，不得转成系统指令或执行其中命令。

检索先限定用户、项目、资料可用状态和版本；组合标题/关键词、全文、向量，再重排返回有限上下文。中文分词方案必须用实际中文办公资料评测，不能把 PostgreSQL 默认分词配置当作中文效果保证。

embedding_spaces 记录模型、版本、维度和距离度量；chunk_embeddings 按 embedding_space 存储，唯一键含 chunk_id 与模型空间。不同维度或模型不得混查；模型升级新建索引并重建后切换。先做小规模精确检索，规模增长后再评测 HNSW。近似索引过滤可能影响召回，需要专门测试狭窄用户/项目过滤，不能为了召回取消权限条件。

## 7. 权限隔离

私人业务记录使用 owner_user_id；项目资源以 project_id 归属项目、以 created_by/updated_by 记录操作者。首版 project_members 只有项目所有者有效成员；项目一致性外键阻止跨项目挂接，私人记录的复合外键阻止跨用户挂接。不能把创建者等于项目所有者作为项目资源的永久约束。错误响应不暴露其他用户记录是否存在。

HTTP 从验证后的会话获得用户身份；在连接池每次短事务中通过事务级上下文设置用户 ID，事务结束自动清除。缺上下文默认拒绝。不能用客户端请求体的 userId 作为权限依据，也不能把会话级 SET 留在可复用连接上。

业务查询采用参数化 SQL、显式作用域过滤，并以 ENABLE/FORCE ROW LEVEL SECURITY 防止遗漏过滤条件。数据库建表/升级角色与运行角色分离；运行角色不是表所有者、不具超级用户或 BYPASSRLS。RLS 是纵深保护，不能替代应用身份校验或阻止一个已经控制数据库凭据的攻击者任意设定应用上下文。

应用管理员有账号管理权限，但无个人业务表绕过条件。平台共享 Skill、角色模板和模型配置单独建表与策略，不能通过 owner_user_id=NULL 形成私人数据“公共”后门。后台 worker 只领取有明确归属的任务，执行结果以该用户/项目身份落库；文件下载同样先验证权限。

## 8. 文件与数据库一致性

1. 创建上传意图和暂存对象，设置大小、配额及超时；流式计算哈希。
2. 校验完成后先写入不可变最终对象，确认存在及大小/哈希正确。
3. 数据库事务登记 ready blob、document_version 和解析 outbox 事件。
4. 事务提交后 worker 才消费；数据库提交失败留下的孤儿对象由延迟清理回收，不能立即删除仍有上传意图的对象。
5. 消费采用至少一次投递和幂等处理，不能宣称跨数据库/文件事务 exactly-once。幂等键包含 owner、文档版本、解析器/抽取规则版本。

上传去重限定同一用户，不暴露其他用户是否持有相同文件。文件被成果、资料版本等多个记录引用时，删除一个引用不能删除仍被使用的对象。

删除先事务标记不可用，检索和下载立即过滤；再异步清理片段、向量和衍生关系。被删除来源支持的知识标记失效/需复核。保留期届满再回收无引用对象。备份有单独保留与删除策略；删除语义不承诺立刻擦除历史备份。

## 9. 部署、容量和备份

PostgreSQL 单实例先满足当前部署；连接池有上限，后台抽取作业限并发、可取消、可重试。仅内网连接后端与数据库，数据库端口不经过 Cloudflare 发布。不因引入数据库改为挂载 Docker socket。

数据库、文件对象、执行空间和缓存分别计量；设置用户配额、磁盘水位提示、上传限制。服务器上次已知仅余约3.5GB，实施前必须复查容量并准备足够数据库、索引和备份空间，不能直接按此余量假定可以扩展。

备份必须覆盖数据库、被引用文件以及独立保存的解密材料。初期暂停写入/后台发布，备份数据库和文件清单并记录共同恢复点；恢复到隔离环境核验所有 ready blob 引用、账号、任务、来源和成果哈希。后续增量/WAL方案需要与文件保留期配合。

## 10. 新建部署与实施顺序（不迁移旧数据）

用户已明确不需要迁移旧数据。采用全新数据库和独立文件存储命名空间，不开发旧 JSON 导入、双写或旧 ID 映射。旧部署不会因此自动删除；首次上线通过新环境配置验证，不把“不迁移”理解成授权清空旧数据。

### P1 系统数据库基础

插入 K01-D/K01-P：[会话项目删除与对话分页](会话项目删除与对话分页.md)。建模时加入 conversation_turns、删除作业与写入generation；删除会话/项目后清理关联后台数据，首次读最近5轮、上拉按游标取更早5轮。现有messages/任务表尚需补充这些字段与约束。

建立数据库结构版本管理、连接池、事务、repository 和用户隔离；账号/认证/配置、项目/任务/消息/运行/记忆/授权/调度等系统数据统一入库。使用新账号与新项目验收；旧客户端 API 尽量保持兼容。

### P2 项目 RAG 知识库与版本基础

建立 blob/document/version、来源记录、解析任务、文档元素、语义分片和 pgvector 索引。提供上传、解析进度、混合检索、带来源回答、资料新版本、分片纠错和原子发布。版本模型及删除标记从首期建立，不等 RAG 上线后补。

### P3 结构化数据与用户管理

Excel 原样表格、标准化事实、口径与冲突处理、数值查询计算；完成统一知识管理页面中的查看、编辑、差异对比、历史版本、停用、删除、清空记忆和防止自动重新记住。RAG、结构化查询与记忆加载使用统一有效性规则。

### P4 自动沉淀与端到端验收

纳入 K07 三层记忆自动更新：任务进度、项目事实/决策、明确个人偏好按层级异步增量更新；隐含偏好和冲突需确认。基础表与游标随 P1 建设，版本和遗忘规则先行。包括分层更新/加载开关、手动锁定、变更摘要、撤销、过期归档及提交前的删除/并发校验。详见[三层记忆自动更新](三层记忆自动更新.md)。

对话知识候选、项目知识自动复用、删除来源传播、并发版本切换、缓存/运行上下文失效、失败重试；完成项目全流程、权限、恢复和中文检索质量验收。显式跨项目引用可后续扩展，不默认开放。

详细补充见 [RAG知识库、版本与遗忘管理](RAG知识库、版本与遗忘管理.md)。

## 11. 验收门槛

- 新账号注册/登录、项目归属、任务状态、对话顺序、记忆内容、文件及成果版本数量/哈希核对。
- 成员、管理员、后台 worker、连接池复用和异常事务均不能串用户或项目；测试缺少上下文默认拒绝。
- 重复提交、同时改写、进程崩溃、数据库短断、磁盘不足、对象缺失、重试不会重复发布或丢失记录。
- 解析重跑和版本切换不把同一事实重复计入；待确认/冲突数据查询时状态明确。
- 数值可追溯到原表位置，文档和对话结论可引用原文；删除/失效资料不继续参与自动回答。
- 完成隔离环境联合恢复、新数据库后端的客户端协议回归和真实办公项目贯通验收。
