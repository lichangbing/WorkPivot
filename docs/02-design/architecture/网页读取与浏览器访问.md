## 实现方案与验收范围

- WebFetch 使用服务端 HTTP(S) GET，解析公开网页、文本和 JSON；返回标题、正文、链接、最终来源和截断状态，不执行网页脚本。文章使用 Mozilla Readability，列表等页面退回 DOM 文本。
- 浏览器使用独立 Playwright/Chromium HTTP 服务，无数据库、业务文件卷或 Docker socket；每次调用新建上下文，在一次调用内打开页面并执行有限的点击、滚动、等待，读取结果及可选截图。关闭上下文后不保留 Cookie。不接受任意 JavaScript、表单提交或登录指令。
- 两者只访问公网 HTTP(S) 标准端口；逐跳重定向及浏览器子资源校验，DNS 解析后固定连接地址，拒绝私网、环回、保留地址。浏览器请求经同一安全传输转发，禁止非 GET 请求、WebSocket、Service Worker 和下载。
- 对话调用沿用外部工具授权。自动化须显式配置网页来源 origin 白名单；旧计划默认无网页权限，确认后以计划配置快照执行；每次调用前后校验租约和撤销状态。浏览器子资源也受来源白名单约束。
- 截图沿用现有成果保存；自动化先暂存，成功后统一发布。Skill 脚本无网络沙箱不变。
- 校验实际正文/编码/重定向/大小限制/取消、SSRF/DNS 固定连接、动态渲染/点击/滚动/截图、隔离/资源释放、对话工具授权和自动化授权范围。真实模型和部署结果单独记录，不用模拟结果替代。

## 2026-10-18 待发布行为：对话WebFetch跳转需重新确认
