## 1. 两个根，不要混

| 根 | 位置 | 性质 |
|---|---|---|
| **数据根** | `~/.workpivot/`（Windows: `%USERPROFILE%\.workpivot`），env `WORKPIVOT_HOME` 可覆盖 | 隐藏目录：账户/配置/转写/审计/日志——**不产出交付物** |
| **工作区根** | `~/WorkPivot/workspace/`（B01 默认，用户可配；每任务一个子目录） | 用户可见：AI 产物直接写盘，资源管理器立即可见 |

## 2. 数据根目录树（M0 全集）

```
~/.workpivot/
├── config/
│   ├── settings.json            # 用户设置：权限档位默认/语言/主题/工作区根路径
│   └── providers.json           # 模型供应商注册表（C02/C03）：base_url/modelId/
│                                #   apiKey(密文,safeStorage)/验活状态/健康账本
├── data/
│   ├── users.json               # 账户：{username, bcryptHash, role, createdAt}
│   │                            #   （首用户=admin，注册开关；A01/J01 单机版）
│   ├── sessions/
│   │   └── index.jsonl          # 会话索引（追加）：{sessionId, taskId, title,
│   │                            #   status, createdAt, updatedAt}
│   └── tasks/<taskId>/
│       ├── task.json            # 任务元数据：{工作目录路径, 模型, 状态(running/
│       │                        #   interrupted/done/stopped), createdAt}
│       ├── transcript.jsonl     # 转写（F01）：用户消息采样前落盘；行结构见 §4
│       └── PROGRESS.md          # 长任务进度档（F04 断点续跑读；AI 维护）
├── audit/
│   └── audit-YYYY-MM-DD.jsonl   # 审计（I03 按天）：时间/会话/用户/工具/参数摘要/
│                                #   decision/界外授权记录
├── skills/                      # 全局技能目录（D01 双层发现之一）
├── logs/
│   └── YYYY-MM-DD/              # 三源日志（K03）：{react,node,main}.log 按天滚动
└── tmp/                         # store 层原子写中转（tmp→rename）；启动时清理
```

**M0 明确不建**（到 M1 再加，防目录蔓延）：`memory/`（E01/E02）、`index.db`（SQLite+sqlite-vec，E03 搜索）、`file-history/`（B03 快照完整版，M0 由任务内 PROGRESS 纪律替代）、`archived_sessions/`。

## 3. store 层约定（K02，唯一写入通道）

1. **原子写**：`writeAtomic(path, data)` = 写 `tmp/` 同盘临时文件 → `rename` 到目标；
2. **.bak 兜底**：覆盖前把旧文件改名为 `.bak`（保留一代）；
3. **坏文件隔离**：读取解析失败 → 原文件移入同目录 `*.corrupt` + 告警日志 + 回退 `.bak`；
4. 所有持久化代码禁止绕过 store 层直接 fs 写（W4 CI 依赖检查不含此项，代码评审盯）。

## 4. JSONL 行结构（转写/索引/审计通用）

```jsonc
{ "ts": "2026-09-07T09:00:00.000Z", "ordinal": 42, "kind": "...", "payload": { } }
```

- `ordinal`：会话内单调递增，重建顺序的唯一依据；
- `kind` 枚举（M0）：`user_message` / `assistant_message` / `tool_use` / `tool_result` / `event`(过程叙事/核验/收尾) / `meta`(任务状态变更)；
- **用户消息在进循环前写入**（kill 后可恢复）；
- parentUuid 链：M0 不加（平铺+ordinal 够用）；T3-01 开工时决定是否预埋（前向兼容项，见 tasks-m0 §5）；
- 每行 UTF-8 / LF，单行一条完整 JSON（不 pretty print）。

## 5. 命名与安全

- taskId：`t-<yyyyMMdd>-<短随机>`；sessionId：`s-<uuid短码>`；
- **密钥永远密文**：providers.json 的 apiKey 经 safeStorage 加密（I04），界面显示打码；审计日志只记参数摘要与命令哈希，不记原文敏感值（I03）；
- 文件名落盘一律走 B02 版本纪律（`{标题} v{X.Y} {日期}.{格式}`）——那是工作区交付物，不在数据根。
