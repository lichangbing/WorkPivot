# 长对话压缩与确认：下一批实施边界

状态：2026-09-16，摘要确认、每模型容量配置和分批整理已实现并部署 WSL（schema v23）。容量由管理员填写，不自动识别模型窗口；按 UTF-8 字节保守估算。现有三层记忆确认与本功能分别验收。下文为目标范围，实际交付边界见 PostgreSQL 适配清单最新记录。

## 使用流程

1. 服务端在启动下一轮之前计算上下文预算。预算包括系统说明、已加载技能、工具定义、有效历史、新消息及输出预留；不能只看浏览器已加载的五轮消息。优先使用模型配置的窗口上限，未知时采用明确标注的保守上限。
2. 接近阈值时，保留最近五个完整轮次，对更早的连续范围整理摘要。每个轮次中的工具调用与结果必须成对保留或一起压缩。单轮已超限时明确提示处理，不从中间截断工具调用。
3. 在聊天区域显示“请核对对话摘要”，列出覆盖轮次、目标、关键约束、已完成事项、待办、用户更正和文件版本引用。用户可查看原对话、修改后确认、拒绝或重新整理。
4. 只有明确点击确认才使用摘要替换模型活动上下文。未回复、刷新、继续发送和自动执行模式均不代表同意。摘要待确认且预算不足时保留输入草稿，暂停新增模型执行。
5. 摘要不删除原聊天、不自动写入个人或项目记忆，也不代表资料已经解析或产物已经存在。

## 服务端持久化与竞态

- PostgreSQL 保存摘要检查点、版本、用户/任务归属、状态、覆盖轮次边界、源内容指纹、知识 epoch、模型生成稿及用户确认稿。使用现有 RLS 用户隔离。
- 状态覆盖生成中、待确认、已确认、已拒绝、已失效、失败；生成作业具备租约与 fencing，刷新或服务重启可恢复状态，过期生成结果不得覆盖新版本。
- 生成前拍摄来源快照，完成和确认时再次检查。新增范围外对话保留为近期历史；不能因摘要生成期间新增消息而漏掉这些消息。来源内容被修改、删除或撤销时拒绝旧确认。
- 原已确认检查点在新摘要待确认或失败期间保留；只有新版确认后才替换。摘要递归整理时必须保留完整来源关系，不能只引用上一段摘要而丢失原始来源。
- 删除任务/项目要清除相关摘要正文；删除记忆或资料导致来源上下文撤销时，同事务让相关摘要失效并清除可能保留的已删除内容。历史版本也适用，不能成为遗忘漏洞。
- 摘要作为带明确来源标识的参考上下文，不能提升为高优先级系统指令。摘要生成阶段不执行工具，不把附件或用户文字中的指令当成摘要器自身命令。

## 分步交付与验收

1. 预算计算、持久化检查点与状态机；测试跨用户不可见、版本冲突、源删除、重启和超限保护。
2. 摘要生成与确认 API、聊天区确认卡片；测试拒绝不生效、用户编辑优先、重复确认幂等、源变化拒绝和输入草稿保留。
3. 接入每轮上下文组装与自动触发；测试连续两次压缩、工具调用配对、新增消息不丢失、摘要失败恢复和删除后不回流。
4. WSL 独立真实模型长对话验收，检查早期约束、更正、待办和文件版本引用仍可准确使用；随后再按用户请求发布公网。

文档解析、向量召回、多用户调度和项目协作不扩展到本批。

## v23 分批整理交付边界

- 管理员在模型管理填写上下文容量，默认 65536，范围 12000—1000000；旧客户端省略字段时保留已有配置。全局 WORKPIVOT_CONTEXT_BUDGET 作为容量上限，未设置时为 1000000，实际取其与模型配置的较小值。并非精确 Token 计数，估算仍预留 8192 回复空间。
- 每批保持完整用户轮次及工具调用配对，逐批合并前批摘要，显示已处理/总批数。只有全部完成、来源校验通过后生成一份待确认稿；中间摘要不进入活动上下文。
- 每批最多等待 120 秒并续租 3 分钟；来源失效或租约过期不能恢复旧结果。失败后手动重试从头整理，不支持中间批次断点续写。
- 原始历史读取上限仍为 2 MB，最多 64 批；单轮超过批次预算、最近五轮本身过大时明确报错。提高配置必须以模型服务实际支持的容量为依据。
- W38 449/449 通过；实际模型两批摘要及确认后续聊通过，保留标题更正、金额单位、未完成库存核对。首次实际调用无正文失败，专项重试成功。模型配置浏览器模拟接口验收通过保存和回显 32000。
