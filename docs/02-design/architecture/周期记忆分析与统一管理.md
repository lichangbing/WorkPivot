# 周期记忆分析与统一管理

## 已确认范围

个人记忆按“用户＋项目”隔离；个人和项目周期都在同一项目内跨任务累计，每10轮分析一次。模型只提交待确认建议，用户确认后保存。统一记忆管理负责查看、修改、删除、建议确认以及分析进度和失败处理。任务记忆继续逐轮提取。

一轮指用户消息对应的成功完成运行；同一对话轮次的重试只计一次，失败、停止、工具调用和自动化执行不计数。无项目任务仅进入个人周期。同一用户的不同项目分别累计，个人周期不跨项目，也不跨用户读取。Schema 52 将旧全局个人批次停用，已有运行不补入新周期；项目已累计的进度保留。

## 数据与后台流程

- `memory_analysis_turns` 以用户、层级、归属、轮次组成唯一键。保存轮次和运行标识，不复制聊天原文。按完成时间排序，每十轮领取为一个批次。
- `memory_analysis_batches` 保存范围、状态、尝试次数、租约、完成时间和简短错误。用户级事务锁串行分批，领取作业使用行锁与租约标识；程序重启后可以恢复到期作业。模型失败可在页面重试，失效来源不可重试发布。
- 每批读取十轮用户原话，对照同范围已有记忆和待确认/已拒绝建议。个人提取稳定偏好与明确个人事实，项目提取背景、目标、约束、决策；不能用助手推测或单次要求臆造长期用户特征。
- 每批最多生成3项新增或修改建议，展示理由、原文依据和修改前内容。模型调用以“记忆整理”计入现有用量。无新增价值时记录完成且零建议。
- 新建议复用 `memory_suggestions`，记录 `analysis_id` 和暂存理由；确认、拒绝、过期时清除理由及临时上下文。保存的记忆继承十轮来源，以便后续删除/遗忘控制。确认前再次验证全部来源、归属、开关、版本及目标锁定状态。
- 相同个人事实与项目事实均仅在对应项目内跨任务去重，临时任务个人范围单独去重；拒绝建议保留既有去重摘要，避免同义建议反复弹出。模型语义去重仍可能不完美，最终由用户决定。
- 逐轮 `MemoryWorker` 仅发布任务层建议，避免和周期个人/项目分析重复。

自动整理总开关及各层“自动更新建议”开关继续生效；来源范围被撤销、任务/项目删除或上下文失效时不能重新保存原内容。已保存记忆仍使用原有修订、回收站和模型上下文失效机制，删除保留30天后由用户确认永久删除。

## 页面与管理

入口：设置 → 记忆管理。

- 已保存记忆：切换个人、项目、任务；项目与任务层跨归属列出完整正文和名称，支持分页、新增、修改、删除。个人记忆提供全部归属、具体项目、临时任务范围及待指定归属筛选；新增需明确选择归属。旧全局个人记忆需选择归属并点击“确认归属并启用”。个人为空时明确说明为空，不将其他层条目误展示为个人记忆。
- 待确认建议：显示归属、建议理由、原文依据、原有内容；支持修改后确认、直接确认和拒绝。确认后回到已保存列表可见。
- 分析与设置：个人和各项目累计进度、总开关、各层开关、最近50条周期分析记录及失败重试。未累计的个人进度显示0/10；尚未产生计数的项目在首次有效轮次后出现。
- 动态与资料中的原记忆入口继续可用，删除统一采用页面内确认，不再依赖 Electron 原生确认框。

正文详情不会写入分析日志。批次状态与建议决定属于管理记录；手动修改和删除沿用原有修订/outbox记录。分析完成不表示记忆已保存。

## 限制与故障行为

不截断十轮原文后假装完整分析：原文总计超过80000字，或既有记忆超过100条/80000字时，批次明确记录原因，不自动保存。模型输入上限也受实际服务限制。单次分析120秒超时，输出最多24000字符；到期执行最多恢复3次。用户可重试模型失败，来源失效则等待新十轮。

运行队列复用已有后台周期，默认约10秒触发；模型调用和排队期间不是严格实时更新。当前管理接口按50条分页展示记忆，分析记录展示最近50条。此实现没有将记忆改存为 AGENTS.md，个人/项目/任务记忆仍存于服务器数据库。

## 验证与部署

验证结果和本地发布版本记录在 `docs/03-project/tasks-postgresql-knowledge.md`；数据库回归使用隔离容器与合成模型输出，界面回归使用真实 Electron 和隔离服务，不改动业务记忆。真实模型对长期偏好的归纳质量仍需在实际使用中观察，不能把合成流程验证视为抽象准确率验收。

后台继续沿用 PostgreSQL 队列，未引入新调度组件。`FOR UPDATE SKIP LOCKED` 仅用于作业领取，用户查看记忆仍使用正常一致性查询；取舍依据为 [PostgreSQL 16 SELECT 官方说明](https://www.postgresql.org/docs/16/sql-select.html)。租约与唯一键在应用层补充重启恢复、重复执行保护。

## 已确认修订：个人记忆按项目隔离（2026-10-19，已实现）

个人记忆改为“用户＋项目”范围，同一项目内跨任务每10轮分析；无项目任务使用独立临时任务范围。项目记忆与任务记忆原有范围不变。旧全局个人记忆保留正文但暂停加载，用户在管理页面指定一个项目或临时任务范围后启用，不自动复制。管理页面提供归属展示、项目筛选和旧记忆归属确认。旧全局个人分析待办失效，新个人周期从本次升级后开始，避免将跨项目历史批次重新用于抽象。验收重点是检索、建议修改/确认、周期证据及界面所有入口的跨项目隔离。

Schema 52 使用 `legacy_personal` 标识旧全局记忆，模型检索与建议修改均排除该标识。指定归属递增修订、写入现有 outbox 管理记录，并检查版本与项目权限；不允许借拆分功能转移归属。项目删除时，该项目的个人记忆也随项目进入回收站；无项目的个人记忆不受影响。
