# RAG 知识库、版本与遗忘管理

日期：2026-09-13；最近更新：2026-10-28。状态：核心链路已实现，当前实例未启用。

依据当前产品边界：不迁移旧数据；RAG 只用于非结构化文档检索；对话、记忆和业务事实保留在 PostgreSQL 权威链路，不默认进入向量库。

## 0. 当前定位

RAG 不是“长期记忆”的同义词，也不是所有数据的统一真相层。

- 当前任务中的少量资料直接解析读取。
- 公开网页即时抓取通过 `web_fetch` 或浏览器完成，默认不持久化。
- 用户偏好、项目约定和任务结论进入三层记忆。
- 金额、日期、合同状态和对象关系进入版本化业务事实。
- 只有大量、长文档或跨任务复用的非结构化资料才启用文档 RAG。

截至 2026-10-28，线上实例没有文档、知识分片和向量空间，因此关键词/向量混合检索代码虽然存在，实际不会召回项目资料。Agent 对 `search_project_documents` 的调用属于按需工具，不是每轮自动注入。

原始文件、不可变版本、失败恢复和派生事实复核边界见[原始文件与多版本文档管理](原始文件与多版本文档管理-20261028.md)。

## 1. 用户体验与存储边界

项目包含长期资料、结构化数据与记忆，任务按需使用。用户日常无需手动翻找材料；系统先检索有效片段和数据，再据此回答或生成成果。无法找到足够证据时明确提示，不用模型猜测补齐。

原始文件和原始对话仍保留为独立来源，用于点击出处、查看片段上下文、核对解析错误和重新解析。RAG 索引不是原件的完整替代，分片、向量和摘要均可重建。用户可以另行删除来源，界面说明影响。

文件存储保存原件和不可变成果；PostgreSQL 保存来源版本、片段正文、结构化数据、记忆、编辑记录、权限和发布状态；pgvector 保存向量索引。用户界面统一称“项目知识库”，不要求用户管理向量。

## 2. 入库与检索

上传文件/选定对话 → 保存来源 → 解析 → 过滤无关内容并生成候选 → 用户勾选确认 → 仅所选内容语义分片/表格识别 → 校验 → 向量化 → 发布可检索版本。

项目知识库只接收文本类检索内容，且默认不入库。未确认的资料仍属于当前任务，但不生成项目知识分片，也不进入默认检索。原始对话、思考与工具日志、临时网页、记忆、业务事实和未勾选章节都不自动入库。Excel 数值和公式走结构化查询，不默认转成文本 RAG。

- 分片优先按标题、章节、段落和表格边界；超长段落再按 token 拆分，并保留有限重叠。初始试验范围为每片400–800 tokens、重叠50–100 tokens，最终参数由中文办公资料评测确定。
- 每片保存 owner_user_id、project_id（任务私有资料可为空）、document_version_id/对话来源、解析批次、chunk_revision_id、标题路径、排序、来源坐标、内容哈希。
- 保存父级结构与相邻片段关系，检索命中后按预算扩展上下文，避免只拿半句条款。表格保留表头、单位及来源；统计计算走结构化查询，不由相似文本拼凑数值。
- 关键词与语义检索结合，模型选择、向量模型及维度有版本。重用未变片段向量时仍建立新版本的正确来源关联，不能跨用户去重泄露信息。
- 检索、重排、数据查询、自动记忆加载都先约束用户、项目、资料状态、有效版本和删除标记。模型只看到获准的结果，返回引用对应具体版本。
- embedding 服务失败时展示“索引处理中/失败”，支持重试；不能把未完成向量化的版本悄悄标成完整可用。人工修改的结构化数据/记忆可以先独立生效，RAG 显示其索引状态。

## 3. 统一版本模型

稳定逻辑 ID + 不可变 revision + 当前生效指针。编辑不会原地覆盖唯一记录，历史版本也不会自动参与默认检索。

| 对象 | 如何更新 | 历史与来源 |
|---|---|---|
| 原始文件 | 上传时明确选择“新增资料”或“更新已有资料” | 创建 document_version，同名不自动合并 |
| RAG 内容 | 修改解析文本生成新的 chunk_revision/知识覆盖层 | 保留原始解析值，标记“用户修订”，不冒充原文 |
| 结构化数据 | 改值、单位、期间或口径形成新的 fact_revision | 显示修改者、原因和源单元格 |
| 对话 | 原始记录保留；纠正通过新的消息或知识修订表达 | 原对话不是可被无痕篡改的事实 |
| 记忆/决策 | 编辑生成新 revision，保存范围与确认状态 | 用户确认优先于自动抽取候选 |
| 解析器/向量升级 | 新建处理批次/embedding space | 不伪装成新上传文档 |

记录 revision_no、parent_revision_id、created_at、created_by、change_reason、content_hash、状态。另存业务适用时间，不把更新时间等同于事实发生时间。同一指标不同期间、主体、统计口径为并存事实，不当作覆盖更新。

编辑请求必须携带 expected_revision；乐观锁冲突返回409，界面显示差异并允许合并/重新应用，禁止后保存者静默覆盖。批量修改表格采用同一 revision_set，以事务整体发布，避免一半新数值、一半旧口径。

版本状态：draft → processing → ready → active；failed 可重试；旧版本标记 superseded。用户可见“准备中、当前使用、失败、历史、已停用、已删除”。索引批次完成后事务切换当前指针并增加 knowledge_epoch，检索不混用新旧片段。

准备新文件版本时，原有效版本可继续服务，但明确显示当前仍在使用旧版。若用户说明旧内容错误，可立即“停用旧版”，处理失败也不能恢复引用错误资料。已发布的事实/记忆修正立即生效，不能被旧索引覆盖。

回退历史版本通过创建一个新修订并重新发布完成，保留操作轨迹。历史检索必须显式指定版本/时间；已删除或被遗忘内容不能借历史入口或回退重新出现。

## 4. 删除、遗忘与防止再次记住

提供不同范围的明确操作，不把关闭自动加载当作删除：

| 操作 | 行为 |
|---|---|
| 停用 | 保留内容和历史，立即退出检索与自动加载，可恢复 |
| 删除一条记忆/知识 | 该逻辑条目及所有历史修订退出使用，记录遗忘规则，清理关联向量与缓存 |
| 删除一个版本 | 用户确认后移除指定版本及其分片、向量和引用；删除当前版后不自动启用旧版，需用户选择 |
| 删除整份资料 | 原件、所有版本及派生片段/向量/抽取数据进入删除流程；标记依赖知识需复核 |
| 清空任务/项目/个人记忆 | 按选定范围批量遗忘，并设置自动学习截点，避免从旧对话重建 |
| 清空项目知识库 | 明确包含哪些原件、数据、记忆和历史版本；展示数量与范围后确认 |

“删除记忆”默认不删除原始对话和文件，但必须阻止该信息继续从已知来源被自动检索和重新抽取。删除弹窗默认选中“今后不再从这些来源自动记住”，展示关联来源并允许用户进一步删除原始资料。

建立 forget_rules，含用户/项目范围、逻辑知识 ID、已知 source_ref/来源版本、实体指标范围（适用时）、删除时的学习截点。规则尽量保存标识和必要匹配信息，不保留被删正文或原文向量。检索扩展相邻片段时同样处理被抑制来源。

从原文只遗忘部分内容时保存来源区间屏蔽；无法可靠界定时暂停相关片段，提示影响。后续重新分片必须映射并继续应用规则；映射失败则待核对，不能默认放行。再上传相同内容或对话重跑不得自动恢复；新的来源有相似信息时提示用户确认。无法保证识别所有改写表达，不宣称“删除一个概念后任何新资料都不会再提到它”。

用户明确选择“重新允许学习”才解除规则并创建新记录；普通版本回退不能解除遗忘。

系统采用先逻辑失效、后物理回收：删除接口成功前事务完成失效标记和 epoch 更新；所有读取即刻过滤，不等待向量清理。后台异步清理内容、历史修订、向量及对象引用；失败可重试，并展示清理状态。

可选回收站与彻底删除分开。回收站中的内容不被检索；“彻底删除”清除在线库正文和历史内容，审计只保留操作/对象ID等必要元数据。仍有其他合法引用的对象按引用管理，不能误删其他资料。

备份受独立保留期约束，不承诺即时擦除所有备份。恢复后对外开放前重放独立保护的删除/遗忘记录，避免恢复已删除内容。既有对话回答、已生成成果及用户已下载副本不会被静默重写；界面提供删除相关服务器副本的范围选择，并说明本地副本需用户自行处理。

## 5. 防止旧缓存与运行任务继续使用

- 每个用户/项目维护 knowledge_epoch，缓存键包含作用域、版本和 epoch。每次返回前验证所用来源仍有效，不能只在首次检索检查。
- 在任务运行中记录本次引用版本和来源关系；版本变化时重新检索或提示基于旧版。用户删除/停用命中的来源时取消相关进行中生成，清空检索上下文，下次继续用新状态构建。
- 已流出的文字无法收回；应明确标记该次回答受资料变更影响，后续输出和成果发布不再继续依赖已删除来源。
- 旧消息自动摘要、任务续跑、项目自动加载、会话压缩、工具响应缓存均使用同一遗忘过滤，防止向量删除后从其他入口回流。

## 6. 表结构补充与接口

在主架构表上补充以下逻辑对象：

- knowledge_items / knowledge_revisions：文本知识统一逻辑标识、不可变修订和生效指针。
- chunk_revisions / retrieval_releases / retrieval_release_chunks：片段修订、原子发布批次及有效片段清单。
- revision_sets / revision_set_items：一次表格/知识批量调整的发布边界。
- provenance_edges：记录文件版本/对话/片段/事实/记忆之间的派生依赖；使用类型化外键，不能靠自由字符串绕过归属校验。
- forget_rules / deletion_requests：作用域、来源抑制、删除范围、在线生效时间、清理状态。
- knowledge_scope_state：用户/项目 epoch、自动学习截点和自动沉淀开关。
- retrieval_runs / retrieval_run_sources：任务使用的确切版本；按需保留最少检索元数据，不复制被删正文。

主要接口语义：项目知识分页搜索；资料上传/更新/重新解析；修订创建（带 expected_revision）；查看历史/差异；发布/停用/回退；删除范围预览和执行；查看清理状态；恢复回收站与显式解除遗忘。所有接口使用服务端认证身份，普通用户可管理自己数据，管理员不能代看其他用户内容。

模型侧提供 search_project_knowledge、get_source_context、query_project_data、propose_memory；写入候选与已确认数据分开。自主永久删除不由模型凭空执行，用户在管理页确认，或通过明确的用户删除指令和范围预览执行。

## 7. 页面规划

项目入口“知识库”：资料、数据、记忆、待核对四个页签。提供名称搜索、类型、状态和时间筛选，显示当前版本/更新时间/处理状态。

详情页：内容、来源、版本历史、差异。操作包含编辑、保存新版本、停用、删除；数据表支持单条和批量修订；记忆可按任务/项目/个人筛选、批量删除和关闭自动沉淀。

删除前显示将影响的片段、数据、记忆和历史范围，不只写含糊的“确定删除”。完成后显示“已停止使用”，另显示物理清理进度；回收站恢复与“重新允许学习”明确区分。

## 8. 验收用例

1. 上传文档后，新任务可直接通过检索回答并引用原文，无需重新上传或人工寻找。
2. 上传V2后默认只用V2；准备期间清晰显示仍使用V1；显式历史查询可查V1，不能混算两版数据。
3. 连续修改三次数值，当前查询只用最新有效值；差异与来源完整；回退形成新修订。
4. 两个窗口同时编辑产生冲突提示；批量表格修改全部成功或全部不发布。
5. 新索引构建失败不丢有效数据；用户停用错误旧版后失败不能重新启用旧版。
6. 删除记忆后，新对话、旧任务续跑、自动摘要、重新解析、相同文件再上传均不从已知来源重新引入。
7. 删除当前资料版本不自动回落历史内容；彻底删除不允许用历史入口、回退或缓存找回正文。
8. 删除发生在生成中时，相关运行取消；延迟索引清理不影响立即停止检索。
9. 删除后从备份恢复，先应用遗忘记录再开放服务；不同账号所有上述操作互不影响。
10. 普通用户、管理员、后台worker都必须遵守个人空间边界；答案对无证据或冲突明确说明。

以上能力作为RAG首版设计约束，分批实现但整体验收完成前不宣称“长期知识与遗忘管理已完成”。
