# 会话、项目关联清理与对话分页

日期：2026-09-13。状态：K01-D/P分批开发中；文件版任务/项目删除已交付，数据库删除及轮次分页已有独立接口验证，完整执行清理与前端分页尚未接通。客户端仅负责展示，后台负责永久业务存储与清理。

实现进度：[K01数据库基础记录](../../03-project/K01-数据库基础实现记录.md)。第三批新增v2轮次/事件、固定5轮分页、轮内事件和正文分段、增量补拉，W38共109项通过；以下设计包含仍待开发的完整目标，不代表公网已支持。

## 1. 删除会话和项目

这里“会话”指任务对应的业务对话，不是登录令牌。普通项目会话和临时会话均可删除；项目删除包含其下全部会话，不再要求用户先逐个删除。

新需求取代旧实现中“项目只移除元数据、不删工作目录、有任务不能删”的行为。删除操作需由本人发起，确认窗口说明范围和不可恢复的在线数据清理；删除不是单纯列表隐藏，也不默认将正文永久留在回收站。

| 删除对象 | 后台清理范围 |
|---|---|
| 会话 | 任务、运行、消息正文/思考/工具事件、计划、授权、会话附件引用、会话私有文件、成果及历史版本、任务记忆和修订、该会话的RAG片段/向量、待处理作业 |
| 项目 | 项目信息、成员关系、全部会话及上述数据、项目资料和所有版本、结构化数据、项目记忆/知识、相关索引、定时任务、通知与项目文件 |

清理所有记录的对象引用后回收无其他有效引用的文件。多个会话可能共用项目工作目录，删除会话不能直接递归删除整个目录；通过文件对象清单、归属和引用判断。删除项目仅清理其专属受管目录，拒绝工作区根目录、上级目录、越界路径和符号链接替代路径。保留被其他合法会话/项目显式引用的资料，同时向用户显示保留的共享对象范围。

如果会话内容已沉淀为项目/个人记忆：清除该来源的派生片段、向量和关联；只有此来源支持的自动条目删除或失效，独立人工内容或仍有其他来源的条目需复核，不能误删无关个人记忆。候选、自动摘要和旧事件重放遵守遗忘规则，不能再次恢复被删除内容。

### 删除协议

1. 校验身份和归属，生成可预览的清理范围。
2. 短事务标记项目/会话 deleting，增加作用域 generation/knowledge_epoch，禁止新消息、新文件、新运行及新学习结果提交；创建唯一删除作业。项目删除需同时阻止并发创建子会话，所有子写入遵守同一项目锁/状态规则。
3. 立即取消关联模型流、执行器作业和定时触发；在途生成结果、上传回调或索引结果提交前重新检查 generation，失效结果不得重新写回。
4. 先清理数据库正文及衍生数据，再处理对象存储。删除作业提前保存最小清理清单，不能删除元数据后丢失文件位置。批量异步清理幂等可重试；FK级联只处理数据库内关系，不能替代文件/索引清理。
5. 正文与文件清理成功才标记 completed；失败显示 pending/failed，可自动重试。删除API返回202及operationId，前端立即移出可用列表并显示“正在清理”，不得将已隐藏误报为已彻底清理。

后台只保留必要的无正文操作审计、删除标记与作业状态，用于幂等和防重学。状态接口鉴权并限制操作者，不能泄露他人对象是否存在。重复删除返回相同操作或已完成结果，不重复创建清理任务。

备份按明确保留期清理，恢复后先重放删除记录再开放服务；不承诺即时擦除历史备份。已经下载或同步到用户电脑的成果不自动删除，本需求只清除后台数据。客户端清除本次会话内存缓存、停止后续同步下载，不擦除用户本地文件。

新数据库无真实内容的默认项目可以重新建立为空容器，但不得借默认项目保护阻止用户清空其中内容或恢复旧数据。

## 2. 最近5轮与上拉分页

2026-09-13交互纠正：桌面客户端点击任务时加载最新5组对话，向上滚动触达历史顶部时每次补入更早1组，不显示页码、上一页/下一页或翻页按钮。本文“分页”仅指服务器按游标分批读取，不是网页翻页模式。一组仍按用户提问及对应回复/思考/工具事件归组，避免将工具事件拆成独立对话计数。数据库接口已按5+1调整，正式客户端接入仍待完成。

“5段对话”暂按5轮处理：一次用户请求及其对应回复、思考和工具调用属于同一轮；重试运行挂在原轮次，不按工具事件数量计数。系统欢迎信息和任务状态提示不单独占一轮。若用户指定按消息条数，单独调整产品口径。

- 打开会话只向服务器请求最近5轮，按时间从旧到新显示并定位到底部；少于5轮全部展示。
- 上拉到历史顶部时，每次请求更早1轮，插入当前列表前方。加载中防止重复请求，失败保留当前位置并提供重试，无更多内容时显示“已到最早消息”。
- 插入历史前记录顶部可见消息ID与其相对像素位置，渲染后恢复锚点，避免页面跳动。连续快速滚动、切换会话均取消/忽略过期响应。
- SSE新事件按稳定消息/事件ID和sequence合并；分页与实时回复不重复、不乱序。读历史时不因新回复强制滚动到底部，提供“有新消息”入口。
- 初始5轮和每次上拉1轮是聊天历史增量加载，不允许前端先下载全历史再截取。后台采用索引和游标，不用偏移量遍历大历史。
- 单轮特别大的工具输出另设片段分页与字节上限，折叠并按需获取，但保留同一轮的归组；不能为了“完整一轮”返回无上限正文。设内存渲染窗口，必要时虚拟列表/释放远处页面，避免上拉最终加载全部DOM。

### 数据与接口

- 增加 conversation_turns：id、owner_user_id、task_id、turn_sequence、创建时间、状态；messages/task_events关联turn_id与run_id。轮次和事件序号由数据库事务分配。
- 索引至少覆盖(task_id,turn_sequence DESC)以及(turn_id,sequence)；作用域过滤与RLS同样适用。
- GET /api/tasks/:id/conversation?limit=5&before=cursor 返回 turns、nextCursor、hasMore、snapshotSequence、事件水位。无before时取最近5轮；后续每次仅取cursor之前1轮。
- 游标包含会话标识、轮次边界和初始快照水位，服务端验证格式及归属；客户端不能拿另一会话游标越权。hasMore通过额外取1轮判断。新消息通过实时流追加，不改变已确定的历史翻页边界。
- 事件数据使用同一响应快照/水位保证初始加载与SSE交接不漏事件，断线按事件序号补拉。

客户端分页仅影响展示。模型上下文、项目RAG和三层记忆继续按服务端上下文预算与权限管理，不因为屏幕只显示5轮就只让模型看到5轮，也不把全部聊天无条件交给模型。

## 3. 验收

- 含多会话、文件和多版成果的项目删除后，后台记录/索引/文件按引用清理；其他用户和项目不受影响。
- 删除普通会话、临时会话、正在运行会话；删除与上传/写入/创建子任务并发，均不能出现数据复活。
- 文件共用目录和共享引用场景不会误删；清理中断、重试、重复请求、备份恢复后仍保持删除状态。
- 0/1/5/6/多轮会话初始展示数量正确；每次上拉1轮，无重复或遗漏。
- 多次工具调用、长输出、跨轮重试保持正确分组；显示最近5轮不等同截取5条事件。
- 上拉加载时锚点稳定，实时新消息不抢滚动位置；切换会话不串内容，失败可重试。
- 大历史场景验证查询使用索引、响应大小有上限、初次加载不读取全部正文；删除会话后未完成分页请求不能重新挂回界面。
