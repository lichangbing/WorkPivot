# 联网搜索工具 web_search（2026-10-24）

状态：已实现，未部署。属于 agent 工具面的补充，不是新链路。

## 1. 背景

文件链路此前**没有任何联网工具**：`web_fetch`/`browser_visit` 只在数据库链路与自动化里构建。模型知道要查资料，却只能猜网址，抓取失败后看起来就是“不去想办法”。对比竞品，Claude Code、Hermes、OpenWorkBuddy、MyAgents 都有搜索工具，Codex 通过 apps/MCP 提供。

## 2. 设计

- 工具名 `web_search`，`kind: 'read'`，参数只有 `query` 与 `count`（1–10，默认 5）。
- 只做检索，**不读正文**：返回 `{title, url, snippet}`，需要内容时用 `web_fetch` 打开具体链接。这样搜索结果不会把整页正文塞进上下文。
- 服务地址由管理员配置，模型只能影响查询词，不能改目标地址；因此不复用 `webUrl` 的公网校验（自托管 SearXNG 在内网是正常部署）。
- 结果过滤：只保留 `http(s)`、无凭据、公网主机的链接；丢弃内网、回环、`localhost`、无点主机与畸形链接；按 URL 去重。
- 搜索内容是**外部不可信数据**，工具描述明确要求不能当指令，引用以 `web_fetch` 读到的原文为准。

### 支持的提供方

| provider | 请求 | 认证 |
| --- | --- | --- |
| `brave` | `GET {url}/res/v1/web/search?q=&count=` | `x-subscription-token` |
| `searxng` | `GET {url}/search?q=&format=json&count=` | 无 |

### 配置

```
WORKPIVOT_SEARCH_PROVIDER=brave|searxng
WORKPIVOT_SEARCH_URL=https://api.search.brave.com   # 或自托管 searxng 地址
WORKPIVOT_SEARCH_KEY=...                            # brave 必填
```

未配置时工具不出现；配置不完整时服务启动失败（`WebTools` 在启动时构建），避免每个对话都报错。

## 3. 文件链路的联网补全

`app.ts` 启动时构建 `WebTools` 并挂进工具集：

- 未配置浏览器服务 → `web_search`（若已配置搜索）+ `web_fetch`
- 配置了 `WORKPIVOT_BROWSER_URL/TOKEN` → 再加 `browser_visit`，截图写入任务目录 `web-artifacts/`

## 4. 限制与风险

- 搜索服务不可用时报错并提示改用 `web_fetch` 读已知地址，不自动降级到其它提供方。
- 结果条数与摘要长度都截断，长尾信息需要 `web_fetch` 补读。
- 敏感信息不要放进查询词（会发给搜索服务）；工具描述已提示，但没有强制过滤。
- 出网仍受部署环境限制：容器 `--network none` 时搜索同样不可用，只有服务端进程能出网。
- 没有结果缓存与配额计数，依赖搜索服务自身限额；后续可接 `requestQuota`。

## 5. 验证

`code/eval/web-search.mts` 8 项通过（注入 fetch，不联网）：未配置不出现、配置非法报错、brave/searxng 请求拼装与认证头、结果归一化与内网过滤、条数收敛、空结果提示、错误状态、空查询与超长查询。

## 6. 本地栈部署（2026-10-24）

`releases/deploy/compose.local-stack.yml` 内置 SearXNG：只在内网 `stack` 网络提供 `:8080/search?format=json`，不暴露到宿主；配置在 `releases/deploy/searxng/settings.yml`（只开 json、关 limiter、关 image_proxy、`enable_http2: false` + 放宽超时）。

- 服务端环境：`WORKPIVOT_SEARCH_PROVIDER=searxng`、`WORKPIVOT_SEARCH_URL=http://searxng:8080`（安装器自动写入 `stack.env`；清空这两个变量即关闭 `web_search`）。
- 安装器：`3/7 准备镜像` 阶段拉取 `searxng/searxng:latest`，拉不到只警告不中断；旧 `stack.env` 会自动补 `SEARXNG_SECRET`。
- 实测（39997）：searxng 容器 healthy，服务端容器 `fetch http://searxng:8080/search?q=python&format=json` 返回合法 JSON；但本机网络下 bing/duckduckgo/brave 引擎请求 `curl_cffi` 超时（SearXNG 日志 `engine timeout`），而同一容器 `wget` 访问 bing 正常——属于本机出网/中间层限制，需要代理出口或改用 `brave` API Key 才能拿到真实结果。
- 因此 R003 的状态是"服务已部署、工具可配置"，真实搜索效果待网络条件具备后复验。
