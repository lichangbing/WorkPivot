# 任务授权与安全边界

| 项 | 值 |
| --- | --- |
| 状态 | 🛠️ 核心已实现；文件链路统一、页面代次和部分旧历史收缩仍在补强 |
| 适用范围 | PostgreSQL 对话、文件链路、Skill、MCP、浏览器、自动化与代码执行 |
| 数据边界 | 用户隔离、任务资源范围、一次性/持续授权、来源有效性 |
| 关联 | [执行与工具](../runtime/工具执行与Agent协作.md)、[企业身份接入](企业身份接入.md) |

## 1. 核心原则

1. **账号有权访问，不代表本轮模型有权读取。**
2. 默认只读；写、执行、联网、外部 MCP 和数据发送分别授权。
3. 授权绑定用户、任务、运行和具体资源版本，不绑定模型自述意图。
4. 外部文档、网页、OCR、MCP 返回和记忆都是不可信数据，不能签发权限。
5. 所有检查在服务端执行；提示词约束和前端隐藏都不是安全边界。
6. 副作用执行前重新检查撤销、来源有效性和运行栅栏。

## 2. 授权对象

每次运行使用一份可版本化的最小授权快照：

```text
ownerUserId
taskId / runId / fence
policyRevision
fileVersionIds
projectKnowledgeScope
memoryScopes
skillReleaseId / artifactTarget
networkTargets
operations
authorizationSource
```

模型只能提出操作，不能写入 `authorizationSource`。文件、网页、摘要、记忆、技能说明和工具描述均不能伪造该字段。

资源范围优先采用固定版本快照。项目范围若允许新增资料，必须由用户显式选择，不能因项目权限自动扩大本轮上下文。

## 3. 权限层次

| 层 | 作用 | 不负责 |
| --- | --- | --- |
| 身份认证 | 证明请求用户和管理员角色 | 限定某轮能读哪些文件 |
| 用户隔离/RLS | 阻止跨用户访问 | 限制同一用户本轮的资源范围 |
| 任务授权 | 固定文件、知识、记忆、网络和操作范围 | 判断业务内容是否安全 |
| 调用审批 | 绑定一次具体工具调用的完整参数 | 替代来源真实性检查 |
| 隔离执行 | 限制代码、依赖、网络和宿主访问 | 保证业务结论正确 |
| 成果核验 | 检查文件存在、结构和目标内容 | 自动证明视觉和业务全面正确 |

上述层必须叠加，不能用其中一层宣称安全闭环。

## 4. 执行模式

| 模式 | 定位 | 行为 |
| --- | --- | --- |
| `manual` 确认模式 | 更严格 | 进入执行前确认一次；联网首次确认；危险操作单独确认 |
| `auto` 自动模式 | 减少打扰 | 已授权范围内自动执行；危险操作仍需确认 |

执行模式只影响重复确认频率，不扩大资源范围。`WORKPIVOT_CODE_APPROVAL=confirm` 可以强制代码执行恢复逐次确认。

当前仍需收敛：

- 确认模式的计划闸门。
- 文件链路统一为 `manual/auto` 两模式。
- 浏览器页面代次和子资源发送策略。
- 旧历史、摘要和专家经验的范围缩小失效。

## 5. 工具风险矩阵

| 类别 | 示例 | 默认要求 |
| --- | --- | --- |
| 只读 | 读已选文件、查结构、检索有效知识 | 校验任务范围，不弹重复卡 |
| 生成成果 | `save_artifact`、PDF/Office 产物 | 写入范围、目标 revision、发布核验 |
| 隔离执行 | `execute_skill`、`run_code` | 输入版本、无网络、资源上限、输出声明 |
| 联网读取 | `web_fetch`、`web_search`、`browser_visit` | 完整 URL/搜索出口策略、SSRF 防护、摘要与正文分离 |
| 数据发送 | 页面填写、查询参数携带本地资料 | 单独授权，不能仅靠域名白名单 |
| 外部 MCP | 第三方工具 | 每次调用确认，校验连接 revision 与 schema |
| 状态变更 | 暂停/取消计划、覆盖成果 | 绑定具体对象和 revision |

工具必须登记真实副作用。`kind=read` 不能凭名称推断；例如截图会生成成果，技能列表工具也可能读写服务状态。

## 6. 调用审批生命周期

```text
模型提出调用
  → 参数 schema 校验
  → 解析真实资源与副作用
  → 校验运行授权
  → 必要时请求用户确认
  → 消费一次性许可
  → 执行前复查撤销与资源版本
  → 执行、记录事件
  → 发布前再次核验
```

审批摘要至少覆盖工具版本、规范化参数、输入版本、技能/MCP revision、输出目标、网络地址、运行栅栏和策略 revision。任何字段改变都不能复用旧许可。

等待默认有超时；停止、断线、用户禁用和撤权会使待批请求失效。重复批准应幂等，批准与停止竞态时执行器在运行工具前再次检查取消信号。

## 7. 文件、知识和记忆范围

- 当前消息选择的附件构成默认读取集合，不自动带入任务全部文件。
- 检索先执行用户、项目、版本和删除状态过滤，再做关键词或向量排序。
- 引用解析和二进制输入使用同一范围检查，不只限制最终下载。
- 记忆读取受层级、项目归属、锁定、来源和加载开关约束。
- 范围缩小时，新一轮请求不得继续携带旧范围资料；已发送给外部模型的数据无法追溯撤回。
- 删除/撤权必须让知识片段、记忆、摘要、引用与缓存同步失效。

## 8. 网络与浏览器

- 只允许公网 HTTP(S)，解析后固定连接地址，阻止私网、回环、保留地址和 DNS 变化绕过。
- 普通网页读取只做 GET；重定向、子资源和浏览器跳转逐项校验。
- 共享浏览器绑定账号、任务、页面会话和页面代次；用户切换页面后旧动作授权失效。
- 搜索结果只返回标题、链接和摘要，正文另行读取并标记为不可信来源。
- 页面填写、点击和查询参数可能外传资料，需要有独立的数据发送授权；域名白名单本身不能防泄漏。

当前自动化使用完整 URL 配置；旧 `webOrigins` 不自动继承。登录态、验证码人工接管和内网访问属于后续阶段。

## 9. 已知限制

- 应用层路径检查不等于 OS 级沙箱；最终执行身份和容器边界仍需目标平台验收。
- 提示注入无法通过正则彻底识别，安全依赖最小权限与工具外校验。
- 已发送到模型、下载到客户端或发布到外部系统的数据不能完全收回。
- 权限控制不能保证模型对恶意资料的总结不受影响，也不能替代业务事实核验。
- 文件链路与数据库链路的部分审批语义仍有差异，不能混用测试结果。

## 10. 验收基线

必须覆盖：

1. 两用户、同用户不同任务/项目/版本、管理员代管和伪造 ID。
2. 附件、网页、OCR、RAG、MCP 返回中的注入文本诱导实际工具调用。
3. 审批后换输入、输出、revision、Skill、MCP schema、URL 或页面代次。
4. 过期、重复消费、停止、断线、重启和撤权竞态。
5. 网络测试确认被拒请求从未发出，并覆盖重定向、子资源和查询参数。
6. 范围缩小后历史、摘要、记忆与引用不再进入下一次模型请求。
7. 正向路径在批准范围内不产生无意义重复确认。
