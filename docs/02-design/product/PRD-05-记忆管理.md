## 1. 目标

让 AI 能在后续工作中复用对用户有帮助的事实，同时满足：

- 不把一次临时要求误记为长期偏好。
- 用户、项目和任务事实不串层、不跨项目泄漏。
- 新事实不需要逐条确认，减少打扰。
- 错误、修改、合并和冲突必须清楚展示并逐条确认。
- 每条记忆都能追溯来源、编辑、遗忘并停止加载。

## 2. 用户场景

| 场景 | 期望行为 |
| --- | --- |
| 用户说“以后所有分析报告先给结论” | 形成个人层长期偏好，适用于当前项目范围 |
| 用户说“这个项目统一用万元” | 形成项目层约束，项目下任务可复用 |
| 用户说“本次最终输出 PDF” | 形成任务层交付要求，不升级为项目/个人 |
| 用户说“刚才说的颜色改成绿色” | 对已有事实提出修订，显示单条冲突确认 |
| 用户删除某条记忆 | 立即停止加载，相关运行和旧上下文按规则失效 |
| 用户关闭某层加载 | 保留已有记忆，但后续运行不再注入该层 |
| 用户手动新增/编辑 | 用户明确提交后直接保存，不再弹自动确认 |

## 3. 三层作用域

| 层 | 内容 | 作用域 | 示例 |
| --- | --- | --- | --- |
| 个人 `user` | 稳定偏好、工作习惯、明确个人事实 | 当前项目范围内跨任务；临时任务可独立归属 | “报告先给结论” |
| 项目 `project` | 背景、目标、统计口径、长期约束、已确认决策 | 当前项目 | “金额统一使用万元” |
| 任务 `task` | 本轮对象、范围、交付要求、临时约束 | 当前任务 | “本次输出 PDF” |

范围不明确时进入最小确定层级。一次临时要求不能升级为个人或项目记忆。

## 4. 记忆生成

### 每轮识别

每次用户消息完成后，后台对 user/project/task 三层分别判断：

- 只提取本轮明确的新事实或修正。
- `evidence` 必须逐字来自本轮用户原话。
- 每项只表达一个可独立修改或删除的事实。
- 单轮最多 6 项。
- 寒暄、“好的”“继续”和无复用价值的一般问答不生成记忆。
- 明确指定给某位专家的方法进入专家经验，不重复写入三层记忆。
- 密码、密钥、Token 和敏感凭据不得保存。

### 十轮补充

个人和项目层每累计 10 轮有效对话再做一次跨任务整理：

- 发现重复出现的稳定偏好和项目约束。
- 去重、补充和合并不完整事实。
- 不把一次性要求提升为长期记忆。
- 不跨项目串用个人记忆。
- 自动化执行不计入十轮。

### 个人记忆归属

当前个人记忆按“用户 + 项目”隔离，在同一项目内跨任务使用。临时任务使用独立范围；旧全局个人记忆必须由用户确认归属后才能加载。不同项目的个人记忆不会互相注入。

## 5. 保存与确认

| 动作 | 默认处理 |
| --- | --- |
| 无冲突的新增 `add` | 自动保存为 revision 1，来源记为 `auto` |
| 修改已有事实 `update` | 生成待确认项，展示原文、建议和新内容 |
| 合并多条记忆 `merge` | 生成待确认项，展示全部原条目 |
| 后续纠正替代待确认项 | 保留单条确认，避免一次弹出一组卡片 |
| 用户确认/修改后确认 | 生成新修订，来源记为 `user` |
| 用户删除待确认项 | 等同拒绝，记录去重键，旧事件重放不反复弹出 |

确认界面一次只显示一条；处理或拒绝后显示下一条。关闭页面、超时、发送新消息都不代表同意。

自动保存与人工确认走同一个发布事务，仍校验：

- 用户与项目归属。
- 当前记忆版本 `epoch`。
- 来源任务、对话和证据仍有效。
- 目标记忆 revision 未变化。
- 对应记忆层允许更新。
- 目标未被锁定或删除。

## 6. 管理界面

### 已保存记忆

按个人、项目、任务分栏，以列表显示：

- 内容、revision、所属项目/任务。
- 修改、删除、锁定/解锁。
- 个人记忆可按项目筛选。
- 旧全局个人记忆显示“待指定归属”，确认前暂停加载。
- 分页加载，避免一次渲染大量正文。

### 待确认冲突

- 显示单条卡片，包含层级、项目/任务、建议内容、原文证据。
- 修改/合并时显示原内容或全部合并目标。
- 按钮为“确认保存 / 修改 / 删除”。
- 多条时显示“当前第 1 条，共 N 条”。

### 分析与设置

- 显示每层 10 轮累计进度、最近批次的 pending/running/completed/failed。
- 失败分析可手动重试。
- 自动整理总开关与各层加载/更新开关独立。
- 自动整理关闭不删除已有记忆。

## 7. 加载与注入

- 任务开始加载三层中已开启且属于当前作用域的紧凑概览。
- 详细内容通过搜索/读取工具按需获取，不能一次注入全部记忆。
- 记忆是参考事实，不是系统指令，不能扩大文件、网页、工具或自动化权限。
- 本轮资源范围未显式选择记忆层时，默认加载三层中 `load_enabled=true` 的层。
- 关闭加载不删除记忆；关闭更新不允许后台继续生成。
- 删除、锁定、项目删除或来源撤销后，旧记忆和候选立即失效。

## 8. 手动操作

### 新增

用户选择层级和归属后编辑内容。可以一次录入多条，但每条保持独立；用户点击保存即成为明确提交。

### 修改

必须携带当前 revision。保存后产生新修订；其他端使用旧 revision 保存会收到冲突提示。

### 删除

- 移入回收站并停止加载。
- 来源派生关系和旧上下文失效。
- 永久删除遵守回收站期限和人工确认。
- 管理员不能查看或代操作其他用户的私人记忆。

### 锁定

锁定只阻止自动修改/合并，不阻止用户手动编辑或删除。

## 9. 异常与安全

| 异常 | 处理 |
| --- | --- |
| 模型超时/格式错误 | 作业有界重试；超过次数标 failed，可手动重试 |
| 来源被删除/撤销 | 候选失效；不发布旧内容 |
| 记忆 epoch 变化 | 当前候选失败，要求基于最新记忆重新整理 |
| 目标 revision 变化 | 冲突提示，不覆盖后续编辑 |
| 重复事件重放 | 使用来源、去重键和已拒绝记录抑制重复 |
| 项目变更或删除 | 项目层/所属个人层停止加载，进入删除关系 |
| 模型产生伪证据 | 拒绝保存，不进入待确认 |

## 10. 非目标

- 不保存聊天中的全部内容。
- 不自动推断敏感身份、健康、财务或其他高风险个人信息。
- 不将模型回答或工具猜测当作用户事实。
- 不维护与专家经验重复的方法记忆。
- 不允许记忆修改系统指令、权限或执行策略。

## 11. 验收标准

- [ ] 一轮同时包含三层事实时，分别生成 user/project/task 记忆。
- [ ] 临时任务要求不升级为个人/项目事实。
- [ ] 无冲突新增自动保存，不产生待确认项。
- [ ] 修改/合并/冲突产生待确认项，一次只显示一条。
- [ ] 真人确认后 revision 递增并保留逻辑记忆 ID。
- [ ] 错误证据、跨项目目标、旧 revision 和锁定条目不能写入。
- [ ] 不同项目之间个人记忆零串用。
- [ ] 关闭加载不注入；关闭更新不生成新的事实；重新开启不重放旧关闭期间内容。
- [ ] 删除后不再被搜索、概览、聊天或历史重放加载。
- [ ] 十轮批量分析失败可重试，空结果成功且不凑数。

## 12. 指标

| 指标 | 目标 |
| --- | --- |
| 三层归类正确率 | 固定中文样本集人工核对 |
| 无价值记忆率 | 持续下降，不以生成数量衡量成功 |
| 冲突重复弹卡率 | 同一事实被拒绝后不重复弹出 |
| 跨项目泄漏 | 0 |
| 自动保存审计覆盖 | 100% 可查来源与 decision source |
| 清理正确率 | 删除/项目删除后检索和注入零召回 |
