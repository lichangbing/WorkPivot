## 1. 产品摘要

**WorkPivot 是面向真实办公交付的私有化 AI 工作台。**

用户以项目组织材料，以任务表达目标；系统在受控工作区内读取资料、调用模型和工具，交付可下载、可继续修改、可追踪版本的办公文件。产品关注的不只是回答质量，还包括权限、过程、结果和恢复能力。

一句话价值：

> 把 AI 从“会聊天”推进到“在明确边界内完成工作，并交付可核验成果”。

## 2. 问题与机会

通用聊天工具进入办公场景后，仍有四类缺口：

| 缺口 | 典型表现 | WorkPivot 的应对 |
| --- | --- | --- |
| 成果不可用 | 回答很长，但最后仍要人工复制到 Word/PPT/表格 | 任务直接产出 Office/PDF/报告等文件，进入成果版本链路 |
| 过程不可信 | 模型声称读取了文件、访问了网页或完成了计算，实际没有证据 | 工具调用、来源、成果和运行状态持久记录；资料问题要求引用原文 |
| 权限不可控 | 文档、网页、命令和记忆混在一个无限上下文中 | 每轮声明文件版本、网页范围、记忆层与工具权限；敏感写操作可审批 |
| 中断与纠错成本高 | 刷新、断网、服务重启后进度和文件状态不明 | 事件持久化、运行恢复、成果版本、回收站、备份恢复 |

## 3. 目标用户

### 3.1 首要用户

- 需要处理内部材料和敏感业务数据的知识工作者。
- 投研、咨询、财务、法务、研究、战略和内部运营团队。
- 希望使用公有云模型能力，但不接受把全部原文和流程交由 SaaS 托管的组织。
- 需要把个人方法沉淀为 Skill，又要求发布前人工审查的小团队。

### 3.2 使用者角色

| 角色 | 主要目标 | 当前支持程度 |
| --- | --- | --- |
| 业务使用者 | 创建任务、提供资料、审阅成果与冲突记忆 | ✅ 核心链路 |
| 平台管理员 | 管理账户、模型、默认技能、配额与运行状态 | 🔄 基础能力已实现，企业治理待补强 |
| IT/运维 | 私有化安装、备份、升级、故障恢复 | 🔄 单机/小团队路径可用，多节点与长稳待验收 |
| 安全/合规人员 | 确认数据边界、权限和审计证据 | 🔄 任务授权与审计基础已实现，企业身份/组织级策略待建设 |

### 3.3 非首要用户

- 只需要开放域闲聊的个人用户。
- 要求零配置、完全托管 SaaS 的消费者用户。
- 首版暂不以大型多租户组织、跨企业实时协作和移动端完整办公为目标。

## 4. 核心用户任务

| JTBD | 用户期望 |
| --- | --- |
| 研究一个主题 | 上传/引用资料，获得有来源的研究结论和可交付报告 |
| 生成办公文件 | 从需求直接生成 Word、Excel、PPT 或 PDF，并继续修订 |
| 修改已有材料 | 指定文件和版本，在受限范围内修改，原件受保护 |
| 持续跟进一个项目 | 跨任务复用项目背景、约定和已确认事实 |
| 沉淀个人工作方法 | 对话生成 Skill 草稿，试运行后确认发布 |
| 周期性执行工作 | 用对话创建计划，经过确认后定时运行 |
| 审计一次运行 | 看到读取了哪些资料、调用了什么工具、产出了什么文件 |
| 出错后恢复 | 停止任务、撤销删除、恢复备份，而不是重新完成全部工作 |

## 5. 产品原则

1. **交付优先**：任务成功以有效成果和证据为准，不以模型自称完成为准。
2. **最小权限**：知识、文件、网页、记忆和工具能力都必须有明确范围。
3. **用户确认高风险变化**：技能启用、自动化生效、记忆冲突和高风险工具执行不能静默完成。
4. **数据属于用户**：用户可查看、修改、导出、删除自己的记忆、文件和任务数据。
5. **失败可解释**：缺少服务、权限或模型能力时明确提示，不伪造成功，不私自降级到不安全路径。
6. **模型可替换**：核心能力不依赖某一模型厂商；协议和工具边界保持中立。
7. **文档与实现同源**：用户行为、权限、数据结构和部署方式变化必须同步更新文档。

## 6. 范围

### 6.1 当前范围内

- 本地账户、会话、用户隔离和基础管理员能力。
- 项目、任务、流式对话、过程事件、停止与恢复。
- 文件上传、文本/Office/PDF 解析、版本与成果下载。
- OpenAI 兼容与 Anthropic 协议模型接入。
- Skill 目录、对话生成 Skill、试运行、确认发布和隔离执行。
- 专家规则、专家经验与来源管理。
- 项目知识检索、混合检索、引用和删除失效。
- 个人、项目、任务三层记忆及冲突确认。
- 网页读取、共享浏览器、联网搜索、MCP。
- Word/XLSX/PPTX 生成与修改、PDF 直接生成、可选 Office 转 PDF。
- 对话创建自动化、周期计划、持久队列和运行记录。
- 回收站、备份、恢复、配额和基础审计。

### 6.2 明确不在当前 RC 范围

- 完整企业微信/OIDC 登录、组织同步和组织级撤权。
- 大型多租户 SaaS 计费、运营和跨企业共享。
- 多人实时共同编辑同一文件。
- 任意网页验证码自动破解或后台长期保存网站登录态。
- 无限制公网命令执行、宿主 shell 回退和任意网络访问。
- 对所有复杂 Office 版式、扫描件和公式结果作无损保真承诺。
- 自生成代码插件默认启用；高风险生成物仍需隔离和人工确认。

## 7. 核心流程

```mermaid
flowchart LR
  A[创建/选择项目] --> B[创建任务]
  B --> C[选择资料、记忆与工具范围]
  C --> D[发送目标]
  D --> E[Agent 规划与工具执行]
  E --> F{需要授权或核对?}
  F -- 是 --> G[用户确认/修改/拒绝]
  F -- 否 --> H[继续执行]
  G --> H
  H --> I[生成或更新成果]
  I --> J[结构检查与来源记录]
  J --> K[预览、继续修改、下载]
```

关键规则：

- 模型不能把工具输出或网页内容当作系统指令。
- 未授权的文件、网页、MCP 和写操作不可用。
- 删除、长期记忆冲突、Skill 启用和自动化启用均需明确交互。
- 运行中断后只能恢复确定性步骤，已经发生的外部副作用不重放。

## 9. 非功能要求

### 安全

- 不同用户的项目、任务、文件、记忆、运行和检索结果默认不可互见。
- 服务运行账户不能拥有数据库超级用户或绕过 RLS 的权限。
- 任何模型可见资料都必须来自本轮授权资源或其合法持久化上下文。
- 文档、网页和工具结果中的指令不得扩大权限。
- 密钥、Token、密码和真实业务样本不得进入日志与仓库文档。

### 可靠性

- 运行状态、工具调发和成果发布可恢复；已发生副作用不得重复执行。
- 删除操作先进入可恢复范围；永久删除必须明确确认。
- 备份必须能验证完整性，并在隔离目标上恢复。
- 外部服务不可用时明确失败或降级，不静默使用高风险替代路径。

### 可用性

- 核心流程使用中文叙事，工具参数和内部异常不直接压到主界面。
- 等待审批、缺少配置、额度不足和来源失效必须有明确下一步说明。
- 长任务刷新后可以恢复查看，不要求用户重新描述需求。

### 可维护性

- 前端只通过 HTTP/SSE 访问服务，不导入服务端或内核内部模块。
- 数据库迁移、API、运行时和前端必须按同一版本配套发布。
- 关键架构取舍记录 ADR；新增跨模块耦合必须先说明边界。

## 10. 数据与隐私

| 数据 | 保存位置 | 默认行为 |
| --- | --- | --- |
| 账户与会话 | PostgreSQL `identity` | 密码哈希；会话可撤销；管理员不能代看私人任务 |
| 项目、任务、运行、事件 | PostgreSQL `workpivot` | RLS 用户隔离；按删除策略进入回收站 |
| 文件原件与成果 | 服务端文件卷 | 与数据库版本和权限记录关联 |
| 记忆 | PostgreSQL，按 user/project/task 作用域 | 无冲突新增自动保存；冲突逐条确认 |
| 文档索引 | PostgreSQL + pgvector | 按用户/项目/版本过滤；删除来源后失效 |
| 模型与连接凭据 | PostgreSQL 加密字段 | 不回读明文；日志脱敏 |
| 临时执行环境 | 隔离容器/临时卷 | 任务结束销毁，不保留后台进程 |

数据默认保存在部署方控制的服务器。模型调用可能把授权范围内的对话、引用材料和工具结果发送给所选模型供应商；部署方必须根据业务要求选择模型和数据范围。

## 11. 成功指标

当前指标用于验收方向，具体基线应在真实业务样本上测量，不能用合成数据替代。

| 维度 | 目标 |
| --- | --- |
| 任务完成 | 用户目标可落到可见成果，失败时不发布伪成功文件 |
| 证据可信 | 资料型回答可回到具体文件、版本和原文位置 |
| 权限正确 | 跨用户、跨项目、未授权网页和未授权文件访问为零 |
| 恢复正确 | 中断后状态可判断，已执行副作用不重放 |
| 记忆正确 | 三层不串用；冲突确认一次一条；被拒绝事实不重复打扰 |
| 交付质量 | Office/PDF 结构有效，视觉与业务正确性纳入人工核验 |
| 可运维性 | 新装、升级、备份、恢复和回退步骤可重复 |

## 12. 验收指标

RC 进入正式版前至少满足：

1. 全新机器按文档完成安装，健康检查通过。
2. 两个普通成员之间的项目、任务、文件、记忆、检索结果零泄漏。
3. 文本、Office、PDF、网页和 Skill 至少各有一条真实业务链路。
4. 任务停止、服务重启、浏览器刷新和模型短时失败均不产生重复副作用。
5. 三层记忆分别落库，冲突单条展示，关闭加载与遗忘行为可验证。
6. 生成文件结构检查、下载哈希和页面预览一致；复杂版式明确标记视觉验收状态。
7. 备份可在新目标恢复；升级失败有配套回退路径。
8. `typecheck`、lint、依赖/许可检查和数据库集成测试通过。

## 14. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 模型工具调用不稳定 | 半成品、错误声明 | 结构检查、运行预算、明确失败、成果核验 |
| 复杂 Office 版式受损 | 业务交付不可用 | 限定支持范围；视觉验收；保留原件和版本 |
| 长任务上下文膨胀 | 质量下降或成本失控 | 分层预算、按需读取、压缩、停止条件 |
| 自动化重放副作用 | 重复邮件/写入/删除 | 操作派发记录、幂等、恢复时不盲目重放 |
| 企业身份和权限复杂 | 无法扩大组织使用 | IAM 与项目协作分阶段实现，不以单用户测试替代 |
| 文档再次腐化 | 开发和运维依据不一致 | 分层索引、唯一事实源、文档随功能提交更新 |
