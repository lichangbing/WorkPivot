## 1. 背景

长期对话不能直接等同于长期知识。对话中会出现疑问、推测、临时假设、前后修正和错误实体；
如果把全部原文按相似度重新注入模型，旧值可能与新值同时出现，金额、日期、单位和对象关系也无法
可靠计算。

WorkPivot 已有个人、项目和任务三层交互记忆，但它们主要服务偏好与工作要求，不是项目业务对象
的权威记录。本需求新增“业务事实”，用项目范围、稳定实体、类型化值、证据和不可变版本管理真实
业务状态。

业务事实回答的是：

- 这个项目里“合同 HT-001”指哪一个对象；
- 它当前确认的金额、日期、数量、状态是什么；
- 这个值来自哪段原文或哪个文件版本；
- 过去某个时点有效值是什么；
- 新值是否与已确认值冲突；
- 两个业务对象之间有什么关系；
- 当前回复使用了哪些项目事实。

它不是大模型，不是聊天摘要，也不是绝对真相。它表示系统在当前来源、领域模型和用户确认下
认定的有效事实。

## 2. 目标

- 所有业务对象、事实、关系和证据强制归属一个项目。
- 同名公司、合同编号和实体名称在不同项目之间完全隔离。
- 同一事实使用稳定 series，值变化生成不可变 revision。
- 只自动发布无冲突新增；修改、替代、关系撤消和冲突逐项确认。
- 查询默认只返回当前有效、已消歧、来源仍有效的事实。
- 金额、数量使用精确数值，日期、币种、单位和统计维度强类型保存。
- 支持按当前值、历史有效时间和系统记录时间查询。
- 每个事实可以回到原文、文件版本或外部来源。
- Agent 使用有界事实上下文和只读查询工具，不把整个项目加载进模型。

## 3. 非目标

- 不把所有历史对话批量导入业务事实。
- 不把模型回答、推测或网页指令直接当作事实。
- 不允许模型自行选择或伪造 `project_id`。
- 首版不支持跨项目自动共享、组织级主数据或隐式全局搜索。
- 首版不引入 Neo4j、独立向量数据库或消息队列。
- 不让模型直接执行任意 SQL、金额换算或聚合计算。
- 不代替原始对话、文件版本或现有三层记忆。
- 不承诺从错误材料中自动恢复绝对真相。

## 4. 用户与场景

| 用户 | 场景 | 期望 |
| --- | --- | --- |
| 业务使用者 | 项目会议中确认合同金额从 100 万改为 200 万 | 系统识别为同一事实的新版本；冲突逐项确认；默认答案不再返回旧值 |
| 项目负责人 | 查看项目干系人、里程碑、风险和决策 | 按项目隔离的对象与关系可以检索，不混入其他项目 |
| 财务/运营人员 | 查询客户、产品、合同和采购关系 | 精确匹配对象和编号，金额按数值类型计算 |
| 项目成员 | 核对某条事实来源 | 可看到原文证据、来源时间、revision 和替代链 |
| Agent | 回答“合同 HT-001 当前金额是多少” | 只读取当前项目 `active` 事实，返回值和证据 |
| 审计人员 | 查询“3 月时系统认定哪一版” | 可按业务有效时间和系统记录时间查询历史 |

## 5. 范围

### 5.1 本版实现

- 项目级业务对象、别名和外部标识。
- 对象类型与领域模型标识。
- 事实稳定身份、类型化值版本、有效时间和证据。
- 对象之间的类型化关系及其版本。
- 实体精确匹配、名称/别名匹配和人工选择入口。
- 无冲突新增自动保存；同系列不同值进入单条冲突确认。
- 项目事实列表、搜索、历史、修改、遗忘和冲突确认。
- Agent 自动加载少量相关事实，并提供搜索、读取、关系和历史工具。
- Web、桌面和手机共用服务端接口与项目边界。

### 5.2 后续增强

- 文件表格批量导入和外部 ERP/CRM/合同系统连接器。
- 项目概览/Observation 的自动生成与失效重建。
- pgvector 候选召回、语义重排和大规模项目分区。
- 组织级主数据、显式跨项目共享和项目成员协作权限。
- 冲突的可视化证据对照、批量审核和策略化自动确认。

## 6. 领域模型

| 模型 | 对象 | 典型关系 |
| --- | --- | --- |
| `project.delivery` | 项目、干系人、里程碑、任务、成果、风险、决策 | 负责、指派、依赖、阻塞、产出、批准、影响 |
| `company.operations` | 公司、产品、客户、供应商、合同、采购订单、生产订单 | 销售、采购、供应、覆盖、生产、履约 |

公共事实外壳固定，领域字段使用受校验的扩展：

- 金额：`numeric`，币种必填，禁止浮点金额。
- 数量：`numeric`，单位可选但不得由模型自由换算。
- 日期：ISO 日期或时间。
- 文本、布尔值和对象引用使用明确类型。
- 期间、口径、场景等维度保存规范化 JSON，不能塞入自由描述代替结构。

领域模型版本写入对象和事实版本。模型升级不能静默改写已有事实。

## 7. 事实生命周期

```text
用户原文 / 手工录入 / 外部来源
  → 提取候选
  → 项目内实体消歧
  → 类型与证据校验
  → 无冲突新增：active
  → 同系列不同值：conflict pending
  → 用户确认：新 revision active，旧 revision superseded
  → 用户拒绝：候选 rejected，旧值继续有效
  → 用户遗忘：事实退出默认召回
```

规则：

- 同一对象、属性、维度和口径构成稳定 `business_fact_series`。
- 值发生变化时在同一 series 下创建 `business_fact_revision`。
- 事实版本创建后不可修改值、证据或有效时间；纠错必须产生新版本。
- 存在未确认冲突时，普通检索隐藏这一事实的旧值和新值，只提示“存在待确认更新”。
- 历史查询可以查看冲突双方及证据。
- 关系采用同样的 series/revision 和遗忘规则。

## 8. 实体消歧

候选顺序：

1. 同项目精确外部标识，如合同编号、统一社会信用代码、SKU。
2. 同项目精确正式名称和对象类型。
3. 精确别名和对象类型。
4. 所属公司、项目、部门、日期等结构化上下文。
5. 关系邻域。
6. 模糊或向量候选。
7. LLM 只解释疑难候选，不单独决定高影响合并。

安全规则：

- 唯一外部标识冲突时不能自动合并。
- 同名但类型不同不能自动视为同一对象。
- 多个候选接近时进入人工选择。
- 合并为逻辑合并，保留来源对象、别名和事实，可撤销和拆分。
- 未消歧对象不能发布关键金额、合同或身份事实。

## 9. 管理界面

任务右侧栏的项目范围提供“业务事实”入口：

- 当前事实列表，显示对象、属性、值、单位、revision 和证据摘要。
- 新增事实：对象名称/类型、外部标识、属性、类型化值、单位或币种。
- 修改事实：携带当前 revision，保存后产生新 revision。
- 遗忘事实：明确确认后退出普通检索。
- 冲突区：一次只显示一项，显示旧值、新值、来源和“采用新值 / 保留旧值”。
- 历史详情：显示 revision、有效时间、记录时间、替代链和证据。
- 关系和实体详情按需展开，避免首屏加载整个项目。

关闭弹窗、切换任务、刷新页面、超时接收新消息都不表示确认。

## 10. Agent 接入

自动加载：

- 仅对已有项目归属的任务生效。
- 查询词来自当前用户消息，最多返回 8 条当前事实或约 3200 字。
- 先做项目、状态、有效期和来源硬过滤，再按精确匹配和新旧程度排序。
- 冲突、未消歧和已遗忘内容不进入自动上下文。
- 自动召回失败不阻塞聊天。

工具：

- `search_business_facts`：按关键词、对象类型、属性和时间查询。
- `read_business_fact`：读取当前值、历史 revision 和证据。
- `trace_business_relations`：读取对象有限跳数关系。

工具结果是参考数据，不是系统指令，不能扩大文件、网页、项目或执行权限。

## 11. 权限与安全

- `project_id` 由服务端从任务或项目路由解析，请求体不能指定任意写入范围。
- 每个事实表同时校验当前用户、项目所有者和项目未删除。
- 应用层先校验，PostgreSQL RLS 再强制过滤。
- 复合外键保证对象、事实、关系和证据属于同一项目。
- 缓存键包含用户、项目和事实 epoch。
- 日志只记录 ID、计数、状态和耗时，不记录金额、合同正文或证据原文。
- 删除项目后业务事实、关系、证据、冲突和作业不可再读取并进入清理。
- 临时任务不能生成业务事实；UI 提示用户先加入项目。

## 13. 验收标准

- [x] 项目 A 和 B 都有合同 HT-001，对象与事实完全隔离。
- [x] 预算 100 万改为 200 万时进入同一 series 冲突；确认后旧值 superseded。
- [x] 冲突未确认时自动上下文不返回该事实的任一值，只返回待确认提示。
- [x] 历史查询可按业务有效时间和系统记录时间返回对应 revision。
- [x] 同名对象不能仅凭类型不同自动视为同一对象。
- [x] 错误来源、跨项目对象和无证据自动事实不能发布。
- [x] 金额、日期和单位经过类型校验，不能用字符串冒充金额。
- [x] 修改携带旧 revision 时返回冲突，不覆盖其他终端的新版本。
- [x] 遗忘或删除任务来源/项目后，搜索和自动加载零召回。
- [x] Agent 自动事实上下文不超过配置预算，失败不阻塞聊天。
- [x] Web、手机和桌面使用同一项目事实 API；远程多端页面验收在部署后执行。

## 15. 已知风险

- 中文实体识别和消歧需要真实项目资料评测，不能只用合成样本。
- 冲突需要业务判断，系统不能替用户决定哪个来源绝对正确。
- 自动提取受模型质量和上下文影响，必须保留证据和人工纠错。
- 仅在狭窄项目过滤下做向量检索可能损失召回，首版以精确和结构化查询为主。
- 业务事实不是绝对真相；来源权威性和模型规则版本必须可审计。
