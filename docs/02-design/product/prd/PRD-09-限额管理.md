## 1. 目标

为自助注册和受管理账户建立统一、可审计的日限额，防止公开试用消耗失控，同时保留管理员按用户开通额度的能力。

## 2. 默认规则

| 账户来源 | 每日对话 | 每日 Token | 每日上传 | 并发任务 |
| --- | --- | --- | --- | --- |
| 自助注册 | 10 | 200,000 | 50 MB | 1 |
| 管理员创建 | 不限 | 不限 | 不限 | 不限 |
| 平台管理员 | 不限 | 不限 | 不限 | 不限 |

自助注册的四项默认值由访问策略配置，只影响之后新增的自助注册账户。管理员创建的账户从创建起四项均为 `0`，即不限；之后可在“限额管理”单独开启限制。

所有每日额度统一按北京时间每天 12:00 进入下一周期。`0` 始终表示不限。

## 3. 限额维度

| 维度 | 计数边界 | 拒绝时机 |
| --- | --- | --- |
| 每日对话 | 每次真正创建新运行的用户消息计 1 次，幂等重试不重复计数 | 创建运行前返回 429 |
| 每日 Token | 每次模型 HTTP 请求预留输入估算，结束后按供应商 usage 或 UTF-8 字节估算结算 | 请求前不足或在流式输出中达到上限时停止 |
| 每日上传 | 只有上传原件计入，Agent 生成的成果不计入 | 写入文件前在事务内检查并扣减 |
| 并发任务 | 当前账号状态为 `running` 的不同任务数 | 新建运行前检查，已有任务不中断 |

Token 限额同时覆盖对话、自动化、记忆整理、专家整理和摘要请求。供应商返回的精确 usage 优先；缺失时估算值明确标记。单次调用可能因供应商结算晚于流式估算而产生少量偏差，但结算后后续调用会立即被拒绝。

## 4. 管理界面

后台新增独立的“限额管理”页面，不与用户资料编辑混在一起。

页面包含：

- 自助注册默认限额：四项统一配置，带 revision 冲突保护。
- 用户限额列表：来源、当前周期用量、四项限额和当前有效状态。
- 单用户保存：使用 `limits_revision` 防止覆盖并发修改。
- 当前用量重置：清零对话、Token、上传和并发统计起点；并发数仍按真实运行即时计算。
- 平台管理员只读保护：不能被设置限制。

## 5. 数据与权限

- 新的额度配置和计数器存放在 `identity.users`。
- 业务运行角色只能读取限额配置并更新 token、上传用量和周期起点，不能读取密码或账户资料。
- 管理读写由身份角色完成；每次修改写入 `identity.audit_events`。
- 并发数从运行表即时计算，不依赖内存计数，多实例共享同一数据库时仍能生效。
- 文件上传和运行创建都在各自数据库事务中完成额度检查与扣减。

## 6. 异常与保护

| 情况 | 行为 |
| --- | --- |
| 达到对话额度 | HTTP 429，提示额度和 12:00 刷新 |
| 达到 Token 额度 | HTTP 429；正在流式生成的请求会停止 |
| 达到上传额度 | HTTP 429，原文件不写入 |
| 达到并发额度 | HTTP 429，不创建新运行 |
| 平台管理员请求限额修改 | HTTP 400，配置不变 |
| 限额 revision 过期 | HTTP 409，要求刷新 |
| 管理员创建账户 | 四项默认均为 `0` |

## 7. 非目标

- 本期不实现月度预算、充值、余额扣款或费用结算。
- 本期不实现模型级、项目级或共享额度池。
- 原全局 100 MB 存储上限继续保留，作为磁盘保护，不替代用户每日上传额度。
- 不自动终止已经运行的普通任务来满足降低后的并发配置。
