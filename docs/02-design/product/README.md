## PRD 写作规则

每份模块 PRD 至少包含：

1. 背景与目标
2. 用户与使用场景
3. 范围和非目标
4. 核心流程
5. 功能要求及稳定编号
6. 异常、权限与数据边界
7. 验收标准
8. 依赖、开放问题和变更记录

要求：

- 行为用可执行语言描述，避免只写“支持”“完善”。
- 权限、删除、失败和恢复路径必须显式。
- 不把计划中的能力写成已实现；统一使用“草稿 / 评审中 / 已确认 / 已实现 / 已归档”。
- 需求变化先改 PRD，再改代码；紧急修复可在同一提交中补齐文档。
