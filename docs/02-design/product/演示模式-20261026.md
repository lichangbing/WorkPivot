# 演示模式：自助注册与 10 次提问额度（2026-10-26）

## 目的

给外部演示用：打开首页即可自己注册账号开始用，不需要初始化令牌；每个账号最多 10 次提问，控制成本与滥用。

## 行为

| 项 | 规则 |
| --- | --- |
| 注册入口 | 登录页点"注册演示账号"，填写用户名/密码即可；首个账号仍自动成为管理员 |
| 账号角色 | 第一个注册者 `admin` + `platform_admin`，之后一律 `member` |
| 额度 | 每个 `member` 默认 10 次**用户消息**（每发一条算 1 次，对话内追问同样计数） |
| 刷新周期 | 按北京时间每天 12:00 进入新周期，已用次数视为 0；管理员仍不受限 |
| 管理员 | `platform_admin` 不受限；`message_quota=0` 也表示不限 |
| 超额 | 消息接口返回 `429`，前端提示并禁用输入框 |
| 展示 | 底部输入区显示"剩余 N 次提问 · 每日北京时间 12:00 刷新"，登录页/工作台右上角由 `/api/auth/state` 的 `quota` 字段提供 |

## 实现

- 表结构：schema v56 给 `identity.users` 增加 `message_quota`（默认 10）与 `messages_used`；schema v58 增加 `quota_reset_at` 与北京时间每日 12:00 计算函数。
- 注册：`AccountRepository.register()` 在事务内判断是否已有用户，决定 admin / member；`/api/auth/register` 改用它。
- 计数：在 `RunRepository.start()` 的事务里先判断是否跨过重置点，再原子地归零并计数；重复 `requestId` 的请求在前面已返回，不重复计数。
- 预检：消息路由进入前先查额度，超额直接 429，避免用户等到模型调用才发现。
- 判定：`quotaDecision()` 与 `quotaPeriodUsed()` 纯函数（管理员/quota=0 不限，过期周期不占新额度），由 `eval/demo-quota.mts` 覆盖边界。
- 前端：登录页新增"注册演示账号"切换；工作台显示剩余次数，按 `resetsAt` 设置一次性刷新计时器，页面跨过 12:00 也会自动读取新额度。

## 运维

- 调整某人额度：`UPDATE identity.users SET message_quota=20 WHERE username_key='xxx';`
- 手动立即重置：`UPDATE identity.users SET messages_used=0,quota_reset_at=workpivot.quota_next_reset(now()) WHERE username_key='xxx';`
- 关闭限制：把该用户 `message_quota` 设为 0（或提升为 `platform_admin`）。
- 额度只在真正开始执行（建 run）时消耗；模型未配置等前置失败不扣次数。

## 已知限制

- 只在数据库链路生效；文件链路仍是旧的 JSONL 任务模型，未接额度。
- 没有验证码/邮箱验证，公开演示存在被批量注册的风险，建议外层加限流或邀请码。
- 计数在 `runs.start`，`/api/tasks/:id/resume` 续跑同样算 1 次。
