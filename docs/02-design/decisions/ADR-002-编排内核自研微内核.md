# ADR-002：编排内核 = 自研微内核（pi 作为退化选项）

- **状态**：✅ 已接受
- **日期**：2026-09-05
- **关联调研**：[研究结论汇总 §5](../../01-research/conclusions/研究结论汇总.md)（技术路线定稿）｜[pi-agent.md](../../01-research/competitors/pi-agent.md)｜[codex.md](../../01-research/competitors/codex.md)｜[claude-code-internals.md](../../01-research/competitors/evidence/claude-code/internals.md)｜[qwenwork.md](../../01-research/competitors/qwenwork.md)
- **决策人/评审人**：lichb（2026-09-05 会话确认）

## 背景

M0 的 T1-04 将编写 agent 循环，这是产品的心脏，事后更换成本极高，必须在写代码前定案。三个背景输入：

1. **研究结论**（2026-08-28 定稿）：编排内核自研微内核；Cordis/jiti 移出首版栈。
2. **用户疑虑**（2026-09-02）：曾提出"从头开发还是基于开源修改"——需要正式收口，避免反复。
3. **新证据**（2026-09-05 源码分析）：pi（MIT，可嵌入）是唯一可整包复用的内核候选；Codex/Claude Code 的循环工程（状态机、压缩管道、权限规则）证明了"薄循环+厚纪律"的可行形态，但也证明复杂度在纪律层而非循环层。

## 候选方案

| 方案 | 简述 | 主要优点 | 主要缺点 |
|------|------|----------|----------|
| A：自研微内核 | 朴素 while 主循环+工具回填（T1-04），纪律层（韧性/权限/压缩）自建 | 零耦合、全栈 TS 同构、按自己 PRD 塑形；M0 单机场景复杂度可控 | 循环工程细节（压缩/恢复/防卡死）要自己踩 |
| B：嵌入 pi-agent-core | MIT 可嵌入内核作为依赖，产品层包在外面 | 最快拿到经过验证的循环 | 产品层与第三方内核耦合；版本跟随/替换迁移成本；内核演进方向不由我们控 |
| C：fork/魔改闭源引擎 | 参照 WorkBuddy/QwenWork 内嵌 Claude Code 衍生品 | —— | **许可死结**（AGPL/商业条款），K05 红线，直接排除 |

## 决策

**采用方案 A：编排内核自研**（朴素循环起步，纪律层按 P0 需求逐步加厚）；**pi-agent-core 仅作为退化选项**——触发条件：**W3（2026-09-25）结束时 F02 成果核验/F05 卡循环检测的 eval 仍不达基线，则启动"嵌入 pi"评估**；平时不做此事。

## 理由与取舍

- **选择依据**：差异化（私有化、模型中立、企业管控）全部在纪律层与产品层，任何开源基座都不提供，基座注定自写；参考仓库的正确用法是格式对齐 + 设计借鉴 + 方法论，不是基座（详见 [研究讨论结论](../../01-research/competitors/claude-code.md) §6.3）。
- **接受的代价**：M0 期间循环工程细节（压缩、恢复、防卡死）需要自己踩坑；缓解=W3 韧性周 + eval 基线 + 竞品逆向文档当规格书。
- **放弃了什么**：放弃了"最快有循环"的路线（方案 B 的核心收益）。pi 保留为保险，不预设启用。

## 影响与后续行动

- 对架构/代码目录的影响：`packages/core` 为自研内核包；内核与产品层接口隔离（C05）从 T1-04 起遵守；工具面按 pi 式基线（W1 四工具→W2 七工具）。
- 需要跟进的事项：
  - T1-04（2026-09-07~09-08）：循环实现，验收 eval 同步产出；
  - 2026-09-25（W3 结束）：对照触发条件评估一次，结论记入本文件变更记录；
  - 竞品源码仓库（codex/claude-code-leak）只读参考，K05 红线不进仓库。
