# 专家经验与双页面验收（2026-10-16）

## 环境和范围

复用独立临时 PostgreSQL 的 rc-browser 与 browser-workflow 入口，通过实际浏览器界面操作。前者预置专家经验建议，后者使用可控模型；没有读取业务账号或调用真实模型。使用工作区现有构建，包含另一批次的任务选择刷新恢复改动；该改动及其原验收文档不纳入本轮提交。

## 专家经验实际操作

- 打开“专家经验确认”，展开来源证据，编辑建议后确认保存，建议卡消失。
- 设置 → 专家 → 我的研究员，确认内容显示为一条独立经验，来源为对话、版本为 1。
- 修改该条经验并保存，版本变为 2；锁定后显示“解锁”，版本为 3，历史记录保留先前内容。
- 手动新增另一条经验及适用条件，显示为第二条独立经验，版本为 1、来源为手动新增。
- 任务切换到默认助手后再切回我的研究员，刷新页面仍保留任务和专家选择。

本轮未实际操作删除经验、锁定后自动建议更新或不同账号的专家隔离，不将已有服务层覆盖当作这些界面操作已经验收。预置专家夹具没有配置模型/成果服务，页面的“产物暂时无法加载”是夹具缺少该能力，不认定为业务回归。

## 双页面实际操作

- 同一浏览器的两个标签页进入同一账号、同一任务；第一页发起生成报告，两个页面均显示同一请求及审批卡。
- 从第二页批准一次，两边审批卡消失，均显示完成回复与一份 Markdown 成果。
- 第一页发起慢响应，两个页面都显示部分回复和停止按钮。
- 验收中两个临时标签页被关闭，因此未完成原计划的“刷新后两个页面同时观察停止”。重新打开页面、选择该任务后，部分回复和停止按钮恢复；点击停止后回到可输入状态。
- 服务端可控夹具统计：approvedOperations=1、cancelledStreams=1、activeStreams=0，确认没有重复审批执行，停止实际生效。

这是同一浏览器共享登录状态的双页面验证，不是两台设备、不同浏览器或独立登录会话验证。未验证系统级断网、浏览器下载落盘或所有记忆状态跨端同步。工作流服务通过已有 /fixture/stop 正常关闭，临时数据库容器清理成功。

## 测试入口修复

发现 rc-browser 把关闭接口注册在 `/api/fixture-stop`，但 createDatabaseApp 末尾的 `/api` 通用处理器先返回 503，接口不可达。改为独立 `/fixture/stop`，显式校验现有会话，未登录返回 401。只修改测试夹具，不向产品后台增加关闭接口。最初失败的测试子进程按确切命令行单独终止，父运行器已清理临时数据库；未终止业务进程。

新增改动 ESLint 通过。关闭接口复验三项通过：未登录 POST 返回 401、随后 health 仍为 200、合成测试账号登录后 POST 返回 200；运行器正常退出并确认临时数据库容器清理成功。没有重新运行全量数据库回归、没有部署 WSL 业务服务或 158。
