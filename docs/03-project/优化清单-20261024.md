## O-01 授权卡文案与搜索确认频率

- **落点**：`packages/server/src/permissions.ts:201-204` 的 `external` 分支硬编码“MCP 外部工具调用：请确认服务、工具和发送参数”。
- **影响**：`web_search`、`web_fetch`、`browser_visit` 都声明 `external: true`，用户每次搜索看到“MCP”文案，与动作不符；搜索是高频操作，逐次弹卡体验差。
- **修法**：文案按工具名生成（联网搜索 / 读取网页 / 浏览网页 / 外部工具），审计原因同步；“只读检索是否给会话级允许”作为产品决策单独确认，默认仍逐次确认。
- **验收**：三种工具各触发一次，卡片标题与动作一致；审计记录可区分工具。

## O-02 目录锁覆盖 bash

- **落点**：`code-tools.ts` 的 `withDirectoryLock` 只包 `run_code`；`app.ts` 的 `executeCommand` 直接调用 `workerCommand`。
- **影响**：快照模式有回写哈希校验，挂载模式没有；同项目两个对话同时 `bash` 会互相覆盖。
- **修法**：锁上移到 `executeCommand` 一层，`bash`、`run_code`、`docker` 模式共用；`run_code` 去掉内部加锁避免重复。
- **验收**：eval 里并发两次 `bash` 断言串行；挂载模式手工并发写同一文件不出现交错内容。

## O-03 read 分页

- **落点**：`packages/core/src/tools.ts:97`，`READ_MAX_BYTES = 512KB`，超限只返回头部。
- **影响**：512KB 约 12 万 token，一次 read 可能吃满上下文；大文件无法分段查看。
- **修法**：加 `offset`/`limit`（按行），返回带行号；超限时提示总行数与建议范围。
- **验收**：eval 覆盖越界 offset、limit 截断、行号正确、提示可续读。

## O-04 输出头尾保留

- **落点**：`BASH_OUTPUT_CAP = 64KB`，只保留前段。
- **影响**：命令失败时错误栈在末尾，模型看到的却是开头。
- **修法（参数按 DeepSeek Harness 定）**：超过 8192 字符时保留**头 4096 + 尾 1024**，中间插入 `[... middle pruned ...]` 标记（中文字符按码点计数，避免切坏代理对）；`run_code` 的 16000 字符截断与工具结果修剪共用同一个 `prune()` 实现；`dsh-compaction-tool-result-pruner` 的默认值即此。
- **验收**：命令在末尾输出错误时能看到错误；大结果中间有明确标记与省略量；UTF-8 边界不出现乱码。

## O-05 用量采集

- **落点**：`core/loop.ts` 未处理 `usage` 事件。
- **影响**：没有 token 统计，无法评估成本与慢轮次。
- **修法**：循环累计 `inputTokens/outputTokens`，随 `RunAgentResult` 返回；服务层写入审计与转写。

## O-06 转写参数限长

- **落点**：`app.ts:860` 原样写 `event.args`。
- **影响**：`write`/`edit`/`run_code` 的参数可达 64KB，转写文件迅速膨胀。
- **修法**：复用数据库链路的做法，对 `code`/`content` 截断并标记 `truncated`；其余参数原样。

## O-07 脚本目录清理

- **落点**：`.workpivot/run-code/<时间戳-随机>/`。
- **影响**：频繁使用后目录持续增长。
- **修法**：保留最近 20 份，启动或执行前清理更早的；清理失败不影响执行。

## O-08 原子写

- **落点**：`writeTool`/`editTool` 的 `writeFileSync`。
- **影响**：进程中断可能留半截文件。
- **修法**：写临时文件后 `rename`（与 `worker-command` 回写一致）。

## O-09 核验闸门

- **落点**：`chat-gate.ts` 的扩展名白名单与 `CLAIM_KEYWORDS`。
- **影响**：`deliver_files` 未登记也放行；非白名单扩展名不校验。
- **修法**：收尾时同时校验“本轮是否登记交付”；扩展名白名单补齐（csv/md 已含，补 zip/png 等按需）。

## O-10 挂载写入上限

- **落点**：`skill-worker.mjs` 挂载模式没有 `/workspace` tmpfs 限额。
- **影响**：脚本写循环可撑满工作区卷。
- **修法**：执行前后统计目录大小差异，超过阈值告警并在结果中提示；极端情况中断（需先验证统计开销）。

## O-11 搜索缓存与配额

- **落点**：`web/search.ts`。
- **影响**：重复查询与高频调用无节流。
- **修法**：接 `requestQuota`；同查询短时缓存（如 5 分钟，内存级）。

## O-12 目录锁跨进程

- **落点**：`directory-lock.ts` 进程内 Map。
- **影响**：多实例部署时锁失效。
- **修法**：改为文件锁或数据库 advisory lock；先确认是否会多实例部署。

## O-13 同轮工具并行

- **落点**：`core/loop.ts` 的 `for (const call of toolCalls)`。
- **影响**：三个独立 read 串行等待。
- **修法（参数按 DeepSeek Harness 定）**：默认并发上限 **10**（`WORKPIVOT_MAX_PARALLEL_TOOLS` 可覆盖，1–32）；只读且无共享状态的工具并行，写类与执行类保持独占 barrier；滚动补位而不是整批等待；任一调用失败不取消其余已开始的调用，结束后按原顺序回填结果。
- **验收**：三次独立 read 的总耗时接近单次；两个 write 不会交错执行；取消时在途调用被中止并标记 `stopped`；结果顺序与调用顺序一致。

## O-14 数据库链路已知项

输出只留头部、无 ANSI 清理、无密钥脱敏、执行日志混用 `skill_executions`、前端把 `run_code` 结果当原始 JSON 渲染、未配置 worker 时没有降级提示。详见 [通用代码执行能力 §7](../02-design/architecture/通用代码执行能力-20261024.md)。

## O-15 「执行模式」设置未接线（已修复）

- **落点**：`runs.ts` 的 `automaticRequest` 只读环境变量；`DatabaseExecutionMode.tsx` / 移动端 `ComposerSettings.tsx` 的选项文案写死“本版仍逐次确认”。
- **修复**：`requestPermission` 在同一事务内读取该用户的 `execution.mode`；`manual` 时 `run_code` 也逐次确认，`auto` 或未设置时保持静默；`WORKPIVOT_CODE_APPROVAL=confirm` 仍强制覆盖。两处前端文案改为说明两种模式，去掉过时提示。
- **验收**：`eval/run-code-execution.mts` 12 项通过，新增“确认模式逐次确认”“自动模式与未设置静默”；`tsc`（server/web/mobile）与 ESLint 通过。
- **未覆盖**：计划闸门（O-16）、联网首次确认（O-17）、文件链路统一（O-18）仍待实现，口径见 [执行模式与授权矩阵](../02-design/architecture/执行模式与授权矩阵-20261024.md)。

## O-16 确认模式计划闸门

- **落点**：`database/execution.ts` 的 `authorizeTools`。
- **影响**：确认模式目前是“每个非只读工具各弹一次”，没有“计划就绪、是否开始执行”的一次性确认。
- **修法**：run 级标记 `gatePassed`；首次调用非只读工具前发一次 `permission_request`（`tool: 'plan'`，附计划摘要），允许后本轮不再拦；拒绝则把决定回填给模型并停止执行。
- **验收**：确认模式下只读阶段不弹卡、首个执行动作弹一次、允许后本轮不再弹、拒绝后模型停止；自动模式无闸门。

## O-17 确认模式联网首次确认

- **落点**：`database/runs.ts` 的 `requestPermission`。
- **影响**：确认模式下每次 `web_fetch` 都会弹卡，查资料被打断多次。
- **修法**：run 级标记 `networkApproved`；首次网络工具确认后，本轮其余网络工具直接放行（外部 MCP 仍逐次）。
- **验收**：连续三次 `web_fetch` 只弹一次；`web_search` 与 `browser_visit` 共享该标记；MCP 不受影响。

## O-18 文件链路统一确认/自动模式

- **落点**：`permissions.ts` 的四档与 `/api/settings/tier`。
- **影响**：数据库链路用“确认/自动”，文件链路用“只读/询问/工作目录/完全”，用户与文档都容易混淆。
- **修法**：文件链路映射为两档（确认/自动），界内写与执行在自动模式静默、界外访问与高危命令仍弹；保留只读档作为可选受限模式或直接移除（需产品确认）。
- **验收**：两套 UI 文案一致；文件链路自动模式下界内写不弹、界外必弹；现有权限回归用例全过。

## O-19 文件链路删除保护

- **落点**：`code-tools.ts`、`core/tools.ts`（`bash`/`run_code` 可删真实文件）。
- **影响**：自动模式下代码删除工作目录文件不可恢复（挂载模式没有回写与回收站）。
- **修法**：执行前记录目录清单与哈希，执行后对比删除项并提示；或把删除改为移到 `.workpivot/trash/`（需覆盖 `bash` 无法拦截的删除，只能事后提示）。
- **验收**：删除后结果里列出被删文件并可找回；未删除时不产生噪音。
