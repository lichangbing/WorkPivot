# 任务提前结束诊断与修复（2026-10-28）

## 现象

用户观察到任务运行一段时间后没有最终成果，部分任务很快结束。需要区分运行预算、模型错误、授权超时和服务重启四类原因。

## 数据证据

检查最近 13 次数据库运行：

- 11 次记录为 `completed`。
- 2 次记录为 `interrupted`，停止原因是 `lease_expired`。
- 最长运行约 916 秒、20 步，没有达到默认 200 步或 30 分钟预算。
- 最近一次运行调用 3 个网页工具，均因确认超时未执行；其中两个并行工具同时申请权限，还触发了一个运行只能有一个待确认请求的唯一约束。
- 最近多次完成的运行只有网页检索和文本回答，没有 `save_artifact`/`create_pdf` 成果，因此“运行完成”不等于“生成了可下载结果”。

## 根因

### 1. 授权请求不够显眼

网页读取确认此前位于聊天滚动区内，用户容易错过。默认 3 分钟到期后自动拒绝，模型只能基于未执行工具继续，最终看起来像“任务没有结果”。

### 2. 并行工具同时申请授权

同一轮多个只读工具可以并行，但数据库只允许一个待确认请求。两个网页工具同时申请时，一个请求被唯一约束拒绝。

### 3. 数据库链路没有启用闲置追问

Agent 循环已有 `onIdle` 兜底，但数据库运行链路未接线。模型只说“我将继续/接下来处理”而没有调用工具时，本轮会直接结束。

### 4. 部署重启会中断运行

两次 `lease_expired` 与服务器镜像重启窗口重合。任务在模型或工具执行中被停止，重启后可人工继续，但这不等于自动重放。

## 修复

- Web 和手机端的工具确认卡片移到输入框上方，不再埋在聊天记录里。
- 确认卡明确显示工具、原因、参数、允许本次、拒绝本次和到期时间。
- 同一运行内的授权判定串行执行；第一个联网许可覆盖后续同类只读网络调用，避免重复弹卡和唯一约束冲突。
- 默认授权等待时间由 3 分钟提高到 10 分钟，并支持配置。
- 数据库运行接入 `onIdle`：用户要求产出但模型只表态、尚未调用工具时，自动追问一次继续执行。
- 系统提示增加规则：工具未确认、超时或拒绝时，必须明确标记结果不完整，不能声称任务已完成。
- 增加运行预算环境配置，无需改代码即可调整步数、时长和上下文预算。
- 思考和工具过程按 Agent 步骤分组：当前步骤自动展开并流式追加，下一步开始时上一 步
  自动收起；本轮结束后整组折叠，历史步骤可单独展开。
- 工具过程不再直接显示内部 JSON，只显示工具名称、运行状态和可读摘要。

## 配置

```dotenv
WORKPIVOT_PERMISSION_TTL_MINUTES=10
WORKPIVOT_AGENT_MAX_STEPS=200
WORKPIVOT_AGENT_MAX_DURATION_MINUTES=30
WORKPIVOT_CONTEXT_CHARS=120000
```

边界：

- 授权等待 1–60 分钟。
- Agent 步数 20–1000。
- 最长运行 1–240 分钟。
- 上下文预算为 `0`（关闭压缩）或 20000–1000000 字符。

## 验收

- 权限确认区位于输入框上方，允许/拒绝整行可点击。
- 允许本次提交 `{decision:"allow",scope:"once"}`。
- Agent 只表态不动手时追问一次并继续。
- 已经调用工具后，短阶段文本不会无条件触发重复追问。
- 当前步骤自动展开、完成步骤合并、运行结束整体收起。
- Web/手机均使用步骤化过程视图；Android 1.7 同步发布。
- TypeScript、ESLint、Web/手机构建、权限 UI、提问 UI 和 Agent 循环测试通过。

## 运维约束

- 发布前检查是否有 `running/waiting` 任务；非紧急部署应等待任务完成或先通知用户。
- `interrupted/lease_expired` 是服务中断，不是模型预算耗尽。
- 文本回答可以直接完成；需要可下载成果时，应使用 `save_artifact`、`create_pdf` 或 Office Skill，并在验收时检查成果链接。
