# M0 任务拆解（tasks-m0）

> **定位**：[plan-2026.md](plan-2026.md) M0 竖切的任务级拆解——每个任务可直接开工，含需求映射、依赖、验收与预估。任务 ID 稳定，状态在此维护：⬜ 未开始 / 🔄 进行中 / ✅ 完成 / ✂️ 裁剪（记入 M1）。
> **输入**：需求清单 v2 P0 条目 ｜ plan-2026 W1-W4 里程碑 ｜ 源码级参考（[claude-code-internals](../01-research/competitors/claude-code-internals.md)、[codex.md](../01-research/competitors/codex.md)——**只学设计，K05 红线：代码/提示词原文不进仓库**）。
> **产能假设**：全职单人，5 工作日/周。每周任务分「必做（演示关键路径）」与「可滑（超产能先滑，按 plan §5 裁剪顺序）」。预估含自测，不含 eval 题编写（随验收顺手写）。
> **制定**：ZCode ｜ 2026-09-05

## 0. 通用工程纪律（每个任务都适用）

1. **持久化必经 store 层**（K02）：原子写(tmp+rename)+.bak+坏文件隔离，从第一个落盘文件起生效。
2. **参考实现只读**：`E:\project\codex`、`E:\project\claude-code-leak` 允许读源码学结构，禁止复制代码/提示词文本。
3. **提交粒度 = 任务**：一个任务一次可运行的 commit；周五演示前打 tag `m0-w<N>`。
4. **验收写成 eval 倾向**：凡是"能机器断言"的验收（kill 恢复、谎报拦截、越界弹窗）当场写成脚本，进 `eval/` 目录（K01 地基）。
5. **前端纪律**（A01.3）：前端只走 localhost HTTP/SSE，禁 import server/core 实现——从第一个组件开始遵守，W4 才加 CI 检查。
