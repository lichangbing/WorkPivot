# M5 企业部署可靠性冲刺（tasks-m5）

> **定位**：2026-09-08 用户定调的 4 周冲刺——在保留现有办公 Agent 功能的前提下，完成**权限隔离、会话安全、数据恢复、部署验证**，达到受控企业试点条件。关键问题未通过验收不得进入发布。
> **周期**：4 周（第 1 周自 2026-09-08 起，每周周末验收，按验收结果滚动调整）。
> **输入**：用户《WorkPivot 企业部署可靠性工作计划》（2026-09-08）+ 09-08 代码现状核查（初始问题清单 19 项：P0×6/P1×8/P2×5，见附录 A；已转入 [可靠性问题台账.md](可靠性问题台账.md)）。
> **编号**：本冲刺为新里程碑 **M5**（区别于 `03-project/README` 的旧阶梯命名；M1 批次 4b 及知识库检索等顺延，见附录 B）。任务 ID 前缀 `RL{周}-{序号}`，避开已占用的 T/M1/U/R/W 系列。评测新套件顺延 **W11-W14**。
> **执行规则**：
> 1. 每个问题单包含：复现步骤、预期行为、修复内容、测试证据（台账：`docs/03-project/可靠性问题台账.md`，RL1-01 建立）。
> 2. 每天更新「已完成、阻塞、下一步」（周报周节内滚动记录）；每周一次周末验收，未通过不进入发布路径。
> 3. 修复与重构分开提交，避免扩大回归范围（重构集中在第 4 周 RL4-01）。
> 4. 测试使用独立数据目录（`WORKPIVOT_HOME`/`WORKPIVOT_WORKSPACE` 指向临时目录，同 eval 惯例），不接触真实账户、密钥和业务文件。
> 5. 优先级依次为：越权与执行边界 → 会话与恢复 → 稳定性 → 代码整理。
> 6. 改 `packages/server`/`packages/core` 后重跑打包链同步桌面快照（`apps/desktop/build/server-deploy`）再验证安装态。
