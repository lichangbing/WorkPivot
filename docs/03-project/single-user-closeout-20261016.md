### 缺陷修复与真实复验

真实模型将明确指定的“专家工作方法”同时提取成个人记忆建议。三层记忆提取指令已增加边界：专家方法及其纠错由独立专家经验系统处理，保留同一消息内独立的任务要求/个人偏好/项目事实。使用同一合成输入和当前提取指令调用 DeepSeek 复验通过：未生成包含库存方法的三层记忆建议，仍保留报告交付任务。首次独立探针使用 4096 输出预算未取得可解析 JSON，取消该探针自设上限、按产品默认请求后 finish_reason=stop，通过断言。提示词约束不构成对任意模型输出的数学保证，建议仍须用户确认。

### 完整办公与专家闭环

第二轮临时环境使用生产 runtime + DeepSeek + 专用 Skill worker + PostgreSQL 16；前端通过浏览器实际上传合成 Excel（A=10、B=20）。预置测试技能要求脚本读取 Excel 并生成 DOCX，用户点击语义一致的每次审批后执行，未绕过产品权限。

- 第一轮生成 budget-report.docx v1，第二轮请求倍率 2，仍为同一 documentId，仅一份当前成果，历史保留 v1/v2。
- 两个版本均通过浏览器下载到本地，并检查 DOCX 的 word/document.xml：v1 为 `Budget total: 30`，v2 为 `Budget total: 60`；下载文件 SHA-256 与各自发布记录一致。
- 认证 HTTP 复核两个历史版本内容、原 Excel 字节未改变、恰好两条 completed 的 Skill 执行记录；浏览器历史版本对话框显示两个版本。
- 初始临时执行镜像尚未安装 Python 时，附件解析失败且界面提供重试；补齐 Python/poppler 的镜像后点击重试，最终解析 completed、界面显示“可检索”。该失败是测试环境准备不完整，不认定为业务缺陷；Office 脚本读取原件的两轮计算均成功。
- 在界面手动新增并锁定库存专家经验，新任务通过真实模型读取原条目并收到纠错请求。数据库只读复核：该轮 expert_jobs 为 completed、attempts=1，唯一经验仍为 active/locked/v2，expert_suggestions 无冲突建议。补齐首轮缺少的后台终态核对。
- 最后核对所有三条 memory_jobs 均 completed，新任务未产生个人记忆建议；无 running 的 task_runs。通过认证关闭接口结束服务，运行器清理临时 PostgreSQL，专用 worker 关闭并删除随机凭据文件；Docker 无剩余运行容器。保留测试镜像、用户提供的密钥文件及已下载的合成成果，不改业务部署。
