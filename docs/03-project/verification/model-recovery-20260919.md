# 模型连接超时定位与有限恢复

## 复现证据

隔离办公验收捕获一次模型请求在约 70.5 秒后失败，原始异常类型为 TypeError，底层代码为 ETIMEDOUT。对应请求的工具调用/结果配对完整；当时 Word 第一版已经发布。故障也发生在第一轮后续请求中，并非只在第二轮出现。不能据此断言此前所有未知错误均为相同原因。

诊断只记录请求序号、消息数量、工具配对计数、耗时及白名单错误类型/代码，不保存上游响应正文、请求内容、地址或密钥。用户界面不暴露这些技术信息。

## 修正

- 模型服务适配层对明确的连接故障及 HTTP 502/503/504 增加一次重试，间隔 500ms。
- 仅在本次请求没有交付任何流事件时重试。正文、思考、工具调用一旦交付，不自动重试，避免重复输出和调用。
- 不自动重试参数/认证/权限/限流错误；外部取消始终优先。
- 重试范围是一次模型请求，不重新运行任务和已执行工具。不保证上游持续不可用时成功，重试失败仍返回明确错误。
- 补充中文超时、连接关闭的安全提示及受限诊断信息，继续屏蔽上游正文和凭据。

## 验收

- 新增模型恢复检查覆盖无输出超时、正文/思考/工具调用后的中断、预算耗尽、400/401/403/429、503、取消等边界。
- 最新真实模型完整通过两轮办公链路：上传 Excel，计算 10+20，生成 Word 版本 1；下一轮系数为 2，生成同一文档版本 2，正文分别核对为 30 和 60。
- 第二轮重建执行器，之后重新创建文件仓库，验证对话恢复、成果身份、两份历史版本及上传原件字节未改变。
- 真实模型成功证明该场景可完成；受控故障测试证明重试边界。该次成功实测未额外统计内部重试次数，不能声称其中必然发生了自动重试。
- 日志：`releases/deploy/artifacts/office-request-diagnostic.log`、`office-recovery-real.log`、`model-recovery-tests.log`。
