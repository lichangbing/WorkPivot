## 交付范围

| 层 | 内容 |
| --- | --- |
| 数据库 | schema v63；项目 profile、业务对象、标识、别名、事实 series/revision、关系 series/revision、证据、冲突、作业和 epoch |
| 权限 | 所有新表强制 RLS；行级用户归属；项目复合外键；临时任务拒绝写入 |
| 服务 | 新增事实创建、更新、历史、遗忘、关系创建/撤销、模型配置、冲突确认和自动提取开关 API |
| 提取 | 新完成任务异步提取；证据必须逐字来自本轮用户消息；无冲突新增自动保存，不同值进入单条冲突 |
| Agent | 每轮有界自动召回；`search_business_facts`、`read_business_fact`、`trace_business_relations` |
| Web | 项目右侧栏业务事实面板：检索、模型、自动提取、对象选择、新增、修改、历史、证据、遗忘、关系和冲突确认 |
| 手机 | 项目业务事实列表、自动提取开关、当前事实、关系和单条冲突确认 |
| 删除 | 任务来源删除使派生事实退出召回；项目删除清理对象、事实、关系、作业、profile 和 epoch |

## 关键规则

- 同一对象、属性、维度和口径使用稳定 `business_fact_series`。
- 值改变生成不可变 `business_fact_revision`，不覆盖旧值。
- 普通检索只返回项目内 active、无阻断冲突的事实。
- 冲突未确认时隐藏旧值与候选值，只显示待确认提示。
- `asOf` 查询业务有效时间；`knownAt` 查询系统当时已知的 revision。
- 自动上下文最多 8 条、约 3200 字；超时或失败不阻断聊天。
- 不自动回填历史对话，不跨项目召回。

专项测试覆盖：

- 两个项目使用相同合同编号，对象与事实不混用。
- 100 万改 200 万进入同一事实冲突；未确认时自动上下文零事实召回。
- 确认新值后旧 revision 为 superseded，新 revision 为 active。
- `asOf + knownAt` 返回变更前正确值。
- 错误金额、旧 revision、跨用户读取和临时任务写入被拒绝。
- 手工及对话来源证据、关系遍历、关系撤销和重新确认。
- 异步提取作业完成；来源任务删除后事实退出召回。
- 项目删除后事实不可再读取。

## 已知限制

- 首版实体消歧支持项目内精确外部标识、规范名和别名；可逆合并、拆分和模糊候选 UI 尚未实现。
- 文件表格批量提取、ERP/CRM 连接器、向量候选和项目概览尚未实现。
- 关系首版是已确认关系的创建、浏览和撤销，不提供任意图计算。
- 自动提取质量仍需使用中文真实业务对话评测；错误候选必须通过来源和人工确认管理。
- 当前项目协作仍以单个项目所有者为主；RLS 已带项目所有权约束，后续成员协作需要统一扩展。
