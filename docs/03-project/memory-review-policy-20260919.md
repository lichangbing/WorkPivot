# 待确认记忆纠错与拒绝去重

## 本批实现

- 整理器比较同一任务、同一记忆层的近期待确认建议。只有本轮明确纠正同一事实时，才能提交替代关系。
- 新建议插入和旧建议失效在一个事务内完成。新卡片标明替代数量；旧卡片不能继续确认。有效记忆仍需用户确认后才会写入。
- 替代时检查任务、层级、记忆版本、目标条目、来源先后和完整上下文依赖。若用户先一步保存或拒绝，迟到的替代结果失败，不覆盖用户决定。
- 支持连续纠错后回到曾被替代的值，拒绝记录及因遗忘失效的建议不因此重放。
- 新建议附带主体、属性、具体值的短语义标识。拒绝后清除建议全文、证据和上下文，保留最多 300 字符的语义标识和哈希供去重。标识本身仍属于用户私有数据，受行级权限限制。
- 后续整理同时比较同任务同层最近 20 条拒绝标识，识别“英文/英语”等同义表达；不同值、主体、范围不得混为重复。来源撤销时清理语义标识，来源任务删除时沿用级联清理。
- schema 27 为新增列、索引和清理触发器，不改变此前迁移校验值。

## 验证

- PostgreSQL 533/533 项通过，包括原子替代、拒绝/确认竞态保护、失效卡片拒绝保存、改回旧值、不同层和值的去重隔离，以及来源撤销清理。
- 真实配置模型与独立临时数据库验证：中文待确认建议被英文建议替代；没有自动写入有效记忆；拒绝英文后，再说英语不会再次出现建议。
- 首次真实测试暴露仅用哈希无法覆盖同义键，已加入近期拒绝标识的语义比较，最终实测通过。
- 类型检查、相关文件 lint 和前端构建通过。测试日志位于 `releases/deploy/artifacts/memory-review-policy-tests.log`、`memory-review-policy-real.log`。

## 边界与下一步

- 语义判断依赖配置模型，不保证所有改写都能识别。待确认比较最多 10 条，且来源必须完整包含在此前五轮上下文中。
- 旧版本已经拒绝且清除全文的建议，不补造语义标识，仍保留原有精确指纹去重。
- 拒绝不阻止用户手动新建记忆。暂未新增单独的拒绝历史管理页面。
- 本批未重新验收专家与三层记忆的全部联合交互、完整 Office 流程和公网部署；这些是下一批工作。
