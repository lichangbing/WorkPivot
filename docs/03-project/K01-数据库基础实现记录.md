# K01 数据库基础实现记录

日期：2026-09-13。状态：第一批代码与独立验证完成，K01 整体仍在开发。

## 已实现

- pg 驱动、独立身份/业务连接池、事务级用户上下文、异常回滚与连接释放。
- v1 新库建表、结构校验和并发初始化锁；不导入旧 JSON。
- 身份库：用户、凭据、会话摘要、认证版本、账号操作审计；注册、创建用户、登录、改密、重置密码、退出。
- 业务库：项目/项目所有者成员关系、任务、顺序消息、个人设置、三层记忆及历史修订、删除标记、knowledge epoch 和 outbox。
- 强制 RLS、跨用户关系约束、运行角色与建表角色分离；身份连接无个人项目读取权限，业务连接无凭据读取权限。
- 项目与设置乐观版本、消息幂等/并发顺序、记忆编辑冲突；记忆删除在线历史、保留无正文的遗忘标记和清理事件。
- 独立 HTTP 验证入口；仅支持已接入的功能，未接入路由返回503，不偷偷回退文件版。验证服务健康名称与正式服务不同，不能误判为完整可连接后台。

## 开发入口

在 code 目录：

```text
node scripts/test-postgres.mjs
node --import tsx scripts/postgres-schema.mts
node --import tsx scripts/postgres-preview.mts
```

测试默认使用本地已存在的 postgres:17-alpine；可通过 WORKPIVOT_TEST_PG_IMAGE 指定其他已审查镜像。Windows 使用 WSL Ubuntu-24.04 的 Docker，Linux 直接使用 Docker。测试自动生成临时凭据、随机回环端口和有标识的独立容器，禁止把 eval/W38 指向业务实例。

手动验证服务先准备一个空数据库和两个互不继承、非超级用户/非BYPASSRLS、非数据库结构所有者的 LOGIN 角色。建表命令读取 WORKPIVOT_DATABASE_ADMIN_URL 和 WORKPIVOT_DATABASE_APP_ROLE/WORKPIVOT_DATABASE_AUTH_ROLE（默认 workpivot_app/workpivot_auth）。仅执行结构创建/校验，不自动创建登录角色或处理线上数据。

验证服务读取 WORKPIVOT_DATABASE_URL（业务角色）、WORKPIVOT_AUTH_DATABASE_URL（身份角色）、WORKPIVOT_ADMIN_INIT_TOKEN（至少24字符）、WORKPIVOT_DATABASE_PREVIEW=1；默认仅监听127.0.0.1:39985。角色凭据来自服务器环境，不提供给客户端。建表账号不用于HTTP运行。

部署模板 releases/deploy/compose.postgres.yml 仅用于独立新库，要求指定已验证的镜像摘要；面向PG15–17数据目录布局，PG18及以后需重新核验。数据库不发布公网端口，后台可加入内部网络。本次未部署该模板，也未创建新的持久业务数据库。
