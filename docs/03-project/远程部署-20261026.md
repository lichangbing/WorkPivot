## 2026-10-26 消息发送与附件上传故障修复

- **现象**：在 `http://115.191.1.188/` 输入消息或选择附件后，点击发送没有请求到达服务端。
- **根因**：页面通过普通 HTTP 的 IP 地址访问，属于非安全上下文；浏览器的 `crypto.randomUUID()` 在该上下文不可用。发送消息、上传附件和自动化请求直接调用该方法时抛出 `crypto.randomUUID is not a function`，请求在发出前即被阻断。
- **修复**：新增前端 `crypto-compat` 兼容层；仅当原生 `randomUUID()` 不可用时，用不受安全上下文限制的 `crypto.getRandomValues()` 生成同语义 UUID v4。主工作台和管理端入口均加载该兼容层。
- **部署**：重新构建 `workpivot-server:local-stack` 镜像，仅重启服务端容器；数据库、文件和登录数据均保留。原文件备份为对应目录下的 `*.bak-pre-randomuuid-20261026`。
- **验证**：在普通 HTTP 页面中完成真实操作，`crypto.randomUUID` 为可用函数；附件上传 `POST .../files` 返回 200，消息 `POST .../messages` 返回 200，界面收到模型回复 `OK`，无页面异常。验证用临时任务、附件和会话均已清理。

### 成员剩余额度即时刷新

- **现象**：普通成员已完成提问，数据库 `messages_used` 正常递增，但页面仍显示登录时读取的旧剩余次数。
- **修复**：每轮发送结束后重新读取 `/api/auth/state`，同步账号额度；发送失败或额度耗尽时也会刷新。
- **验证**：普通成员从“剩余 7 次提问”发送一轮后，页面即时更新为“剩余 6 次提问”，接口无异常。验证产生的任务和额度计数已恢复。

### 每日 12 点额度刷新

- **现象**：此前只有累计 `messages_used`，没有周期字段或重置任务，北京时间 12 点不会生效。
- **修复**：schema v58 增加 `quota_reset_at` 和 `quota_next_reset()`；以 `Asia/Shanghai` 为准，每天 12:00 进入新周期。计数事务在跨点时原子归零再扣本次，避免并发重复清零。
- **页面**：`/api/auth/state` 返回 `resetsAt`；页面在到点时自动重新读取额度，并显示“每日北京时间 12:00 刷新”。
- **部署**：已执行 schema v58。三个现有账号均清零一次，下一重置时间初始化为北京时间 12:00。
- **验证**：页面接口对 `lichb` 返回 `used=0, remaining=10, resetsAt=2026-10-27T04:00:00.000Z`；数据库边界函数在 11:59:59 返回当日 12:00、在 12:00:00 返回次日 12:00。临时跨点计数记录为 1 后回滚，未污染业务数据。

### 无冲突记忆自动保存

- **规则调整**：任务、用户、项目层的新事实若无冲突，后台直接保存；只有修改已有记忆、合并记忆或出现冲突/纠正时生成待确认项。
- **确认交互**：冲突确认一次只展示一条，处理完才显示下一条；按钮为“确认保存 / 修改 / 删除”，避免一次弹出大量内容。
- **实现**：自动提取与十轮分析只自动接受本次新建、无替代目标、无冲突的 `add` 候选；`update`、`merge` 与带替换关系的候选保持待确认。schema v60 增加 `decision_source`，区分 `auto` 与 `user`。
- **验证**：真实模型“蓝色封面”事实自动保存为 revision 1；随后“改为绿色”生成单条冲突，人工确认后更新为 revision 2。两条冲突并发时页面只显示第 1 条，删除后自动显示第 2 条。测试任务和记忆已清理。

### 每轮识别个人、项目、任务三层

- **原因**：此前逐轮提取只负责任务记忆，个人和项目记忆要等满10轮补充分析，因此短期看起来只有会话/任务记忆。
- **修复**：每轮同时识别三层，临时要求不能误升为个人或项目事实；每10轮的个人/项目跨任务补充分析继续保留，用于补漏与整理稳定事实。
- **界面与提示词**：同步修改聊天系统提示、十轮分析提示和记忆管理说明，明确“无冲突新增自动保存，修改/合并/冲突逐条确认”，避免模型仍按旧规则声称所有记忆都要确认。
- **部署**：已重新构建并部署 `workpivot-server:local-stack`，服务容器 healthy；数据库 schema 为 v60。
- **验证**：使用真实模型处理一条同时包含个人、项目、任务事实的消息，后台自动写入三层各 1 条，均为 revision 1、`decision_source=auto`；不再产生额外待确认项。临时项目、任务、运行和记忆已清理。
- **历史数据**：`lichb` 原有5轮已完成记录不会强制重跑。原对话主要是任务执行或“继续”，没有明确的跨任务个人偏好或项目长期约束，因此不会为了数量强行生成个人/项目记忆；后续新轮次会立即参与三层识别。
