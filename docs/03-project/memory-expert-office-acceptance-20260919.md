# 专家、三层记忆与办公链路联合验收

本批以当前 schema 27 的 WSL 版本为基础补充自动化验收，不改动产品界面或数据库结构，并修正验收中发现的办公工具指引歧义。测试使用独立临时 PostgreSQL 和虚构资料，现有用户资料未改动，不挂载 Docker socket。

## 专家与记忆

新增联合测试纳入 W38 回归，目前 554/554 项通过。

- 同一轮分别形成三层记忆建议和专家经验建议，未确认内容不进入有效上下文。
- 锁定记忆后，两条整理管线的旧建议不能继续写入；用户仍可手动编辑锁定条目。
- 手动修改个人记忆不改变项目、任务记忆内容。
- 切换专家只加载新专家经验，三层记忆继续保留，其他用户不能读取这些数据。
- 手动调整并锁定专家经验保留修订历史，同时阻止旧上下文下的三层记忆建议继续确认。
- 同一来源任务删除后，派生项目记忆与专家经验清除；独立手写的记忆和经验保留。

这些验证使用真实 PostgreSQL、应用权限和可控模型输出。当前采用保守的统一上下文失效策略：锁定或手动修改可能同时让另一类待确认建议失效，并非两类建议可以始终互不影响地确认。

使用已配置模型、独立测试库及隔离执行 Worker：上传虚构 Excel，读取 10、20 两项金额，按 Skill 脚本生成 Word；下一轮将系数改为 2，更新同一成果版本。

验收检查最终答复、实际工具调用、DOCX 内真实计算结果、成果唯一身份及版本号。扩展检查在下一轮重新创建执行器，以及重新创建文件仓库后读取两个历史版本和上传原件。重建应用对象不等同于操作系统进程故障恢复。

## 工具指引与错误提示修正

- execute_skill 明确要求 inputs 使用文件版本 ID，未列入的文件不会进入隔离环境。
- 产物 name 只填写文件名，命令中的输出路径才使用 /workspace；更新须指定原 documentId 和当前 revision。
- 无解析服务的实例明确提示 Office/PDF 应通过 Skill 读取，避免反复按纯文本读取。
- 模型错误按认证、限流、上游服务故障、超时、连接及未知错误分类；不显示上游正文、地址或凭据。
- 联调脚本补齐正式服务已有的后台 Office 解析器；此前缺失解析器的测试不代表完整部署能力。
- 实测过程曾出现模型参数误用及模型请求失败，不能以一次成功宣称整体稳定性已完全达标。
