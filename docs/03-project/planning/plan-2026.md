# 2026 开发计划（plan-2026）——M0 竖切

> **定位**：M3（MVP 开发）的执行排期。当前聚焦 **M0 竖切**：4 周跑通「登录 → 建任务 → 对话 → agent 在真实工作目录干活 → 交付 Word → 安全可控 → 重启可恢复」的最小闭环，作为回答 Q5（首批种子客户）的演示敲门砖。
> **输入**：[需求清单 v2](../../02-design/product/requirements/历史需求基线.md)（已冻结，开发直接依据）＋ 六册 PRD ＋ 30 页原型（UI 照抄，不再设计）。
> **制定**：ZCode ｜ 2026-09-03 ｜ 状态：🔄 执行中（日期为建议值，周粒度浮动可接受，验收判据不变）
> **任务级拆解**：见 [tasks-m0.md](tasks-m0.md)（每个任务含需求映射/依赖/验收/预估，2026-09-05 基于竞品源码分析结论细化）。

## 0. 执行原则

1. **竖切优先，不按模块推进**（R8 缓解）：每周结束交付一个能演示的完整故事，而不是某个模块"做完了"。
2. **薄实现合法，无声砍非法**：M0 允许「薄」实现（功能成立但边界裁剪/配置简化），完整化登记到 M1；凡本周不做的 P0 条目必须出现在 §3 矩阵里，不允许默默消失。
3. **安全底线从第一行代码起**：第一把 API key 就走 I04 加密（不留明文债务）；bash 工具晚于 I01 沙箱上线（工具可以少，纪律不能晚）。
4. **时间盒**：每周五演示；不达标按 §5 裁剪顺序砍演示项，不动安全与数据完整性。
5. **形态 A 拆分纪律**（A01.3：前端禁 import 服务层、禁 Electron 专属 API）从 W1 起作为代码纪律执行，CI 自动检查 W4 补上（C05）。

## 2. M0 总验收（一场演示讲完整个故事）

1. 首次启动 → 注册（自动成为管理员）→ 管理员新建用户 → 新用户登录；
2. 新建任务绑定工作目录 → 对话下达「整理这些材料生成一份报告」；
3. 过程主线中文推进（获取了什么→做了什么→结论），界外访问弹授权，危险命令被拦；
4. 中途 kill 进程 → 重启 → 任务显示「已中断」→ 继续 → 完成；
5. 交付 `报告 v1.0 2026-xx-xx.docx`，写后自检通过，版本链可查，双击 Word/WPS 可开；
6. **加分项（C03 验收的事实验证）**：拔掉外网，全程用本地 Ollama 模型重跑一遍，功能完整；
7. 审计日志能还原上面每一步的危险决策与界外授权。
