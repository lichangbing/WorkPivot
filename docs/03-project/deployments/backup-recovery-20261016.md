# 单用户联合备份与隔离恢复验收

## 实现范围

实现 PostgreSQL 与文件存储的离线联合备份、校验、隔离恢复和恢复前安全快照。对应统一计划 SU-R1-01、SU-R1-02。界面入口、定时备份、保留周期、容量告警和自动切换部署仍在后续任务范围内。

备份使用真实 `pg_dump` 自定义格式，保留 GRANT/REVOKE。恢复使用 `pg_restore --single-transaction --no-owner`，保留原角色权限，拒绝覆盖已有数据库对象和文件目录。采用单事务而非仅 `--exit-on-error`，是为了转储后段失败时也能回滚前面已创建的对象。依据：[PostgreSQL 16 恢复参数](https://www.postgresql.org/docs/16/app-pgrestore.html)、[转储参数](https://www.postgresql.org/docs/16/app-pgdump.html)。

备份期间使用独立借出的数据库连接，持有各用户文件发布锁及业务表共享锁，直到转储、文件复制、引用校验和原子发布结束；发布前复查同一连接，连接丢失时不得发布备份。运行中任务或后台作业会阻止备份。运维仍须先停止应用和 worker，环境变量仅表示操作者已完成停写，不能代替停服务。

恢复后校验数据库版本校验值、运行角色授权、强制 RLS 和全部原件引用的大小/哈希；撤销旧登录会话，将在途任务、审批和后台执行置为中断或需手动重试，防止恢复后重放旧副作用。恢复前源仍可访问时，自动取得其当前遗忘清单，并复用已有规则清理旧备份中的已删除资料、记忆、专家经验及上下文。

## 操作说明

在 `code` 目录运行，需要与服务器主版本兼容的 PostgreSQL 客户端工具。独立目标必须预先创建为空数据库，并预建源库记录的两个受限运行角色；使用独立建表/恢复账号，不使用应用账号恢复。需要换角色名或跨版本迁移时，先使用对应版本恢复，不自动改写归属和权限。

配置中的数据库连接地址通过受保护本地配置文件加载，不写入命令历史、文档或聊天。数据库转储本身包含用户资料、密码哈希和加密模型/MCP 配置，备份目录应按敏感资料保存。服务器加密主密钥未打入备份包，须单独保管；恢复后沿用原主密钥才能解密原模型配置。

创建与校验：

```bash
# 停止应用和后台执行器后设置以下变量；连接地址从受保护配置文件加载。
export WORKPIVOT_BACKUP_OFFLINE=1
# WORKPIVOT_DATABASE_ADMIN_URL 指向当前源数据库。
# WORKPIVOT_DATABASE_FILES_ROOT 指向当前源文件目录。
pnpm backup:create /受保护备份目录/本次备份
pnpm backup:verify /受保护备份目录/本次备份
```

恢复命令所需环境变量：

| 变量 | 含义 |
|---|---|
| `WORKPIVOT_RESTORE_OFFLINE=1` | 已准备独立离线恢复目标 |
| `WORKPIVOT_BACKUP_OFFLINE=1` | 已停止当前源写入，允许创建安全快照 |
| `WORKPIVOT_DATABASE_ADMIN_URL` | 目标空库；库名以 `_restored` 或 `_restore_test` 结尾 |
| `WORKPIVOT_DATABASE_FILES_ROOT` | 不存在的目标目录；目录名以 `_restored` 或 `_restore_test` 结尾 |
| `WORKPIVOT_RESTORE_CURRENT_DATABASE_URL` | 恢复前当前源的管理连接 |
| `WORKPIVOT_RESTORE_CURRENT_FILES_ROOT` | 恢复前当前源文件目录 |
| `WORKPIVOT_RESTORE_SAFETY_BACKUP` | 新建 before-restore 安全快照的目标目录 |

```bash
pnpm backup:restore /受保护备份目录/待恢复备份
```

CLI 当前要求原数据源可访问，以创建安全快照和读取更新的遗忘清单。数据源完全损毁时，库函数可以对空目标恢复而省略此步骤，但 CLI 尚未提供灾难恢复模式；不能声称在缺少最新遗忘清单时也能防止历史删除内容复活。

恢复不会自动改现有服务的连接或挂载。先在隔离目标验证账号登录、任务、记忆和文件下载，再按部署流程同时切换数据库、身份数据库和文件目录；原源及 before-restore 快照保留用于回退。后置结构/引用校验失败时不发布文件目录，隔离目标库可能已完成数据库恢复，应保留排查并另建空目标重试，禁止直接连接业务服务。转储执行中的失败由单事务回滚，不自动删除任何已有数据库。
