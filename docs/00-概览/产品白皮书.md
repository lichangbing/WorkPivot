# WorkPivot 产品白皮书

| 项 | 值 |
| --- | --- |
| 文档类型 | 产品白皮书 |
| 状态 | ✅ 当前口径；面向产品、售前、交付与内部研发 |
| 适用版本 | `v0.3.0-rc.6`，schema v72 |
| 更新日期 | 2026-11-04 |
| 产品定位 | 面向真实办公交付的私有化 AI 工作台 |

> **核心主张：** WorkPivot 不把“把更多内容塞进模型”当作能力。系统把项目材料、会话经历、工作执行、结构化事实和用户偏好分层持久化，再按当前问题动态组装最小、充分、可追溯的上下文，以降低遗忘、串项和无证据回答。

## 1. 产品是什么

WorkPivot 是后台持续运行的 AI 工作台。用户用项目组织资料，用任务表达目标；Agent 在明确文件和工具权限内读取材料、调用 Skill、执行工具，并交付可预览、可修改、可追踪版本的 Word、Excel、PPT、PDF 和报告。

产品重点不是生成一段看起来合理的文字，而是形成：

```text
项目资料
  → 明确任务
  → 受控执行
  → 可见过程
  → 成果版本
  → 证据与验收
```

主要服务对象包括投研、咨询、财务、法务、研究、战略与内部运营团队。

## 2. 需要解决的问题

通用聊天工具进入业务工作后，通常存在四类问题：

| 问题 | 典型表现 | WorkPivot 的解决方向 |
| --- | --- | --- |
| 上下文膨胀 | 聊天越长、资料越多，模型越容易忽略关键约束 | 每轮检索并按预算组装，不加载全部历史 |
| 事实不可靠 | 旧值、新值、推测和原文同时出现 | 用业务事实、版本、冲突和证据分层 |
| 工作不可追踪 | 做过哪些任务、产出在哪里、如何完成不清楚 | 建立持久工作记忆与成果引用 |
| 交付不可验证 | 模型声称完成，但文件不存在或不可打开 | 成果登记、机器核验、预览、版本和审计 |

## 3. 核心产品对象

### 3.1 项目

项目是业务边界和长期上下文容器，组织：

- 项目资料和文件版本；
- 会话、任务和成果；
- 项目规则与业务事实；
- 团队成员和访问权限；
- 项目记忆与知识检索范围。

### 3.2 会话

会话是一段连续的用户—Agent 交互，保存：

- 用户请求和 Agent 回复；
- 工具调用和执行过程；
- 中断、继续和恢复；
- 影响工作的关键决定；
- 关联的任务和材料版本。

会话记忆不是整段聊天的副本，而是从会话中提炼并保留来源的结构化情景记录。

### 3.3 工作项

工作项是“要完成并交付什么”的业务单位，回答：

- 安排过什么；
- 为什么做；
- 使用了哪些材料和角色；
- 采用什么方法；
- 当前状态如何；
- 产出了哪些成果；
- 成果版本和位置在哪里；
- 还有哪些未完成事项。

当前 RC.6 使用任务、运行记录、工具派发和成果版本等对象承载工作项能力；统一工作项视图属于后续收敛方向。

### 3.4 成果与证据

成果以不可变版本保存，具有文件 ID、版本 ID、哈希和存储位置引用。聊天中的一句“已经生成”不能替代成果记录。

原始文件、会话事件、工具结果和用户确认是证据来源；项目概览、记忆摘要和模型推断是派生内容。

## 4. 上下文与记忆

### 4.1 严格定义

> **上下文是每轮调用模型时临时组装并发送的内容。记忆是持久化保存、可被后续任务检索复用的来源数据。**

上下文不是记忆本身；持久化保存也不自动等于记忆。

| 内容 | 持久化 | 是否自动成为记忆 |
| --- | --- | --- |
| 聊天消息、工具调用、运行事件 | 是 | 否，首先是事件和证据 |
| 当前任务步骤、等待、检查点 | 是 | 否，属于工作项运行状态 |
| 文件字节和页面快照 | 是 | 否，属于文件或知识版本 |
| 业务事实 | 是 | 否，属于结构化业务数据 |
| 用户偏好 | 是 | 是，属于用户记忆 |
| 会话情景摘要 | 是 | 是，属于会话记忆 |
| 项目稳定背景与规则 | 是 | 是，属于项目记忆 |
| 工作项执行与成果索引 | 是 | 是，属于工作记忆 |

WorkPivot 作为后台服务，不依赖终端 Agent 在客户端关闭后丢失的进程内短期记忆。但每次模型调用仍需要工作上下文；后台运行、任务恢复和多实例执行都要求状态持久化。

### 4.2 四类记忆

| 记忆 | 核心问题 | 主要内容 |
| --- | --- | --- |
| 用户记忆 | 用户是谁、通常怎样工作 | 角色、职责、偏好、表达习惯、默认工作方式 |
| 会话记忆 | 这次沟通发生了什么 | 目标、角色、材料版本、讨论、决定、成果、未决事项 |
| 项目记忆 | 项目当前是什么情况 | 项目背景、稳定规则、当前阶段、关键决定、概览 |
| 工作记忆 | 做过什么、怎么做的、结果在哪里 | 工作项、状态、方法、运行引用、成果版本、下一步 |

四类记忆按归属和使用目的划分，不把“短期/长期”作为并列第五类。后台统一持久化，但通过会话范围、项目范围、工作项周期和保留策略管理生命周期。

### 4.3 四类记忆的边界

```text
用户记忆   = 用户如何工作
会话记忆   = 这次沟通发生了什么
项目记忆   = 项目当前稳定认知
工作记忆   = 做过什么、怎么做的、成果在哪里
```

不应出现：

- 把用户偏好写成项目业务事实；
- 把聊天摘要当成合同金额的权威值；
- 把所有工具日志复制进工作记忆；
- 把项目所有会话合并成一段不可追溯的总摘要；
- 把当前运行状态写入跨项目用户偏好。

## 5. 工作记忆

### 5.1 设计目标

工作记忆是持久化工作台账。它让后台 Agent 在新会话、新运行或跨天工作中快速回答：

- 之前安排过什么任务；
- 当时用了哪些角色和材料；
- 如何完成；
- 产出了什么；
- 成果当前在哪里；
- 还剩什么问题。

### 5.2 工作项结构

```text
工作项
├─ 目标与任务
├─ 当前状态与下一步
├─ 使用角色 / 专家
├─ 输入材料和文件版本
├─ 计划与方法引用
├─ 运行、检查点和审批引用
├─ 成果 ID、版本、哈希和存储位置
├─ 关键决定与未决事项
└─ 来源会话、项目和用户
```

“当前工作”是当前会话或执行通道中的具体工作项或运行，不是全系统唯一任务。后台可以同时存在多个用户和多个活动工作项。

### 5.3 工作记忆不保存什么

- 完整隐藏思考；
- 全部工具参数和工具原始返回；
- 文件正文或二进制字节；
- 可覆盖的历史版本；
- 没有来源的模型猜测。

这些内容分别保留在受控事件、运行、文件和成果版本中；工作记忆只保存可读摘要、标识和引用。

## 6. 动态上下文装配

### 6.1 ContextPack

每轮上下文由服务端按当前问题动态装配：

```text
ContextPack
├─ 系统规则
├─ 当前用户请求
├─ 当前工作记忆
├─ 相关工作项历史
├─ 相关用户记忆
├─ 相关项目记忆
├─ 相关会话记忆
├─ 已确认业务事实
├─ 原始文件证据
└─ 当前 Skill / 程序方法
```

### 6.2 装配原则

1. 当前明确请求先于旧偏好和历史摘要。
2. 已确认业务事实用于精确值、关系和计算。
3. 项目概览用于项目导航，不覆盖业务事实。
4. 会话和工作记忆用于连续性和经验，不被当作系统指令。
5. 文件证据按当前用户确认的版本读取。
6. 角色、项目成员、材料版本和删除状态均在召回时复核。
7. 只加载当前问题所需的最小充分集合，详细内容按需读取。

### 6.3 当前实现基线

当前 RC.6 已实现：

- 服务端根据本轮 `memoryScopes` 召回已确认记忆；
- 自动召回最多 8 条、约 3200 字符，单条约 520 字符；
- 中文使用二至四字片段和英文词项做轻量相关性排序，再补充各层最新条目；
- 记忆变更会推进知识 epoch，使活动模型流停止并要求重新读取；
- 搜索结果通过 `search_memory`、`read_memory` 按需展开；
- 业务事实和项目文件知识分别有独立召回与证据链路。

当前自动记忆召回属于轻量词法排序，不等同于完整语义检索。后续可增加结构化元数据、混合召回与重排，但不能绕开权限、版本和证据硬过滤。

## 7. 事实、记忆与证据

### 7.1 业务事实

业务事实回答项目里的结构化业务问题：

- 合同 HT-001 当前金额是多少；
- 项目负责人是谁；
- 里程碑 M2 依赖什么；
- 某个值在某时间区间内是否有效。

业务事实具有项目范围、对象、类型化值、来源、revision、有效时间和冲突状态。它不是普通自然语言记忆。

### 7.2 原始证据

原始证据包括：

- 对话事件；
- 文件版本；
- 网页快照；
- 工具结果；
- 用户明确的确认记录。

证据证明某句话或某项操作发生过，不自动证明内容正确。模型只看到证据摘要时，不能声称已经读取完整原文。

### 7.3 派生内容

项目概览、会话摘要、工作摘要和记忆条目都是派生内容。它们必须：

- 保留来源引用；
- 可重建；
- 有版本或更新时间；
- 在来源失效时失效；
- 不覆盖更权威的业务事实。

## 8. 事实优先级与冲突

建议采用以下判断顺序：

1. **当前用户明确指令**决定本轮目标、范围和临时行为；
2. **已确认业务事实**决定项目业务值和对象关系；
3. **原始文件和对话证据**用于核验事实与结论；
4. **项目/会话/工作记忆**提供背景、偏好和连续性；
5. **模型推断**仅作为解释或候选，必须标明不确定性。

冲突处理原则：

- 当前指令可以改变本轮任务，不能静默改写业务事实；
- 记忆与业务事实冲突时，业务事实优先，记忆进入待复核；
- 多份来源给出不同金额或日期时，显示冲突，不混合成一个答案；
- 没有足够证据时回答“资料不足”，不能用记忆补全；
- 被拒绝、删除或来源失效的内容不得重新进入上下文。

## 9. 记忆写入规则

| 输入内容 | 默认归属 |
| --- | --- |
| 当前请求、回复、工具过程 | 对话事件 |
| 当前目标、步骤、等待、检查点 | 当前工作项运行记录 |
| 会话决定、成果和未决事项 | 会话记忆 |
| 项目背景、稳定规则和概览 | 项目记忆 |
| 用户角色、偏好和工作习惯 | 用户记忆 |
| 合同金额、负责人、日期、对象关系 | 业务事实 |
| 文件字节和页面快照 | 文件/知识版本 |
| 可复用方法 | Skill / 程序方法 |

写入规则：

- 临时要求不自动提升为长期偏好；
- 原始聊天不能自动成为业务事实；
- 工作完成但未交付时，不得写成已完成成果；
- 用户删除或来源撤销后，派生记忆和索引停止召回；
- 无冲突新增可自动保存；修改、合并、替代和冲突需要确认。

## 10. 准确性与反幻觉机制

WorkPivot 不以“注入更多内容”作为降低幻觉的唯一手段，而是组合以下机制：

1. **分层存储**：聊天、事实、记忆、知识和成果各司其职。
2. **有界召回**：按相关性和预算选择内容，不加载全量历史。
3. **来源追溯**：记忆和工作摘要保留来源；业务事实保留证据。
4. **权限复核**：召回时检查用户、项目、角色、材料和删除状态。
5. **版本检查**：文件、业务事实和记忆 revision 变化后旧上下文失效。
6. **冲突显式化**：冲突不交给模型静默调和。
7. **资料不足声明**：没有足够证据时停止确定性结论。
8. **成果验收**：文件存在、可打开、结构检查和必要视觉预览不等于业务正确，仍需分层验收。

## 11. 工作交付流程

```text
创建/选择项目
  → 创建会话和工作项
  → 选择角色、材料和记忆范围
  → 组装本轮上下文
  → 计划与必要确认
  → 工具执行和成果生成
  → 成果登记、版本和预览
  → 用户验收或继续修改
  → 写入工作记忆、会话记忆和候选事实
```

工作项可以跨多个会话和运行。每次运行结束都要保留：

- 当前状态；
- 已完成步骤；
- 使用的方法；
- 生成成果及其版本；
- 未完成事项；
- 是否发生外部副作用。

## 12. 当前版本与规划边界

### 12.1 当前 RC.6 已具备

- PostgreSQL 主存储、用户隔离和项目任务链路；
- 用户、项目、任务三层持久记忆；
- 每轮有界记忆召回、自动保存与冲突确认；
- 十轮周期分析和来源复核；
- 项目业务事实、关系、证据、版本与冲突；
- 不可变文件版本、知识确认、RAG 和引用；
- 会话事件、运行检查点、中断恢复和交付状态；
- Skill、专家、自动化和多端工作区；
- 当前任务运行记录、成果版本和下载链路。

### 12.2 目标口径中待统一

- 将现有 `task` 记忆逐步映射到工作记忆；
- 建立统一工作项聚合视图，而不是复制现有运行和成果；
- 形成结构化会话记忆，记录角色、材料版本、决定和未决事项；
- 建立可重建、带来源和有效期的项目概览；
- 区分全局用户画像与项目级覆盖偏好；
- 把记忆、会话、工作、事实和知识接入统一上下文装配服务。

以上事项是已接受的产品架构方向，不代表 RC.6 已全部实现。

## 13. 数据与安全边界

- 不同用户的项目、任务、文件、记忆和运行默认不可互见。
- 项目业务事实强制归属项目；临时任务不生成业务事实。
- 记忆不能扩大文件、网页、工具或项目权限。
- 网页和文件内容是数据，不是系统指令。
- 删除和撤权会传播到后续召回；已发送给外部模型的内容无法追溯撤回。
- 审计记录保存操作和来源标识，不记录密钥、口令或未脱敏业务正文。
- 备份、恢复和离线清单必须继续执行遗忘与撤权规则。

## 14. 产品价值

WorkPivot 的差异化不在于“让一个模型记住所有聊天”，而在于：

1. 让项目知识、工作成果和会话经历都有明确归属；
2. 让 Agent 每轮只读取与当前任务相关的内容；
3. 让业务事实与普通偏好、历史摘要和模型推断分开；
4. 让成果位置、版本和来源可追踪；
5. 让人工确认、失败恢复和删除传播成为系统机制；
6. 让私有化模型与企业自己的资料、权限和流程共同工作。
