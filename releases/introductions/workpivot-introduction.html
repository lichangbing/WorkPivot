A workspace for lasting professional work

让专业工作持续推进，
让知识与经验逐步积累。

WorkPivot 是支持企业私有部署的 AI 专业工作平台。通过后台集中管控、内网模型接入、分层记忆与人工确认，让 AI 在可控的数据环境中延续项目背景、执行办公任务，并积累经过确认的工作方法。

项目承载长期工作上下文压缩与确认三层记忆专家经验后台统一管理私有部署
研究 · 财务 · 项目管理 · 专业办公当前基线：单用户使用规模 RC.1 候选版
02 / Why WorkPivot

专业工作的价值，来自长期连续的积累。

研究一个行业、跟踪一家公司、推进一个项目，往往持续数周甚至数月。资料在更新，判断在调整，工作的背景、过程和方法需要一起延续。

01 / CONTINUITY

少一些重复交代

角色、表达偏好、项目背景和判断标准有明确归属。后续任务按范围读取已保存记忆，减少重复输入背景。

02 / CONTEXT

长对话也能继续推进

对话增长后整理工作摘要，保留关键限制、阶段结论和未完成事项，经用户核对后用于后续上下文。

03 / METHOD

把纠正转化为可复用的方法

将用户明确提出的工作方法整理为专家经验建议，经确认后在同一专家的其他任务中复用。

04 / CONTROL

把 AI 能力放入统一管理范围

模型配置、公共技能和专家模板在后台维护；执行权限和用户数据边界在服务端检查。

首个重点场景：持续研究一个项目

研究员不断补充财报、Excel 数据和讨论结论，使用周期型、成长型或中小市值型项目框架，逐步完善判断。财务人员与项目负责人是后续可拓展人群，具体行业流程仍需逐项验证。

03 / Memory under your control

记忆会积累，生效由用户决定。

上下文压缩负责延续当前工作；长期记忆负责在未来任务中复用重要信息。两者分别管理，都保留用户核对与确认的环节。

PERSONAL

个人记忆

保存用户角色、稳定偏好和常用工作要求，例如报告表达风格、关注领域和核对习惯。

PROJECT

项目记忆

保存项目背景、目标、研究框架和判断标准。周期型、成长型、中小市值型模板可供选用后调整。

TASK

任务记忆

保存当前任务的约束、关键事实和需要延续的事项，在对应任务范围内使用。

长上下文压缩：把漫长过程整理为可继续的工作摘要

已实现

在模型容量预算约束下分批整理长对话，提炼已完成工作、关键结论、限制条件和未完成事项。原始对话记录保留，摘要不应把推测变成事实，也不意味着模型能够无限记住全部原文。

识别上下文压力

依据模型容量与当前上下文预算触发整理。

分批生成摘要

保留工作状态、约束、重要结论与待办。

人工核对与确认

查看和修改摘要，纠正遗漏及概括偏差。

继续推进任务

后续上下文使用已确认摘要延续工作。

已实现
沟通中出现重要信息

识别有长期价值的事实、偏好或纠正。

生成有证据的建议

区分新增、修改、合并，展示来源和原内容。

用户编辑、确认或拒绝

未经确认的候选不参与后续记忆使用。

按范围保存与复用

保存确认后的最终内容，保留版本与来源。

交互示意 · 不连接实际账户

“以后比较库存数据，先核对统计时间和范围；口径不同要先解释差异。”

下一次任务会使用什么？

尚未确认，不作为已保存经验使用。

来源：用户明确提出的研究方法。这里演示专家经验确认；个人、项目和任务记忆也遵循相应的确认流程。

记忆可管理，也可遗忘

支持查看、新增、编辑、锁定和删除；分层控制读取与自动更新。修改或删除使旧上下文、旧建议失效；来源删除会传播到相关衍生记忆，无法安全拆分时保守整条失效。

自动模式不跳过记忆确认

任务执行模式与记忆保存决策分开。模型可以提出建议，但用户决定最终生效内容。“学习”指保存并复用确认后的信息和经验，不是训练或修改模型参数。

04 / Expertise that carries forward

专家有明确的方法，也有自己的经验。

专家设定定义如何工作，私人经验记录经用户确认、值得复用的方法。三层记忆继续负责具体的用户、项目和任务背景。

已实现

专家设定

  • 角色定位与判断原则
  • 启动时需要核对的规则和背景
  • 关联的 Skill 名称与能力要求
  • 私人经验的加载与自动建议开关
已实现

专家经验

  • 手动新增、编辑、锁定、历史版本与删除
  • 自动提出新增、纠正和合并建议
  • 展示原文证据、适用条件和原经验
  • 确认后跨任务复用，按关键词继续检索
公共模板 → 私人副本 → 个人使用 → 确认后的经验积累

后台发布专家模板，用户创建私人副本并调整。模板升级不会直接覆盖私人设定；任务可选择专家，项目可设置默认专家。运行中禁止切换，恢复上下文不自动重跑历史工具。

当前每个任务使用一个专家。默认直接加载最近十条有效经验，其余可通过工具检索；经验整理目前针对用户明确提出的方法或纠错，不将所有工具结果自动归纳为成功经验。

05 / Central governance

统一管理能力，明确划分数据权限。

集中管控贯穿配置、执行和数据生命周期。客户端负责交互，后台调用模型、组织上下文、检查权限并保存状态。

管控层次管理对象具体价值
能力层模型配置与凭据、公共 Skill、专家模板、默认记忆模板；按授权管理 MCP 接入统一配置和发布，减少重复维护；用户从可用能力中选择
运行层模型调用、执行授权、任务状态、失败重试、容量预算任务有进度和反馈，外部操作受权限约束，执行结果可核对
数据层项目、任务、对话、原件、产物、记忆、经验、版本及来源服务端集中保存，按归属访问，变更与删除有一致性规则

管理员：管理公共能力

在 /admin 配置模型，维护发布的技能包、默认记忆和专家模板。用户侧保持面向工作本身的入口，减少配置负担。

用户：掌握私人内容

私人项目、记忆和专家经验按用户隔离。业务管理员不会因管理身份而自动获得通过应用接口读取他人私人内容的权限。

业务权限隔离不等于阻止持有数据库超级管理员或宿主机权限的运维人员访问底层数据；企业仍需管理这些高权限账户。

06 / Private deployment & data boundary

连接私有模型，把数据处理留在企业环境。

支持自建后台，并按兼容协议接入企业控制环境中的模型服务。要形成完整的数据边界，需要同时约束模型、工具、联网能力、日志和备份。

07 / Skills, tools & deliverables

工作方法、执行能力和数据连接，各有分工。

通过可组合的技能和工具扩展办公能力，产物与过程材料分别管理。

SKILL / 方法与操作

可管理的技能包

包含 SKILL.md、脚本、模板及辅助资源。支持文件树编辑、新建文件或目录、导入、发布和停用；用户从技能市场加载可用技能。

MCP / 外部连接

连接工具与数据源

通过配置的 MCP 服务访问外部能力。工具调用仍受授权规则约束；内网部署需要核对连接目标及外发内容。

OUTPUT / 工作成果

生成并管理交付物

结合办公 Skill 处理 Word、Excel、PPT 等文件。服务端保存原件和产物，支持成果下载及历史版本核对。

组合示例：研究方法 Skill + 文档生成 Skill + 数据服务 MCP

研究技能规定核对步骤和报告结构，办公技能完成文件处理，MCP 提供经授权的数据连接。自定义研报格式可使用业务方法与模板组合，不必把所有规则塞进一个通用 Word 技能。

面向工作的交互

项目与任务组织、聊天及附件、任务监控、产物、技能/MCP 与记忆入口；黑白主题切换。打开任务先加载最近五轮对话，上拉继续加载更早内容。

过程透明与多端延续

区分正式回复、思考与工具调用，显示执行反馈；支持确认与自动两种模式。当前任务使用 SSE 推送事件并在断线后补拉；同一用户多端更新不等于团队共享。

当前数据库网页版 RC 包含成果下载与版本管理；旧薄客户端特有的自动成果同步未计入本次 RC 验收范围。办公文档处理增强仍按计划暂缓。

权限、版本与一致性

业务数据按用户归属隔离；修改和确认检查版本，重复确认保持幂等。删除任务、项目或来源资料，会撤销相关上下文并清理受影响的衍生记忆。

备份与遗忘一起考虑

数据库与文件配套备份。恢复旧备份时，在离线环境回放较新的可信保留清单，防止已删除的记忆和原件重新生效；无法推断清单之后未记录的删除。

当前已具备项目资料分片与关键词检索；pgvector、embedding、向量/混合 RAG 以及结构化指标库仍为规划或暂缓内容，不属于当前已上线技术组件。多用户公平调度与自动扩缩也尚未交付。

09 / Product research

围绕具体机制研究竞品，形成自己的产品取舍。

比较记忆何时生成、谁决定生效、如何管理、能力如何扩展，而非仅比较是否有“记忆”或“Agent”。以下为公开资料研究，未进行统一环境性能测试。

研究对象公开能力与参考重点对 WorkPivot 的启发

记忆官方说明

办公入口、能力市场、成果交付，以及记忆的用户管理体验。

WorkPivot 的差异化方向：把这些机制组合成长期工作的完整流程

项目连续性 + 分层记忆 + 压缩与人工确认 + 专家经验 + 服务端集中管控。我们的重点是这些能力如何共同服务专业工作，不宣称单项功能行业独有，也不预设竞品缺少相同能力。

建议持续对照的维度：项目组织、上下文管理、记忆确认、专家能力、Skill/MCP、数据控制、部署方式和使用门槛。外部资料会更新，上表为 2026-09-16 介绍时的研究摘要。

10 / Collaboration ahead

多位成员共同推进项目，多个专家分别贡献能力。

团队合作面向真实用户；多智能体协作面向 AI 的自动分工。两项能力分别规划，不能把多端登录或多个专家配置当作已经完成的团队协作。

当前已实现

多专家配置与任务级选择

用户可以创建多个专家，不同任务选择不同专家。专家拥有自己的规则和私人经验；当前每个任务由一个专家执行。

例如，分别建立行业研究、财务分析和风险检查任务，手动选择对应专家。

后续规划

多智能体自动协作

主控智能体拆解问题、分派专家子任务、汇总结果；专业专家可分别分析、交接和审核，并处理结论分歧。

后台需要控制权限、并发、预算与上下文边界。当前未实现自动组织多个专家完成整份报告。

后续规划 · 第三阶段

以项目为单位的团队合作

成员、共享与任务

  • 邀请成员，区分负责人、编辑者和只读成员。
  • 明确选择共享的资料、成果和任务。
  • 分派任务，跟踪进度，评论并审核交付。

共同记忆与权限边界

  • 项目记忆由有权限的成员审核确认，处理编辑冲突。
  • 授权范围内实时同步，断线补拉。
  • 成员退出后停止后续访问、下载和事件推送。
默认保持私人边界

加入项目组不会自动共享个人记忆、私人对话或私人专家经验。团队复用经验需要显式发布和审核。已导出到个人设备的文件无法承诺远程收回，在线共同编辑文档与离线合并属于进一步增强。

11 / A complete working story

用一次持续研究，串起整个产品。

演示场景：跟踪一家公司的库存变化。将资料、判断口径、工作方法和最终成果放进同一个项目，观察 AI 如何随工作推进积累可确认的背景。

建立项目，明确研究框架

选择或调整项目记忆模板，写明目标、观察指标、相反证据和结论失效条件；选择研究员专家。

补充资料，提出具体工作要求

上传报告与数据，说明希望比较的区间和输出形式；后台保存资料，模型通过可用工具读取相关内容。

执行分析，核对过程与成果

通过 Skill/MCP 执行经授权的步骤，查看回复、调用与任务状态，下载生成的成果并检查版本。

纠正研究方法，人工确认专家经验

提出“先统一统计时间与范围”的要求，查看带来源的经验建议，编辑后确认，而非直接将模型概括视为事实。

继续长对话，确认阶段摘要

工作累积后整理摘要，检查关键约束、已完成事项和未完成问题，再继续推进。

开启新任务，验证复用与遗忘

同一专家读取已确认经验；调整或删除记忆后，验证新任务不会继续加载已撤销内容。

用实际工作验证价值

试用时记录背景重复输入次数、资料整理耗时、成果返工次数、记忆建议采纳率与跨任务复用效果。效率提升比例应来自真实试用数据，不预先承诺。

类型检查、lint、依赖边界与网页构建通过。真实模型验证了专家建议、编辑确认、跨任务复用与删除；浏览器验证了专家管理及确认操作。

恢复与交付验证

数据库及文件配套恢复、旧备份结合较新清单的删除回放均已验证。测试数量不等于生产成熟度，真实模型与浏览器验收为不同测试流程。

第一阶段 · RC.1

单用户完整工作流程

项目、任务、聊天与附件，三层记忆、摘要确认、专家经验、Skill/MCP、成果与版本、基本恢复。

第二阶段 · 规划

多用户并发与调度

持久队列、执行池、公平调度，用户与模型额度，跨实例恢复和压测；按需求推进自动扩缩。

第三阶段 · 规划

项目团队协作

成员角色、显式共享、任务分派、项目记忆审核，实时同步、并发冲突与撤权传播。

独立能力路线

多智能体自动分工与经验转 Skill 后续细化；向量 RAG、结构化指标库及文档处理增强目前暂缓。当前本地 WSL 已运行 RC.1；截至本介绍基线，公网仍为 preview.38，RC 远端发布受 SSH 连通性影响。此页不自动检测部署状态。
