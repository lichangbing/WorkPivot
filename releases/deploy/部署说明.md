# WorkPivot 服务端部署说明（M5 开发版）

**当前部署**：后台已独立部署至192.168.1.158:39800，桌面v0.3.0-preview.2已改为纯客户端。具体配置、访问方式和首次登录见[部署记录](192.168.1.158.md)。下文Windows通过WSL执行的说明属于先前单机形态；新版客户端无需本机WSL/Docker，也不会执行任务命令。

2026-09-08 已在 WSL Ubuntu 24.04 / Docker 29.7.2 实测构建、非 root 服务、Linux 常规回归和隔离卷备份恢复。尚未发布 RC；真实模型业务验收、生产 HTTPS 和历史版本跨版本迁移仍需目标环境验证。

## 首次部署

1. Linux x64 主机准备 Docker、Compose 和 HTTPS 域名；备份工具需要宿主 Node.js 22。
2. 将仓库根 .env.example 复制为 .env，用两份独立随机值填写主密钥与初始化凭据，例如分别执行 `openssl rand -hex 32`。限制 .env 读取权限，独立保管密钥备份，不提交仓库。
3. 仓库根执行 `docker compose up -d --build`，检查日志和健康端点。若桥接网络下载超时，可先在 code 目录执行 `docker build --network=host -t workpivot-server:0.3.0-dev .` 再启动 Compose。
4. 端口仅绑定 127.0.0.1:39800。同机配置 Caddy，参考 [Caddyfile.example](Caddyfile.example)，替换实际域名并验证证书、SSE 流式响应和多人登录。生产 HTTPS 尚未实机验收。
5. 浏览器首注册填写用户名、密码和初始化凭据；之后注册关闭，由管理员分配账户、项目负责人和成员。

默认 Compose **不挂载 Docker socket**。可使用对话、文件工具、项目和后台功能；命令执行缺少隔离环境时明确失败，不回退到宿主 shell。

## 命令执行环境

Windows 桌面通过默认 WSL 发行版内的 Docker 调度一次性 Linux 容器。须先启动 WSL/Docker 并构建执行镜像；无需把 socket 挂入容器。该路径已通过真实文件及 Word/Excel/PPT 生成测试。命令使用 POSIX shell、Node.js 和相对路径；本版不提供 Python、网络下载或 Windows cmd 兼容。

容器中的服务调度工作容器需要显式启用 [docker-compose.execution.yml](../../docker-compose.execution.yml)，并填写 WORKPIVOT_DOCKER_GID（通过 `stat -c %g /var/run/docker.sock` 获取）。这会把 Docker 管理权限交给服务，适用于经授权的专用 Docker 主机，不能把非 root 等同于 Docker API 最小权限。本次用户选择暂不允许 socket 挂载测试，因此这一路径**未验证，不应作为已验收功能启用**。

执行只复制可读取的任务文件，排除链接、其他私有项目和其他临时任务。工作容器无网络、非 root、只读根目录、无 capabilities、禁止提权，限制 CPU/内存/进程数；应用数据目录为空且只读。输入只读，工作区使用内存盘。成功后通过受限标准输出导出普通文件，销毁容器，再检查写权限和原文件指纹；非零退出、取消、链接产物、权限拒绝或冲突不回写。

单次输入和输出各限 128 MiB、10000 项，命令最多 120 秒，后台进程不保留。服务异常退出后工作容器通常在 150 秒内自动退出，下次执行清理同一实例的遗留容器和暂存文件；同一数据目录仅允许一个服务实例使用。回写预检后逐文件原子替换，**不提供跨文件事务**。大型工程应缩小任务目录。

WORKPIVOT_EXECUTION_MODE=trusted-local 仅用于非 production 的合成数据回归，生产忽略此值。该模式不具备文件系统沙箱隔离，不用于业务部署。

preview.4 起，命令执行默认关闭，未启用时不会向模型提供命令工具。只有显式 WORKPIVOT_EXECUTION_MODE=docker 才选择隔离执行；上述 execution 覆盖配置已包含此值。192.168.1.158 保持默认关闭，不应用该覆盖配置。可继续处理文本、Markdown、CSV；依赖脚本的 Word/Excel/PPT 生成尚不可用。

## 配置

| 变量 | 规则 |
|---|---|
| WORKPIVOT_SECRET_KEY | 64 位十六进制；跨重启、升级与恢复保持一致 |
| WORKPIVOT_ADMIN_INIT_TOKEN | 对外首启至少 24 字符，Compose 要求明确配置 |
| WORKPIVOT_SESSION_TTL_HOURS | 默认 24，正数且不超过 720；旧无期限会话需重新登录 |
| WORKPIVOT_IMAGE | 默认 workpivot-server:0.3.0-dev；正式部署固定已验收镜像 |
| WORKPIVOT_EXECUTION_IMAGE | 工作容器镜像，应与服务预装文档依赖一致 |
| WORKPIVOT_EXECUTION_ROOT / VOLUME | 可选 Docker 调度暂存目录和对应卷名；多实例必须独立 |
| WORKPIVOT_HOME / WORKSPACE | 默认 /data/workpivot 和 /data/workspace |
| WORKPIVOT_WEB_DIST | 镜像默认 /app/apps/web/dist，托管用户端和管理端 |
| WORKPIVOT_ALLOW_EXTERNAL_DIRECTORIES | 默认关闭，仅管理员显式启用后可建界外项目 |

Electron 使用系统加密；Node 服务缺失主密钥拒绝启动。对话、引用文件和工具输出会发送给模型供应商，应按业务数据范围选择模型服务。

## 备份、恢复与回滚

在 Linux Docker 宿主运行 [snapshot.mjs](snapshot.mjs)：

    node releases/deploy/snapshot.mjs backup workpivot-server /secure-backups/workpivot-20260908
    node releases/deploy/snapshot.mjs restore /secure-backups/workpivot-20260908 wp-restored-data wp-restored-workspace

备份目录必须不存在。工具读取实际命名卷，停止服务后打包两个卷、记录镜像 ID 和 SHA-256，结束后恢复原运行状态。备份不含主密钥、Compose 配置及镜像二进制，三者须另行安全保管；镜像可用 docker image save 保存。归档含业务数据，应限制访问。

恢复先校验摘要和本地镜像，再创建两个全新卷，拒绝覆盖已有卷。卷权限恢复为 UID/GID 1000，并清空恢复副本的会话主文件及备份，避免历史令牌复活。用原主密钥、记录的镜像 ID 和恢复卷在隔离端口启动，验证账户、项目、文件和供应商后再切换入口。

升级前保存完整快照、旧镜像和旧配置。回滚须同时恢复匹配数据与镜像；不识别新密文的旧程序不能直接读取升级后的数据。当前验证的是快照恢复和固定镜像回滚，不等同于所有历史版本迁移通过。旧 root 卷先备份，再仅针对已确认业务卷调整为 1000:1000。

[rehearsal.mjs](rehearsal.mjs) 自动创建、验证和清理合成测试容器与卷，不挂载 Docker socket。报告位于 code/eval/deployment-baseline.json；不包含真实模型、生产 HTTPS 和 socket 调度验收。
