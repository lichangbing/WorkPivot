# 数据恢复与删除记录回放

恢复只在离线的新数据库和独立文件副本操作；不要先恢复旧备份对外提供服务。本工具将旧状态与较新的无正文保留清单对照，撤销已删除或版本不再一致的内容。

1. 暂停源服务写入，保留 PostgreSQL、文件、密钥和配置的一致性备份。使用源库的受保护 `WORKPIVOT_DATABASE_ADMIN_URL` 和受限 `WORKPIVOT_DATABASE_URL` 执行 `tsx scripts/restore-retention.mts export /protected/retention.json`。输出只包含归属 ID、保留对象 ID 和版本；文件不能已存在，避免覆盖较新的清单。将最新清单单独保存，恢复旧备份时使用最新可信清单。
2. 恢复数据库到名称以 `_restored` 结尾的新库，并将原件恢复到新的目录。恢复数据库角色，两个连接都指向这个离线库：管理员连接只处理身份状态，业务连接必须通过无超级用户权限、无 BYPASSRLS 的角色检查。
3. 设置 `WORKPIVOT_OFFLINE_RESTORE=1`、`WORKPIVOT_DATABASE_FILES_ROOT` 指向恢复目录，运行 `tsx scripts/restore-retention.mts apply /protected/retention.json`。普通名称的业务库会被拒绝；不自动启动服务。
4. 工具撤销旧登录、运行上下文和摘要，删除清单中已不存在的项目、任务、文件及私人专家；对已删除或版本不一致的记忆/经验清除正文及历史。版本不一致的专家设定清空并停用，避免旧角色内容悄悄生效。原始对话展示可保留，但模型不会重放旧上下文，用户检查后重新发起。
5. 离线验证归属隔离、遗忘、文件完整性和配置后，才切换业务服务连接。原备份保持只读。脚本失败时禁止上线，可重新恢复副本再执行；回放支持重复执行。

清单仅能覆盖导出时已知的删除，不能推断清单之后未记录的操作。正常备份策略需要约定导出频率、保留周期及可接受的数据恢复时间点；没有可信较新清单时，不得声称任意旧备份已完成遗忘校验。

验收：临时 PostgreSQL 上实际执行“创建记忆/经验/原件→备份→删除→导出新清单→恢复旧备份与文件→回放清单”。删除内容均不可再读取，保留原件字节一致；数据库回归另覆盖跨用户隔离和重复回放。不会清除外部备份介质上的原始副本，备份介质按独立保留策略处理。
