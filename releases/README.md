## 版本阶段

| 阶段 | 目的 | 出口条件 |
| --- | --- | --- |
| Preview | 快速验证功能链路 | 可运行、可回退，允许功能不完整 |
| RC | 单用户/小团队候选交付 | 核心任务、权限、文件、备份、恢复和真实模型链路通过 |
| Stable | 正式私有化版本 | RC 门槛 + 长稳、第二设备、复杂业务样版、许可和完整运维材料 |
| Enterprise | 组织化部署 | 稳定版 + IAM、组织同步、项目协作与分级审计 |

## 发布目录约定

```text
releases/
├── CHANGELOG.md
├── README.md
├── deploy/                  # Compose、Dockerfile、安装/升级/恢复脚本
└── vX.Y.Z/                  # 版本说明、校验和与必要发布材料
```

大体积安装包、镜像和备份不提交 Git。发布说明应记录：

- 版本、日期、commit/tag 和镜像 ID。
- 数据库 schema 与迁移范围。
- 新增、变更、修复和破坏性变更。
- 安装/升级/回退步骤。
- 实际验证项、未验证项和已知限制。
- 制品地址与 SHA-256。

## 发布流程

1. 更新 PRD、架构、状态和 CHANGELOG。
2. 通过类型检查、lint、文档链接、许可、核心集成测试与真实冒烟。
3. 生成数据库和文件联合备份。
4. 构建固定版本镜像并记录 ID/摘要。
5. 在隔离环境执行安装和升级/回退。
6. 在目标环境执行健康检查与用户主路径验收。
7. 发布后在 `STATUS.md` 写明“已部署到何处”和未覆盖范围。

## 命名

遵循语义化版本：

- `v0.x.y`：研发与候选阶段。
- `v1.0.0+`：正式私有化交付。
- `-preview.N`：开发预览。
- `-rc.N`：发布候选。

已发布目录不要复用或覆盖。历史发布说明保留当时事实；后续修订使用新版本或新增勘误段。
