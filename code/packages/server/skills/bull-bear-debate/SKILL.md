# 多空辩论

用两个互相独立的子代理分别构建看多与看空论证，再由主代理当裁判做对照评分。
目的是**暴露分歧**，不是给出"正确"结论；结论必须带条件与反证。

## 何时使用

- 用户要对一个标的、项目或方案做正反评估、风险评估、投决参考。
- 用户明确要求"多空""正反""红蓝对抗""挑毛病"。
- 不适用于事实查询、格式转换、单步计算。

## 输入

1. 明确辩题：标的/方案名称 + 评估周期（如"未来 12 个月"）。
2. 明确证据范围：用 `list_uploaded_files` 和用户本轮指定附件，只引用已授权的文件与网页。
3. 若辩题或周期缺失，先用 `ask_user` 提一个问题确认，不要自行假设。

## 步骤

### 1. 并行构建双方论证（各一次 `delegate`）

两次委派必须**互相看不到对方**，所以分别调用、分别给背景，不要在一次任务里让它们对话：

- 看多：`task` 写"为<辩题>构建看多论证：3-5 条核心论据，每条给出证据来源（文件名+位置或网页 URL）与可验证的量化指标"。
- 看空：`task` 写"为<辩题>构建看空论证：3-5 条核心反驳，每条给出证据来源与可能被证伪的条件"。
- 两次 `context` 里放同一份背景（辩题、周期、证据清单），并明确"只基于这些资料，不足处标注缺口"。
- `max_steps` 建议 12-20；子代理结论要求包含：论点、证据、关键假设、最可能出错的环节。

### 2. 裁判对照

拿到两份结论后，主代理按同一维度逐条对照，不要简单罗列：

| 维度 | 看多主张 | 看空主张 | 证据强度 | 分歧性质 |
|---|---|---|---|---|
| （逐条） | | | 强/中/弱，注明来源 | 事实分歧 / 假设分歧 / 时间尺度分歧 |

再给出：

1. **评分**：看多、看空各 0-10 分，说明扣分点。
2. **共识**：双方都认可的事实（这部分风险最低）。
3. **关键分歧**：决定结论的那 1-2 条，以及各自成立需要什么条件。
4. **条件化结论**："若 A 成立则偏多，若 B 出现则偏空"，禁止只给单向结论。
5. **反证清单**：出现哪些信号应推翻当前判断。

### 3. 产出

- 用 `save_artifact` 保存 Markdown 报告，文件名 `多空辩论 <辩题> v1.0 <日期>.md`。
- 用 `deliver_files` 登记，确保用户可下载。
- 正文先给结论与关键分歧，再展开双方论证与证据表。

## 纪律

- 所有论据必须能追溯到已读取的资料；没有证据的推断标"假设"，不得伪装成事实。
- 不得因为用户语气倾向而调整评分；两边证据强度不对称时如实写出。
- 子代理失败或超预算时，说明缺哪一侧、结论可靠性下降，不得用单边论证冒充辩论。
- 资料不足时先补问或标注缺口，不要用"一般来说"填充。
